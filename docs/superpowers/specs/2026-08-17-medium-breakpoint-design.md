# 미디엄 구간 설계 (창 폭 720–1199px)

- 상태: 승인 대기 (2026-08-17)
- 브랜치: `feature/medium-breakpoint`
- 관련 문서: [design-system ADR-001](../../design-system/decisions/adr-001-breakpoint-tokens.md) ·
  [app-shell ux-spec §3](../../features/app-shell/ux-spec.md) ·
  [design-system tokens.md §4](../../design-system/tokens.md) ·
  [와이어프레임](../../design-system/wireframes/medium-breakpoint.html)

## 1. 문제

창을 화면 절반으로 두면 가운데 타이머 카드만 짓눌린다.

`App.tsx` 의 본문은 좌(`w-[300px]`) · 중(`flex-1`) · 우(`w-[360px]`) 3컬럼이다. `flex-1` 은
`flex-basis: 0` 이므로 가운데 칸은 고유 폭이 없고, 좌우 고정폭 660px 과 여백·간격 96px 을
뺀 나머지를 그대로 자기 폭으로 받는다.

```
타이머 폭 = 창 폭 − 756px
```

창이 1280px 이면 524px 로 넉넉하지만, 절반인 756px 이면 계산값이 0에 수렴한다. 게다가
가운데 섹션에 걸린 제약은 `min-h-[320px]` 즉 **높이**뿐이고 최소 폭이 없다. 같은 요소의
`overflow-hidden` 이 flex 자동 최소 크기까지 0으로 떨어뜨려, 내용이 요구하는 폭조차
바닥 역할을 못 한다. `window.ts` 에도 `minWidth` 가 없어 하한이 없다.

근본 원인은 ADR-001 이 승인한 3구간 반응형이 문서로만 존재하고 코드에 미구현이라는
점이다. 와이드 레이아웃 하나가 모든 창 폭을 감당하고 있고, 그 결과 폭이 모자랄 때 가장
먼저 사라지는 것이 **타이머** 다. "타이머가 코어 루프, 계획은 레이어" 라는 ADR-001 의
접힘 우선순위와 정확히 역행한다.

## 2. 범위

- **한다**: 미디엄 구간(720–1199px) 레이아웃, MONTH 오버레이와 타이틀바 토글, 구간 전환
  연속성, 타이머 최소 폭, 창 최소 폭.
- **안 한다**: 내로우 구간(1컬럼 + 탭). ux-spec §5 의 연속성 규칙 중 내로우가 얽힌 행도
  이번 구현 대상이 아니다. 내로우가 없는 동안은 창 하한으로 그 구간에 진입 자체를 막는다.

## 3. 결정

### D1. `--bp-medium` 을 800px → 720px 로 내린다

- **문제**: 이 맥북은 논리 해상도 1512pt 이라 절반 창이 약 756px 인데, ADR-001 의 미디엄
  하한은 800px 이다. 즉 사용자가 실제로 겪는 그 폭은 미디엄이 아니라 내로우 구간이고,
  미디엄만 구현하면 문제의 화면이 그대로 남는다.
- **결정: 미디엄 구간을 `720px 이상 1200px 미만` 으로 다시 긋는다.**
- **근거**: 미디엄 레이아웃의 실측 하한이 720px 이다 — 우측 계획 컬럼 360px + 간격 24px +
  좌우 여백 48px 을 빼면 타이머에 288px 이 남고, 타이머 내용(링 최대 220px, 조절 칩 6개
  줄)이 그 폭에 들어간다. 800px 은 ADR-001 이 스스로 "시안 실측 전 추정치" 라고 적어 둔
  값이며, 같은 문서가 조정 시 tokens.md 와 ADR 을 함께 갱신하라고 지시한다.
- **안 그러면**: 노트북 화면을 반으로 갈라 쓰는 가장 흔한 배치에서 앱이 계속 깨진다.

### D2. 창 최소 폭을 720px 로 건다

- **문제**: 내로우를 이번에 만들지 않으므로 720px 아래는 대응이 없는 구간이다.
- **결정: `BrowserWindow` 에 `minWidth: 720` 을 준다.** 값의 출처는 D1 의 `--bp-medium`
  이며 상수를 따로 박지 않는다.
- **안 그러면**: 사용자가 창을 더 줄일 수 있고, 그 순간 지금과 똑같이 눌린 화면이 나온다.
  하한이 없으면 "미구현" 이 "버그" 로 보인다.
- 내로우가 구현되면 하한을 ADR-001 §3 의 목표치(~420px)로 내린다.

### D3. MONTH 오버레이는 우측 계획 컬럼(WEEK·TODAY)을 덮는다

- **문제**: ux-spec §3.1 은 오버레이가 좌측에서 슬라이드-인 하고 폭은 와이드의 MONTH 컬럼
  폭(300px)을 유지한다고 정했다. 그런데 756px 창에서 타이머 칸은 324px 이라, 좌측에서
  300px 짜리 오버레이가 뜨면 타이머를 거의 통째로 덮는다. 같은 표가 "열린 동안에도
  타이머·WEEK·TODAY 조작이 가능하다(PRD R10)" 라고 못박고 있어 문자 그대로 모순이다.
- **결정: 오버레이를 우측에 붙이고 WEEK·TODAY 컬럼 위를 덮는다.** 폭 300px, 슬라이드-인
  방향은 우측에서 왼쪽으로.
- **근거**: 타이머는 어떤 상태에서도 보이고 조작 가능해야 한다. MONTH 와 WEEK·TODAY 는
  둘 다 계획 레이어이므로, 좁은 화면에서 계획끼리 자리를 교대하는 것이 "타이머가 코어
  루프, 계획은 레이어" 원칙과 일치한다.
- **안 그러면**: MONTH 를 여는 순간 남은 시간과 일시정지 버튼이 가려진다. 세션 중에
  이번 달 진행을 확인하려면 타이머를 시야에서 지워야 한다.
- ux-spec §3.1 의 방향 규칙을 이 결정으로 개정한다. 오버레이가 비모달이고 스크림·포커스
  트랩이 없다는 나머지 규칙은 그대로 유지한다.

### D4. 구간 판정은 React 훅 한 곳이 소유한다

- **문제**: 구간 판정을 CSS 미디어 쿼리에 두면 ux-spec §5 의 연속성 규칙("와이드에서
  미디엄으로 넘어오면 오버레이가 열린 상태로 진입한다")을 표현할 수 없다. 그것은 상태가
  아니라 **전환 이벤트** 에 반응하는 규칙이다.
- **결정: `useBreakpoint()` 훅이 `matchMedia` 로 `'wide' | 'medium'` 을 반환하고, 레이아웃
  분기와 오버레이 상태를 모두 React 가 판단한다.**
- **안 그러면**: 판정 출처가 CSS 와 JS 두 곳으로 갈린다. 값이 어긋나는 순간 "레이아웃은
  미디엄인데 토글은 안 보인다" 같은, 재현 조건이 창 폭 1픽셀인 버그가 생긴다.
- 경계값 자체는 `src/shared/layout/breakpoints.ts` 한 곳에 두고 훅과 main 프로세스가 함께
  읽는다. tokens.md §4 가 값의 출처라는 ADR-001 §2 의 원칙은 그대로다 — 코드에 리터럴
  `720` · `1200` 을 직접 적는 곳은 이 파일뿐이다.

### D5. 타이머 섹션에 최소 폭 288px 을 준다

- **결정: 타이머 섹션에 `min-w-[288px]` 을 준다.** 창 하한(D2)과 함께 두 겹이다 — 하한이
  구간 진입을 막고, 최소 폭이 그 안에서 타이머가 더는 눌리지 않게 받친다.
- **안 그러면**: 우측 컬럼 폭이 나중에 바뀌거나 여백이 늘면 타이머만 다시 조용히 줄어든다.

## 4. 구조

### 4.1 새로 만드는 것

| 파일 | 책임 |
|---|---|
| `src/shared/layout/breakpoints.ts` | `BP_MEDIUM = 720` · `BP_WIDE = 1200` 상수. main·renderer 공용 |
| `src/renderer/shared/layout/useBreakpoint.ts` | `matchMedia` 를 구독해 `'wide' \| 'medium'` 반환 |
| `src/renderer/features/shell/MonthColumn.tsx` | 마일스톤 카드 + 캘린더 카드 묶음. 와이드의 좌 컬럼과 미디엄의 오버레이가 **같은 것을 렌더한다** |
| `src/renderer/features/shell/MonthOverlay.tsx` | 우측 슬라이드-인 오버레이 껍데기. 닫기 버튼·`Esc`·포커스 이동 담당 |
| `src/renderer/features/shell/MonthToggle.tsx` | 타이틀바의 MONTH 토글 버튼 (lucide `PanelRight`) |

`MonthColumn` 분리가 핵심이다. 와이드 컬럼과 미디엄 오버레이가 각자 마일스톤·캘린더를
렌더하면 두 벌이 되고, 카드 구성이 바뀔 때 한쪽만 고치는 사고가 난다.

### 4.2 고치는 것

| 파일 | 변경 |
|---|---|
| `src/renderer/app/App.tsx` | 구간에 따라 좌 컬럼을 렌더하거나 오버레이로 넘긴다. 타이머 섹션에 `min-w` 추가. 주석의 "반응형은 만들지 않는다" 를 갱신 |
| `src/renderer/features/shell/TitleBar.tsx` | 미디엄일 때만 MONTH 토글 렌더. "MONTH 토글은 아직 없다" 주석 제거 |
| `src/main/window.ts` | `minWidth: BP_MEDIUM` |
| `docs/design-system/tokens.md` §4 | `--bp-medium` 720px |
| `docs/features/app-shell/ux-spec.md` §3.1·§5 | 오버레이 방향·덮는 대상, 구간 경계 |
| `docs/design-system/decisions/adr-011-*.md` | 신규 — ADR-001 §1·§3 을 부분 superseded |

ADR-001 을 직접 고치지 않는 이유는 프로젝트 규칙이다 — 뒤집힌 결정은 기존 ADR 을 수정하지
않고 superseded 표기 후 새 ADR 을 추가하며, 일부만 뒤집힌 경우 어느 절이 죽고 어느 절이
살아 있는지 명시한다. ADR-001 §2(소비 방식)는 그대로 살아 있다.

### 4.3 상태 소유

오버레이 열림 상태는 `App` 이 `useState` 로 든다. 저장하지 않는다 — ux-spec §3.1 이 콜드
스타트 초기값을 "접힘" 으로 정했고, 그 이후의 값은 §5 의 연속성 규칙이 결정한다.

| 전환 | 오버레이 결과 |
|---|---|
| 콜드 스타트 (미디엄) | 닫힘 |
| 와이드 → 미디엄 | **열림** — 와이드에서 MONTH 가 보이고 있었으므로 가시성이 이어진다 |
| 미디엄 → 와이드 | 오버레이가 사라지고 MONTH 가 좌 컬럼 자리로 복귀 |
| 미디엄 안에서 토글·`Esc`·닫기 버튼 | 사용자 조작대로 |

구간 전환 중에 데이터 리페치·mutation 을 트리거하지 않는다 (ux-spec §5).

### 4.4 접근성 (ux-spec §8.1)

- 오버레이는 **비모달** 이다. 포커스 트랩을 걸지 않고 스크림도 두지 않는다. `Tab` 으로
  오버레이 밖(타이머)에 도달할 수 있어야 한다. 덮이는 WEEK·TODAY 는 열려 있는 동안
  `inert` 다 — 트랩이 없다는 것과 "가려진 컨트롤에 `Tab` 이 닿아도 된다"는 다른 말이다.
- **사용자가 토글로 연 경우에만** 포커스가 오버레이 첫 요소로 이동하고, 갇히지 않는다.
  구간 전환으로 저절로 열린 오버레이는 포커스를 가져오지 않는다.
- 닫는 경로는 **토글 재클릭 · `Esc` · 오버레이 우상단 닫기 버튼** 셋뿐이다. 바깥 클릭으로
  닫지 않는다 — 타이머 버튼은 정의상 "밖" 이므로, 일시정지를 누를 때마다 오버레이가
  예고 없이 닫히게 된다.
- 구간 전환으로 포커스된 요소가 사라지면 포커스를 그 요소를 담고 있던 카드 컨테이너로
  옮긴다. `body` 로 되돌리지 않는다.
- 토글·닫기 아이콘은 lucide-react 컴포넌트다. 이모지 금지.
- **오버레이에 모션을 두지 않는다.** 슬라이드-인을 구현했다가 실측 후 걷어냈다 — 판이
  미끄러지는 동안 눈이 붙잡을 모서리가 없어 "상태 변화 전달"이라는 목적을 못 했다. 층은
  `--glass-shadow` 가 만든다. 전이가 없으므로 `prefers-reduced-motion` 분기도 두지 않는다
  ([design-system ADR-011](../../design-system/decisions/adr-011-medium-range-revision.md) §2).

## 5. 테스트

전부 vitest + Testing Library 로 닫는다. `matchMedia` 는 jsdom 에 없으므로 구간을 주입하는
테스트 헬퍼를 만들어 `window.matchMedia` 를 목으로 세운다.

| 대상 | 검증 |
|---|---|
| `useBreakpoint` | 경계값 앞뒤(719·720·1199·1200)에서 반환값. 리스너 정리 |
| `App` (와이드) | MONTH 컬럼이 있고 타이틀바에 토글이 없다 |
| `App` (미디엄) | MONTH 컬럼이 없고 토글이 있다. 토글로 오버레이가 열린다 |
| 연속성 | 와이드에서 미디엄으로 바뀌면 오버레이가 열린 상태가 된다. 반대 방향은 컬럼으로 복귀한다 |
| 닫기 경로 | 토글 재클릭·`Esc`·닫기 버튼으로 닫힌다. 오버레이 밖 클릭으로는 닫히지 않는다 |
| 비모달 | 오버레이가 열린 상태에서 타이머 시작 버튼이 클릭 가능하다 |
| `MonthColumn` | 와이드 컬럼과 오버레이가 같은 카드 구성을 렌더한다 |

창 최소 폭(`minWidth`)은 main 프로세스 설정이라 단위 테스트 대상이 아니다 — 실행 확인으로
검증하고, 값이 `BP_MEDIUM` 을 참조하는지만 코드로 본다.

## 6. 검증

- `pnpm vitest run` 전량 통과 (기준선 794 tests).
- `pnpm dev` 로 띄워 창을 1280 → 756 → 720 → 719 로 줄이며 눈으로 확인한다. 719 에서
  더 줄어들지 않아야 한다.
- 와이어프레임([medium-breakpoint.html](../../design-system/wireframes/medium-breakpoint.html))과
  실제 화면의 전환 동작이 일치하는지 대조한다.
