# PRD — 뽀모도로 데스크톱 앱 (월/주/일 계획 통합)

> 이직 준비(코테·포트폴리오·NestJS 학습)를 위한 개인용 집중 관리 도구.
> 타이머 + TODO + 캘린더에 월간/주간/일간 계획 계층을 결합한 Electron 앱.
> **디자인/동작 레퍼런스: `pomodoro-mockup-v7.html`** — 이 시안이 UI와 인터랙션의 기준이며, 본 문서는 시안에 담기지 않은 규칙과 데이터 구조를 명세한다.

---

## 0. 대상과 범위

- 사용자: 1인 (개인용). 로그인/멀티유저/동기화 없음.
- 플랫폼: Electron 데스크톱 (macOS 우선, Windows 호환 고려).
- 언어: 한국어 UI.
- v1은 로컬 단독 동작. 네트워크 기능 없음.

---

## 1. 핵심 설계 원칙 (구현 시 모든 판단의 기준)

1. **타이머가 코어 루프, 계획은 레이어.** 계획(월/주/일)이 하나도 없어도 타이머와 기록은 완전히 동작해야 한다. 계획은 있으면 풍부해지는 것이지, 없다고 막히는 게 없어야 한다.
2. **세 레벨은 서로 다른 질문에 답한다.**
   - 월 = "이번 달이 끝나면 뭐가 달라져 있나?" → 결과물(마일스톤), 상태로 기술, 2~3개.
   - 주 = "그 결과를 위해 이번 주 얼마만큼?" → 할당량(quota) + 뽀모 예산. 숫자가 처음 등장하는 레벨.
   - 일 = "지금 뭐 하나?" → 새로 계획하지 않고 주간 풀에서 **pull**만 한다. 하루 3개 이하 권장.
3. **뽀모 예산은 추정치.** 초과는 실패가 아니다. 초과 시 빨간색/경고 금지 — 앰버 글로우 + `+N 🔥` 배지로 긍정 처리. 계획 시점의 과적(할당 합 > 예산)만 경고하되, 확정을 막지는 않는다.
4. **자동 이월도 자동 폐기도 하지 않는다.** 주가 넘어가는 시점에 한 번 분류하되, 기본값은 이월(pre-selected)이고 예외만 손댄다. 아무것도 안 건드려도 합리적인 결과가 나와야 한다.
5. **리뷰는 안내하되 강제하지 않는다.** 배너로 알리고, 무시해도 앱의 모든 기능이 동작한다.
6. **시스템은 사실만 보여주고 판단은 사용자에게.** 이월 횟수 배지("3주째"), 예산 대비 소진 등은 표시만 한다. "버리세요" 류의 훈계 금지.
7. **실패 프레임 제거.** "미달성 N건" 대신 "다음 주로 넘어갈 N건". 리뷰 요약은 실제로 한 일(소진 뽀모, 공부한 날)이 먼저.
8. **집계는 아래→위 단방향 파생.** session → task → week item → milestone. 상위 레벨의 소진량은 절대 별도 저장하지 않고 항상 하위에서 집계한다. 부모-자식 수치 불일치는 구조적으로 불가능해야 한다.

## 2. 도메인 모델

### 2.1 계층 구조

```
Milestone (월, 결과물)
 └─ WeekItem (주, 할당량 + est🍅 + 요일 배치 의도)
     └─ Task (일 단위 조각 — 첫 pull 때 생성됨)
         └─ Session (타이머 1회 완료)
```

- WeekItem → Milestone 연결은 선택 (`milestone_id` nullable, UI에서 "기타").
- Task → WeekItem 연결은 필수 (task는 항상 어떤 주간 항목의 자식).
- Session → Task 연결은 선택. 연결 없는 세션 = **미분류 집중**.
- 오늘 TODO 목록은 별도 엔티티가 아니라 **task의 뷰**다. "오늘 목록에 있다"는 task의 속성(예: `pulled_date`)이지 복사본이 아니다. 오늘 목록에서 × 로 빼도 task는 주간에 남는다.

### 2.2 스키마 (SQLite + Drizzle 기준 제안)

시안은 인덱스 참조를 썼지만 **실제 구현은 반드시 ID 참조 + soft delete**. 인덱스 참조는 항목 삭제 시 참조가 깨진다.

```
settings
  key TEXT PK, value TEXT(JSON)
  -- weekly_capacity: [8,4,2,4,2,4,0] (일~토 요일별 가용 뽀모 "개수" — 분 단위 아님)
  -- focus_min / short_break_min / long_break_min (기본 25/5/15 — 변경은 주간 리뷰에서만, §3.8)
  -- last_settled_week: '2026-W33' (ISO week)

milestones
  id, month TEXT('YYYY-MM'), title, done INTEGER, sort_order,
  created_at, archived_at NULL

week_items
  id, week TEXT('YYYY-Wnn'), title, est_pomos INTEGER,
  milestone_id NULL FK, days TEXT(JSON, [0..6]),  -- 요일 배치 의도, 빈 배열 = 미배치
  carry_from_id NULL FK(week_items.id),           -- 이월 사슬. 이월 횟수는 사슬 길이로 파생
  status TEXT('active'|'done'|'dropped'),
  created_at, deleted_at NULL

tasks
  id, week_item_id FK, title, est_pomos INTEGER,
  done INTEGER, pulled_date TEXT NULL('YYYY-MM-DD'),  -- 오늘 목록 포함 여부
  created_at, deleted_at NULL

sessions
  id, started_at, ended_at, duration_sec,
  kind TEXT('focus'|'short'|'long'),
  task_id NULL FK,          -- NULL = 미분류
  note TEXT NULL            -- 사후 캡처 한 줄

week_settlements
  week TEXT PK, settled_at, budget INTEGER,
  focus_min INTEGER, short_break_min INTEGER  -- 그 주의 뽀모 베이스라인 스냅샷 (§3.8)
```

**파생값 규칙 (저장 금지, 항상 쿼리로 계산):**

| 값 | 계산 |
|---|---|
| task 소진 | `count(sessions where task_id = t.id and kind='focus')` |
| week item 소진 | 자식 task 소진 합 |
| milestone 이번 주/이번 달 소진 | 연결된 week_items의 소진 합 (기간 필터) |
| 주간 총 소진 | 그 주 focus 세션 수 전체 (미분류 포함) |
| 미분류 | 그 주 focus 세션 중 task_id IS NULL |
| 이월 횟수 | carry_from_id 사슬 길이 |
| 주간 기본 예산 | `sum(weekly_capacity)` (플래너 기본값, 주별 오버라이드 가능) |
| 캘린더 점 | 날짜별 focus 세션 수 (≥1 점, ≥4 진한 점) |

## 3. 기능 명세

### 3.1 타이머 (중앙, 코어)

- 모드: 집중 25분 / 짧은 휴식 5분 / 긴 휴식 15분 (기본값, 설정 가능).
- 시간 조절: ±1 / ±5 / ±10분 칩. 실행 중에도 조절 가능, 하한 1분.
- 시작/일시정지/초기화. 진행률 링(SVG, 틸→앰버 그라디언트).
- **집중 대상(◎):** 오늘 목록의 task 하나를 지정. 링 안에 이름 표시. 미지정/완료 상태면 "자유 집중".
- **세션 완료 시 (focus 모드만):**
  1. sessions에 무조건 insert (task_id는 집중 대상 또는 NULL).
  2. 집중 대상이 있으면 해당 task의 🍅 도트가 채워짐(파생). est 초과분은 밝은 앰버 extra 도트 + `+N`.
  3. 집중 대상이 없으면(자유 집중) **사후 캡처 바** 표시: "이 25분, 뭐 했는지 한 줄 남길래요?" — 입력 시 완료된 task로 소급 생성해 세션을 연결, 건너뛰기/Esc 시 미분류로 남음. 다음 세션 시작 시 자동 닫힘. **시작 전에 묻는 다이얼로그 절대 금지.**
  4. 알림음/OS 노티 (Electron Notification).
- 휴식 완료는 기록하되 집계에 미포함.
- 타이머는 main process에서 시간 기준으로 관리 (renderer setInterval 의존 금지 — 백그라운드 스로틀링 대응). 트레이 아이콘에 남은 시간 표시하면 가산점.

### 3.2 일 레이어 — 오늘 할 일

- 목록 = `tasks where pulled_date = today and deleted_at is null`.
- 항목 표시: 제목, 출처(`↳ 주간 항목명`), 🍅 도트(est 대비 spent), 완료 체크.
- 체크 → task.done 토글 (주간·마일스톤 집계에 즉시 반영).
- × → `pulled_date = null` (오늘 목록에서만 제거, task는 주간에 잔존). **삭제가 아님.**
- 직접 입력 추가도 가능: 이 경우 주간 미연결 임시 task 취급. 여기에 귀속된 세션은 주간 집계에서 미분류로 잡힌다. (구현 단순화를 위해 "기타" 가상 week_item에 붙이는 방식도 허용 — 단, UI상 미분류로 표기)
- 자정 경과 시 미완료 task는 자동으로 `pulled_date` 유지하지 않음(다음 날 오늘 목록에서 사라지고 주간 풀로 반납). 어떤 확인창도 띄우지 않는다.
- 빈 상태 카피: 주간 할당 있으면 "위 주간 할당에서 +오늘로 를 눌러 오늘 몫을 골라오세요 (3개 이하 권장)", 없으면 "계획이 없어도 타이머는 돌아가요."

### 3.3 주 레이어 — 이번 주 할당

**일반 뷰:**
- 항목별: 제목, 마일스톤 태그(M1/M2/…), 이월 배지(`N주째`, carry 사슬 ≥1일 때), 🍅 소진/est, task 완료 수, 요일 핍(일~토 — 배정 요일만 활성, 지난 요일 흐림, 오늘 앰버).
- 오늘 배정된 항목은 테두리 강조 + 목록 상단 정렬. **자동으로 오늘 목록에 push하지 않는다** — 요일은 예약이 아니라 배치 의도.
- 소진 ≥ est는 완료가 아니다. 항목 완료는 사용자가 별도로 체크(또는 자식 task 전부 done 시 완료 제안). 시간을 다 쓴 것과 일이 끝난 것을 구분한다.
- 미분류 집중이 1개 이상이면 점선 테두리의 톤 낮춘 행으로 표시: "미분류 집중 🍅 N — 할 일에 연결되지 않은 세션". pull 버튼 없음.
- 하단 고정: 뽀모 예산 게이지. `소진 / 예산`, 초과 시 앰버 글로우 + `+N 🔥`. 카피 "예산은 추정치예요 — 넘어가도 괜찮아요". 예산 미설정 시 바 숨기고 소진량만.

**task 드롭다운 (▶ 또는 "+오늘로"):**
- 항목을 펼치면 누적된 task 목록: 완료(취소선·흐림), 이미 오늘 목록에 있는 것("오늘 목록에" 표기·선택 불가), 선택 가능한 것(체크박스, 다중 선택).
- 하단에 새 task 입력 + est 스테퍼. **task가 하나도 없으면** 안내: "오늘 할 몫을 쪼개서 적어요 — 이게 첫 task가 돼요."
- "오늘로 가져오기" → 새 입력분 생성 + 선택분 모두 `pulled_date = today`.
- 즉, **첫 pull은 생성, 이후 pull은 선택.** task 목록은 계획서가 아니라 그 항목으로 뭘 해왔는지의 누적 기록이며, 주말 리뷰의 이월 판단 재료가 된다.

**주간 플래너 ("+이번 주 할당 잡기" / 수정):**
- 최대한 가볍게. 일요일 기준 4단계: ① 예산 확인(기본값 유지 시 클릭 0, 산출 힌트 표시) ② 항목 추가(제목 + est 스테퍼 + 마일스톤 칩[M1..Mn, 기타]) ③ 항목별 요일 칩(일~토, 다중 선택, **선택 사항** — 미선택 = 미배치) ④ 경고 확인.
- **계획 시점 검증 2종 (둘 다 경고만, 차단 금지):**
  - 총량: est 합 > 예산 → "+N 과적이에요. 하나 줄이거나 다음 주로 미룰까요?"
  - 요일별 부하: 항목 est를 배정 요일 수로 균등 분산 → 요일별 합 vs `weekly_capacity` 막대 그래프. 초과 요일 앰버 + 헤더에 "화·목 넘침". 미배치 항목은 부하에 미산입.
- 주중 재수정 허용. 확정 시 기존 항목의 task 이력·carry 사슬 유지 (ID 기준 매칭).

### 3.4 월 레이어 — 마일스톤

- 이번 달: 인라인 편집(제목 추가/삭제, 2~3개 권장 힌트), 체크 토글, M번호 자동 부여.
- 각 마일스톤에 연결된 주간 할당의 소진 롤업 표시: "이번 주 🍅 8/12" (v1은 이번 주 기준, 월 누적은 v1.1).
- **캘린더의 ‹ › 가 곧 마일스톤 네비게이션.** 별도 탭/모달 금지. 캘린더 월 이동 시 마일스톤 카드가 동기 전환:
  - 지난달: 읽기 전용 + 딤 + "N/M 달성 · 보관됨" 배지. 수정 불가 (리뷰 데이터 보호).
  - 미래/빈 달: "아직 계획 전" + "+ N월 계획 잡기" 고스트 CTA.
- 월 판별은 `'YYYY-MM'` 문자열 사전순 비교 (zero-pad 필수).

### 3.5 캘린더 + 날짜 기록

- 월 그리드. 공부한 날(focus 세션 ≥1) 틸 점, ≥4 앰버 큰 점. 오늘 앰버 숫자.
- 날짜 클릭 → 하단 패널: `M월 D일`, 🍅 횟수, 그날 task 완료/미완료 목록(pulled_date 기준). 오늘 선택 시 실시간 동기화.
- 스트릭 표시: "이번 주 N일 공부 중" (타이머 하단).

### 3.6 주간 리뷰 (정산)

**트리거 — 저장된 알림 큐를 만들지 말 것.**
- 저장값은 `last_settled_week` 하나. 앱 시작/포커스 시 `현재 주 > last_settled_week + 1`이면 정산 대기로 판정.
- **정산은 항상 최대 1건.** 여러 주를 비웠어도 배너/리뷰는 하나로 병합:
  - 결정 대상 = 마지막으로 **활동(세션 또는 계획)이 있던 주**의 미완료 항목들.
  - 중간의 완전 빈 주(세션 0, 신규 결정 없음)는 자동 통과 — 단, 미완료 항목의 이월 카운트에는 건너뛴 주 수가 반영된다 (사슬에 빈 주 수만큼 가산하거나, 주차 차이로 파생 계산).
  - 계획만 잡고 손도 안 댄 주는 빈 주가 아님 — 전부 spent 0 미완료로 리뷰에 포함.
- 배너 (주간 카드 상단, 앰버 톤): "지난주(범위) 정산이 기다려요 · 다음 주로 넘어갈 N건" + [리뷰 시작]. 배너를 무시해도 타이머·새 주 플래너 등 전 기능 정상 동작.
- 공백 복귀 시 요약 문구는 죄책감 없이 사실만: "2주 쉬었어요 · 마지막 주 🍅 20 소진".

**리뷰 패널 구성 (순서 고정):**
1. 요약 — 실제로 한 일 먼저: "지난주 N일 공부, 🍅 M 소진 (예산 B)". 달성률 % 크게 띄우지 않는다.
2. 끝낸 것들 ✓ 목록.
3. 남은 것들 — **전부 "다음 주로" pre-selected.** 항목별 3택:
   - `다음 주로`: 남은 몫(est − spent, 최소 1)으로 이월. carry +1.
   - `줄여서`: 스테퍼 노출, 기본값 = 남은 몫의 절반(올림). 축소 이월. carry +1.
   - `보내주기`: 폐기 (soft delete, status='dropped'). "버리기" 워딩 금지.
   - 이월 배지 표시. **carry ≥ 2 (3주째 이월)인 항목은 기본 선택을 비워서 한 번 의식적으로 고르게 한다** — 이월이 기본값이라는 원칙의 유일한 예외.
4. 안내: "미분류 🍅 N은 기록으로만 남아요. 할당이 틀린 건 실패가 아니라 정보예요."
5. [다음 주 시작 (이월 🍅 N 포함)] → 이월/축소분이 새 주 week_items로 생성(carry_from_id 연결, days 빈 배열), `last_settled_week` 갱신, `week_settlements` 기록. 이후 사용자가 플래너를 열어 신규 할당 + 요일 배치를 이어서 할 수 있다 (리뷰와 플래닝은 분리된 단계).

**월말 정산:** 공백/월 경계가 겹쳐도 별도 알림을 추가하지 않는다. 같은 복귀 화면에 섹션 하나로 병합: "8월 마일스톤 2/3 달성 · 미달성 1건 9월로 재설정할까요?" 마일스톤은 이월이 아니라 **재설정**(다음 달 맥락에서 유효한지 재판단) — v1은 "9월 마일스톤으로 복사" / "보관" 2택이면 충분.

### 3.7 콜드 스타트 / 빈 상태

- 첫 실행: 타이머 즉시 사용 가능, "자유 집중" 표시. 온보딩 투어 없이 각 패널의 빈 상태 카피가 역할을 설명한다 (시안 v7 카피 그대로 사용).
- 월 빈: "이번 달이 끝나면 뭐가 달라져 있을까요?" + CTA.
- 주 빈: "이번 주 할당을 잡으면 뽀모 예산이 여기 보여요" + CTA. 예산 미설정 상태에서도 소진 카운트는 표시.
- 계획 없이 완료한 세션 → 미분류 + 사후 캡처 플로우 (3.1 참조).

### 3.8 뽀모 예산의 단위와 베이스라인 변경

**1🍅의 정의: focus 세션 1회 완료 = 1🍅, 길이 무관 (횟수 기준).**
- 근거: 예산은 추정치(원칙 3)이므로 세션 중 ±조절에 의한 분 단위 오차는 노이즈로 취급한다. 세션별 `duration_sec`은 기록되므로 시간 기준 통계는 언제든 파생 가능 (v1 범위 밖).
- **세션 중 ±1/±5/±10 조절 = 그날의 예외 대응.** 뽀모의 정의(베이스라인)를 바꾸지 않는다. 35분짜리 세션도 1🍅.

**가용량과 예산: 뽀모 개수로 직접 입력 (분 단위 환산 금지 — 계산 부담).**
1. 설정 화면(M4)에서 요일별 가용 뽀모를 개수로 정의 (`weekly_capacity`, 예 `[8,4,2,4,2,4,0]`).
2. 주간 기본 예산 = 그 합. 플래너 예산 필드에 기본값으로 채워지고 힌트에 산출 근거 표시.
3. 플래너의 예산 입력은 그 주 한정 오버라이드 (회식·명절 등). 확정 시 `week_settlements`에 스냅샷.

**뽀모 길이 변경 = 베이스라인(측정 단위)의 재정의 — 일요일 주간 리뷰에서만 가능.**
- 집중/휴식 길이는 상시 설정 항목이 아니다. **주간 리뷰 패널의 마지막 섹션** ("다음 주 시작" 버튼 직전)에 배치: "다음 주 뽀모 길이 — 집중 25분 / 휴식 5분 (유지)". 기본 접힘, 안 건드리면 유지.
- 근거: 주중에 단위가 바뀌면 주간 소진·예산·지난주 비교가 전부 왜곡된다. 단위 변경은 "내 집중력이 변했다"는 자기 평가이므로 리뷰(성찰) 시점에 속한다. 주 경계에서만 바뀌므로 진행 중인 주의 게이지가 흔들리는 케이스 자체가 존재하지 않는다.
- **길이 변경 시 가용량 재확인 제안 (자동 변환 금지):** "집중 50분이면 아침 블록에 2🍅 — 요일별 가용량을 조정할까요?" 기계적 환산값을 제안으로 보여주되 최종 확정은 사용자. (길이를 바꾸는 사람은 휴식 비율도 달라지므로 자동 환산이 맞지 않는다.)
- **콜드 스타트 예외:** 첫 리뷰 이전에는 변경 기회가 없으므로, 최초 실행 시(또는 첫 주간 플래너에서) 한 번 설정 가능. 이후로는 리뷰 전용.
- `week_settlements`에 그 주의 focus/휴식 길이를 스냅샷 → "어느 주의 🍅가 몇 분짜리였는지" 이력 보존, 시간 기준 통계 복원 가능.
- 실적 기반 보정(최근 N주 평균 소진 참고치 병기)은 v1.1 후보. 표시만 하고 자동으로 낮추지 않는다 — 하향 나선 방지.

## 4. 레이아웃 & 디자인

- 3컬럼: 좌(MONTH 마일스톤 카드 + 캘린더 카드) / 중(타이머) / 우(WEEK 할당 카드 + TODAY 카드). 각 카드에 MONTH/WEEK/TODAY eyebrow 라벨.
- **글래스모피즘 "밤의 온실" 테마** — 시안 v7의 CSS 변수·수치를 그대로 이식:
  - 배경 `#0c1a16` + 틸/앰버/모스 라디얼 광원 + 미세 별.
  - 유리 카드: `rgba(255,255,255,0.055)`, `backdrop-filter: blur(24px) saturate(140%)`, 1px 보더, inset 하이라이트.
  - 액센트: teal `#6fd4b8`, amber `#f0b671`. 타이머 링은 teal→amber 그라디언트.
  - 폰트: Gothic A1(본문) + Azeret Mono(숫자·타이머, tabular-nums). 로컬 번들 권장 (오프라인 동작).
- 스크롤 영역 규칙 (시안 v3/v7 검증됨): 카드 = flex column, 고정 요소(헤더/입력/게이지) `flex-shrink: 0`, 스크롤 영역만 `flex: 1; min-height: 0; overflow-y: auto` + 상하 `mask-image` 페이드. **`min-height: 0` 누락 주의.**
- `prefers-reduced-motion` 존중. Electron 프레임리스 + 커스텀 타이틀바(트래픽 라이트 영역 drag).

## 5. 기술 방향

- Electron + React + TypeScript. 번들러는 Vite 기반(electron-vite 등).
- 로컬 DB: **better-sqlite3 + Drizzle ORM + drizzle-kit** (Prisma는 플랫폼별 쿼리 엔진 바이너리 패키징 문제로 배제).
  - 네이티브 모듈은 **main process 전용.** renderer는 contextBridge/IPC로만 접근. `contextIsolation: true`, `nodeIntegration: false`.
  - 프로덕션 마이그레이션 전략을 초기부터 설계 (drizzle-kit 마이그레이션을 앱 시작 시 적용).
- 타이머 tick은 main process, wall-clock 기준 (`Date.now()` 차분 — sleep/스로틀 복원 대응).
- 상태 관리: renderer는 Zustand 권장. DB가 source of truth, 스토어는 캐시.
- 테스트: Vitest + Testing Library(집계/리뷰 병합 로직, 컴포넌트), Playwright는 핵심 경로(세션 완료 전파, 리뷰 확정)만.
- 주차 표기는 ISO week (`YYYY-Wnn`), 주 시작 요일은 일요일 기준으로 통일 (시안과 동일 — capacity 배열 인덱스 0=일).

## 7. Non-Goals (v1에서 하지 않는 것)

- 클라우드 동기화, 모바일, 통계 대시보드(주간 리뷰 요약 이상의 차트), 뽀모도로 외 시간 추적, 자동 스케줄링/AI 추천, 실적 기반 예산 자동 보정(참고치 표시는 v1.1 후보), task 단위 요일 배정(항목 단위로 충분함이 검증되기 전까지).

## 8. 열린 결정 (구현 중 판단 필요 시 원칙 1~8로 회귀)

- 항목 "완료"의 확정 방식: 자식 task 전부 done 시 자동 제안 vs 항상 수동. (제안: 자동 제안 + 수동 확정)
- 직접 추가 임시 task의 저장 위치: 가상 "기타" week_item vs week_item_id nullable. (제안: 주차별 시스템 생성 "기타" 항목 — 집계 쿼리 단순화)
- 사후 캡처로 생성된 task의 주간 귀속: 미분류 유지 vs "기타" 항목 소속. (제안: "기타" 소속, 미분류 카운트에서 제외)
