# ADR-009: 시간 포맷 규약 — 4종 분류 + 시간 모듈 초크포인트

- 상태: accepted (2026-08-04) · **보강 (2026-08-06)** — §3 의 초크포인트에
  [ADR-022](adr-022-calendar-key-pairing.md) §1 이 `localKeys(atEpochMs?)` 를 더한다.
  **한 행에 함께 저장되는 달력 키 짝은 한 번의 시계 읽기에서 나온다** — 개별 함수를
  잇달아 부르면 자정 경계에서 서로 다른 주가 나온다. §1·§2·§4 와 §3 의 나머지는 유효하다.
- 결정 근거 원장: [2026-08-04 기획 검증 세션](../../decision-log/2026-08-04-planning-session.md) §A (Q1·Q2·Q9 파생)

## Context

이 앱의 시간 값은 성격이 다른 네 부류가 섞여 있다 — 일이 벌어진 시각(`started_at`),
날짜·주·월 귀속 키(캘린더 점, 주간 집계), 경과 시간(`duration_sec`), 타이머 IPC 의
런타임 값(ADR-005 의 `startedAt`). 초안 PRD 에는 포맷 규약이 없어 컬럼마다 표현이
갈릴 수 있었고, Q9(주 키) 논의에서 실무 타임포맷 관리 방식을 비교하며 다음이 확인됐다:

- SQLite 에는 날짜 타입이 없다. **TEXT ISO 8601 이 사실상 표준**이다 (내장
  `date()`/`strftime()` 이 이 포맷만 이해). epoch INTEGER 는 콘솔에서 직독 불가라 배제.
- 순간을 UTC 로 저장하고 **쿼리 시점에 로컬로 변환해 귀속**시키면, 타임존 이동 시
  과거 캘린더 점·주간 집계가 통째로 소급 이동한다. "8월 4일에 공부했다"는 사실이
  오늘의 타임존 설정에 따라 변하면 안 된다. 또한 술어에 `strftime()`/`date()` 를
  씌우면 인덱스가 무효화된다.
- 하루 경계 = **로컬 자정**(Q1), 자정을 걸친 세션의 날짜 귀속 = **`started_at` 기준**(Q2)
  이 이미 확정돼 있다.

## Decision

### 1. 시간 값 4종 분류

| 종류 | 의미 | 포맷 | 해당 값 |
|---|---|---|---|
| **순간** | 일이 벌어진 시각 | UTC ISO 8601 `'...Z'` TEXT | `started_at`, `ended_at`, `created_at`, `updated_at`, `planned_at`, `settled_at`, `completed_at`, `dropped_at`, `archived_at`, `deleted_at` |
| **달력 키** | 로컬 기준 귀속 단위 | `'YYYY-MM-DD'` / `'YYYY-MM'` TEXT | `local_date`, `local_week`, `pull_date`, `origin_week`, `month`, 주 키(`weeks.week`) |
| **길이** | 기간 | INTEGER + 단위 접미사 | `duration_sec`(초), `focus_min` 등 설정 길이(분) |
| **런타임** | 타이머 IPC 내부값 | epoch ms (number) | ADR-005 의 `startedAt` 등 — **저장 금지** |

- **길이의 단위는 컬럼명 접미사로 강제한다** (`_sec` / `_min`). 접미사 없는 시간 컬럼 금지.
  측정된 경과는 초(`duration_sec`), 사용자 설정 뽀모 길이는 UI 단위와 같은 분(`focus_min` 등).
- **런타임 값은 저장 경계에서 변환한다** — 세션 기록 시 epoch ms → 순간(UTC ISO)·길이(초).
  DB·문서·IPC 계약 어디에도 epoch ms 가 영속되지 않는다.

### 2. 달력 키는 "쓰는 순간 1회 계산, 이후 불변"

달력 키는 **행을 쓰는 순간 로컬 시간으로 1회 계산해 저장하고, 이후 재계산하지 않는다.**
조회 시 순간(UTC) 컬럼에서 날짜를 파생하는 방식은 금지 — 타임존 이동에 과거 기록이
흔들리고 인덱스를 못 탄다. 이것은 PRD 원칙 8(집계값 저장 금지)의 위반이 아니다:
달력 키는 아래→위로 합산되는 파생 집계가 아니라 **그 행 자신의 사실**(그 세션이 어느
로컬 날짜에 시작됐는가)이다.

### 3. 시간 모듈 초크포인트

`now()` / `dayKey()` / `weekKey()` / `monthKey()` 는 **`src/shared/` 의 시간 모듈 하나가
소유**한다. 그 모듈 내부를 제외하고 `new Date()` 직접 호출 금지. 포맷 통일이 규율이
아니라 구조로 유지되고, 테스트에서 가짜 시계를 주입해 자정 경계·연말(53주 연도)
케이스를 재현할 수 있다.

### 4. 경계에서 검증

zod IPC 계약(ADR-007)과 SQLite CHECK(ADR-011)에 포맷별 스키마/GLOB 패턴을 걸어,
잘못된 포맷은 저장 자체가 안 되게 한다.

## Consequences

- (+) 프로젝트의 저장 시간 포맷이 3개(순간/달력 키/길이)로 닫힌다. 컬럼명과 타입만
  보면 포맷을 판별할 수 있다.
- (+) 타임존을 옮겨도 과거 캘린더 점·주간 집계·스트릭이 불변이다.
- (+) 시간 관련 버그의 수사 범위가 시간 모듈 하나로 좁혀진다.
- (−) 순간(UTC)과 달력 키(로컬)의 이중 체계다. 변환 로직은 시간 모듈에만 존재해야
  하며, 화면·쿼리 코드에서 즉석 변환을 하는 순간 규약이 무너진다 — 코드 리뷰 관찰 지점.
- (−) 달력 키가 불변이므로, 세션 기록 후 타임존을 바꾼 사용자에게는 "현지 시간 기준
  어제"가 아니라 "기록 당시 로컬 기준 날짜"로 보인다. 1인 로컬 앱에서 의도된 동작으로
  수용한다.
