# ADR-017: 포매터 — Prettier 도입 (ADR-016 §2 대체)

- 상태: accepted (2026-08-05)
- 관계: [ADR-016](adr-016-lint-and-git-hooks.md) **§2 만 대체한다**(포매터 미도입 결정).
  ADR-016 의 나머지 절(§1 ESLint 아키텍처 규칙, §3 훅 3종, §4 훅에서 타입검사·테스트 제외,
  §5 로컬 훅은 최종 방어선 아님, §6 TypeScript 6.x 고정)은 **모두 그대로 살아 있다.**

## Context

ADR-016 §2 는 포매터를 도입하지 않기로 했다. 근거는 "1인 개발이라 스타일 충돌 비용이
아직 없다"였다. 그 전제가 사용자에 의해 뒤집혔다 — **이 저장소는 포크·기여를 받을 수 있고,
그 경우 서식 통일은 사후가 아니라 사전에 있어야 한다.** 기여자가 다른 서식으로 PR 을 올린
뒤에 통일하면 그 PR 의 diff 는 내용과 서식이 뒤섞여 리뷰가 불가능해진다.

ADR-016 §2 의 반대 근거였던 "전 파일 리포맷 커밋이 발생한다"는 실측으로 해소됐다:
현재 소스 파일 전부가 이미 Prettier 기본 스타일과 일치했고, 실제로 재정렬된 파일은
`eslint.config.js` 하나였다.

다만 **마크다운은 실측 결과 도입하면 안 되는 것으로 판명됐다.** Prettier 는 표 셀을
글자 수로 패딩하는데 한글은 두 칸 폭으로 렌더된다 — 정렬한다면서 오히려 어긋나게 만들고,
`docs/design-system/tokens.md` 한 파일에서만 252줄이 바뀌었다. 게다가 `docs/origin/` 은
읽기 전용이라(docs/CLAUDE.md) 포매터가 손대는 것 자체가 규칙 위반이다.

## Decision

1. **Prettier 를 도입한다.** 설정은 기존 코드가 이미 따르고 있던 스타일을 그대로 명문화한다:
   `semi: false`, `singleQuote: true`, `printWidth: 100`, `trailingComma: 'none'`.
   서식 논쟁을 없애는 것이 목적이므로 개인 취향으로 값을 조정하지 않는다.
2. **서식의 결정권은 Prettier 단독이다.** `eslint-config-prettier` 를 ESLint flat config
   **마지막**에 두어 충돌하는 규칙을 끈다. ESLint 는 아키텍처 규칙만 본다 (ADR-016 §1).
3. **마크다운과 `docs/` 는 포매팅 대상에서 제외한다** (위 Context 의 CJK 정렬·읽기 전용 사유).
   기획 문서의 서식은 사람이 정한다.
4. **`pre-commit` 훅에서 스테이지된 파일을 자동 포맷한다** (lint-staged: prettier → eslint 순).
   포맷을 "검사해서 거부"하지 않고 "고쳐서 통과"시키는 이유는, 서식은 사람이 판단할 것이
   없기 때문이다. 반면 ESLint 아키텍처 규칙은 사람이 고쳐야 하므로 거부한다.
5. 수동 실행은 `pnpm format`(수정) · `pnpm format:check`(검사)로 제공한다. CI 를 붙이면
   `format:check` 를 쓴다.

## Consequences

- (+) 기여자가 어떤 에디터를 쓰든 커밋되는 서식이 같아진다. PR diff 에 서식 잡음이 없다.
- (+) 서식 관련 리뷰 코멘트가 사라진다. 리뷰는 내용만 본다.
- (−) 포매터가 커밋 시점에 파일을 조용히 고친다. 커밋한 내용과 디스크의 내용이 미세하게
  다를 수 있다 — 에디터에 Prettier 를 연동해 두면 체감되지 않는다.
- (−) 마크다운이 제외되므로 **문서 서식은 여전히 사람이 지켜야 한다.** 자동화되지 않는
  영역이 남아 있다는 사실을 알고 있어야 한다.
- (−) `printWidth: 100` 은 임의값이다. 다만 이미 쓰고 있던 폭이라 재정렬 비용이 0 이었고,
  값 자체보다 "하나로 고정됐다"는 사실이 중요하다.
