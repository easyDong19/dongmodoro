# ADR-010: 주 정의 — 월요일 시작, 주 키 = 월요일 날짜, plan_lead_days

- 상태: accepted (2026-08-04) · **CHECK 식 정정됨 (2026-08-05, [ADR-019](adr-019-constraint-implementation.md) §2·§9)**
  - **결정은 유효하다** — DB 가 월요일 아닌 주 키를 거부한다.
  - 이 문서가 제시한 CHECK 식 `strftime('%w', week) = '1'` 은 **fail-open** 이다:
    `strftime` 이 NULL 을 반환하는 입력(`'0000-00-00'` 등)에서 비교가 NULL 이 되어
    통과한다. 실행 형태는 NULL-safe `week IS date(week) AND strftime('%w', week) = '1'`
    이며 ADR-019 §2 가 소유한다.
  - 본문의 "(SQLite 검증 실증)" 표기는 **사실이 아니다** (실증되지 않았다).
  - 본문은 이력으로 그대로 둔다.
- 결정 근거 원장: [2026-08-04 기획 검증 세션](../../decision-log/2026-08-04-planning-session.md) §A (Q8-1·Q9·plan_lead_days)
- 판정식 시각화: [2026-08-04-settlement-flow.html](../../decision-log/2026-08-04-settlement-flow.html)

## Context

초안 PRD 는 주 키를 "ISO week 문자열(`'YYYY-Wnn'`) + 일요일 시작"으로 기술했는데,
이 조합은 존재하지 않는다 — ISO 8601 주는 정의상 월요일 시작이다 (2026-08-02 일요일은
ISO W31 소속, python 으로 검증). 또한 2026년은 53주 연도라 `'W52'+1='W53'` 같은
문자열 산술이 성립하지 않아, 주 키로 ISO 문자열을 쓰면 산술마다 달력 라이브러리를
거쳐야 한다. "일요일에 주간 계획을 세운다"는 사용자 습관이 "주가 일요일에 시작한다"는
정의와 뒤엉켜 있던 것이 근본 원인이다.

## Decision

### 1. 주 시작 = 월요일 (Q8-1)

일반 통용 기준을 따른다. `weekly_capacity` 배열 인덱스 0 = 월요일. 시안 v7 의 요일
UI(DOW 배열, 캘린더 그리드, 요일 칩)는 전부 월요일 시작으로 변경한다.
주 시작 요일은 **설정이 아니라 고정값**이다 — 확장 가능해야 하는 것은 계획일이며,
그건 아래 plan_lead_days 가 담당한다.

### 2. 주 키 = 그 주 월요일 날짜 `'YYYY-MM-DD'` (Q9-E)

- 주 키는 ADR-009 의 **달력 키 가족**에 속하며, 기존 포맷 `'YYYY-MM-DD'` 를 그대로
  쓴다. `'2026-08-03'` 은 달력만 알면 직독되는 절대 기준이고, 사전순 = 시간순이다.
- 주 산술은 날짜 산술이다: 다음 주 = +7일. 53주 연도 문제가 소멸한다.
- DB 가 월요일 아닌 값을 거부한다: `CHECK (strftime('%w', week) = '1')` (SQLite 검증 실증).
- `W32` 같은 주 번호 라벨은 **렌더 전용**이다. 주 시작이 월요일이므로 표시용 주 번호가
  진짜 ISO 주 번호와 일치한다 — 저장하지 않고 표시 시점에 계산한다.

### 3. 계획일 모델 = plan_lead_days

"주간 계획은 일요일에 세운다"를 주 정의에서 분리해 파라미터로 만든다.

- **계획일 = 주 시작 D−`plan_lead_days`일.** 기본값 1 (= 일요일). v1 에서는 설정 UI
  미노출, settings 에 저장만 한다.
- **계획 대상 주** = `week_of(오늘 + plan_lead_days)`.
- **정산 범위** = 워터마크+1주 … 계획 대상 주−1주 구간의 미완료 항목 전체를 정산
  화면 1개에 병합 (Q6). 몇 주를 비웠든 정산은 항상 1개, 항목 수만 늘어난다.
- **워터마크(`last_settled_week`)는 정산한 주가 아니라 항상 "계획 대상 주 − 1" 을
  기록**하고, 첫 실행 초기값도 동일하다 (Q5) — 설치 직후 헛배너와 병합 정산 후
  무한 배너를 함께 막는다.
- 알려진 부작용 수용: 일요일 밤 정산 확정 뒤 같은 날 이어서 한 세션은 이미 정산된
  주에 귀속된다 (정산 요약에는 미포함, 캘린더·소진 집계에는 정상 반영). 막지 않는다.

## Consequences

- (+) 주 관련 산술이 전부 날짜 산술로 환원된다. 이월 배지 "N주째" 도
  `(week − origin_week)/7 + 1` 한 줄이다 (ADR-011).
- (+) 계획일을 나중에 토요일·월요일로 바꾸는 요구는 `plan_lead_days` 값 변경만으로
  흡수된다. 주 키·집계·정산식은 불변.
- (−) 시안 v7 의 일요일 시작 요일 UI 를 전부 뒤집어야 한다 — 기능 문서(ux-spec)가
  이 ADR 기준으로 작성된다.
- (−) 주 키가 날짜처럼 생겨서 "하루"로 오독될 수 있다. 컬럼명(`week`, `local_week`,
  `origin_week`)과 CHECK 제약이 방어선이다.
