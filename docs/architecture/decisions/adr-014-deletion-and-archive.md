# ADR-014: 삭제·보관 표현 — soft delete 범위와 보관의 집계 중립성

- 상태: accepted (2026-08-04)
- 근거: [2026-08-04 리뷰 결정](../../decision-log/2026-08-04-review-decisions.md) D4 + 정합성 감사 지적
- 관계: [ADR-011](adr-011-schema-final.md) 이 정의하지 않은 삭제 표현을 보완한다

## Context

정합성 감사에서 **기능 문서 3개가 각자 삭제 컬럼의 존재를 전제하고 있는데 스키마 ADR 에는
그 정의가 없다**는 사실이 확인됐다 — weekly-review 는 `week_items.deleted_at` 을 조회
조건에 쓰고, today-tasks 는 "삭제되지 않은 task"를 목록 구성 조건으로 쓰며, milestones 는
"`milestones` 에는 `archived_at` 만 있고 `deleted_at` 이 없다"를 TBD 로 남겼다.

동시에 milestones 리뷰에서 **보관(archive)이 지난달 달성률의 분모를 깎는다**는 결함이
나왔다. 규칙이 "보관된 마일스톤은 N·M 양쪽에서 제외"였고, 월말에 미완료 마일스톤을
보관하는 것이 정상 경로였다 — 3개 중 1개 완료한 달에서 남은 2개를 보관하면
배지가 "1/3"에서 **"1/1 달성"** 으로 바뀐다. 아무것도 더 하지 않았는데 33% 가 100% 가 되고,
보관 해제로 왕복도 가능하다. 이건 실패를 숨기는 게 아니라 성공을 조작하는 것이다.

## Decision

### 1. soft delete 는 `week_items`·`tasks` 두 테이블에만 둔다

- `week_items.deleted_at`·`tasks.deleted_at` (순간, NULL = 살아 있음). 사용자가 만든
  계획 단위를 되돌릴 수 있게 하고, 이미 붙은 세션의 FK 를 깨지 않기 위함이다.
- 폐기(`dropped_at`)와는 다른 개념이다: 폐기는 "이 계획을 보내준다"는 **의사 표시**로
  이력에 남고 정산 요약에 집계되며, 삭제는 "이건 없던 일"로 목록·집계에서 빠진다.
- 모든 조회는 `deleted_at IS NULL` 을 기본 조건으로 갖는다.

### 2. `sessions` 는 삭제하지 않는다

세션은 벌어진 사실이다. v1 에 세션 삭제·수정 UI 를 두지 않는다(Q4 — 오조작 롤백은
필요해지면 후속 버전에서 재검토). 따라서 `sessions.deleted_at` 은 만들지 않는다.

### 3. `milestones` 는 물리 삭제 + 보관

- 삭제는 물리 삭제다. 이력 보존은 삭제가 아니라 **보관**(`archived_at`)이 담당한다.
- `week_items.milestone_id` FK 는 `ON DELETE SET NULL` 이다. 마일스톤을 지우면 연결된
  주간 항목은 사라지지 않고 미연결("기타")이 된다 — 연결이 선택이므로 정상 상태다.

### 4. 보관은 집계에 중립이다 (달성률 분모 유지)

지난달 배지 `N / M` 을 **그 달의 스냅샷**으로 정의한다.

- `M` = 그 달에 존재했던(=물리 삭제되지 않은) 마일스톤 수. **보관 여부와 무관하다.**
- `N` = 그중 `completed_at` 이 있는 수.
- **보관은 목록 표시에서만 제외**한다. 분모를 바꾸지 않으므로 배지를 조작할 수 없다.
- `M = 0` 이면 배지를 렌더하지 않는다("0/0 달성"을 만들지 않는다).
- 보관된 항목이 있는 달의 배지에는 보관 사실을 함께 표시한다(초안이 이미 그렇게 했다).

원장 Q15 는 "지난달 카드는 배지만 표시"를 결정했을 뿐, 보관이 분모를 깎는다고 결정한
적이 없다 — 이 ADR 은 Q15 를 뒤집는 것이 아니라 정의되지 않았던 부분을 채운다.

## Consequences

- (+) 기능 문서 3개가 전제하던 컬럼에 정의가 생긴다. "삭제 방식 TBD"가 닫힌다.
- (+) 달성률이 조작 불가능해진다. 보관은 화면 정리 수단으로만 남는다.
- (+) 마일스톤 삭제가 하위 데이터를 파괴하지 않는다.
- (−) 마일스톤은 되돌릴 수 없다(물리 삭제). 삭제 확인이 필요하고, 실수의 대가는
  "제목을 다시 입력"이다 — 하위 항목·세션은 보존되므로 손실이 제한된다.
- (−) 보관해도 배지 분모가 줄지 않으므로 "지난달 달성률이 낮게 남는다". 실패 프레임을
  만들지 않기 위해 배지는 판단 없이 숫자만 보여준다(원칙 6·7).
- 제약 추가이므로 초기 마이그레이션에 포함한다(ADR-011 §6 — SQLite 는 이후 추가 시
  테이블 재작성).
