# ADR-018: 첫 실행 상태 — capacity 미설정의 표현과 시딩 목록

- 상태: accepted (2026-08-05)
- 관계: [ADR-013](adr-013-baseline-budget-effect.md) §1 의 "`weeks.budget` 은 NOT NULL 정수"를
  **부분 정정**한다. §2(행 생성 시점)·§3(편집·효력 분리)·§4 는 그대로 유효하다.
  [ADR-011](adr-011-schema-final.md) §1 의 `weeks` 컬럼 정의도 이 ADR 기준으로 읽는다.
- 결정 근거 원장: [2026-08-05 DB 계층 착수 전 심사](../../decision-log/2026-08-05-db-layer-audit.md) §D1 · §R1 · §R2
  (기각한 대안과 미룬 항목이 그쪽에 있다)

## Context

DB 계층 구현에 들어가기 전, 계획된 스키마와 백엔드 구조를 사전 맥락이 없는 심사자 둘에게
각각 검토시켰다. 그 결과 **문서 세 곳이 각각은 옳은데 겹치면 막히는 지점**이 발견됐다.

1. [pomo-baseline R8] `weekly_capacity` 의 미설정 상태는 **NULL 이고 오류가 아니다.**
   첫 실행에 기본 배열을 넣지 않으며, 특히 `[0,0,0,0,0,0,0]` 초기화를 **금지한다** —
   그렇게 하면 "이번 주 예산 0개"라는 사용자의 의사 표시와 "아직 정하지 않았다"가
   데이터상 구분 불가해진다.
2. [ADR-013 §2 / pomo-baseline R14] `weeks` 행은 계획·정산·**그 주의 첫 세션** 중 가장
   먼저 오는 때 생성되며, 그 순간 베이스라인 3종과 `capacity`·`budget` 을 함께 박제한다.
3. [계획된 DDL] `weeks.capacity` 와 `weeks.budget` 이 `NOT NULL` 이다.

[app-shell R31] 은 첫 실행 온보딩을 **건너뛸 수 있다**고 정했다. 따라서 `weekly_capacity`
가 NULL 인 채로 앱을 쓰는 것은 비정상이 아니라 **정상 경로**다. 그 사용자가 아무것도
계획하지 않고 첫 뽀모를 완주하면, 세션을 기록하기 위해 `weeks` 행을 먼저 만들어야 하는데
`capacity` 에 넣을 값이 없다. 막다른 길이 양쪽이다:

- `[0,0,0,0,0,0,0]` 을 넣는다 → R8 이 금지한 구분 불가 상태가 **스냅샷에 영구히 박제**된다.
  스냅샷은 불변이므로(R19) 나중에 고칠 수도 없다.
- INSERT 를 포기한다 → 세션 기록 트랜잭션이 롤백된다 → **timer PRD 의 목표 1**
  ("계획이 0개여도 타이머·기록·알림이 완전히 동작한다")이 첫 화면에서 실패한다.

별개로, **무엇을 시딩하고 무엇을 시딩하지 않는지가 어느 문서에도 없다.** R6 은 전역
기본값 25/5/15 가 `settings` 에 저장된다고 하고 R8 은 `weekly_capacity` 를 넣지 말라고
하는데, 누가 언제 그 값을 쓰는지는 정의된 적이 없다.

## Decision

### 1. `weeks` 행이 담는 두 스냅샷을 성격에 따라 분리한다

`weeks` 행의 컬럼은 두 종류이고 값의 존재 조건이 다르다.

| 스냅샷 | 컬럼 | 값이 항상 있는가 |
|---|---|---|
| 길이 기준 | `focus_min` · `short_break_min` · `long_break_min` | **있다** — R6 의 전역 기본값이 항상 존재한다 |
| 계획 의사 | `capacity` · `budget` | **없을 수 있다** — 사용자가 정한 적 없으면 NULL |

**`capacity` 와 `budget` 을 nullable 로 하고, 길이 3종은 NOT NULL 을 유지한다.**

ADR-013 이 `weeks` 행을 도입해 막으려던 것은 "8월에 25분으로 보낸 주가 9월에 50분
기준으로 보이는" **길이 기준의 소급 왜곡**이었다. 그 목적은 길이 3종이 NOT NULL 로
남는 한 그대로 달성된다. 예산은 애초에 사용자가 정한 적 없으면 없는 것이 사실이며,
그 사실을 NULL 로 기록하는 것이 `[0,…]` 을 지어내는 것보다 정직하다.

### 2. `유효 예산` 계약(pomo-baseline R11)의 판별 조건을 넓힌다

- (현행) 행이 없으면 "기록 없음"
- (개정) **행이 없거나 `budget` 이 NULL 이면** "기록 없음"

반환값 집합은 바뀌지 않는다 — 여전히 **뽀모 개수 또는 "기록 없음"** 두 가지이고,
조회 시점에 `sum(weekly_capacity)` 로 예산을 파생하는 경로는 이 계약에 없다.
판별 조건만 실제 데이터 상태에 맞춰졌다.

### 3. R17("세션이 있는 주는 반드시 자기 스냅샷을 가진다")은 유지한다

행 생성 시점(ADR-013 §2)은 손대지 않는다. 첫 세션에 `weeks` 행이 생기는 것은 그대로이고,
다만 그 행의 `capacity`·`budget` 이 NULL 일 수 있을 뿐이다. 따라서 "스냅샷이 없으면
전역값으로 해석한다"는 경로는 여전히 존재하지 않는다.

이 불변식은 [ADR-019](adr-019-constraint-implementation.md) 의 FK
(`sessions.local_week → weeks.week`)가 DB 레벨에서 강제한다.

### 4. 시딩 목록을 확정한다

`settings` 의 초기화를 세 부류로 나눈다.

| 부류 | 키 | 값 | 근거 |
|---|---|---|---|
| **정적 시딩** | `focus_min` · `short_break_min` · `long_break_min` | 25 · 5 · 15 | pomo-baseline R6 |
| | `plan_lead_days` | 1 | ADR-010 |
| | `theme` | `'system'` | design-system ADR-008 |
| **계산 부트스트랩** | `last_settled_week` | weekly-review §0.2 가 계산 | 정적 기본값이 아니다 |
| **시딩하지 않음** | `weekly_capacity` | — | pomo-baseline R8 |

- 정적 시딩은 **키가 없을 때만** 넣는다. 이미 있으면 값을 건드리지 않는다 (멱등).
- 시딩은 마이그레이션 직후·창 생성 이전에 1회 수행한다. 계산 부트스트랩도 같은 시점이며
  그 규칙은 weekly-review 소관이므로 여기서 재정의하지 않는다.
- **목록에 없는 키는 시딩하지 않는다.** 새 설정 키를 추가할 때 이 표를 갱신한다.

### 5. `settings.value` 의 NULL 표현

R8 은 미설정을 "`settings` 키 부재 **또는 NULL**"이라고 적었으나, `value` 는 `NOT NULL`
이라 후자를 표현할 수 없다. **키 부재만을 미설정으로 정의한다** — 값을 지우는 조작은
행을 삭제한다. `value` 는 NOT NULL 을 유지하고 JSON 유효성 검사를 건다
([ADR-019](adr-019-constraint-implementation.md)).

## Consequences

- (+) 온보딩을 건너뛴 사용자의 첫 뽀모가 정상 기록된다. timer 의 목표 1 이 성립한다.
- (+) "아직 정하지 않았다"와 "예산 0 으로 하겠다"의 구분이 전역 설정뿐 아니라 **주 스냅샷
  에서도** 유지된다. R8 이 우려한 상태가 어디에도 만들어지지 않는다.
- (+) 길이 기준의 소급 왜곡 방지(ADR-013 의 본래 목적)는 그대로다.
- (+) 시딩 대상과 비대상이 한 표로 고정돼, "누가 언제 기본값을 쓰는가"라는 질문이 사라진다.
- (−) 과거 주 중 **예산 기록이 없는 주**가 존재하게 된다. 그 주의 예산 표시는 "기록 없음"
  이고, 주간 게이지의 분모가 없다. 사용자가 계획한 적 없으므로 사실에 부합한다.
- (−) `유효 예산` 계약의 판별 조건이 두 항목이 됐다. 계약을 읽는 곳은 여전히 pomo-baseline
  R11 한 곳뿐이므로(R13 의 초크포인트 원칙) 분기가 화면으로 번지지는 않는다.
- (−) 시딩 목록이 늘거나 줄면 이 ADR 을 갱신해야 한다. 목록을 코드에만 두면 같은 질문이
  반복되므로 문서에 둔다.
