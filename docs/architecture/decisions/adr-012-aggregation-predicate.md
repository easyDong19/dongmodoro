# ADR-012: 집계 술어 단일화 — 세션의 주 = 항목의 주, pull 주 제한 폐기

- 상태: accepted (2026-08-04) · **§4 의 수식은 [ADR-027](adr-027-other-row-domain.md) 로 정정됨 (부분)**
  - §4 안에서 수식(`Σ(is_system = 0 인 항목)`)과 서술문("폐기 항목의 소진도 흡수된다")이
    서로를 무효화하고 있었다. ADR-027 이 **서술문을 의도로 확정하고 수식을 정정**한다 —
    Σ 의 정의역은 `is_system = 0 AND dropped_at IS NULL AND deleted_at IS NULL` 이다.
  - **§1·§2·§3 과 Consequences 는 전부 유효하다.** 집계 술어의 주 조건, pull 주 제한 폐기,
    이월의 재부모화·`milestone_id` 승계는 이 문서가 계속 소유한다.
  - 아래 본문은 이력으로 그대로 둔다 (docs/CLAUDE.md 의 ADR 정정 규칙).

- 관계: [ADR-011](adr-011-schema-final.md) §2 의 "pull 은 오늘이 속한 주의 항목으로 제한한다"를 **폐기**한다 (부분 정정)

## Context

Q10 은 "주간 총 소진(날짜 기준)과 항목별 소진(관계 기준)이 어긋날 수 있다"는 문제를
**pull 대상을 오늘이 속한 주의 항목으로 제한**하는 방식으로 닫았고, 그 결과
`게이지 = 항목 합 + 미분류` 가 "구조적으로 항상" 성립한다고 기능 문서들이 서술했다.

기획 문서 리뷰에서 이 등식이 **조건부**임이 드러났다. Q10 이 제약하는 것은 *pull 시점*의
주이고, 등식이 요구하는 것은 *세션의 주 = 그 세션이 붙은 task 의 부모 항목의 주*인데
둘은 같은 조건이 아니다. 갈라지는 경로 세 개가 확인됐다:

1. **주 경계의 집중 대상** — 일요일 23:59 에 그 주 항목의 task 를 pull 하고 집중 대상으로
   지정한 뒤 00:01 에 시작하면, 세션은 다음 주(Q2 — started_at 기준)에 기록되는데
   부모 항목은 지난 주 소속이다. "집중 대상을 하루 경계에서 무효화한다"는 규칙은 없었다.
2. **사후 캡처의 "그 주"** — 자유 집중 세션에 소급 task 를 붙일 때 기준이 "세션의 주"인지
   "오늘의 주"인지 어느 문서에도 없었다. 자정을 걸친 세션에서 두 값이 다르다.
3. **이월** — 이월은 새 주에 새 항목을 만든다(ADR-011 §4). 미완료 task 를 새 항목으로
   재부모화하면 이미 붙은 세션의 관계 기준 귀속이 다음 주로 이동하고, 재부모화하지
   않으면 지난 주 항목은 pull 제한 때문에 **다시 시작할 방법이 없다.**

즉 Q10 은 대가(내일 몫을 미리 고를 수 없음)를 지불하면서 목표를 달성하지 못했다.

## Decision

### 1. 항목별 소진은 주 조건을 명시해 집계한다

```
항목 소진 = count(sessions s JOIN tasks t ON s.task_id = t.id
                  WHERE t.week_item_id = <항목>
                    AND s.kind = 'focus'
                    AND s.local_week = <그 항목의 week>)
```

`sessions.local_week` 는 기록 시 1회 계산 후 불변이므로(ADR-009 §2, ADR-011 §3),
**모든 세션은 자기 주에서 정확히 한 번 세어진다.** 항목의 주와 어긋나는 세션은 그 주의
미분류로 떨어진다. 따라서 `주간 총 소진 = Σ(항목 소진) + 미분류` 가 **정의상** 성립하며,
위 세 경로가 전부 자동으로 닫힌다.

### 2. pull 대상의 주 제한을 폐기한다

오늘 목록으로 가져올 수 있는 항목은 그 주에 국한되지 않는다. Q10 의 제약과 그에 딸린
UI 상태("다음 주 항목은 선택 불가")를 없앤다. `task_pulls.pull_date` 는 여전히
**오늘 날짜만** 기록한다 — 미래 날짜 pull(내일 몫 미리 담기)은 별개 결정이며 v1 비범위다.

### 3. 파생 규칙 세 가지를 함께 확정한다

- **사후 캡처의 시스템 "기타" 항목은 세션의 `local_week` 기준**으로 선택·생성한다
  ("오늘"의 주가 아니다).
- **이월 시 미완료 task 의 재부모화를 허용한다.** §1 의 주 조건 때문에 과거 주의 숫자가
  소급 이동하지 않으므로 안전하다. 이로써 "지난 주 미완료 조각을 이번 주에 재개"가 성립한다.
- **이월은 `milestone_id` 도 승계한다.** 승계하지 않으면 여러 주에 걸친 결과물의 월간
  진척이 주 경계마다 0 으로 초기화된다.

### 4. 화면의 "기타" 행 소진은 차액으로 정의한다

시스템 항목은 그 자체가 week_item 이므로 `Σ(항목 소진)` 에 이중 계상될 수 있다.
화면의 기타 행 값은 독립 계산하지 않고

```
기타 행 소진 = 주간 총 소진 − Σ(is_system = 0 인 항목의 소진)
```

으로 정의한다. 이중 계상이 산술적으로 불가능해지고, 목록에 표시되지 않는 폐기 항목의
소진도 자동으로 이 값에 흡수된다.

## Consequences

- (+) 등식이 사용자 제약 없이 정의상 성립한다. 검증은 인수 기준이 아니라 쿼리 형태로 닫힌다.
- (+) 개념이 줄었다 — pull 주 제한, "다음 주 항목 선택 불가" 상태, 그에 딸린 인수 기준,
  "내일 몫을 오늘 밤 미리 시작 불가"라는 대가가 모두 사라진다.
- (+) 이월의 미정의 갈림길(재부모화 여부)이 닫힌다.
- (−) 항목 소진 쿼리에 조건이 하나 늘어난다. 이 조건을 빠뜨리면 조용히 틀린 숫자가
  나오므로, 집계는 한 곳(도메인 함수)에서만 계산하고 화면이 직접 SQL 을 만들지 않는다
  (ADR-008 의 계층 규칙과 정합).
- (−) 한 항목의 세션이 여러 주에 걸쳐 있으면 "그 항목에 총 몇 뽀모를 썼나"는 주별 값의
  합으로만 얻는다. 이월 사슬을 거슬러 합산하는 화면은 v1 에 없다.
- ADR-011 §2 의 pull 제한 문장은 이 ADR 로 폐기된다. 나머지(`task_pulls` 행 승격,
  과거 날짜 이력 보존)는 유효하다.
