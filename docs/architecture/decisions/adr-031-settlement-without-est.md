# ADR-031: est 소멸의 귀결 — 정산 처분 2택, 차액 유지, 측정 시간의 정확한 정의

- 상태: accepted (2026-08-13)
- 관계:
  - [ADR-030](adr-030-time-as-progress-currency.md) §3 의 두 문장을 **정정**한다.
    ① "처분(이월/폐기)과 워터마크 판정은 변화 없다" → 처분은 **2택으로 줄어든다**
    (워터마크 판정은 실제로 변화 없다). ② "계획에 없던 집중은 차액 계산이 아니라
    자유 focus 세션의 시간 직접 합산" → **차액을 유지한다**(§2).
    §1·§2·§4 와 §5 의 귀속 술어는 그대로 유효하다.
  - [ADR-030](adr-030-time-as-progress-currency.md) 의 관계 절 중
    **[ADR-027](adr-027-other-row-domain.md) 폐기 표기를 취소**한다 — ADR-027 은
    폐기되지 않고 **통화만 교체된 채 살아 있다**(§2). ADR-012 §4 의 폐기는 유효하다.
  - [ADR-018](adr-018-first-run-state.md) 시딩 목록 인용 정정: ADR-030 이 "§5 시딩
    목록"이라 쓴 것은 **§4** 의 오기다.
  - [ADR-019](adr-019-constraint-implementation.md) §1 의 `est_pomos` CHECK 2종과
    이월 est 하한 규칙을 **폐기**한다.
- 결정 근거: [2026-08-12 시간 통화 전환 세션](../../decision-log/2026-08-12-time-currency-session.md)
  이후의 계획 감사(2026-08-13) — 계획서가 답하지 않은 결정 공백 3건

## Context

ADR-030 이 `week_items.est_pomos` · `tasks.est_pomos` 컬럼 제거를 결정한 뒤, 구현 계획
([2026-08-12-time-currency](../../plans/2026-08-12-time-currency.md))을 착수 전 감사했다.
계획서가 실행 불가능한 지점 세 곳이 나왔고, 셋 다 **계획이 스스로 정할 수 없는 결정**이다
(docs/CLAUDE.md — 계획은 결정을 만들지 않는다).

### 1. 정산의 `줄여서` 는 est 위에 서 있다

정산 처분 3택 중 `줄여서 이월` 은 정의상 **이월하되 est 를 줄이는** 선택지다
(weekly-review PRD R14-1·R15). 구현도 그렇다 — 예외 타입이
`{ kind: 'carry_reduced'; estPomos }` 이고, 기본값이 `남은 몫`의 절반(올림),
클램프가 `max(1, remaining)` 이며, `remaining = max(0, est − 소진)` 이다.

est 가 사라지면 **줄일 대상이 없다.** 그런데 ADR-030 §3 은 "처분과 워터마크 판정은
변화 없다"고 적었고 계획서도 "처분 3택은 건드리지 않는다"고 적었다. 두 문장 다
컬럼이 사라진 뒤에는 참일 수 없다. 게다가 확정 트랜잭션은 이월 항목을
`est_pomos: est` 와 함께 INSERT 하므로, 컬럼 drop 직후 **없는 컬럼에 쓰는 코드**가 된다.

### 2. `기타` 행을 "자유 focus 합"으로 좁히면 시간이 증발한다

ADR-027 은 기타 행 소진을 **차액**으로 정의했다:
`주간 총 focus − Σ(화면에 보이는 항목)`. 이 정의역이 흡수하던 것은 셋이다.

| 흘러드는 경로 | 근거 |
|---|---|
| ① 진짜 미분류 (`task_id IS NULL`) | ADR-012 §4 |
| ② 사후 캡처로 시스템 `기타` 항목에 붙은 조각의 세션 | 캡처 순간 `task_id` 가 채워져 미귀속이 아니게 된다 |
| ③ 폐기·삭제된 항목의 세션 | ADR-027 §1·§2, week-plan A24 |

ADR-030 §3 이 지시한 "자유 focus 세션의 시간 직접 합산"은 ① 만 잡는다. ②③ 의 시간이
**총합에도, 항목 합에도, 기타 행에도 나타나지 않는다.** ② 는 정상 경로다 — 캡처 바에
한 줄 적는 순간 그 25분이 화면에서 사라진다.

여기에 통화 전환이 새 문제를 하나 더 얹는다. **개수는 정수라 검산 항등식이 공짜였지만
분 단위 표시는 아니다.** 항목 3개가 각 90초면 각각 `2분`으로 반올림되어 합이 6분인데,
실제 총합 270초는 `5분`이다. 사용자가 화면에서 눈으로 검산하면 틀린다 — ADR-027 §1 이
지키려던 성질이자 PRODUCT.md 포지셔닝 2번이 금지하는 상태다.

### 3. `측정 시간` 이라는 이름이 실제 동작보다 많은 것을 약속한다

ADR-030 Context 는 `sessions.duration_sec` 를 "모든 세션의 **실제 경과 초**"라고 적었다.
코드는 그보다 좁다.

- **자연 만료**: `duration_sec` = 그 세션에 설정된 길이 그대로. 자리를 비운 채 만료돼도
  전부가 집중 시간이 된다.
- **조기 완료**: 실제 경과.
- **일시정지 구간은 빠진다** (의도된 동작).
- **미완료 세션은 행 자체가 없다** — 초기화·모드 탭 전환·앱 종료로 버려진 세션은
  20분을 집중했어도 기록이 0이다.

개수 통화에서는 "1뽀모를 못 채웠다"로 납득되던 것이, 시간 통화에서는 **잰 시간을
버리는 것**으로 읽힌다. 이름이 스톱워치를 약속하는데 동작은 그렇지 않다.

## Decision

### §1. 정산 처분은 2택이 된다

`다음 주로` · `보내주기` 만 남긴다. `줄여서` 를 제거한다.

줄일 대상(est)이 없어졌기 때문이며, 시간으로 대체하지 않는다 — **이월 항목의 측정
시간은 정의상 0이므로**(아직 하지 않은 일이다) 시간을 줄인다는 조작이 성립하지 않는다.

폐기되는 것: weekly-review PRD R14-1·R15·R36, ux-spec §5.2·§5.3 의 축소 스테퍼,
`carry_reduced` 예외 타입과 `estPomos` 페이로드, `remaining` 파생, 확정 응답의
`carriedPomos`.

**이월 규모를 말하던 카피는 건수로 바꾼다.** PRD R40 이 요구한 "3주 만에 60뽀모가 한
주로 쏟아지는 사실"은 시간으로 표현할 수 없으므로(이월분의 시간은 0), `이월 N건` 이
그 자리를 대신한다. 최종 문구는 weekly-review ux-spec 소관이다.

**워터마크 판정은 실제로 변화 없다** — `settings.last_settled_week` 단독 판정이고
est 를 읽지 않는다. ADR-030 §3 의 그 부분은 옳다.

### §2. 기타 행은 차액을 유지한다 — 통화만 바뀐다

```
기타 행 측정 시간 = 주간 총 focus 초 − Σ(화면에 보이는 항목의 focus 초)
```

Σ 의 정의역은 ADR-027 §1 그대로다 (`is_system = 0 AND dropped_at IS NULL AND
deleted_at IS NULL`). 주간 총합은 ADR-027 §2 그대로 그 주 완료 focus 세션 전체이며,
항목의 폐기·삭제가 이 값을 줄이지 않는다. 표시 조건 3갈래(ADR-027 §3)도 유지하되
세 번째 갈래를 `기타 행 측정 시간 > 0` 으로 읽는다.

따라서 **ADR-027 은 폐기되지 않는다.** ADR-030 의 관계 절이 ADR-027 을 ADR-012 §4 와
묶어 폐기한 것은 "차액 개념 자체가 사라진다"는 전제 위에서였고, 그 전제를 이 결정이
뒤집는다. ADR-012 §4 의 폐기(개수 기반 수식)는 유효하다 — 통화가 바뀌었으므로.

**차액은 초 단계에서 계산한다.** 반올림은 표시 직전 한 번만 일어나므로 Context 2 의
항등식 문제가 구조적으로 사라진다: 화면의 `총합 = Σ항목 + 기타` 는 초에서 참이고,
표시된 분은 그 참인 값을 각자 반올림한 결과다. 사용자가 분 단위로 검산했을 때 ±1분이
어긋날 수는 있으나, **어느 숫자도 다른 화면과 모순되지 않는다.** 개수 시절의 완전
검산 가능성은 통화 전환의 대가로 명시적으로 수용한다.

부수 효과로 ADR-027 §2 의 대가도 그대로 승계된다 — 폐기·삭제된 항목의 시간이
`계획에 없던 집중` 이라는 부정확한 라벨 아래 표시된다. v1 이 수용한 부정확이며
2.0.0 도 수용한다.

### §3. `측정 시간` 은 "타이머가 돈 시간"이다

용어의 정의를 다음으로 확정한다.

> **측정 시간** — 완료된 focus 세션에서 타이머가 실제로 돈 시간의 합.
> 일시정지 구간은 빠지고, 중단·폐기된 세션은 포함되지 않는다.

"실제 경과"라는 표현을 쓰지 않는다 — 벽시계 경과가 아니기 때문이다. CONTEXT.md 의
정의를 이 문장으로 갱신한다.

**진행 중인 세션의 경과는 집계에 비추지 않는다.** 타이머 카드의 카운트다운이 유일한
진행 표시로 남는다. 완료 시점에 숫자가 뛰는 동작을 유지하되, 그 사실을 카피가
설명한다 (문구는 각 ux-spec 소관). 계약에 `runningSec` 를 얹지 않는다 — 4개 화면의
무효화 주기를 새로 설계해야 하고, 얻는 것이 "숫자가 살아 있다"는 체감뿐이다.

**중단·폐기된 세션의 경과는 버린다.** 현행 동작(초기화·모드 탭 전환·앱 종료 시
기록 없음)을 유지한다. 확인 대화를 넣지 않는다 — PRODUCT.md 원칙 4("막는 화면이
없다")와 정면으로 부딪히고, 시간 통화가 그 원칙을 뒤집을 근거가 되지는 않는다.
대신 이 손실이 일어난다는 사실을 timer 기능 문서에 명시한다.

## Consequences

- 정산 화면의 조작이 단순해진다. 축소 스테퍼·클램프·`remaining` 파생이 통째로
  사라지고, 정산은 **사실 요약 + 2택 처분 + 워터마크 전진**이 된다.
- `Stepper` 컴포넌트의 유일한 소비자가 없어진다. 제거 대상이다.
- 차액 유지로 **Task 2 의 합산 조회 설계가 바뀐다** — "자유 focus 초"를 따로 구하는
  것이 아니라 주간 총합과 항목별 합을 구해 차액을 낸다. 계획서를 이에 맞춰 고친다.
- ADR-027 이 되살아나므로 그 문서의 폐기 표기를 정정해야 한다 (상태 줄에만 기록,
  본문은 이력으로 둔다).
- `측정 시간` 의 정의가 좁아진 만큼, "왜 안 잰 시간이 잡히나"(자리 비운 채 만료)와
  "왜 잰 시간이 사라지나"(중단)라는 두 질문이 사용자에게 남는다. 문서로 답을 준비하되
  동작은 바꾸지 않는다.
- 이월 규모를 건수로 말하게 되어, 여러 주가 밀렸을 때의 압박을 시간으로 보여주던
  경로가 없어진다. 이월 항목에 측정 시간이 쌓이기 시작하면 다시 볼 자리다.
