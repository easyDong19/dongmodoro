## Context

지금까지 계획과 진행의 통화는 **뽀모 개수**였다. 할당·조각에 예상 뽀모(`est_pomos`)를
매기고, 주간 예산(`weeks.budget`)·요일별 가용량(`weekly_capacity`)과 비교해 과적을
경고하고, 정산에서 `계획 대비 소진` 과 차액을 보여줬다. PRODUCT.md 포지셔닝 1번이
"뽀모 개수가 단일 통화다"라고 명시했다.

실사용에서 두 문제가 확인됐다.

1. **계획 시점의 숫자 입력이 플로우를 무겁게 한다.** 사용자 원문: "예상뽀모를
   추가하는건 플로우를 복잡하게 함." 할 일 하나를 잡을 때마다 개수를 추정해야 하고,
   그 추정이 예산·과적·차액 로직 전체를 지탱하느라 삭제할 수도 없었다.
2. **개수 예산을 보호하는 장치(효력 지연)가 "설정이 안 먹는" 경험을 만들었다**
   (ADR-029 의 Context).

한편 "얼마나 했나"의 사실값은 이미 있다 — `sessions.duration_sec` 가 M2부터 모든
세션의 실제 경과 초를 저장한다. 개수 통화를 버려도 진행 표시의 재료는 새로 만들
필요가 없고, 과거 주에도 소급 적용된다.

## Decision

### §1. 통화 교체

계획의 통화(예상 뽀모·예산·가용량)를 **폐지**한다. 진행 표시의 통화는 **측정 시간** —
완료 focus 세션의 `duration_sec` 를 **조회 시점에 합산해 파생**하는 값이다.
어디에도 저장하지 않는다 ("소진량을 저장하지 않는다" 원칙은 통화가 바뀌어도 그대로다).

**뽀모의 정의는 좁아진다**: 집계 화폐가 아니라 **타이머 사이클 단위**다.
1뽀모 = focus 세션 1회 완료(길이 무관)라는 정의 자체는 유지된다.

### §2. 층별 질문의 재정의

| 층 | 답하는 질문 | 숫자 |
|---|---|---|
| 월 마일스톤 | 이번 달이 끝나면 뭐가 달라져 있나 | 없다 (변화 없음) |
| 주간 계획 | **이번 주에 무엇을 하나** | **없다** — 입력 숫자가 사라진다 |
| 오늘 목록 | 지금 뭐부터 | 없다 (변화 없음) |

"얼마만큼"이라는 질문에 답하는 층은 **없어진다.** 과적을 계획 시점에 알 방법이
사라지는 트레이드오프를 인지하고 결정했다 (원장 §미결 1 — 대체 신호는 필요해지면
그때 결정).

### §3. 화면별 표시

- **주간 카드**: 예산 게이지(`소진/예산`) → **이번 주 측정 시간 합**. 항목마다 누적
  집중 시간. 요일 핍은 배치 표시만 남고 부하 표시는 죽는다.
- **오늘 목록**: 항목당 `소진/예상 뽀모` → **누적 집중 시간**.
- **정산 요약**: `계획 대비`·차액 → **측정 시간 요약**(총 집중·항목별·자유 집중).
  "계획에 없던 집중"은 차액 계산이 아니라 **자유 focus 세션의 시간 직접 합산**이다.
  처분(이월/폐기)과 워터마크 판정은 변화 없다.
- **마일스톤 롤업**: `이번 주 3/8` → **귀속된 주의 측정 시간**(`이번 주 3시간 20분`).
  월 층의 "수치 입력 없음" 원칙과 충돌하지 않는다 — 입력이 아니라 파생이다.
- **플래너**: 항목 추가는 제목(+마일스톤 연결·요일 배치)으로 끝난다. est 스테퍼·예산
  입력·과적 경고를 제거한다.

### §4. 스키마

제거한다:

- `week_items.est_pomos` · `tasks.est_pomos` (컬럼 drop)
- `weeks` 테이블 전체 — 남은 용도가 스냅샷·예산 박제뿐이고, 정산 필요 판정은
  워터마크(`settings.last_settled_week`) 단독 판정이라 테이블 없이 성립한다.
  `planned_at`·`settled_at` 이력은 함께 사라진다 (구제하지 않는다 — 어떤 화면도
  읽지 않는 값이다).
- `settings.weekly_capacity` 키

보존한다: `sessions`(전 컬럼) · `week_items` · `tasks` · `milestones` 의 기록.
기존 데이터는 **마이그레이션으로 이관**하며 초기화하지 않는다.

### §5. 시간 합산의 귀속과 표기

- 세션 → 항목 귀속은 `sessions.task_id` → `tasks.week_item_id` 체인을 따르고, 주
  귀속은 저장된 `local_week` 를 그대로 쓴다 (ADR-025 §1-2 — renderer 재계산 금지,
  ADR-012 §1~§3 의 술어 유지).
- 합산 대상은 **완료된 focus 세션**이다. 휴식 세션은 시간 통화에도 산입하지 않는다
  (뽀모 집계에서 제외하던 규칙의 연속).
- 표기 형식(`N시간 M분`, 0 의 표현 등)은 기능 문서(ux-spec) 소관이다. 이 문서는
  "초 단위 저장값을 조회 시점에 합산해 분 단위 이상으로 표시한다"까지만 정한다.

## Consequences

- **PRODUCT.md 포지셔닝 1번("뽀모 개수가 단일 통화")·3번("편집은 언제든, 효력은
  다음 주부터")이 죽는다.** 2번("소진량을 저장하지 않는다")·4번("막는 화면이
  없다")은 살아남는다 — 시간도 저장하지 않고 파생하며, 과적 경고가 사라져 막는
  화면은 오히려 줄었다.
- CONTEXT.md 에서 `예상 뽀모` 용어가 죽고 `측정 시간` 이 생긴다. `뽀모`·`롤업` 의
  정의가 갱신된다. (이 결정을 만든 PR 에서 함께 갱신한다.)
- 기능 문서 5곳(pomo-baseline·week-plan·weekly-review·today-tasks·milestones)의
  요구사항이 대폭 줄거나 재작성된다 — 문서 갱신은 해당 코드를 바꾸는 PR 이 동반한다.
- 파괴적 스키마 변경 + 화면 의미 변경이므로 **2.0.0** 이다.
- 마이그레이션이 지나간 DB 는 1.x 로 되돌릴 수 없다 (컬럼·테이블이 사라진다).
  마이그레이션 직전 자동 백업(기존 `userData` 백업 경로)이 유일한 복귀선이다.
