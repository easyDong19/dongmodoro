# ADR-027: 차액 정의역 정정 — Σ 는 "화면에 표시되는 항목"이다

- 상태: accepted (2026-08-07) · **폐기됨 (2026-08-12, [ADR-030](adr-030-time-as-progress-currency.md))**
  - 차액이라는 개념 자체가 사라진다. "계획에 없던 집중"은 이제 차액 계산이 아니라
    자유 focus 세션의 측정 시간 직접 합산이다. 본문은 이력으로 그대로 둔다.
- 관계: [ADR-012](adr-012-aggregation-predicate.md) §4 의 **수식을 정정**한다.
  같은 절의 **서술문("폐기 항목의 소진도 자동으로 이 값에 흡수된다")은 유효하며, 이 문서는
  그 서술문이 참이 되도록 수식을 고치는 것이다.** ADR-012 §1~§3(집계 술어의 주 조건,
  pull 주 제한 폐기, 이월 규칙)과 Consequences 는 전부 살아 있다.
  [ADR-014](adr-014-deletion-and-archive.md) §1 의 "삭제는 목록·집계에서 빠진다"가
  주간 총 소진에는 적용되지 않는다는 것을 §2 에서 명시한다.
- 발견 경로: M3a 구현 계획서 작성 중 인수 기준 A24 와 수식이 충돌 → 3인 리뷰(옹호·적대·중립)가
  독립적으로 같은 지점을 지적

## Context

ADR-012 §4 는 화면의 "기타 — 계획에 없던 집중" 행 소진을 차액으로 정의했다. 그런데 **같은
절 안에서 수식과 서술문이 서로를 무효화한다.**

수식은 이렇게 쓴다:

```
기타 행 소진 = 주간 총 소진 − Σ(is_system = 0 인 항목의 소진)
```

`is_system = 0` 은 폐기(`dropped_at`) 항목도 포함한다 — 폐기는 삭제가 아니고 행은 남기
때문이다(ADR-014 §1). 따라서 수식대로면 폐기 항목의 소진은 **Σ 에 들어간다.**

바로 다음 문장은 이렇게 쓴다:

> 목록에 표시되지 않는 폐기 항목의 소진도 자동으로 이 값에 **흡수된다.**

흡수되려면 Σ 에서 **빠져야** 한다. 두 문장은 동시에 참일 수 없다.

week-plan 의 인수 기준 A24 가 어느 쪽이 의도였는지를 확정한다:

> 3뽀모를 소진한 항목을 폐기하면 항목은 목록에서 사라지지만 주간 총 소진은 줄지 않고,
> **그 3뽀모가 기타 행 값에 나타난다.**

나타나려면 Σ 에서 빠져야 하므로 **서술문이 의도이고 수식이 오기**다. week-plan R18 도 같은
방향이다("폐기가 주간 총 소진을 줄이지 않으므로 사용자는 3뽀모의 행방을 기타 행에서
추적할 수 있다").

이 모순이 실제로 위험한 이유는 두 술어가 **다른 파일에서 각자 구현**되기 때문이다. 항목
목록 쿼리는 폐기를 제외하고(화면에 안 보여야 하므로), 차액 계산은 수식을 그대로 옮긴다.
둘이 어긋나도 **에러가 없고 숫자만 틀린다.** 그리고 이 어긋남은 M3b 정산에서 정상 경로가
된다 — 이월 3택의 "보내주기"가 항목을 대량 폐기하므로, 정산 직후 주간 카드에서 소진이
통째로 사라져 보인다.

부수적으로, `deleted_at`(소프트 삭제) 항목을 Σ 와 주간 총 소진에서 어떻게 다룰지가 어느
문서에도 없었다. v1 에 주간 항목을 소프트 삭제하는 UI 가 없어 도달 불가 경로이지만,
술어를 코드에 박는 이상 정해야 한다.

## Decision

### 1. Σ 의 정의역은 "그 주에 화면 목록으로 표시되는 항목"이다

```
Σ 의 정의역 = is_system = 0 AND dropped_at IS NULL AND deleted_at IS NULL
```

ADR-012 §4 수식의 `Σ(is_system = 0 인 항목의 소진)` 을 위 정의역으로 읽는다. 각 항목의
소진은 ADR-012 §1 의 주 조건 술어를 그대로 쓴다(이 문서는 그것을 바꾸지 않는다).

이렇게 두면 화면의 등식이 **문자 그대로** 성립한다:

```
주간 게이지 소진 = Σ(목록에 보이는 항목의 소진) + 기타 행 소진
```

"보이는 것의 합 + 기타 = 전체"이므로 사용자가 화면에서 직접 검산할 수 있고, 구현에서는
**목록 쿼리와 차액의 정의역이 같은 것 하나**가 되어 어긋날 자리가 없어진다.

### 2. 주간 총 소진은 그 주 focus 세션 수 전체다 — 항목의 폐기·삭제가 이 값을 줄이지 않는다

```
주간 총 소진 = count(focus 세션 WHERE local_week = 그 주)
```

항목을 폐기하거나 삭제해도 이 값은 변하지 않는다. 따라서 그 소진은 §1 의 차액에 의해
기타 행으로 옮겨 간다.

**ADR-014 §1 의 "삭제는 목록·집계에서 빠진다"는 주간 총 소진에 적용되지 않는다.** 그
문장이 말하는 집계는 항목 자신의 값과 마일스톤 달성률의 분모이고, 주간 총 소진은 성격이
다르다 — 이것은 **세션에서 직접 파생되는 사실**이며(원칙 8) 같은 세션이 캘린더 점과
타이머 기록에도 나타난다. 항목 하나를 지웠다고 "이번 주 12뽀모"가 9뽀모가 되면 **같은
사실을 말하는 세 화면이 서로 다른 숫자를 말하게 된다.** 그것이 이 앱이 구조적으로
금지하려던 상태다(PRODUCT.md Positioning 2).

대가는 명시적으로 수용한다: 폐기·삭제된 항목의 소진이 `기타 — 계획에 없던 집중` 이라는
이름 아래 표시된다. 그 집중은 **계획에 없던 것이 아니라 계획이 사라진 것**이므로 라벨이
정확하지 않다. 그럼에도 이 배치를 택하는 이유는 (a) 그 뽀모가 화면 어딘가에는 반드시
남아야 하고 (b) 폐기 이력을 별도 행으로 세우는 것은 정산의 관심사이지 주간 카드의 것이
아니기 때문이다. week-plan ux-spec §3.4 가 이미 이 흡수를 "3뽀모의 행방을 추적하는 유일한
자리"로 설명하고 있다.

### 3. 기타 행의 표시 조건에 `기타 행 소진 > 0` 을 포함한다

기존 표시 조건(week-plan R17 · ux-spec §3.4)은 두 갈래였다:

- 그 주에 미분류 focus 세션이 있다, **또는**
- 부모 없는 조각(시스템 "기타" 항목에 붙은 task)이 있다

**이 조건은 §1·§2 아래에서 불완전하다.** 폐기된 항목의 소진만 있는 주 — 미분류 세션도
없고 부모 없는 조각도 없는 주 — 에서는 두 갈래 모두 거짓이라 행이 숨겨지는데, 차액은
3뽀모다. **A24 가 요구하는 3뽀모가 화면에서 증발한다.**

조건을 셋으로 확장한다:

```
표시한다 ⟺ 미분류 focus 세션이 있다
        OR 부모 없는 조각이 있다
        OR 기타 행 소진 > 0
```

세 번째 갈래가 폐기·삭제로 흘러든 소진을 잡는다. 앞의 두 갈래는 **소진이 0 이어도** 행을
띄우기 위해 남는다(R17 — 사용자가 직접 만든 조각이 카드 어디에도 안 나타나는 것을 막는다).

## Consequences

- (+) 목록 쿼리의 정의역과 차액의 정의역이 **같은 하나**가 된다. 두 곳이 어긋날 구조적
  여지가 사라진다.
- (+) 화면의 등식을 사용자가 눈으로 검산할 수 있다 — 보이는 항목의 도트 합 + 기타 행 =
  게이지.
- (+) M3b 정산의 대량 폐기 후에도 주간 카드 숫자가 보존된다.
- (−) 폐기·삭제된 항목의 소진이 `계획에 없던 집중` 이라는 부정확한 라벨 아래 표시된다.
  라벨을 고치려면 기타 행을 두 줄로 쪼개야 하는데, 그것은 주간 카드가 아니라 정산의
  관심사다. v1 은 이 부정확을 수용한다.
- (−) 표시 조건이 세 갈래가 되어 판정 비용이 는다. 세 번째 갈래는 차액을 이미 계산한
  뒤이므로 추가 쿼리는 없다.
- **주간 항목 소프트 삭제 UI 를 도입한다면 이 ADR 을 다시 봐야 한다.** §2 는 삭제된
  항목의 소진이 기타 행으로 새는 것을 허용하는데, 삭제의 사용자 의도가 "없던 일로
  하겠다"이므로 그때는 세션 자체의 처리(재귀 삭제 / 미분류 승격)를 함께 정해야 한다.
  지금 정하지 않는 이유는 도달 경로가 없고, 없는 UI 를 위해 술어를 복잡하게 만드는 비용이
  실익보다 크기 때문이다.
