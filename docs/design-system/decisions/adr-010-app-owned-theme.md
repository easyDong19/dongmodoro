# ADR-010 (design-system): 테마는 앱이 소유한다 — ADR-008 §4 를 뒤집는다

- 상태: accepted (2026-08-11)
- **supersedes: [ADR-008](./adr-008-light-theme.md) §4** (OS 추종 + 트레이 3택 전환).
  **ADR-008 §1·§2·§3·§5 는 그대로 유효하다** — 특히 §2 의 라이트 팔레트 13개 전수 검증과
  §5 의 고대비 우선 규칙은 이 ADR 이 건드리지 않는다. 뒤집히는 것은 §4(전환 경로) 하나다.
- 사용자 결정: 2026-08-11 (`system` 제거 · 2택 · 타이틀바 전환 · 기본 다크)
- 관련: [ADR-006](./adr-006-theme-scope.md) §2 (고대비), [ADR-008](./adr-008-light-theme.md) (라이트 팔레트),
  [architecture ADR-018](../../architecture/decisions/adr-018-first-run-state.md) (시딩 기본값)

## Context

[ADR-008 §4](./adr-008-light-theme.md) 가 전환 경로를 두 가지로 정했다 — 기본은
`prefers-color-scheme` 로 **OS 를 따르고**, 수동 전환은 **트레이 `테마 ▸` 서브메뉴 3택**
(`시스템 따라가기` / `라이트` / `다크`)이다. 저장값은 `system` / `light` / `dark`,
기본 `system`.

**그 결정이 구현되지 않은 채 남았고, 구현하려는 순간 세 가지가 드러났다.**

### 1. 전환 경로가 테마를 app-shell 전체의 인질로 만들었다

트레이는 혼자 들어올 수 없다. [app-shell PRD R25](../../features/app-shell/prd.md) 가
**"창 닫기=숨김과 트레이 상주는 분리 배포할 수 없다"** 고 정했고, 그 이유도 명시돼 있다 —
트레이 없는 빌드에서 창 닫기를 숨김으로 바꾸면 복귀 경로가 0개인 유령 상태가 된다.

따라서 ADR-008 §4 대로 하려면 **트레이 + 창 수명주기 + 복귀 4경로 + 종료 경로 재배선**을
먼저 지어야 한다. 표시 설정 하나가 셸 전체를 선행 조건으로 갖는 구조다.

### 2. `system` 은 값이 값을 가리키는 간접 상태다

화면이 어두운 이유가 **저장값과 OS 둘로 갈린다.** "지금 왜 이렇지"를 물을 때 확인할 곳이
둘이고, 자동 테스트에서 재현하려면 OS 선호까지 흉내내야 한다.

### 3. 구현이 없는 동안 앱은 사실상 OS 를 따르고 있었다 — 결정이 아니라 사고로

[tokens.css](../../../src/renderer/shared/styles/tokens.css) 에 `@media (prefers-color-scheme: light)`
경로가 완성돼 있는데 그것을 덮을 `data-theme` 을 아무도 설정하지 않았다. 그래서 OS 가
라이트면 앱도 라이트로 떴다. **ADR-008 §4 의 "기본" 항목만 우연히 만족된 상태**였고,
수동 전환 경로는 존재하지 않았다.

### 실측: `nativeTheme.themeSource` 가 두 세계를 한 출처로 묶는다

프레임리스 타이틀바로 가면 **창 컨트롤은 OS 가 그리는데 그 색은 CSS 를 따라오지 않는다.**
순진하게 짜면 테마 해석이 두 곳(렌더러 CSS · main 의 컨트롤 색)에 생긴다.

Electron 의 `nativeTheme.themeSource` 를 설정하면 **렌더러의 `prefers-color-scheme`
미디어 쿼리까지 함께 움직인다.** main 이 한 번 설정하면 CSS 와 창 컨트롤이 같은 출처에서
나오고, **[tokens.css](../../../src/renderer/shared/styles/tokens.css) 는 한 줄도 고치지
않는다** — ADR-008 §1 이 세운 CSS 구조가 그대로 산다.

## Decision

### 1. 저장값은 `light` / `dark` 둘이고 기본은 `dark` 다

- `system` 을 **없앤다.** OS 선호를 읽어 추종하지 않는다.
- `settings` 테이블 `theme` 키의 값은 `light` 또는 `dark`, 시딩 기본값은 **`dark`**.
- 저장값이 이 둘 중 하나가 아니면(기존 DB 의 `system` 포함) **`dark` 로 판정하고 그 값을
  즉시 되쓴다.** 읽을 때마다 조용히 넘기면 저장소에 영원히 잘못된 값이 남는다.
  시딩은 멱등이라(architecture ADR-018 §4 "키가 없을 때만") 기본값 변경만으로는
  기존 DB 가 갱신되지 않는다.

### 2. 전환 경로는 타이틀바의 2택 세그먼트다

- 커스텀 타이틀바에 `[Sun|Moon]` 2세그먼트를 둔다. 선택된 쪽에 배경 **+ 보더**를 함께 준다
  ([ADR-006 §3](./adr-006-theme-scope.md) — 고대비 모드에서 배경이 사라지므로 보더가 제2 신호다).
- **새 화면을 만들지 않는다.** ADR-008 §4 의 이 원칙은 유지된다 — 타이틀바는 셸의 기존
  구성 요소이며 탭·컬럼이 늘지 않는다 (app-shell PRD R35).
- **트레이가 나중에 생기면 그쪽도 2택**이다. 3택으로 되돌리지 않는다.

`system` 이 없어졌으므로 2택이 성립한다. 3택 UI 에서 `system` 만 빼면 "한 번 누르면
OS 추종으로 되돌아갈 수 없는 문"이 되지만, 추종 자체를 없앴으므로 되돌아갈 곳이 없다.

### 3. 적용 채널은 `nativeTheme.themeSource` 이고, `data-theme` 은 테스트·문서 전용이다

- **런타임에 `data-theme` 속성을 설정하지 않는다.** main 이 창 생성 **이전에**
  `nativeTheme.themeSource` 를 설정하고, 그것이 렌더러의 `prefers-color-scheme` 을 결정한다.
- ADR-008 §1 이 명시한 `:root[data-theme='light']` 선택자는 **지우지 않고 존치**한다.
  용도가 바뀔 뿐이다 — 브라우저만으로 라이트를 강제해야 하는 **테스트와 문서**
  (와이어프레임의 테마 미리보기가 이미 이 선택자를 쓴다)의 진입점이다.
  죽은 코드가 아니라 **런타임과 다른 두 번째 진입점**으로 규정한다.
- 창 생성 이전에 적용하므로 **첫 페인트 깜빡임이 구조적으로 발생할 수 없다.**

### 4. 고대비 모드는 여전히 OS 가 이긴다 — 이 ADR 이 뒤집지 않는다

`forced-colors: active` 에서는 [ADR-006 §2](./adr-006-theme-scope.md) 와
[ADR-008 §5](./adr-008-light-theme.md) 가 그대로 적용된다. 유리·blur·광원을 포기하고
시스템 색을 따르며, **앱의 테마 선택은 그 환경에서 아무 효과가 없다.**

"앱 안에서만 결정한다"는 §1~§3 의 범위이고 **일반 모드에 한정된다.** 이것까지 앱이
가져가면 접근성 회귀다.

### 5. 창 컨트롤 색은 CSS 밖에 한 벌 더 존재한다 — 알려진 예외

Windows·Linux 는 창 컨트롤을 OS 가 그리고 그 색을 `titleBarOverlay` 로 **JS 가 지정**해야
한다. main 프로세스는 CSS 커스텀 프로퍼티를 읽을 수 없으므로 `--bg-deep`·`--ink` 의 값
4개(2테마 × 2색)가 TS 상수로 존재한다.

- "raw hex 금지"([principles §5](../principles.md))의 **실질적 예외**이며 이 ADR 이
  명시적으로 허용한다.
- 대신 **한 파일에 가두고 기계로 감시한다** — 그 파일의 테스트가 `tokens.css` 를 직접 읽어
  값의 문자열 일치를 단언한다. 토큰을 바꾸고 여기를 안 고치면 테스트가 먼저 깨진다.
- 알파가 있는 토큰을 쓰지 않는다. 창 컨트롤 글리프는 배경과 합성되지 않는 자리다.

## Consequences

- (+) **테마가 독립적으로 배포된다.** 트레이·창 수명주기·복귀 경로를 선행하지 않는다.
- (+) 상태 공간이 3 → 2 로 줄고, 해석 지점이 한 곳(`themeSource`)이 된다. 화면이 어두운
  이유가 항상 저장값 하나로 설명된다.
- (+) **첫 페인트 깜빡임 0.** 창이 태어나는 순간 이미 올바른 테마다.
- (+) **[tokens.css](../../../src/renderer/shared/styles/tokens.css) 수정 0.** ADR-008 §1 의
  두 경로 구조가 그대로 유효하고, 라이트 팔레트(§2)도 손대지 않는다.
- (+) `nativeTheme.on('updated')` 구독이 불필요하다. `themeSource` 가 항상 명시값이므로
  전환 시점에 창 컨트롤 색을 같이 갱신하면 끝이다.
- (−) **OS 의 일몰 자동 다크 전환과 어긋난다.** macOS·Windows 둘 다 그 기능이 있고, 켜 둔
  사용자는 낮에 다른 앱이 전부 밝아져도 이 앱은 선택한 채로 남는다. **이 대가를 명시적으로
  수용한다.** 앱 안에서 한 번 누르면 되고, 그 대신 상태가 항상 예측 가능해진다.
- (−) 색 값 4개가 CSS 밖에 존재한다(§5). 대조 테스트로 감당 가능한 수준까지 낮췄지만
  0 은 아니다.
- (−) 기존 DB 의 `system` 값을 정규화하는 코드가 영구히 남는다. 사용자가 1명이라 언젠가
  지울 수 있지만, 지우는 시점을 판단할 근거가 없어 남긴다.
- (−) ADR-008 을 읽는 사람이 §4 만 죽었다는 것을 알아야 한다. 상태 줄에 표기했다.
- (−) Windows·Linux 는 **실기 검증 없이** 코드만 들어간다. app-shell PRD **A17** 은
  이번에 닫히지 않는다. `titleBarOverlay` 의 색 갱신과 CSS 환경 변수 활성화가 그 두 OS 에서
  의도대로 동작하는지는 미검증으로 남는다.
