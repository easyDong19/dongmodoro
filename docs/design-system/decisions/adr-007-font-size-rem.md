# ADR-007 (design-system): 폰트 크기만 rem, 루트 62.5%

- 상태: accepted (2026-08-05)
- 관련: [ADR-004](./adr-004-focus-and-target.md) (`--target-min` 은 px 여야 한다), [ADR-001](./adr-001-breakpoint-tokens.md) (브레이크포인트는 px)

## Context

토큰의 치수 값이 전부 px 였다. rem 전환 여부를 검토했고, 결론은 **범주마다 다르다**는 것이다.

### rem 의 실익은 이 앱에서 생각보다 작다

- **WCAG 2.1 SC 1.4.4(텍스트 200% 확대)는 px 로도 이미 충족된다.** Electron 은
  `Ctrl/⌘ +/-` 줌이 px 를 포함해 전부 배율 조정한다.
- **Electron 렌더러는 OS 글자 크기 설정을 상속하지 않고, 브라우저 설정 UI 도 없다.**
  즉 rem 으로 바꿔도 지금은 아무도 루트 크기를 바꿀 수 없다.

남는 실익은 하나다: **앱 안에 "글자 크기" 설정을 만들 수 있게 되는 것.** 루트 한 줄로
전체가 비례 확대된다. 타입 스케일이 9~12px 로 유난히 작은 이 앱에서는 그 설정이 실제로
필요해질 가능성이 높다고 판단했다.

### rem 으로 가면 안 되는 범주가 있다

`--target-min: 24px` 은 **rem 이 될 수 없다.** WCAG 2.2 SC 2.5.8 이 "24 **CSS px**" 라는
절대 단위로 쓰여 있어서, rem 이면 루트가 작아질 때 기준 미달이 된다. 이것은 취향이 아니라
기준 문서의 단위 문제다.

브레이크포인트도 마찬가지다 — 창 폭에 관한 값이라 글자 크기에 반응할 이유가 없고,
[ADR-001](./adr-001-breakpoint-tokens.md) 이 이미 Tailwind 설정에 px 로 물질화했다.

## Decision

### 1. 폰트 크기만 rem 으로 바꾼다

| 범주 | 단위 | 이유 |
|---|---|---|
| **폰트 크기** (`--text-*`) | **rem** | 글자 크기 설정의 단일 지점이 된다 |
| radius (`--radius-*`) | px 유지 | 모서리가 글자 크기에 따라 변할 이유가 없다 |
| 포커스 링 두께·오프셋 | px 유지 | 1~2px 헤어라인이 rem 이면 소수 px 로 흐려진다 |
| **`--target-min`** | **px 필수** | SC 2.5.8 이 절대 단위로 요구한다 |
| 브레이크포인트 | px 유지 | 창 폭의 문제다 (ADR-001) |
| 모션·레이어 | 해당 없음 | ms·정수 |

### 2. 루트는 62.5% 로 둔다

```css
html { font-size: 62.5%; }   /* 1rem = 10px (사용자 기본값 16px 기준) */
body { font-size: var(--text-md); }
```

| 토큰 | px | 62.5% 기준 | 16px 기준(기각) |
|---|---|---|---|
| `--text-2xs` | 9px | **0.9rem** | 0.5625rem |
| `--text-xs` | 10px | **1rem** | 0.625rem |
| `--text-sm` | 11px | **1.1rem** | 0.6875rem |
| `--text-md` | 12px | **1.2rem** | 0.75rem |
| `--text-lg` | 14px | **1.4rem** | 0.875rem |
| `--text-xl` | 17px | **1.7rem** | 1.0625rem |
| `--text-display` | 56px | **5.6rem** | 3.5rem |

62.5% 는 퍼센트이므로 **사용자 기본값에 대한 비례성이 보존된다** — 사용자가 기본을 20px
로 두면 1rem 이 12.5px 이 되고 전체가 함께 커진다. 값이 읽기 쉬운 것이 채택 이유다.

`html` 에 62.5% 를 걸면 `body` 가 10px 를 상속하므로 **`body` 에 `--text-md` 를 명시**한다.
이것을 빠뜨리면 기본 본문이 10px 로 렌더된다.

### 3. 타이머 링 지름을 `em` 으로 묶는다

`--text-display` 가 rem 이 되면 200% 확대에서 56px → 112px 이 된다. 링은 현재 **236px
고정**이라 `88:88` 이 링을 넘친다. **px 였을 때는 보이지 않던 결함이 rem 이 노출한 것**이며,
어차피 고쳐야 한다.

- 링 지름을 `em` 으로 표기해 `--text-display` 와 함께 비례 확대되게 한다
  (`4.2em` ≈ 236 / 56).
- SVG 는 `viewBox` 로 비율을 유지하고 CSS 폭·높이만 `em` 으로 준다.

## Consequences

- (+) "글자 크기" 설정을 나중에 루트 한 줄로 구현할 수 있다.
- (+) 기능 문서 8개를 **한 줄도 고치지 않는다.** principles §5 가 "토큰 이름으로만 기술"을
  강제해 둔 덕에, 단위 전환이 tokens.md 기준 CSS 블록과 와이어프레임 두 곳으로 닫힌다.
- (+) 타이머 링의 확대 결함이 지금 드러나 함께 닫힌다.
- (−) 단위가 섞인다(폰트 rem / 나머지 px). 섞이는 이유가 SC 2.5.8 의 절대 단위 요구라는
  점을 이 ADR 이 근거로 남긴다.
- (−) 루트 62.5% 는 관용구이지만 초보자에게는 마법처럼 보인다. tokens.md 기준 CSS 블록에
  주석으로 이유를 남긴다.
- (−) 지금 당장 얻는 사용자 가치는 없다 — 루트를 바꿀 UI 가 아직 없기 때문이다. "글자 크기"
  설정을 v1 에 만들지는 않으며, 이 ADR 은 그것을 가능하게만 해 둔다.
