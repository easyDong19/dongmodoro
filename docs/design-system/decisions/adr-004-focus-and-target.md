# ADR-004 (design-system): 포커스 링과 조작 타깃 최소 크기

- 상태: accepted (2026-08-05)
- 근거: [v1 와이어프레임](../wireframes/v1-wireframe.html) 타깃 크기 실측 (2026-08-05)
- 관련: [ADR-003](./adr-003-contrast-baseline.md) (대비 기준), [ADR-001](./adr-001-breakpoint-tokens.md) (구간)

## Context

두 가지가 정의된 적이 없다.

**포커스 링.** `focus-visible`·`outline` 이 design-system 과 features 전체에 **0건**이다.
그런데 app-shell ux-spec §8.1 은 포커스 동작을 여러 개 규정한다 — MONTH 오버레이는
비모달이라 포커스 트랩을 걸지 않고 `Tab` 으로 밖에 나갈 수 있어야 하며, 구간 전환으로
포커스된 요소가 사라지면 포커스를 그 요소를 담고 있던 카드 컨테이너로 옮긴다. **포커스가
어디 있는지 보이지 않으면 이 규칙들은 구현할 수도 검증할 수도 없다.**

**조작 타깃 크기.** WCAG 2.2 SC 2.5.8 Target Size (Minimum)이 **24×24 CSS px** 를 AA 로
요구한다. 와이어프레임 실측은 대부분이 그 아래였다.

| 요소 | 실측 | 판정 |
|---|---|---|
| 체크박스 | 15px | 미달 |
| 캐럿 · × (목록에서 빼기) | 17px | 미달 |
| 캘린더 월 이동 화살표 | 19px | 미달 |
| 스테퍼 `−`/`+` | 22px | 미달 |
| 칩 · small 버튼 | 약 23.5px | 미달 |
| 일반 버튼 · 모드 탭 · 내로우 탭 | 28~34px | 통과 |

이것은 개별 버그가 아니다. `--text-2xs` 9px 에 패딩 4px 를 주면
`9 × 1.5 + 8 + 보더 2 ≈ 23.5px` 로 **어떻게 해도 24 에 닿지 않는다.** 패딩을 더 주면
3컬럼 밀도가 깨진다. 타입 스케일과 정보 밀도가 만든 구조적 충돌이다.

## Decision

### 1. 포커스 링은 `--ink` 기반이다 — 의미 색을 쓰지 않는다

| 후보 | 대비 (광원 0.20, glass-strong) | 판단 |
|---|---|---|
| **`--ink`** | **9.61:1** | 채택 |
| `--teal` | 6.01:1 | 기각 — teal 은 "진행·완료"를 뜻한다 |
| `--amber` | 5.94:1 | 기각 — amber 는 "초과·휴식"을 뜻한다 |

teal·amber 는 principles §3 의 상태 → 색 매핑에 이미 의미가 배정돼 있다. 포커스에 그
색을 쓰면 "포커스된 것"과 "진행 중인 것"이 같은 색이 된다. 새 의미 색을 만드는 것은
토큰 추가라 또 다른 ADR 이 필요하고, `--ink` 가 대비도 가장 높으므로 그럴 이유가 없다.

토큰 3종:

| 토큰 | 값 |
|---|---|
| `--focus-ring-width` | `2px` |
| `--focus-ring-offset` | `2px` |
| `--focus-ring-color` | `--ink` 와 같은 값 (`#eef4ef`) |

- 소비는 `:focus-visible` 에서만 한다 — 마우스 클릭에 링이 뜨지 않게 `:focus` 를 쓰지 않는다.
- 링을 제거하는 `outline: none` 을 대체 표시 없이 쓰지 않는다.
- 오프셋을 두므로 요소 자신의 보더와 겹쳐 읽히지 않는다.

### 2. 히트 영역과 라벨 크기를 분리한다

토큰 **`--target-min: 24px`** 을 추가하고, 규칙을 principles 에 넣는다.

> 조작 가능한 요소의 **히트 영역**은 시각적 크기와 무관하게 `--target-min` 이상이다.
> **라벨·아이콘을 키워 이를 달성하지 않는다** — 투명 패딩 또는 `::after` 확장으로 넓힌다.

이 규칙이 밀도와 접근성의 충돌을 푼다. 9px 라벨을 유지하면서 클릭 영역만 24px 로 넓히면
3컬럼 밀도가 그대로 남는다.

**적용 대상**: 체크박스, 캐럿, `×`, 캘린더 월 이동 화살표, 스테퍼 `−`/`+`, 칩, small
버튼. **캘린더 날짜 셀은 이미 약 30px** 로 통과한다.

### 3. SC 2.5.8 의 예외를 쓰지 않는다

이 조항에는 인라인·필수·간격 등 예외가 있지만 이 앱에서는 원용하지 않는다. 위 목록은
전부 카드 안의 독립 컨트롤이고, 예외를 쓰면 "어느 것이 예외인가"를 매번 판단해야 한다.
단일 규칙 하나가 싸다.

## Consequences

- (+) app-shell §8.1 의 포커스 규칙들이 처음으로 구현·검증 가능해진다.
- (+) 9px 타입 스케일을 유지하면서 SC 2.5.8 을 만족한다 — 타입 스케일 재설계를 피했다.
- (+) 포커스 색이 상태 색과 충돌하지 않아 상태 → 색 매핑 4행이 그대로 유지된다.
- (−) 히트 영역이 시각 경계보다 커지므로 **인접 컨트롤 간 간격이 24px 리듬에 묶인다.**
  칩을 촘촘히 붙이던 자리(조절 칩 `−10 −5 −1 | +1 +5 +10`, 요일 칩 7개)에서 히트 영역이
  겹칠 수 있다. 겹침은 허용하지 않으며, 그 경우 간격을 늘린다 — 밀도의 실제 비용이 여기서
  발생한다.
- (−) spacing 토큰이 아직 없어서(tokens.md §10) 그 간격이 raw px 로 들어간다. Task 7 에서
  spacing 을 정할 때 `--target-min` 을 제약으로 함께 본다.
- (−) 포커스 링이 유리 카드 경계와 가까운 요소에서 잘릴 수 있다(`overflow: hidden` 스크롤
  영역). 오프셋 2px 를 고려해 스크롤 컨테이너에 패딩을 남긴다 — 구현 시 확인 항목이다.
