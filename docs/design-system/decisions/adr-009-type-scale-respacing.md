# ADR-009 (design-system): 타입 스케일 재간격 — 값 2개와 사용 규칙 3개

- 상태: accepted (2026-08-05)
- 근거: audit(2026-08-05, P3) + critique(2026-08-05, P1) 이중 지적 + typeset 평가(격리 서브에이전트) 실측
- 관련: [ADR-007](./adr-007-font-size-rem.md) (rem 전환 — 이 변경이 기준 CSS 블록 한 곳으로 닫히는 이유)

## Context

토큰 스케일은 7단계(9/10/11/12/14/17/56px)인데, **실제로 일하는 것은 5단계뿐**이었다.

- `--text-md`(12px)는 `body` 기본값으로만 존재하고 제품 문자열은 사실상 전부
  sm/xs/2xs 를 명시한다.
- `--text-xl`(17px)은 "화면 단위 제목" 역할인데 실사용은 내로우 축약형의 타이머
  숫자뿐이다 — 데이터 역할이 제목 토큰을 입고 있다.
- 남는 조작 대역 9/10/11 은 +1px 사다리(배율 1.09~1.11)로, **같은 톤이면 구분되지
  않는다.** 주간 항목 행에서 제목(11px `--ink`)과 메타(10px `--ink-dim`)를 가르는
  것은 사실상 톤 100% 다.

이 사다리는 설계된 것이 아니라 **흡수된 것**이다 — tokens.md §2.2 스스로 "시안의
16개 크기를 7단계로 정규화"했다고 기록한다. 정규화는 중복을 없앴지만 간격을
설계하지는 않았다.

구체적 실패 지점 (typeset 평가 실측):

1. **정산 패널의 섹션 제목이 본문과 같은 크기다** — `1 · 요약`~`5 · 확정` 이
   11px/600 이고 그 아래 행들도 11px/400. 380px 컬럼의 11px 텍스트 더미에서
   굵기 하나로 5개 섹션을 스캔해야 한다.
2. **읽어야 하는 안내 문장이 메타 토큰을 입고 있다** — "바꾼 길이는 다음 주부터
   적용돼요 · 이번 주 기록은 그대로예요" 같은 완결 문장이 10px `--ink-dim` 이다.
   4.61:1 로 AA 는 통과하지만, 어두운 배경의 한글 10px/400 은 편안한 하한
   아래다. 문장은 메타가 아니라 읽기 역할이다.
3. **0.14em 자간이 한글 9px 에 적용되는 곳이 있다** — 자간 확대는 라틴 대문자
   (MONTH/WEEK/TODAY)가 얻는 것이지 한글은 응집만 잃는다. 플래너 단계 라벨
   ("① 이번 주 예산")이 그 예다.
4. **200% 확대에서 주간 행 둘째 줄이 넘친다** — 폰트는 rem 이라 2배가 되는데
   행의 flex 에 `wrap` 이 없어 도트+숫자+핍이 340px 컬럼을 뚫는다 (ADR-007 이
   보장하려던 확대 경로의 실측 구멍).

## Decision

### 1. 값 2개만 움직인다 — 토큰 이름 불변

| 토큰 | 전 | 후 | 근거 |
|---|---|---|---|
| `--text-sm` | 11px (1.1rem) | **12px (1.2rem)** | 조작 대역의 주력(목록 제목·행 본문). 메타(xs 10px)와 **1.2 배율**의 실질 간격이 처음 생기고, 어두운 배경 한글의 편안 하한 위로 올라온다 |
| `--text-md` | 12px (1.2rem) | **13px (1.3rem)** | sm 위를 유지. 본문(다이얼로그·안내)이 한 단계 편해진다 |

새 스케일: **9 / 10 / 12 / 13 / 14 / 17 / 56.** 핵심 간격은 10→12(1.2) 하나이며,
이것이 "제목 vs 메타"라는 이 앱의 가장 빈번한 인접을 기하학으로 가른다.

md 13 ↔ lg 14 의 1px 인접은 수용한다 — lg 는 항상 600(카드 제목)이고 md 는
400(본문)이라 굵기가 주 분리자이며, 두 역할이 같은 줄에 인접하는 화면이 없다.

기능 문서 8개는 토큰 **이름**만 참조하므로 이 값 변경으로 고칠 것이 없다
(라이트 테마 때와 같은 이득 — principles §5 의 배당).

### 2. 사용 규칙 3개

| 규칙 | 내용 |
|---|---|
| **2xs + tracking-wider 는 라틴 대문자 전용** | eyebrow(MONTH/WEEK/TODAY)가 유일한 정당한 사용자다. **한글에 9px + 0.14em 을 쓰지 않는다** — 한글 소형 라벨은 `--text-xs` + `--tracking-normal`. 1~3자 배지(`M1`·`3주째`·`W32`)는 글랜스 토큰이라 2xs 유지 가능하되 자간은 normal |
| **안내 "문장"은 `--text-sm`** | 완결 문장으로 읽어야 하는 안내(게이지 보조 문구, 정산 길이 안내)는 sm + `--ink-dim`. `--text-xs` 는 조각·메타(비율, 날짜 범위, 카운트) 전용으로 좁아진다. 톤이 "부차적"을 말하고 크기가 "읽을 수 있음"을 보장한다 |
| **섹션 제목은 `--text-md` + 600** | 같은 크기 더미에서 굵기 혼자 섹션을 가르게 하지 않는다. 정산 패널이 첫 적용 대상 |

### 3. 확대 결함을 함께 닫는다

주간 행 둘째 줄(`.item-sub` 상당)에 `flex-wrap: wrap` — 200% 확대에서 넘치는 대신
줄바꿈한다. 내로우 축약형의 타이머 숫자는 인라인 스타일 3벌이 아니라 **이름 있는
역할 셀렉터 1개**(mini-clock 상당: `--text-xl` + 600 + mono)로 굳힌다 — 같은 역할이
세 군데서 따로 조립되지 않게.

### 4. 하지 않는 것

- 패밀리·굵기 3종·`--text-lg`/`--text-xl`/`--text-display` 값·line-height 1.5: 불변.
  평가가 전부 "적합" 판정.
- 단계 수 축소(7→6): md 가 이제 본문 역할을 실제로 얻으므로 7개 이름을 유지한다.
- 행에서 요소를 빼는 것: critique P2(distill 몫), 구현 후 판단.

## Consequences

- (+) 조작 대역에 기하학적 위계가 처음 생긴다(10→12 = 1.2). 톤 혼자 지던 짐을
  크기가 나눠 든다.
- (+) 기능 문서 수정 1줄(weekly-review 의 안내 문구 토큰 지정)로 닫힌다.
- (+) 200% 확대 경로가 실제로 성립하게 된다 — ADR-007 의 약속을 실측이 메운다.
- (−) 모든 목록이 1px 커지므로 한 화면에 보이는 행 수가 근소하게 준다. 3컬럼
  밀도는 실측 확인 항목(구현 후) — 문제가 되면 행 패딩에서 회수하고 글자에서
  회수하지 않는다.
- (−) md↔lg 1px 인접이 남는다(굵기 분리로 수용). 나중에 lg 를 15px 로 올리는
  선택지가 있으며 그때 이 ADR 을 갱신한다.
- (−) 와이어프레임은 시스템 폰트 렌더다 — **번들 Pretendard 의 9~12px 실렌더와
  폴백(Apple SD Gothic Neo 600 굵기 재현)은 구현 후 실기 확인 항목**으로 남는다.
