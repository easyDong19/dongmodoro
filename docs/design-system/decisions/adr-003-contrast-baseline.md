# ADR-003 (design-system): 대비 기준선과 잉크 3단계의 역할 분리

- 상태: accepted (2026-08-05)
- 근거: [v1 와이어프레임](../wireframes/v1-wireframe.html) 대비비 실측 (2026-08-05)
- 관련: [ADR-002](./adr-002-glass-surface-tokens.md) (유리 표면이 배경을 밝히는 주체)

## Context

토큰 체계에 **대비 기준이 한 번도 없었다.** `principles.md` §2 가 "색만으로 의미를
전달하지 않는다" 를 규율로 걸었지만 "얼마나 보여야 하는가"의 수치가 없어서 위반을
판정할 방법이 없었다. 실측하니 위반이 이미 있었다.

이 앱에서 대비가 어려운 이유는 **배경이 한 색이 아니라 세 겹**이기 때문이다.

```
1층  --bg-deep                   rgb(12,26,22)   가장 어둡다
2층  + 라디얼 광원 (glow-teal 등)  rgb(22,60,52)   밝아진다
3층  + 유리 카드 (--glass~strong)  rgb(43,77,70)   더 밝아진다
```

같은 `--ink-dim` 텍스트가 1층 위에서 **5.57:1(통과)**, 3층 위에서 **3.76:1(미달)** 이다.
카드가 광원의 밝은 부분에 겹치는지에 따라 판정이 갈리고, 그것은 사용자도 구현자도
통제할 수 없다. 값 하나의 버그가 아니라 **배경 밝기의 상한이 규정되지 않은 구조적 결함**이다.

### 실측 (WCAG 2.1, 최악 배경 = 광원 위 `--glass-strong`)

| 토큰 | bg-deep | 광원 위 glass | 광원 위 glass-strong | 판정 |
|---|---|---|---|---|
| `--ink` | 16.02 | 9.26 | 8.31 | 전 구간 통과 |
| `--ink-dim` (55%) | 5.57 | 4.03 | **3.76** | 배경에 따라 갈린다 |
| `--ink-faint` (32%) | 2.72 | 2.36 | **2.26** | 전 구간 미달 (3:1 조차) |
| `--teal` | 10.03 | 5.80 | 5.20 | 통과 |
| `--amber` | 9.90 | 5.72 | 5.14 | 통과 |
| `--danger` | 7.42 | 4.29 | **3.85** | 텍스트 미달 |
| `--glass-border` (14%) | — | 1.51 | — | 비텍스트 3:1 미달 |

### 기각된 해법 두 개

**광원만 낮추기 — 불가능.** 광원 실효 알파를 0.05(사실상 제거)까지 낮춰도
`--ink-faint` 는 **2.58:1** 이다. 32% 알파 자체가 대비를 만들지 못한다.

**알파만 올리기 — 위계가 붕괴한다.** 최악 배경에서 4.5:1 을 맞추려면 `--ink-dim` 과
`--ink-faint` 가 **둘 다 65%** 를 요구한다. 즉 두 토큰이 같은 값이 되어 잉크 3단계가
2단계로 무너진다.

### 조합 실측

| | dim 55% | 58% | **60%** | 62% | 65% |
|---|---|---|---|---|---|
| 광원 0.30 (와이어프레임 현재) | 3.77 | 4.00 | 4.16 | 4.33 | 4.59 ✓ |
| 광원 0.25 | 3.95 | 4.20 | 4.38 | 4.56 ✓ | 4.84 ✓ |
| **광원 0.20** | 4.14 | 4.42 | **4.61 ✓** | 4.80 ✓ | 5.11 ✓ |
| 광원 0.15 | 4.33 | 4.63 ✓ | 4.84 ✓ | 5.05 ✓ | 5.38 ✓ |

## Decision

### 1. 대비 기준을 명시한다 — 판정 배경은 최악 조건이다

> 텍스트는 **WCAG 2.1 AA 4.5:1**, 아이콘·보더·의미 있는 그래픽은 **3:1** 을 만족한다.
> **판정 배경은 최악 조건(광원 위 `--glass-strong`)으로 한다.**

"최악 조건으로 판정한다"가 이 결정의 핵심이다. 이 문장이 없으면 다음 검증도 "어두운
배경에서 재보니 통과한다"로 끝난다.

AAA(7:1)는 목표로 삼지 않는다 — `--ink-dim` 을 90%까지 올려야 하고 그러면 보조 텍스트가
본문과 구분되지 않는다.

### 2. `--ink-dim` 55% → **60%**, 광원 실효 알파 상한 **0.20**

두 값을 함께 움직여 4.61:1 을 얻는다(여유 0.11). 어느 한쪽만 바꾸는 것보다 변화가 작다 —
알파 5%p 차이는 눈에 거의 안 보이고, 광원은 밝기가 3분의 2로 줄지만 "밤의 온실" 인상이
유지된다.

**광원 상한의 정의**: 배경 광원 레이어의 **실효 알파**(토큰 자신의 알파 × 렌더 시
opacity)가 0.20 을 넘지 않는다. `--glow-teal` 이 0.55 이므로 opacity 는 0.36 이 상한이다.
이 값은 지금까지 어디에도 규정되지 않았고, 와이어프레임이 쓴 0.55 는 근거 없는 임의값이었다.

### 3. `--ink-faint` 는 값을 바꾸지 않고 **용도를 좁힌다**

WCAG 2.1 SC 1.4.3 은 **비활성 UI 요소를 대비 요건에서 면제**한다("Incidental — inactive
user interface components"). 이 면제 위에서만 32% 를 유지한다.

| 용도 | 판정 | 색 |
|---|---|---|
| 비활성 버튼·선택 불가 항목·하한/상한에 닿은 스테퍼 | 면제 | `--ink-faint` 유지 |
| 그 달에 속하지 않는 캘린더 앞·뒤 빈 칸 | 비활성 취급 | `--ink-faint` 유지 |
| 미배정 요일 핍 | "부재"의 표현 — 정보를 전달하지 않는다 | `--ink-faint` 유지 |
| **eyebrow (`MONTH`/`WEEK`/`TODAY`)** | 정보 전달 텍스트 | **`--ink-dim` 으로 이동** |
| **출처 주 라벨 (`W33`)** | 정보 전달 텍스트 | **`--ink-dim` 으로 이동** |
| **입력 placeholder** | 정보 전달 텍스트 | **`--ink-dim` 으로 이동** |

`--ink-faint` 의 정의가 "가장 연한 잉크" 에서 **"꺼져 있음을 표현하는 색"** 으로 좁아진다.
eyebrow 이동이 특히 중요하다 — app-shell ux-spec §1 이 그것을 "컬럼이 어느 레이어인지
알리는 **유일한 표지**"로 정의했는데, 9px + 2.26:1 이면 그 유일한 표지를 읽을 수 없다.

### 4. 보더는 **분리**한다 — 카드 테두리와 컴포넌트 경계는 다른 요건이다

`--glass-border` 를 3:1 로 만들려면 흰색 **38%** 가 필요하고(현재 14%), 그것은 유리
표면을 파괴한다. SC 1.4.11 의 적용 범위를 정확히 읽어 나눈다 — 이 조항은 **UI 컴포넌트의
경계**와 **의미 있는 그래픽**에 적용되며, 장식적인 카드 테두리에는 적용되지 않는다.

| 대상 | 토큰 | 대비 |
|---|---|---|
| 카드·오버레이 테두리, 내부 구분선 | `--glass-border` 14% / `--glass-border-soft` 8% 유지 (장식) | — |
| **체크박스·입력 필드·스테퍼의 경계** | 신규 **`--control-border`** = `rgba(238,244,239,0.45)` | 3.50:1 |

`--control-border` 를 흰색이 아니라 `--ink` 기반으로 두는 이유는 잉크 계열과 색온도를
맞추기 위함이다. 입력창이 어디까지인지 판별되지 않는 것이 실제 문제였다.

### 5. `--danger` 를 텍스트 색으로 쓰지 않는다

`--danger` 는 광원 상한 0.20 기준에서도 **4.45:1** 로 4.5 에 못 미친다. 브랜드 색을
바꾸는 대신 사용 위치를 제한한다.

- **허용**: 아이콘, 보더, 배경 강조 (비텍스트 3:1 통과)
- **금지**: 글자 색. 파괴적 액션의 라벨 텍스트는 `--ink` 를 쓴다

principles §2 가 이미 "`--danger` 를 쓰는 요소는 아이콘·문구가 의미를 함께 전달해야
한다"를 요구하므로, 의미 전달은 아이콘이 이미 맡고 있다. 색을 글자에서 빼도 잃는 것이 없다.

## Consequences

- (+) 대비 판정이 처음으로 **가능해진다.** 기준과 판정 배경이 문서에 있으므로 위반을
  기계적으로 검증할 수 있다.
- (+) 잉크 3단계가 유지된다. 값을 올려 해결하지 않고 용도를 좁혀 해결했기 때문이다.
- (+) 유리 표면·브랜드 색을 하나도 포기하지 않았다.
- (−) **`--ink-dim` 이 밝아지면 감쇠 표현이 약해진다.** milestones R20 의 "지난달 카드는
  시각적으로 감쇠(`--ink-dim`)" 가 덜 감쇠로 읽힌다. 색이 아닌 수단(테두리 제거, 배경 톤)의
  보강이 필요할 수 있다 — 이 ADR 의 범위 밖이며 발견 사항으로 남긴다.
- (−) 광원이 어두워지므로 시안 v7 의 인상과 멀어진다. 시안은 대비 검증을 거치지 않은
  초안이므로 이 어긋남은 수용한다.
- (−) `--ink-faint` 의 허용 용도가 표로 고정되어, 새 용도가 생길 때마다 "정보 전달인가
  비활성인가"를 판단해야 한다. 그 판단이 애매하면 `--ink-dim` 을 쓴다(안전한 쪽).
