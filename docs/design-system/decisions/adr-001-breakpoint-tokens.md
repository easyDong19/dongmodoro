# ADR-001 (design-system): 반응형 브레이크포인트 토큰

- 상태: accepted (2026-08-04)
- 결정 근거 원장: [2026-08-04 기획 검증 세션](../../decision-log/2026-08-04-planning-session.md) §D (Q17·Q17-1)

## Context

시안 v7 은 3컬럼(MONTH·WEEK·TODAY) 고정 레이아웃이라 좁은 창에서 성립하지 않는다.
AI 추천은 "최소 창 크기 고정 + 반응형 없음"이었으나 사용자가 기각했다 — "지금 단계에서
레이아웃 결정을 해야 편하다." 이에 3단계 반응형 계획(Q17-1)이 승인됐고, 경계값은
tokens.md 토큰 + ADR 로 남기기로 했다.

접힘 우선순위의 근거는 시각 철칙이 아니라 제품 원칙이다: "타이머가 코어 루프, 계획은
레이어" — 창이 좁아질수록 계획 레이어(MONTH → WEEK)부터 접히고, 타이머와 오늘 목록이
끝까지 남는다.

## Decision

### 1. 브레이크포인트 토큰 2개 → 구간 3개

| 토큰 | 값 | 정의하는 구간 |
|---|---|---|
| `--bp-wide` | `1200px` | **와이드** (`≥ 1200px`): 시안 3컬럼 그대로 |
| `--bp-medium` | `800px` | **미디엄** (`800–1199px`): MONTH 컬럼 접힘 → 토글 시 오버레이. WEEK/TODAY 유지 |
| (기본) | — | **내로우** (`< 800px`): 1컬럼 — 타이머 상단 고정(축약형) + `오늘 | 주간 | 월간` 탭 |

- 구간은 이 3개로 닫는다. 새 구간(=새 브레이크포인트 토큰) 추가는 새 ADR.
- 값은 [tokens.md](../tokens.md) §4 가 유일한 출처다. 코드에 `1200` / `800` 리터럴
  직접 기입 금지.

### 2. 소비 방식 — 이 토큰만은 CSS 변수로 소비할 수 없다

CSS 미디어 쿼리는 `var()` 를 해석하지 못한다 (`@media (min-width: var(--bp-wide))` 는
무효). 따라서 브레이크포인트는 토큰 문서를 출처로 삼되 **Tailwind `screens` 설정에
1회 물질화**해 소비한다:

```js
// tailwind config — 값의 출처는 tokens.md §4
screens: { md: '800px', wide: '1200px' }
```

JS 에서 창 크기 로직이 필요하면 같은 상수를 shared 모듈에서 import 한다. 값이 두 곳
(tokens.md 문서 + 설정 상수)에 존재하는 것은 이 토큰 종류의 알려진 한계이며, 변경 시
둘을 함께 고치는 것을 이 ADR 이 명시한다.

### 3. 최소 창 크기

내로우 레이아웃이 성립하는 크기로 하한을 건다. 목표치 **~420×640** — 확정값은
app-shell 구현 시 실측으로 정하고, 확정되면 tokens.md 에 기록한다 (TBD).

## Consequences

- (+) 기능 문서(app-shell ux-spec 등)가 "와이드/미디엄/내로우" 이름으로 레이아웃을
  기술할 수 있다 — 픽셀 값이 문서 곳곳에 흩어지지 않는다.
- (+) 창 크기 대응이 설계 단계에서 닫혀, 구현 중 즉흥 미디어 쿼리가 생길 여지가 없다.
- (−) 브레이크포인트는 토큰 체계(기술 형식 = CSS Custom Property 로 통일)의 유일한 예외다 —
  미디어 쿼리 한계로 설정 파일에 물질화된다. tokens.md 에 예외임을 명시한다.
- (−) 경계값(800/1200)은 시안 실측 전 추정치다. 구현 중 조정이 필요하면 tokens.md 와
  이 ADR 을 함께 갱신한다.
