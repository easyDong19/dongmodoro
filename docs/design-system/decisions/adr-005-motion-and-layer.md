# ADR-005 (design-system): 모션 3단계와 레이어 5단계

- 상태: accepted (2026-08-05)
- 값의 출처: `docs/origin/pomodoro-mockup-v7.html` `transition` 실측 (인용만) + app-shell 명세에 실재하는 레이어
- 관련: [principles.md §4](../principles.md) (모션 철칙)

## Context

**모션.** ux-spec 들이 전이를 여러 개 지시한다 — MONTH 오버레이 슬라이드-인(app-shell
§3.1), 드로어 펼침·게이지 바 변화·편집 대상 주 전환(week-plan §9), 타이머 링 진행(timer
§8), 정산 섹션 접힘·패널 등장(weekly-review §9). 그런데 **시간과 이징이 어디에도 없다**
(design-system·features 전체 0건). 이 상태로 구현에 들어가면 각 컴포넌트가 값을 발명하고,
그것은 tokens.md 변경 규칙이 금지한 순서다.

**레이어.** `z-index`·스태킹 정의도 **0건**이다. 그런데 겹칠 것들이 이미 명세돼 있다:
MONTH 오버레이, 종료 확인 다이얼로그, 정산 배너, 확정 후 토스트, 내로우 축약형 고정 바.

**`prefers-reduced-motion` 의 현재 처리가 지나치게 거칠다.** principles §4 는 시안에서 온
`* { transition: none !important }` 를 지시한다. 이것은 모션만 죽이지 않고 **상태 변화
피드백까지 함께 죽인다** — 버튼이 눌렸는지, 값이 바뀌었는지 알리는 신호가 사라진다.
reduced-motion 은 "움직임을 줄여달라"이고 "피드백을 없애달라"가 아니다.

### 시안 v7 transition 실측

| 값 | 사용 | 쓰인 곳 |
|---|---|---|
| `.15s` | 15회 (지배적) | hover, background, transform, opacity, border-color |
| `.2s` | 3회 | 일반 전이 |
| `.3s` | 2회 | width, height (펼침) |
| `.4s ease` | 2회 | 진행 바 width, 링 `stroke-dashoffset` |

이징은 시안이 대부분 **생략(브라우저 기본 `ease`)** 이고, 명시한 2곳도 `ease` 다.

## Decision

### 1. 모션 3단계

| 토큰 | 값 | 용도 | 흡수한 실측값 |
|---|---|---|---|
| `--motion-fast` | `150ms` | hover, 색·배경·보더 전이, 포커스 링 | `.15s`, `.2s` |
| `--motion-medium` | `300ms` | 오버레이 슬라이드, 드로어 펼침, 섹션 접힘 | `.3s` |
| `--motion-slow` | `400ms` | 진행 바 width, 타이머 링 채움 | `.4s` |
| `--ease-standard` | `ease` | 전부 | 시안이 실제로 쓴 값 |

`--ease-standard` 를 그럴싸한 `cubic-bezier(...)` 로 바꾸지 않는다. 시안 실측값이 `ease`
이고, 더 나은 곡선이 필요하다는 근거가 아직 없다. 근거가 생기면 그때 이 ADR 을 갱신한다.

3단계 밖의 시간을 새로 만들지 않는다.

### 2. `prefers-reduced-motion` 은 **토큰을 0 으로 재정의**한다

`* !important` 전역 킬을 폐기하고 이렇게 바꾼다.

```css
@media (prefers-reduced-motion: reduce) {
  :root {
    --motion-fast: 0ms;
    --motion-medium: 0ms;
    --motion-slow: 0ms;
  }
}
```

- 결과는 동일하다 — 전이 없이 **즉시 반영**된다(ux-spec 들이 요구하는 동작).
- 다른 점은 `!important` 로 전체를 덮지 않는다는 것이다. 상태 변화의 결과는 그대로
  전달되고, 필요하면 개별 예외를 둘 수 있다.
- **모션의 자리에 대체 표시를 없애지 않는다**: 슬라이드로 알리던 등장은 즉시 표시로,
  링 채움으로 알리던 진행은 숫자·바의 즉시 갱신으로 남는다.

장식성 무한 애니메이션 금지(초과 글로우의 펄스 포함)는 principles §4 그대로 유지된다 —
이 결정은 그것을 완화하지 않는다.

### 3. 레이어 5단계

app-shell 명세에 **실재하는 것만** 넣는다. 미래를 위한 빈 칸을 만들지 않는다.

| 토큰 | 값 | 대상 |
|---|---|---|
| `--layer-base` | `0` | 카드·컬럼 |
| `--layer-sticky` | `10` | 내로우 축약형 고정 바, 카드 하단 고정 게이지 |
| `--layer-overlay` | `20` | MONTH 오버레이, 첫 실행 온보딩 오버레이 |
| `--layer-dialog` | `30` | 종료 확인, 삭제 확인 |
| `--layer-toast` | `40` | 정산 확정 결과 토스트 |

- 배경 광원·별은 스태킹 컨텍스트 안에서 `z-index: -1` 로 카드 아래에 둔다. 창 요소에
  `isolation: isolate` 를 걸어 이 음수 값이 창 배경 위에만 머무르게 한다.
- 위 5단계 밖의 값을 코드에 직접 쓰지 않는다. 새 레이어가 필요하면 ADR 로 추가한다.
- **정산 배너는 자기 레이어를 갖지 않는다** — 카드 안에 인라인으로 얹히므로 `--layer-base`
  다. 배너가 오버레이가 아니라는 것이 weekly-review 의 설계이므로 그것을 그대로 반영한다.

## Consequences

- (+) 구현이 시간·이징·스태킹 값을 발명하지 않는다. Task 7 이 옮길 것이 실제로 존재한다.
- (+) reduced-motion 이 한 곳(`:root` 재정의)에서 처리되고, 상태 피드백을 죽이지 않는다.
- (+) 레이어가 5개로 닫혀 "일단 9999" 가 생길 자리가 없다.
- (−) `.2s` 를 `--motion-fast` 150ms 로 흡수했으므로 시안보다 미세하게 빨라지는 전이가
  3곳 있다. 체감 차이는 없다고 판단했으나 구현 후 확인 항목이다.
- (−) 모션 3단계로는 표현할 수 없는 전이(스태거, 시퀀스)가 나오면 ADR 이 필요하다.
  v1 에 그런 요구가 없으므로 지금 만들지 않는다.
- (−) 레이어를 문서에 고정했으므로 새 오버레이 성격의 화면(설정 등)이 들어올 때 이 표를
  갱신해야 한다. app-shell PRD R35 가 "새 화면은 탭을 늘리지 않고 오버레이로"를 이미
  규정하므로 그 경로는 `--layer-overlay` 를 재사용한다.
