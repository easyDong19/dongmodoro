# 시각 철칙 (Design Principles)

> 출처: `docs/origin/pomodoro-prd.md` §1 원칙 3·6·7, §4 / `docs/origin/pomodoro-mockup-v7.html` 사용 실태
> 모든 화면·컴포넌트 설계는 이 철칙을 통과해야 한다. 개별 기능의 ux-spec 이 이 문서와 충돌하면 **이 문서가 이긴다.**

## 1. 실패 프레임 금지

> **2.0.0 정정.** 이 절의 원래 1번 규칙은 `뽀모 예산 초과는 실패가 아니다` 였고,
> 초과를 `--amber` 글로우 + `+N` 배지(불꽃 아이콘)로 긍정 처리하라고 지시했다.
> **그 규칙의 근거 개념이 소멸했다** — 예산·과적이 폐기되면서
> ([ADR-030](../architecture/decisions/adr-030-time-as-progress-currency.md))
> 넘길 분모 자체가 앱에 없다. 초과 상태가 없으므로 초과의 시각 처리도 없다.
> **철칙은 약해지지 않는다** — 아래가 그 자리를 그대로 잇는다.

- **비교 대상이 없는 숫자를 결핍으로 프레이밍하지 않는다.** 측정 시간은 분모 없이
  표시되므로 `적다`·`부족`·`목표 대비` 를 뜻하는 색·아이콘·문구를 붙이지 않는다.
  진행 바처럼 **없는 목표를 추측하게 만드는 형태도 금지**다 (week-plan ux-spec §7).
  세션 0인 주는 `0분` 이라는 사실이지 실패가 아니다.
- "미달성 N건" 류의 부정 표현 대신 "다음 주로 넘어갈 N건". 정산 요약은 실제로 한 일(측정 시간, 공부한 날)을 먼저 보여준다. (PRD 원칙 7)
- 시스템은 사실만 표시하고 판단하지 않는다. 이월 배지("3주째")는 보여주기만 하고, "버리세요" 류의 훈계 문구를 넣지 않는다. (PRD 원칙 6)

## 2. `--danger` 사용 조건

`--danger` 는 **사용자가 무언가를 없애는 행위**에만 쓴다. (값은 테마마다 다르다 — [tokens.md §1.4](./tokens.md))

- 허용: 삭제 버튼 hover, 이월 분류에서 "버리기(drop)" 선택 상태, 마감 임박(`hot`) 날짜 강조 — 시안 v7의 실제 사용처 전부가 이 범주다.
- 금지: 목표 미달, 이월 누적, 측정 시간이 적음 등 **성과·진척 관련 표현.** 이 경우는 §1에 따라 중립(`--ink-dim`)으로 처리한다. (2.0.0 이전에는 `예산 초과` 가 이 목록의 첫 항목이었다 — 개념이 폐기됐다.)
- 색만으로 의미를 전달하지 않는다. `--danger` 를 쓰는 요소는 아이콘·문구가 의미를 함께 전달해야 한다.
- **텍스트 색으로 쓰지 않는다.** 다크에서 3.85:1 로 AA(4.5:1)에 못 미치기 때문이다. 라이트 값은 4.63:1 로 통과하지만 **두 테마에서 규칙을 같게 유지한다** — 테마에 따라 라벨 색이 달라지면 같은 버튼이 다른 컴포넌트가 된다. 아이콘·보더·배경 강조에만 쓰고(비텍스트 3:1 통과), 파괴적 액션의 라벨 글자는 `--ink` 다 — 의미 전달은 위 규칙에 따라 아이콘과 문구가 이미 맡고 있다 ([ADR-003 §5](./decisions/adr-003-contrast-baseline.md), [ADR-008 §2](./decisions/adr-008-light-theme.md)).

## 3. 상태 → 색 매핑

| 상태 | 색 | 비고 |
|---|---|---|
| 진행·집중·완료 | `--teal` | 주 액센트 |
| 휴식·온기·강조 | `--amber` | 부 액센트. **2.0.0 에서 `초과` 가 이 행에서 빠졌다** — 예산이 폐기돼 초과 상태가 없다. 남은 용처는 휴식 모드, 캘린더의 `오늘` 숫자·진한 점, 배경 광원, 타이머 링 그라디언트다 |
| 파괴적 행위 | `--danger` | §2 조건 하에서만 |
| 중립·메타 | `--ink-dim` / `--ink-faint` | 판단이 필요 없는 정보 |

이 4행 밖의 새로운 "의미 있는 색"을 만들려면 토큰 추가이므로 ADR이 필요하다 ([tokens.md](./tokens.md) §10).

포커스는 이 4행에 들어가지 않는다 — **포커스 링은 `--ink` 기반**이며 의미 색을 쓰지 않는다. teal·amber 를 포커스에 쓰면 "포커스된 것"과 "진행 중인 것"이 같은 색이 된다 ([ADR-004 §1](./decisions/adr-004-focus-and-target.md)).

## 3.5 색만으로 구분되는 상태를 만들지 않는다

§2 의 "색만으로 의미를 전달하지 않는다"를 상태 표현 전체로 확장한다. 고대비 모드(`forced-colors: active`)와 색각 이상에서는 색이 사라지거나 뒤바뀌므로, **모든 상태 구분에 색 외의 신호가 하나 더 있어야 한다.**

| 상태 | 색 외의 신호 |
|---|---|
| 캘린더 기본 점 / 진한 점 | 지름 차이 |
| 캘린더 "오늘" | `--weight-semibold` |
| 캘린더 "선택" | 배경 + 보더 |
| 요일 핍 지난 / 오늘 / 다가올 | 윤곽선만 / 바깥 링 / solid — **불투명도 차이로 구분하지 않는다** |
| 세그먼트 토글 선택 상태 | 보더 (배경만으로 구분하지 않는다) |

근거와 전수 확인 결과는 [ADR-006 §3](./decisions/adr-006-theme-scope.md).

> **2.0.0 에서 이 표의 두 행(`뽀모 도트 채움/미채움`·`뽀모 도트 초과`)이 빠졌다.**
> 진행이 도트가 아니라 측정 시간 **텍스트**로 표시되면서 소비자가 전멸했고, 컴포넌트도
> 제거됐다. 텍스트는 애초에 색만으로 구분되는 상태가 아니므로 대체 신호가 필요 없다.
> 다만 새 규칙이 하나 붙는다 — **`0분` 과 `—`(값 없음)는 다른 사실이므로 같은 표기로
> 뭉개지 않는다** (week-plan ux-spec §0.3).

## 4. 모션

- `prefers-reduced-motion: reduce` 를 **항상 존중**한다. 처리 방식은 [tokens.md §6](./tokens.md) 의 모션 토큰을 `0ms` 로 재정의하는 것이다 — 전이 없이 즉시 반영된다.
- **`* { transition: none !important }` 전역 킬은 폐기됐다** (시안 v7 에서 온 규칙). 모션만 죽이지 않고 상태 변화 피드백까지 함께 죽이기 때문이다. reduced-motion 은 "움직임을 줄여달라"이고 "피드백을 없애달라"가 아니다 ([ADR-005 §2](./decisions/adr-005-motion-and-layer.md)).
- 모션의 자리에 대체 표시를 없애지 않는다: 슬라이드로 알리던 등장은 즉시 표시로, 링 채움으로 알리던 진행은 숫자·바의 즉시 갱신으로 남는다.
- 모션은 상태 변화의 결과를 전달할 때만 쓴다. 장식성 무한 애니메이션 금지 (배경 광원·별은 정적 렌더가 기본).

## 5. 토큰 강제

- 기획 문서(ux-spec 포함)와 구현 코드에서 색·폰트 크기·radius·유리 표면(backdrop·하이라이트·shadow)·모션 시간·레이어·포커스·타깃 크기는 **[tokens.md](./tokens.md) 의 토큰 이름으로만** 기술한다. raw hex·px 직접 기입 금지.
- 토큰에 없는 값이 필요하면: 기존 토큰으로 흡수 가능한지 먼저 검토 → 불가하면 ADR 로 토큰 추가 → 그 뒤에 사용. 순서를 뒤집지 않는다.
- 아직 토큰화되지 않은 유일한 범주는 **spacing** 이며, M1 Task 7 에서 실제 레이아웃과 함께 정한다 (tokens.md §10).

## 6. 아이콘 — UI 에 이모지 금지

- **렌더되는 UI(라벨·배지·버튼·빈 상태 카피 포함)에 이모지를 쓰지 않는다.**
  이모지는 플랫폼마다 렌더가 다르고 토큰(색·크기)의 통제를 받지 않으며, 특유의 "AI 생성물" 인상을 남긴다.
- 아이콘은 **lucide-react 아이콘 컴포넌트**로 통일한다 (shadcn/ui 의 기본 아이콘셋 — [architecture ADR-003](../architecture/decisions/adr-003-ui-tailwind-shadcn.md) 과 정합).
  `currentColor` 상속으로 §3 의 상태 → 색 매핑을 그대로 따르게 한다.
- lucide 에 적절한 글리프가 없는 도메인 심볼은 **토큰 기반 커스텀 SVG/CSS 컴포넌트**로 만든다.
  이모지로 대체하지 않는다. (2.0.0 이전의 예시였던 뽀모 도트는 진행 표시가 측정 시간
  텍스트로 바뀌면서 제거됐다 — 지금 이 범주에 해당하는 컴포넌트는 없다.)
- 초안 PRD·시안·기획 문서 안의 🍅/이모지 표기는 **문서용 속기**일 뿐, 구현 지시가 아니다.
  ux-spec 을 쓸 때는 "타이머 링", "재생 아이콘(lucide `Play`)" 처럼 컴포넌트·아이콘 이름으로 기술한다.

## 7. 접근성 기준선 — 판정 가능한 수치로만 기술한다

"보기 좋게" 같은 표현으로 접근성을 기술하지 않는다. 아래 4개는 전부 기계적으로 검증된다.

| 항목 | 기준 | 근거 |
|---|---|---|
| 텍스트 대비 | **4.5:1** (WCAG 2.1 AA). 판정 배경은 **테마마다 다르다** — 다크는 광원 위 `--glass-strong`(카드 안), 라이트는 광원 위 **카드 밖**(타이틀바) | [ADR-003](./decisions/adr-003-contrast-baseline.md) · [ADR-008 §2](./decisions/adr-008-light-theme.md) |
| 아이콘·보더·의미 있는 그래픽 대비 | **3:1** (SC 1.4.11). 장식적인 카드 테두리는 대상이 아니다 | ADR-003 §4 |
| 포커스 표시 | `:focus-visible` 에 `--ink` 링 2px + 오프셋 2px. `outline: none` 을 대체 표시 없이 쓰지 않는다 | [ADR-004](./decisions/adr-004-focus-and-target.md) §1 |
| 조작 타깃 | 히트 영역 **`--target-min`(24px) 이상** (WCAG 2.2 SC 2.5.8 AA). **라벨을 키워 달성하지 않는다** — 투명 패딩으로 넓힌다 | ADR-004 §2 |

- 판정 배경이 "최악 조건"이라는 점이 이 기준선의 핵심이다. 어두운 배경에서 재서 통과시키는 검증을 반복하지 않기 위한 규정이다.
- **테마에 따라 최악의 방향이 뒤집힌다.** 다크는 글자가 밝으니 배경이 밝아질수록 나빠지고, 라이트는 글자가 어두우니 배경이 어두워질수록 나빠진다. 한 테마의 판정 배경으로 다른 테마를 검증하면 통과한 것처럼 보인다 ([ADR-008 §2](./decisions/adr-008-light-theme.md)).
- AAA(7:1)는 목표로 삼지 않는다 — `--ink-dim` 을 90% 까지 올려야 하고 그러면 보조 텍스트가 본문과 구분되지 않는다.
- 비활성 UI 요소는 SC 1.4.3 이 대비 요건에서 면제한다. `--ink-faint` 는 **그 면제 범위 안에서만** 쓴다 (tokens.md §1.3 의 허용 표).
