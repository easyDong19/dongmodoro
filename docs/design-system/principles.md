# 시각 철칙 (Design Principles)

> 출처: `docs/origin/pomodoro-prd.md` §1 원칙 3·6·7, §4 / `docs/origin/pomodoro-mockup-v7.html` 사용 실태
> 모든 화면·컴포넌트 설계는 이 철칙을 통과해야 한다. 개별 기능의 ux-spec 이 이 문서와 충돌하면 **이 문서가 이긴다.**

## 1. 실패 프레임 금지

- 뽀모 예산 **초과는 실패가 아니다.** 초과 시 빨간색·경고 아이콘·경고 문구 금지.
  초과는 `--amber` 글로우 + `+N 🔥` 배지로 **긍정 처리**한다. (PRD 원칙 3)
- "미달성 N건" 류의 부정 표현 대신 "다음 주로 넘어갈 N건". 리뷰 요약은 실제로 한 일(소진 뽀모, 공부한 날)을 먼저 보여준다. (PRD 원칙 7)
- 시스템은 사실만 표시하고 판단하지 않는다. 이월 배지("3주째")·소진율은 보여주기만 하고, "버리세요" 류의 훈계 문구를 넣지 않는다. (PRD 원칙 6)

## 2. `--danger` 사용 조건

`--danger`(`#e8907e`)는 **사용자가 무언가를 없애는 행위**에만 쓴다.

- 허용: 삭제 버튼 hover, 이월 분류에서 "버리기(drop)" 선택 상태, 마감 임박(`hot`) 날짜 강조 — 시안 v7의 실제 사용처 전부가 이 범주다.
- 금지: 예산 초과, 목표 미달, 이월 누적 등 **성과·진척 관련 표현.** 이 경우는 §1에 따라 `--amber` 또는 중립(`--ink-dim`)으로 처리한다.
- 색만으로 의미를 전달하지 않는다. `--danger` 를 쓰는 요소는 아이콘·문구가 의미를 함께 전달해야 한다.

## 3. 상태 → 색 매핑

| 상태 | 색 | 비고 |
|---|---|---|
| 진행·집중·완료 | `--teal` | 주 액센트 |
| 초과·휴식·온기 | `--amber` | 초과는 항상 긍정 프레임 |
| 파괴적 행위 | `--danger` | §2 조건 하에서만 |
| 중립·메타 | `--ink-dim` / `--ink-faint` | 판단이 필요 없는 정보 |

이 4행 밖의 새로운 "의미 있는 색"을 만들려면 토큰 추가이므로 ADR이 필요하다 ([tokens.md](./tokens.md) §5).

## 4. 모션

- `prefers-reduced-motion: reduce` 를 **항상 존중**한다. 시안 v7 기준: `@media (prefers-reduced-motion: reduce) { * { transition: none !important; } }` — 모든 화면에 동일 적용.
- 모션은 상태 변화의 결과를 전달할 때만 쓴다. 장식성 무한 애니메이션 금지 (배경 광원·별은 정적 렌더가 기본).

## 5. 토큰 강제

- 기획 문서(ux-spec 포함)와 구현 코드에서 색·폰트 크기·radius 는 **[tokens.md](./tokens.md) 의 토큰 이름으로만** 기술한다. raw hex·px 직접 기입 금지.
- 토큰에 없는 값이 필요하면: 기존 토큰으로 흡수 가능한지 먼저 검토 → 불가하면 ADR 로 토큰 추가 → 그 뒤에 사용. 순서를 뒤집지 않는다.
