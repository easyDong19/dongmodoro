> 리뷰 후속 결정 반영: [2026-08-04 리뷰 결정](../../decision-log/2026-08-04-review-decisions.md) D1·D2 · [ADR-012](../../architecture/decisions/adr-012-aggregation-predicate.md) · [ADR-013](../../architecture/decisions/adr-013-baseline-budget-effect.md)
> 시각 값은 전부 [tokens.md](../../design-system/tokens.md) 토큰 이름으로 기술한다.

> 이모지 금지 — 아이콘은 lucide-react 컴포넌트명, 뽀모 개수는 뽀모 도트 컴포넌트로 기술한다 (principles §6).

## 1. 전체 흐름

```
배너 (주간 카드 상단)  ──[정산 시작]──▶  정산 패널
                                          1 요약
                                          2 끝낸 것들
                                          3 남은 것들 — 항목별 3택
                                          4 안내 + 뽀모 길이 진입점
                                          5 확정 버튼 ──▶ 패널 닫힘, 배너 소멸
```

- 정산 패널은 **모달이 아니다.** 열려 있는 동안에도 타이머·오늘 목록 조작이 가능해야
  한다 (PRD R7, 원칙 5). 강제 통과 화면·순차 마법사 금지.
- 패널이 열려 있는 동안 다른 화면에서 항목이 완료·삭제·추가돼도 **확정은 실패하지
  않는다** (PRD R29). 화면은 예외(줄여서·보내주기)만 전송하고, 나머지는 확정 시점에
  서버가 다시 조회해 이월한다.
- 확정 버튼의 라벨은 계획 대상 주가 오늘이 속한 주인지에 따라 갈린다 (§7).
- 패널의 배치 위치(주간 컬럼 인라인 확장 / 오버레이)는 반응형 구간에 따라 달라지며
  app-shell ux-spec 이 정의한다. 이 문서는 내부 구성과 문구만 정의한다.

## 2. 배너 상태

주간 카드 상단, 앰버 톤(`--amber` 텍스트/보더 + `--glass` 표면). `--danger` 를 쓰지
않는다 — 정산 대기는 파괴적 행위도 실패도 아니다 (principles §2, §1).
아이콘은 lucide `CalendarClock`.

| 상태 | 조건 | 문구 | 액션 |
|---|---|---|---|
| 없음 | 정산 범위가 빈 범위 | (배너 자체를 렌더하지 않는다) | — |
| 이번 주 마감 | 범위가 1주이고 그 주 = 오늘이 속한 주 | `이번 주 마감이 기다려요 · 다음 주로 넘어갈 N건` | `정산 시작` |
| 지난 주 | 범위가 1주이고 과거 주 | `지난 주(W35) 정산이 기다려요 · 다음 주로 넘어갈 N건` | `정산 시작` |
| 여러 주 병합 | 범위가 2주 이상 | `W33–W35 정산이 기다려요 · 다음 주로 넘어갈 N건` | `정산 시작` |
| 넘어갈 것 없음 | 범위는 비었지 않으나 미완료 항목 0건 | `이번 주 마감하고 다음 주를 시작할까요` | `정산 시작` |

- `W35` 같은 주 번호는 **렌더 전용 라벨**이다 (ADR-010 §2). 저장값이 아니다.
- "미달성", "밀린", "숙제", "지연" 류 단어 금지. N 은 항상 **넘어갈** 건수다 (원칙 7).
- 배너에 닫기(×)를 둘 수 있으나, 닫아도 다음 실행 시 판정에 의해 다시 나타난다 —
  판정은 저장값에서 파생되며 "무시했다"는 상태를 따로 저장하지 않는다.

## 3. 정산 패널 — 1. 요약

**실제로 한 일을 먼저 놓는다** (원칙 7). 달성률 %는 크게 띄우지 않으며, 필요하면
보조 메타(`--ink-dim`, `--text-xs`)로만 둔다.

| 범위 | 문구 |
|---|---|
| 1주 (오늘이 속한 주) | `이번 주 마감 — N일 공부, 뽀모 M 소진 (예산 B)` |
| 1주 (과거 주) | `지난 주(W35) — N일 공부, 뽀모 M 소진 (예산 B)` |
| 여러 주 병합 | 헤더 `W33–W35 — 뽀모 M 소진` + 주별 한 줄 목록 (`W33 · 2일 공부, 뽀모 6`) |
| 공백 주 포함 | 판단 없이 사실만: `2주 쉬었어요 · 마지막으로 공부한 주(W32) 뽀모 20 소진` |
| 기록이 전혀 없는 범위 | `이 기간에는 기록이 없어요` (`--ink-dim`). 주별 목록을 렌더하지 않는다 |

- 주별 목록에 나오는 주는 **기록이 있는 주**(세션 ≥ 1 또는 항목 ≥ 1)뿐이다. 완전히
  빈 주는 행을 만들지 않고 "N주 쉬었어요" 문장으로만 센다 (PRD R11).
- "마지막으로 공부한 주"는 **정산 범위 밖일 수 있다** — 범위와 독립적으로 조회한
  값을 쓴다 (PRD R31). 그런 주가 아예 없으면(첫 사용) 이 문장을 렌더하지 않는다.
- "이번 주 마감" 문구는 의도된 선택이다. 일요일에 확정하면 그 주에는 아직 하루가
  남아 있고, 정산 후 그날 밤에 돌린 세션은 요약에 안 잡히지만 캘린더·항목 소진에는
  반영된다 (PRD R26). "지난 주"라고 쓰면 그 어긋남이 거짓말이 된다.
- 소진 수는 뽀모 도트 컴포넌트 + 숫자 병기. 숫자는 `--font-mono` + tabular-nums.
- 예산 초과 시 빨강·경고 금지. `--amber` 글로우 + `+N` 배지(lucide `Flame` 동반)로
  긍정 처리한다 (principles §1). 단, **이월이 겹쳐 한 주에 쏟아진 경우**의 사실은
  이 시각 언어가 아니라 §7 의 중립 문장이 담당한다 (PRD R40).

## 4. 정산 패널 — 2. 끝낸 것들

- 목록 기준: **항목의 `week` 이 정산 범위 안**이고 `completed_at` 이 있는 항목.
  완료 시각(`completed_at`)이 범위 밖이어도 포함된다 — 그 항목이 어느 주의 계획이었는지가
  기준이다. 시스템 "기타" 항목은 제외한다 (`is_system = 0`).
- 접힘 가능(기본 펼침), 0건이면 섹션 자체를 숨긴다.
- 행: lucide `Check`(`--teal`) + 제목(`--ink`) + 소진 뽀모(`--ink-dim`).
- 여기서는 아무 조작도 하지 않는다 — 완료의 사실은 이미 사용자 클릭으로 만들어졌다 (Q14).

## 5. 정산 패널 — 3. 남은 것들 (항목 3택)

### 5.0 섹션 머리말과 정렬

- 정렬 (PRD R34): **이월 N주째가 큰 항목이 위로**, 같으면 주(오래된 주 먼저) → 생성 순.
- 3주 이상 넘어온 항목이 1건 이상이면 섹션 위에 중립 사실 한 줄
  (`--ink-dim` · `--text-xs`): `3주 이상 넘어온 항목 4건`
  - 판단·권유 문구 금지. "정리하세요"·"버릴 때예요" 류를 붙이지 않는다 (원칙 6).
  - 이 정렬과 문장이 초안의 "3주째부터 기본 선택 비우기" 요구를 대체한다 (§5.2 가정 블록).

### 5.1 행 구성 (좌 → 우)

| 요소 | 내용 |
|---|---|
| 제목 | 항목 제목. `--ink` · `--text-lg` |
| 출처 주 라벨 | 범위가 2주 이상일 때만. `W33` · `--ink-dim` · `--text-2xs` (읽어야 하는 정보이므로 `--ink-faint` 를 쓰지 않는다 — [ADR-003 §3](../../design-system/decisions/adr-003-contrast-baseline.md)) |
| 이월 배지 | `N주째`. **N ≥ 2 일 때만 표시.** `--ink-dim` · `--text-2xs` · `--radius-sm`. 색으로 강조하지 않는다 |
| 남은 몫 | 뽀모 도트 컴포넌트 + `뽀모 3 남음`. `--ink-dim` |
| 3택 세그먼트 | `다음 주로` / `줄여서` / `보내주기` (§5.2) |

- 이월 배지는 사실 표시 전용이다. 색·아이콘으로 경고하지 않고 "버리세요" 류 훈계
  문구를 붙이지 않는다 (principles §1, 원칙 6).
- 남은 몫·이월 배지 N 의 계산식은 technical-spec 파생식 표를 따른다. 화면은 그 값을
  받아 표시만 한다 (PRD R14·R20).
- 시스템 "기타" 항목은 이 목록에 나타나지 않는다 (PRD R16).

### 5.2 3택 세그먼트의 상태

| 선택 | 라벨 | 시각 | 부가 UI |
|---|---|---|---|
| 이월 (기본) | `다음 주로` | 선택 상태 `--glass-strong` + **보더** + `--teal` 텍스트 | 없음 |
| 축소 이월 | `줄여서` | 선택 상태 `--glass-strong` + **보더** + `--amber` 텍스트 | 스테퍼 등장 (§5.3) |
| 폐기 | `보내주기` | 선택 상태 `--glass-strong` + **보더** + lucide `ArchiveX`(`--danger`) | 행 전체를 `--ink-faint` 로 흐림 |

- **선택 상태에 보더가 필수다** — `--glass-strong` 배경은 고대비 모드에서 사라지므로
  배경만으로 선택을 표현하면 어느 것이 선택됐는지 알 수 없다
  ([ADR-006 §3](../../design-system/decisions/adr-006-theme-scope.md)). `aria-pressed` 는
  스크린리더용이고 시각 신호를 대체하지 않는다.
- `보내주기` 의 `--danger` 는 **아이콘에만** 쓴다 — 라벨 글자는 `--ink` 다. `--danger` 는
  최악 배경에서 3.85:1 로 텍스트 AA 를 만족하지 못한다
  ([ADR-003 §5](../../design-system/decisions/adr-003-contrast-baseline.md)). 의미 전달은
  아이콘과 `보내주기` 라는 문구가 이미 맡는다.

- **모든 항목의 기본 선택은 `다음 주로`** 이며 (원칙 4), 사용자가 아무것도 건드리지
  않고 확정해도 유효한 결과가 나온다. 기본 선택은 전송되지 않는다 — 확정 요청은
  `줄여서`·`보내주기` 만 담는다 (PRD R29).
- `--danger` 는 "보내주기" **선택 상태**에만 쓴다. 미선택 상태의 라벨은 중립색이며,
  색 단독으로 의미를 전달하지 않도록 아이콘·문구를 함께 쓴다 (principles §2).
- 문구는 `보내주기` 로 고정한다. "버리기"·"삭제" 워딩 금지.

> ⚠️ 가정: 초안 §3.6 은 "이월 3주째 이상인 항목은 기본 선택을 비워 한 번 의식적으로
> 고르게 한다"는 예외를 제안했다. **v1 에서는 채택하지 않는다** — 확정 결정인
> 원칙 4("아무것도 안 건드리고 확정해도 합리적 결과가 나와야 한다")와 정면으로
> 충돌하고, 기본 선택이 빈 행이 하나라도 있으면 클릭 1회 확정이 깨진다.
> 대신 **초안의 니즈는 클릭 1회를 깨지 않는 방식으로 흡수한다** — 3주 이상 항목을
> 목록 상단으로 올리고(§5.0), 그 건수를 섹션 위 중립 사실로 한 줄 적고, 행에 이월
> 배지를 표시한다. 재도입이 필요하면 별도 결정으로 다룬다.

### 5.3 축소 스테퍼

- 기본값·하한·상한은 technical-spec 파생식 표의 "축소 기본값"과 클램프 규칙을 따른다
  (PRD R15). 화면은 서버가 준 `remaining` 을 상한으로 쓴다.
- `−` / 숫자(`--font-mono`, tabular-nums) / `+`. `--radius-sm`.
- 하한·상한에 닿으면 해당 버튼만 비활성(`--ink-faint`). 경고 문구·흔들림 애니메이션 금지.
- 잘려나간 몫은 이력에 남지 않는다 (PRD R36). 그 사실을 화면에서 경고하지 않는다 —
  줄이는 것은 실패가 아니다 (원칙 7).

## 6. 정산 패널 — 4. 안내와 뽀모 길이 진입점

- 계획에 없던 집중 안내 (그 값이 1 이상일 때만):
  `계획에 없던 집중 N은 기록으로만 남아요. 할당이 틀린 건 실패가 아니라 정보예요.`
  - 이 값은 미분류 세션과 시스템 "기타" 항목의 세션을 합친 **차액**이다 (PRD R32).
    "미분류"라는 단어를 화면에 쓰지 않는다 — 주간 카드의 "기타 — 계획에 없던 집중"과
    같은 개념이므로 같은 말을 쓴다 (Q11).
- 뽀모 길이 진입점 (PRD R24):
  - 표시: `뽀모 길이 — 집중 25 · 짧은 휴식 5 · 긴 휴식 15` + `조정` (ghost 버튼)
  - 보조 문구: `바꾼 길이는 다음 주부터 적용돼요 · 이번 주 기록은 그대로예요`
    (`--ink-dim` · `--text-sm` — 완결 문장은 메타 토큰(xs)을 쓰지 않는다,
    [ADR-009 §2](../../design-system/decisions/adr-009-type-scale-respacing.md))
  - "정산에서만 바꿔요" 류 문구 금지 — 길이는 언제든 편집할 수 있고, 정산에 있는 것은
    **진입점**일 뿐이다 (ADR-013 §3).
  - `조정` 화면은 확정 전에 **변경 전/후 주간 총 집중 시간**을 숫자로 함께 보여준다
    (PRD R38 · ADR-013 §4). 예: `주 24개 · 지금 10시간 → 바꾸면 20시간`.
    가용량·예산을 자동으로 고쳐 제안하지 않는다 (원칙 6).
  - `조정` 을 눌렀을 때의 입력 UI·유효 범위·기본값은 **pomo-baseline 소관**이다.
    이 패널은 진입점과 현재 값 표시까지만 책임진다.
  - 길이 변경은 **정산 확정과 별개**로 저장된다. 정산을 확정하지 않고 패널을 닫아도
    길이 변경은 남고, 정산을 확정해도 진행 중인 주의 값은 바뀌지 않는다.

## 7. 정산 패널 — 5. 확정 버튼

### 7.1 라벨

계획 대상 주가 오늘이 속한 주일 수 있다(평일 지각 정산 — ADR-010 §3). 라벨을
"다음 주"로 고정하지 않고 조건 분기한다.

| 계획 대상 주 | 이월 뽀모 합 | 문구 |
|---|---|---|
| 오늘이 속한 주 | ≥ 1 | `이번 주 시작 (이월 뽀모 N 포함)` |
| 오늘이 속한 주 | 0 | `이번 주 시작` |
| 다음 주 | ≥ 1 | `다음 주 시작 (이월 뽀모 N 포함)` |
| 다음 주 | 0 | `다음 주 시작` |

- 이월 뽀모 합 0 은 "전부 보내주기" 또는 "남은 항목 0건"인 경우다.

### 7.2 중립 사실 한 줄

버튼 위, `--ink-dim` · `--text-xs`. 이월 뽀모 합이 1 이상이면 항상 표시한다.

```
이월 60 · 다음 주 예산 20
```

- 3주 만에 복귀해 60뽀모가 한 주로 들어오는 상황과 "한 주를 알차게 보낸" 상황에
  **같은 시각 언어(앰버 글로우 + 불꽃)를 쓰지 않기 위한 줄**이다 (PRD R40, 원칙 6).
- 막지도, 캡을 두지도, 줄이라고 권하지도 않는다 (원칙 4). 두 숫자를 나란히 놓기만 한다.
- 예산 숫자는 계획 대상 주의 예산이며, 그 주의 스냅샷이 아직 없으면 기본 예산
  (가용량 합)을 쓴다. 계산 규칙은 technical-spec 파생식 표.
- 문장의 주 표현도 §7.1 과 같은 조건 분기를 따른다 (`이번 주 예산 20` / `다음 주 예산 20`).
- "예산 초과", "무리예요", "위험" 류 단어 금지.

### 7.3 확정 후

- primary 버튼, `--radius-md`. 확정 전 별도 확인 다이얼로그를 두지 않는다 —
  파괴적 행위가 아니고(폐기도 soft), 확정 후 플래너에서 계속 편집할 수 있다.
- 확정 후: 패널이 닫히고 배너가 사라진다. 이어서 플래너로 넘어갈 수 있으나
  **자동으로 열지는 않는다** — 정산과 플래닝은 분리된 단계다 (week-plan 소관).
- 확정 결과 토스트는 사실만: `다음 주로 N건 넘어갔어요` (계획 대상 주가 오늘이 속한
  주면 `이번 주로 N건 넘어갔어요`). 축하·칭찬 문구 금지 (원칙 6).
- 응답에 **화면이 몰랐던 자동 이월 항목**이 실려 오면 (패널을 열어둔 사이 새로 생긴
  항목 등) 토스트에 사실을 한 줄 덧붙인다 (PRD R30):
  `그 사이 추가된 2건도 함께 넘어갔어요` — 사과·경고 문구 금지.

## 8. 예외 화면

| 상황 | 화면 |
|---|---|
| 정산할 것 없음 | 배너를 렌더하지 않는다. 진입점이 없으므로 패널도 열리지 않는다. 메뉴 등으로 직접 열린 경우: `지금 정산할 주가 없어요` (`--ink-dim`) + `닫기` |
| 첫 실행 (새 DB) | 배너 없음 (워터마크 초기값 규칙 — PRD R4). 빈 상태 안내는 app-shell 콜드 스타트 소관 |
| 여러 주 병합 | §3 주별 요약 목록 + §5.1 출처 주 라벨. 화면은 여전히 1개, 스크롤만 길어진다 (PRD R6) |
| 넘어갈 항목 0건 | 요약과 확정 버튼만 남는다. 3택 섹션은 숨기고 안내 한 줄: `넘어갈 항목이 없어요 — 이번 주를 마감할까요` |
| 패널을 열어둔 사이 목록이 변함 (완료·삭제·추가) | **에러 화면 없음.** 확정은 성공한다. 사라진 항목의 예외는 서버가 무시하고, 새 항목은 이월된다. 결과는 §7.3 의 토스트 한 줄로만 알린다 (PRD R29·R30) |
| 확정 중 정산 범위가 달라짐 | 인라인 안내 `날짜가 바뀌어서 정산 범위를 다시 불러왔어요` + 새 데이터로 재렌더 (판정 근거: technical-spec `STALE_RANGE`). 범위가 **커지는** 경우도 여기 해당한다 |
| 확정 실패 (트랜잭션 롤백) | 인라인 안내 `저장하지 못했어요 — 다시 시도해 주세요`. 선택 상태 유지. 아무것도 반영되지 않았음을 명시 (PRD R22) |

### 8.1 범위가 달라진 재렌더에서 "선택을 유지"의 뜻

`STALE_RANGE` 후 재조회하면 목록의 행 집합이 달라질 수 있다. 다음 규칙으로만 처리하며,
사용자가 손댄 값을 조용히 버리지 않는다.

- **기존 행**: 항목 id 로 대조해 선택(`줄여서`·`보내주기`)과 스테퍼 값을 **그대로 유지**한다.
  단 새 `remaining` 이 더 작아졌으면 스테퍼 값을 상한으로 클램프한다.
- **새로 들어온 행**: 기본 선택 `다음 주로` 로 시작한다 (원칙 4).
- **사라진 행**: 조용히 제거한다. 그 항목에 대한 선택은 폐기된다.
- 선택을 전부 초기화하거나 패널을 닫는 처리는 하지 않는다.

## 9. 모션·아이콘

- 섹션 접힘·패널 등장 전이만 허용(상태 변화 결과 전달). 장식성 무한 애니메이션 금지.
  `prefers-reduced-motion: reduce` 시 전이 없이 즉시 반영 (principles §4).
- 이모지 금지. 이 문서에 등장하는 아이콘은 lucide `CalendarClock`, `Check`, `Flame`,
  `ArchiveX` 이며, 뽀모 개수는 토큰 기반 뽀모 도트 컴포넌트다 (principles §6).

## 10. 반응형

- 구간별 배치(인라인 확장 / 오버레이 / 탭 내부 전체 화면)와 최소 창 크기는
  app-shell ux-spec 이 정의한다. 이 문서는 섹션 순서와 문구만 고정한다.
- 내로우 구간에서도 섹션 순서(요약 → 끝낸 것들 → 남은 것들 → 안내 → 확정)는 바뀌지
  않는다. 확정 버튼은 스크롤 하단 고정으로 항상 도달 가능해야 한다.
