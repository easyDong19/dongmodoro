# PRD: app-shell

> 출처: docs/origin/pomodoro-prd.md §4(레이아웃)·§3.7(콜드 스타트) (초안) + [결정 원장](../../decision-log/2026-08-04-planning-session.md) §D (Q17·Q17-1), §B (Q16)
> 초안과 이 문서가 다르면 이 문서가 이긴다.

## 문제

초안의 레이아웃은 3컬럼 고정이고, 창 크기·창 닫기·첫 실행에 대한 정책이 없다.
이대로 두면 세 가지가 각각 앱을 망가뜨린다.

1. **창이 좁아지면** 3컬럼이 성립하지 않는다. 무엇을 먼저 접을지 정해두지 않으면
   구현 중 즉흥 미디어 쿼리가 생기고, 타이머가 계획 카드에 밀려 잘리는 일이 생긴다.
2. **창을 닫으면** — 타이머는 main 이 소유하므로([ADR-005](../../architecture/decisions/adr-005-timer-architecture.md))
   창이 없어도 계속 돈다. 그런데 창 닫기가 곧 종료라면 이 구조의 이점이 전부 사라지고,
   반대로 창만 닫히는데 복귀 경로가 없으면 앱이 유령이 된다.
3. **첫 실행에** 계획이 하나도 없는 상태는 정상 상태다(원칙 1). 그 화면이 오류처럼
   보이면 앱은 첫 화면에서 실패한다.

## 대상 사용자

- 앱 소유자 1인 (로컬 단독, 로그인·멀티유저 없음)
- 사용 맥락: "타이머를 켜고 창을 최소화한 채 딴 일을 한다" — 창이 보이지 않는 시간이
  기본값인 앱이다.

## 목표

1. 창 크기 대응을 **설계 단계에서 닫는다** — 구간 3개, 각 구간에서 무엇이 남고 무엇이
   접히는지 확정.
2. 좁아질 때 접히는 순서가 제품 원칙을 그대로 반영한다 — 계획 레이어(MONTH → WEEK)가
   먼저 접히고 타이머·오늘이 끝까지 남는다.
3. 창 닫기와 앱 종료를 사용자가 혼동하지 않는다. 창을 닫아도 세션이 유실되지 않고,
   복귀 경로가 항상 하나 존재한다.
4. 계획 0개 상태에서 첫 화면이 각 패널의 역할을 스스로 설명한다 — 온보딩 투어 없이.

## 범위 / 비범위

**범위:** 창 골격(프레임리스 + 커스텀 타이틀바), 3컬럼 배치와 반응형 3단계, MONTH
컬럼 접힘·오버레이 토글, 내로우 1컬럼 탭 전환과 타이머 축약형의 배치, 최소 창 크기,
창 닫기·최소화·종료의 수명주기 정책, 트레이 아이콘과 트레이 메뉴, 콜드 스타트 화면의
조합, 리사이즈 중 상태 보존, 스크롤 영역 규칙.

**비범위:**
- 타이머 카드 내부 구성·상태 기계·종료 확인 다이얼로그의 문구 (→ timer. 이 문서는
  "창/앱 수명주기가 언제 그 확인을 요구하는가"까지만 정의한다)
- 각 컬럼 안의 카드 내용과 그 빈 상태 카피 (→ today-tasks, week-plan, milestones,
  calendar-records. 셸은 "첫 실행에 어떤 조합이 보이는가"만 정의하고 문구는 위임한다)
- 자정 경계의 맥락 힌트 (Q18 → today-tasks)
- 크래시 복원 — 강제 종료·크래시 시 진행 중 세션의 복구 (Q16 소결정: v1 에서 만들지 않음)
- 설정 화면 (M4)
- 창 위치·크기의 세션 간 기억 — v1 비범위. 매 실행 기본 크기로 시작한다.
- macOS 코드 서명·공증 ([ADR-004](../../architecture/decisions/adr-004-packaging-deploy.md), M4 미결)

## 요구사항

### 창 골격

- **R1.** 프레임리스 창 + 커스텀 타이틀바를 쓴다. 타이틀바에는 트래픽 라이트 영역,
  앱 이름, 오늘 날짜 라벨이 놓이고 그 영역이 창 드래그 핸들이 된다.
- **R2.** 최소 창 크기는 **내로우 레이아웃이 성립하는 하한**으로 건다. 목표치
  ~420×640 이며 확정값은 구현 시 실측으로 정한다 (TBD — 확정 시
  [tokens.md §4](../../design-system/tokens.md) 에 기록).
- **R3.** 카드의 스크롤 규칙: 카드는 flex column, 고정 요소(헤더·입력·게이지)는
  `flex-shrink: 0`, 스크롤 영역만 `flex: 1; min-height: 0; overflow-y: auto` +
  상하 마스크 페이드. 세 구간 전부 이 규칙을 따르며, 창 전체가 스크롤되지 않는다.

### 반응형 3단계 (Q17·Q17-1)

경계값은 [ADR-001 (design-system)](../../design-system/decisions/adr-001-breakpoint-tokens.md)
이 소유한다. 이 문서는 토큰 이름으로만 구간을 부른다.

- **R4.** 구간은 3개이며, 그 외 중간 단계를 만들지 않는다.

  | 구간 | 조건 | 배치 |
  |---|---|---|
  | 와이드 | 폭 ≥ `--bp-wide` | 3컬럼 — 좌 MONTH(마일스톤+캘린더) / 중 타이머 / 우 WEEK+TODAY |
  | 미디엄 | `--bp-medium` 이상 `--bp-wide` 미만 | 2컬럼 — MONTH 컬럼 접힘(토글 시 오버레이). 타이머 + WEEK/TODAY 유지 |
  | 내로우 | 폭 < `--bp-medium` | 1컬럼 — 타이머 축약형 상단 고정 + `오늘 / 주간 / 월간` 탭 |

- **R5.** 접힘 순서는 계획 레이어부터다 — MONTH 가 먼저 접히고, 그다음에도 좁으면
  WEEK 가 탭 뒤로 들어간다. **타이머와 오늘 목록은 어느 구간에서도 접히지 않는다.**
- **R6.** (미디엄) MONTH 는 토글 버튼으로 오버레이로 열린다. 열려 있는 동안에도
  타이머 조작이 가능해야 한다 — 화면 전체를 덮는 모달로 만들지 않는다.
- **R7.** (내로우) 타이머는 **축약형**으로 상단에 고정되고 탭을 전환해도 사라지지
  않는다. 축약형은 진행률 링 없이 `MM:SS` + 현재 모드 + 시작/일시정지로 구성된다
  (timer ux-spec §9 가 이 배치의 정의를 셸에 위임).
- **R8.** 구간 전환은 창 폭 하나만 본다. 전환 시 진행 중 타이머, 입력 중인 텍스트,
  선택된 날짜, 열려 있던 드로어·오버레이의 상태는 **유실되지 않는다**.
- **R9.** 구간 전환·오버레이 개폐의 전이 애니메이션은 `prefers-reduced-motion: reduce`
  에서 즉시 반영으로 대체한다 ([principles §4](../../design-system/principles.md)).

### 창 수명주기 (Q16)

- **R10.** 창 닫기(×)는 **창만 닫는다.** 앱은 종료되지 않고 타이머는 main 에서
  계속 돌며, 세션 완료 판정·기록·OS 알림도 창 없이 수행된다
  ([ADR-005](../../architecture/decisions/adr-005-timer-architecture.md)).
- **R11.** 진짜 종료는 앱 종료(⌘Q) 뿐이다. 종료 시 진행 중 세션은 기록되지 않는다.
- **R12.** focus 가 실행 중(running/paused)인 상태의 종료 요청은 **확인을 1회** 거친다.
  셸은 이 확인을 요구·중재하는 쪽이고, 다이얼로그의 문구·버튼·조건은 timer 가 소유한다
  (timer ux-spec §7). 셸이 그 문구를 따로 정의하지 않는다.
- **R13.** 창이 닫힌 상태에서의 종료 요청도 R12 를 따른다 — 확인이 필요하면 창을
  복원해 보여준다. 사용자가 못 보는 확인창을 만들지 않는다.
- **R14.** 최소화는 창 닫기와 동일하게 아무 사실도 만들지 않는다 (타이머 계속).

### 트레이

- **R15.** 창이 닫혀도 앱이 살아 있으므로 **트레이가 유일한 복귀 경로다.** 앱이 실행
  중이면 트레이 아이콘이 항상 존재한다.
- **R16.** 트레이 메뉴는 최소 두 항목을 제공한다 — `창 열기`(복원·포커스), `종료`.
  `종료`는 R12 의 확인을 그대로 거친다.
- **R17.** OS 알림 클릭 시 창이 복원되며, **타이머를 자동 시작하지 않는다**
  (timer ux-spec §6 과 동일 규칙).
- **R18.** 트레이 아이콘에 남은 시간을 표시하는 것은 가산점 항목이며 v1 필수가 아니다.
  아이콘 형태·남은 시간 표기 방식·알림음 세부는 **TBD** (결정 원장 §F 미결, M4).

### 콜드 스타트 / 빈 상태 (§3.7)

- **R19.** 첫 실행(계획·세션 0개)에서 타이머는 즉시 사용 가능하고 "자유 집중" 상태다.
  온보딩 투어·환영 모달·설정 강요 화면을 만들지 않는다.
- **R20.** 첫 실행 화면의 조합은 셸이 정의한다 — 세 컬럼이 전부 자리에 있고, 각 카드는
  비어 있는 대로 자기 역할을 설명하는 카피와 CTA 를 보인다. **각 카드의 빈 상태 문구는
  해당 기능이 소유한다** (오늘 목록 → today-tasks / 주간 카드·예산 게이지 → week-plan /
  마일스톤 → milestones / 캘린더·날짜 패널 → calendar-records). 셸은 문구를 복제하지 않는다.
- **R21.** 빈 상태를 오류로 표현하지 않는다 — 경고색·경고 아이콘·"데이터 없음" 류의
  실패 프레임 금지 ([principles §1](../../design-system/principles.md)).
  계획 0개는 정상 상태다.
- **R22.** 계획이 0개여도 타이머 시작→완료→세션 기록→알림이 전 구간 동작한다 (원칙 1).

### 시각 규칙

- **R23.** 색·폰트·radius·브레이크포인트는 [tokens.md](../../design-system/tokens.md)
  의 토큰 이름으로만 기술·구현한다. raw hex/px 직접 기입 금지.
- **R24.** 렌더되는 UI(탭 라벨·트레이 메뉴·버튼·빈 상태 카피)에 이모지를 쓰지 않는다.
  아이콘은 lucide-react 컴포넌트, 도메인 심볼(뽀모 도트)은 토큰 기반 커스텀 SVG/CSS
  ([principles §6](../../design-system/principles.md)).

## 성공 지표

- 최소 창 크기부터 전체 화면까지 폭을 연속으로 끌어도 타이머와 오늘 목록이 한 번도
  잘리거나 사라지지 않는다.
- 계획 데이터가 0인 새 DB의 첫 화면에서 사용자가 아무 것도 설정하지 않고 첫 세션을
  완주할 수 있다 (원칙 1 검증).
- 창을 닫은 채 완주한 세션의 유실 0.
- 구간 전환 중 상태 유실 0 (진행 중 타이머·입력 중 텍스트·선택 날짜).
