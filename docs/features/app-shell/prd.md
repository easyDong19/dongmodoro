# PRD: app-shell

> 출처: docs/origin/pomodoro-prd.md §4(레이아웃)·§3.7(콜드 스타트) (초안) + [결정 원장](../../decision-log/2026-08-04-planning-session.md) §D (Q17·Q17-1), §B (Q16)
> + [2026-08-04 리뷰 결정](../../decision-log/2026-08-04-review-decisions.md) (케이스 7·8 반영, ADR-013 §3 파생)
> 초안과 이 문서가 다르면 이 문서가 이긴다.

## 문제

초안의 레이아웃은 3컬럼 고정이고, 창 크기·창 닫기·첫 실행에 대한 정책이 없다.
이대로 두면 네 가지가 각각 앱을 망가뜨린다.

1. **창이 좁아지면** 3컬럼이 성립하지 않는다. 무엇을 먼저 접을지 정해두지 않으면
   구현 중 즉흥 미디어 쿼리가 생기고, 타이머가 계획 카드에 밀려 잘리는 일이 생긴다.
2. **창을 닫으면** — 타이머는 main 이 소유하므로([ADR-005](../../architecture/decisions/adr-005-timer-architecture.md))
   창이 없어도 계속 돈다. 그런데 창 닫기가 곧 종료라면 이 구조의 이점이 전부 사라지고,
   반대로 창만 닫히는데 복귀 경로가 없으면 앱이 유령이 된다.
3. **"창 닫기 = 숨김"은 혼자 성립하지 않는다.** 이 결정은 트레이 상주·Dock/작업표시줄
   복귀·단일 인스턴스 잠금 **3개를 동반 필수로** 끌고 온다. 하나라도 빠지면
   (a) Windows 에서 종료 경로가 사라지고 (b) Dock 클릭에 아무 일도 안 일어나고
   (c) 두 번째 실행이 같은 DB 를 열어 타이머 2개·알림 2회가 생긴다
   ([리뷰 케이스 7](../../decision-log/2026-08-04-review-decisions.md)).
4. **첫 실행에** 계획이 하나도 없는 상태는 정상 상태다(원칙 1). 그 화면이 오류처럼
   보이면 앱은 첫 화면에서 실패한다.

## 대상 사용자

- 앱 소유자 1인 (로컬 단독, 로그인·멀티유저 없음)
- 사용 맥락: "타이머를 켜고 창을 최소화한 채 딴 일을 한다" — 창이 보이지 않는 시간이
  기본값인 앱이다.

## 목표

1. 창 크기 대응을 **설계 단계에서 닫는다** — 구간 3개, 각 구간에서 무엇이 남고 무엇이
   접히는지 확정.
2. 좁아질 때 접히는 순서가 제품 원칙을 그대로 반영한다 — 계획 레이어(MONTH → WEEK)가
   먼저 접히고 타이머·오늘이 끝까지 남는다.
3. 창 닫기와 앱 종료를 사용자가 혼동하지 않는다. 창을 닫아도 세션이 유실되지 않고,
   복귀 경로가 항상 존재한다.
4. **모든 지원 플랫폼에서 종료 경로와 복귀 경로가 각각 최소 1개 존재한다** — 플랫폼
   관용구 하나(단축키 하나)에 수명주기를 얹지 않는다.
5. 계획 0개 상태에서 첫 화면이 각 패널의 역할을 스스로 설명한다 — 온보딩 투어 없이.

## 범위 / 비범위

**범위:** 지원 플랫폼별 창 관용구의 차이 흡수, 창 골격(프레임리스 + 커스텀 타이틀바),
3컬럼 배치와 반응형 3단계, MONTH 컬럼 접힘·오버레이 토글, 내로우 1컬럼 탭 전환과 타이머
축약형의 배치, 최소 창 크기, 창 닫기·최소화·종료의 수명주기 정책, 단일 창 불변식과 복귀
경로 열거, 단일 인스턴스 잠금, 트레이 아이콘과 트레이 메뉴, 콜드 스타트 화면의 조합과
첫 실행 온보딩 화면의 자리, 리사이즈 중 상태 보존, 스크롤 영역 규칙.

**비범위:** (각 항목에 "미래에 어디로 들어가는가"를 함께 적는다 — 나중에 셸의 세 곳을
동시에 건드리지 않기 위한 예약이다. 슬롯 규칙은 R35.)

- 타이머 카드 내부 구성·상태 기계·종료 확인 다이얼로그의 문구 (→ timer. 이 문서는
  "종료 요청 경로가 무엇이고 언제 그 확인을 요구하는가"까지만 정의한다)
- 각 컬럼 안의 카드 내용과 그 빈 상태 카피 (→ today-tasks, week-plan, milestones,
  calendar-records. 셸은 "첫 실행에 어떤 조합이 보이는가"와 "카피가 존재하는가"만
  정의하고 문구는 위임한다)
- 베이스라인·가용량 편집의 규칙·기본값 (→ pomo-baseline. 셸은 첫 실행 온보딩의 **자리**만
  정의한다 — R31)
- 자정 경계의 맥락 힌트 (Q18 → today-tasks)
- 크래시 복원 — 강제 종료·크래시 시 진행 중 세션의 복구 (Q16 소결정: v1 에서 만들지 않음).
  → 미래에 다루더라도 셸의 슬롯을 쓰지 않는다(복원은 main 의 시작 시 판정).
- 설정 화면 (M4) → **슬롯 예약**: 트레이 메뉴의 세 번째 항목 + 타이틀바 우측 아이콘
  진입, 화면 자체는 내로우에서도 오버레이. **탭·컬럼을 늘리지 않는다** (R35).
- 트레이의 타이머 조작(시작/일시정지) (M4) → **슬롯 예약**: 트레이 메뉴 `창 열기` 아래
  구분선 위 그룹.
- 창 위치·크기의 세션 간 기억 — v1 비범위. 매 실행 기본 크기로 시작한다.
  → 미래에 붙으면 창 생성 시점의 복원값일 뿐이며 R8 의 구간 판정을 바꾸지 않는다.
- macOS 코드 서명·공증 ([ADR-004](../../architecture/decisions/adr-004-packaging-deploy.md), M4 미결)

## 요구사항

### 플랫폼 범위

- **R1.** 지원 플랫폼은 **macOS·Windows·Linux** 다. 특정 플랫폼 전용 관용구에 기능을
  얹지 않으며, 플랫폼별로 달라지는 규칙은 이 문서가 **플랫폼 조건으로 명시**한다.
  ([ADR-004](../../architecture/decisions/adr-004-packaging-deploy.md) 가 배포 대상을
  macOS 로 한정하지 않으므로 Windows·Linux 빌드가 나오는 것이 기본값이다.)
- **R2.** 수명주기는 **"종료 요청(quit request)"** 이라는 플랫폼 중립 개념 위에 쓴다.
  종료 요청의 발생 경로는 다음으로 **열거되며, 이 열거는 셸이 소유한다.**

  | 경로 | 조건 |
  |---|---|
  | 플랫폼 종료 단축키 | macOS `⌘Q`, Windows·Linux `Ctrl+Q` |
  | 앱 메뉴의 Quit 항목 | 해당 플랫폼이 앱 메뉴를 갖는 경우 (macOS) |
  | 트레이 메뉴 `종료` | 전 플랫폼 — **트레이가 없는 빌드가 없다**(R25) |
  | OS 주도 종료 | 로그아웃·재시동·시스템 종료·강제 종료 (R23 — 확인 없음) |

  요구사항·인수 기준의 문장에서는 **플랫폼 단축키 리터럴을 쓰지 않고 "종료 요청"으로
  부른다.** 어느 플랫폼에서도 사용자가 도달 가능한 종료 요청 경로가 최소 2개 존재한다
  (단축키 + 트레이).
- **R3.** **창 닫기는 종료 요청이 아니다.** 타이틀바의 창 닫기 버튼(×)과 Windows·Linux 의
  `Alt+F4`, macOS 의 `⌘W` 는 모두 **창 닫기**로 동작한다(R16). 창 닫기에 확인을 붙이지
  않는다 — 잃는 것이 없다.
- **R4.** 타이틀바의 슬롯 정의는 **플랫폼 조건**이다. 창 컨트롤(닫기·최소화·최대화)이
  놓이는 변은 OS 관용구를 따르고, 셸의 요소는 그 변을 침범하지 않는다.

  | 플랫폼 | 창 컨트롤 | 셸 요소 배치 |
  |---|---|---|
  | macOS | 좌측 (트래픽 라이트) | 좌측 컨트롤 영역 오른쪽부터 앱 이름 → 우측에 날짜 라벨·MONTH 토글 |
  | Windows·Linux | 우측 | 좌측부터 앱 이름 → 날짜 라벨·MONTH 토글, **우측 창 컨트롤 폭을 비워 둔다** |

  구현은 창 컨트롤 영역 폭을 플랫폼별 상수로 예약하고, 그 영역과 겹치는 클릭 타깃을
  두지 않는다.

### 창 골격

- **R5.** 프레임리스 창 + 커스텀 타이틀바를 쓴다. 타이틀바에는 창 컨트롤 영역(R4),
  앱 이름, 오늘 날짜 라벨이 놓이고 빈 영역이 창 드래그 핸들이 된다.
- **R6.** 최소 창 크기는 **내로우 레이아웃이 성립하는 하한**으로 건다. 목표치
  ~420×640 이며 확정값은 구현 시 실측으로 정한다 (TBD — 확정 시
  [tokens.md §4](../../design-system/tokens.md) 에 기록).
- **R7.** 스크롤 규칙: **각 카드는 독립 스크롤 영역을 가지며, 창 전체는 어느 구간에서도
  가로·세로로 스크롤되지 않는다.** 구현 레시피(flex 구성·마스크 페이드)는
  [ux-spec §2](./ux-spec.md) 가 소유한다.

### 반응형 3단계 (Q17·Q17-1)

경계값은 [ADR-001 (design-system)](../../design-system/decisions/adr-001-breakpoint-tokens.md)
이 소유한다. 이 문서는 토큰 이름으로만 구간을 부른다.

- **R8.** 구간은 3개이며, 그 외 중간 단계를 만들지 않는다.

  | 구간 | 조건 | 배치 |
  |---|---|---|
  | 와이드 | 폭 ≥ `--bp-wide` | 3컬럼 — 좌 MONTH(마일스톤+캘린더) / 중 타이머 / 우 WEEK+TODAY |
  | 미디엄 | `--bp-medium` 이상 `--bp-wide` 미만 | 2컬럼 — MONTH 컬럼 접힘(토글 시 오버레이). 타이머 + WEEK/TODAY 유지 |
  | 내로우 | 폭 < `--bp-medium` | 1컬럼 — 타이머 축약형 상단 고정 + `오늘 / 주간 / 월간` 탭 |

- **R9.** 접힘 순서는 계획 레이어부터다 — MONTH 가 먼저 접히고, 그다음에도 좁으면
  WEEK 가 탭 뒤로 들어간다. **타이머와 오늘 목록은 어느 구간에서도 접히지 않는다.**
- **R10.** (미디엄) MONTH 는 토글 버튼으로 오버레이로 열린다. **비모달**이다 — 화면
  전체를 덮지 않고, 열린 동안에도 타이머 조작이 가능하며 스크림을 넣지 않는다.
  비모달이므로 닫힘 경로는 **토글 재클릭 / `Esc` / 오버레이 내부의 닫기 버튼** 세
  가지뿐이며, **오버레이 밖 클릭으로 닫지 않는다** (타이머 버튼은 정의상 "밖"이므로
  밖 클릭 닫힘과 비모달은 동시에 성립하지 않는다).
- **R11.** (내로우) 타이머는 **축약형**으로 상단에 고정되고 탭을 전환해도 사라지지
  않는다. 축약형의 구성·금지 조작은 [ux-spec §4.1](./ux-spec.md) 이 유일하게 정의한다
  (timer ux-spec §9 가 이 배치의 정의를 셸에 위임했다). 이 PRD 는 구성 목록을
  복제하지 않는다.
- **R12.** 주간 정산 패널(weekly-review 소유)의 **자리는 셸이 정의한다** — 와이드·미디엄
  에서는 WEEK 카드 자리를 인라인으로 점유하고, 내로우에서는 `주간` 탭 전체를 차지한다.
  패널 내용·문구·결정 전송은 weekly-review 소관이다. 배너는 R12 와 무관하게 해당 카드
  상단에 붙는다.
- **R13.** 구간 판정의 **1차 출처는 CSS 미디어 쿼리**다. JS 판정이 필요한 경우
  (포커스 이동·탭 렌더 등) 같은 상수를 공유해 판정하며(ADR-001 §2), `resize` 처리는
  rAF 또는 디바운스로 합쳐 프레임당 1회만 반영한다. 두 판정이 서로 다른 값을 쓰는
  경로를 만들지 않는다.
- **R14.** 구간 전환은 창 폭 하나만 본다. 전환 시 진행 중 타이머, 입력 중인 텍스트,
  선택된 날짜, 열려 있던 드로어·오버레이의 상태는 **유실되지 않는다.** 경계 폭을
  왕복해도(넓힘 → 좁힘 → 넓힘) **탭 선택과 각 스크롤 위치가 보존된다** — 구간 전환이
  상태를 초기화하는 경로를 만들지 않는다.
- **R15.** 구간 전환·오버레이 개폐의 전이 애니메이션은 `prefers-reduced-motion: reduce`
  에서 즉시 반영으로 대체한다 ([principles §4](../../design-system/principles.md)).

### 창 수명주기와 복귀 경로 (Q16 + 리뷰 케이스 7)

- **R16.** 창 닫기(×)는 **창만 닫는다.** 앱은 종료되지 않고 타이머는 main 에서
  계속 돌며, 세션 완료 판정·기록·OS 알림도 창 없이 수행된다
  ([ADR-005](../../architecture/decisions/adr-005-timer-architecture.md)).
- **R17. 단일 창 불변식.** 셸은 언제나 창을 **0개 또는 1개** 갖는다. 두 번째 창을
  만드는 경로가 존재하지 않는다.
- **R18.** 복귀 경로는 다음 **네 개**이며, 모두 "기존 창이 있으면 그것을 복원·포커스,
  없으면 1개를 만든다"는 동일한 동작으로 수렴한다(R17).

  | 경로 | 동작 |
  |---|---|
  | 트레이 `창 열기` | 복원 + 포커스 |
  | OS 알림 클릭 | 복원 + 포커스. **타이머를 자동 시작하지 않는다**(R28) |
  | Dock / 작업표시줄 아이콘 클릭 | 트레이 `창 열기` 와 **완전히 동일**하게 처리한다 |
  | 앱 재실행 시도 | 두 번째 인스턴스가 기존 인스턴스의 창을 포커스하고 즉시 종료한다(R19) |

  Dock/작업표시줄 클릭은 창을 닫은 사용자가 **가장 먼저 하는 행동**이므로, 이 경로가
  없으면 사용자는 앱이 죽었다고 판단하고 재실행한다.
- **R19. 단일 인스턴스 잠금은 필수다.** 두 번째 실행은 창을 만들지 않고, 기존 인스턴스에
  복귀 신호를 보낸 뒤 즉시 종료한다. 근거: 이 앱은 **DB 파일을 단독 소유**하고
  **타이머를 단일 소유**한다([ADR-005](../../architecture/decisions/adr-005-timer-architecture.md)).
  잠금이 없으면 두 번째 프로세스가 같은 DB 를 열어 타이머 2개가 돌고, 알림이 2회 오고,
  시작 시 백업이 살아 있는 인스턴스의 DB 위에서 실행된다.
- **R20.** 종료 요청(R2)이 완료되면 진행 중 세션은 기록되지 않는다. 이미 기록된 세션·
  계획 데이터는 영향받지 않는다.
- **R21. 종료 확인의 소유권 경계.** 셸은 **종료 요청 경로의 열거**(R2)와 그 경로 전부가
  동일한 확인을 거친다는 사실을 소유한다. 확인 다이얼로그의 **조건("종료 요청 시 focus 가
  running/paused 인 경우")·문구·버튼은 timer 가 소유한다** (timer ux-spec §7). 셸은
  문구를 복제하지 않으며, timer 의 조건문이 특정 플랫폼 단축키로 한정되지 않도록 이
  열거를 참조 대상으로 제공한다.
- **R22.** 창이 닫힌 상태의 종료 요청도 R21 을 따른다 — 확인이 필요하면 **창을 먼저
  복원해** 보여준다. 사용자가 못 보는 확인창을 만들지 않는다.
- **R23. OS 주도 종료는 확인을 요구하지 않는다.** 로그아웃·재시동·시스템 종료·강제 종료
  에서는 확인 다이얼로그를 띄우지 않고 진행 중 세션을 유실한다. 이 경로를 막거나 지연
  시키지 않으며, 진행 중 세션의 복구도 하지 않는다 — **크래시 복원과 동일 취급**
  (Q16 소결정: v1 비범위).
- **R24.** 최소화는 창 닫기와 동일하게 아무 사실도 만들지 않는다 (타이머 계속).

### 트레이

- **R25. 창 닫기=숨김과 트레이 상주는 분리 배포할 수 없다.** 두 규칙은 하나의 배포
  단위다. **트레이가 없는 빌드에서는 창 닫기(×)가 종료로 동작한다** — 복귀 경로가 0개인
  유령 상태를 어떤 중간 빌드에서도 만들지 않는다. 트레이 존재 자체는 M1 이며(M4 로
  미루지 않는다), M4 로 남는 것은 **아이콘의 형태와 표시 세부**뿐이다(R29).
- **R26.** 앱이 실행 중이면 트레이 아이콘이 항상 존재한다. 창이 닫힌 동안 트레이는
  복귀 경로 4개(R18) 중 **항상 사용 가능한 하나**다.
- **R27.** 트레이 메뉴는 최소 두 항목을 제공한다 — `창 열기`, `종료`. `창 열기` 는
  **창이 이미 열려 있어도 비활성화하지 않는다** (포커스만 옮긴다 — 비활성 항목은
  "앱이 응답하지 않는다"로 오독된다). `종료` 는 R21 의 확인을 그대로 거친다.
- **R28.** OS 알림 클릭 시 창이 복원되며, **타이머를 자동 시작하지 않는다**
  (timer ux-spec §6 과 동일 규칙).
- **R29.** 트레이 아이콘에 남은 시간을 표시하는 것은 가산점 항목이며 v1 필수가 아니다.
  아이콘 형태·남은 시간 표기 방식·알림음 세부는 **TBD** (결정 원장 §F 미결, M4).
  이 TBD 는 아이콘의 *형태*에 한하며, 트레이의 *존재*는 R25 로 확정이다.

### 콜드 스타트 / 빈 상태 (§3.7)

- **R30.** 첫 실행(계획·세션 0개)에서 타이머는 즉시 사용 가능하고 "자유 집중" 상태다.
  온보딩 투어·환영 모달·설정 강요 화면을 만들지 않는다.
- **R31. 첫 실행 온보딩 설정 화면의 자리.** 베이스라인 길이·가용량은 상시 편집 가능하며
  ([ADR-013 §3](../../architecture/decisions/adr-013-baseline-budget-effect.md)),
  **첫 실행 온보딩이 그 편집 경로 중 하나**다. 셸은 그 화면의 자리만 정한다 —
  **첫 실행 시 1회 오버레이**(비모달 아님, 셸의 다른 오버레이와 달리 이 화면은 진입
  직후 1회만 뜬다), 명시적으로 **건너뛸 수 있고**, 건너뛰면 R30 의 기본 상태로 들어간다.
  다시 열리는 경로는 상시 편집 진입점(pomo-baseline 소관)이며, 두 번째 실행부터는
  자동으로 뜨지 않는다. **표시 항목·기본값·검증 규칙은 pomo-baseline 이 소유한다** —
  셸은 값도 문구도 정의하지 않는다.
- **R32.** 첫 실행 화면의 조합은 셸이 정의한다 — 세 컬럼이 전부 자리에 있고,
  **각 카드는 비어 있을 때 자기 역할을 설명하는 카피 1개 이상과 CTA 1개 이상을
  실제로 렌더한다.** 셸의 검증 대상은 "그 두 요소가 존재하는가"이며,
  **문구 내용은 해당 기능이 소유한다** (오늘 목록 → today-tasks / 주간 카드·예산 게이지
  → week-plan / 마일스톤 → milestones / 캘린더·날짜 패널 → calendar-records).
  셸은 문구를 복제하지 않는다. 소유 기능이 **신규 작성해야 하는 항목**(초안에 카피는
  있으나 CTA 원문이 없는 것 — 오늘 목록의 계획 0개 분기, 캘린더 날짜 패널)은
  [ux-spec §7.2](./ux-spec.md) 표에 표시한다.
- **R33.** 빈 상태를 오류로 표현하지 않는다 — 경고색·경고 아이콘·"데이터 없음" 류의
  실패 프레임 금지 ([principles §1](../../design-system/principles.md)).
  계획 0개는 정상 상태다.
- **R34.** 계획이 0개여도 타이머 시작→완료→세션 기록→알림이 전 구간 동작한다 (원칙 1).

### 미래 슬롯 예약

- **R35.** 비범위 항목이 v1 이후 들어올 때 **셸의 슬롯을 새로 만들지 않는다.** 트레이
  메뉴 항목 수·내로우 탭 수(3개)·와이드 컬럼 수(3개)는 셸의 확정 골격이며, 새 화면은
  기존 슬롯 안의 진입점 + 오버레이로 들어온다. 비범위 목록의 각 항목에는 "미래에 어디로
  들어가는가"가 함께 적혀 있고(범위/비범위 절), 그 예약과 다른 배치가 필요해지면
  **셸의 골격 변경으로 취급해 이 문서를 먼저 고친다.**

### 시각 규칙·접근성

- **R36.** 색·폰트·radius·브레이크포인트·유리 표면은 [tokens.md](../../design-system/tokens.md)
  의 토큰 이름으로만 기술·구현한다. raw hex/px 직접 기입 금지.
- **R37.** 렌더되는 UI(탭 라벨·트레이 메뉴·버튼·빈 상태 카피)에 이모지를 쓰지 않는다.
  아이콘은 lucide-react 컴포넌트, 도메인 심볼(뽀모 도트)은 토큰 기반 커스텀 SVG/CSS
  ([principles §6](../../design-system/principles.md)).
- **R38.** 유리 표면의 backdrop·inset 하이라이트·드롭 섀도는
  [tokens.md §5](../../design-system/tokens.md) 의 Surface 토큰 6종으로만 기술·구현한다
  (`--glass-backdrop` · `--glass-highlight` · `--glass-shadow` / 컨트롤용 `--control-*`).
  셸이 이 표면의 최대 소비자이므로 셸 구현 전에 토큰을 확정했다 —
  근거는 [ADR-002 (design-system)](../../design-system/decisions/adr-002-glass-surface-tokens.md).
  **창 자체의 그림자는 토큰이 아니다** (프레임리스 창이라도 OS 가 그린다).
  레벨 추가·값 변경은 ADR 선행이며([tokens.md §10](../../design-system/tokens.md)) 구현에서
  raw 값을 먼저 쓰지 않는다.
- **R39.** 접근성 최소선: 내로우 탭은 `tablist`/`tab`/`tabpanel` role 과 좌우 화살표
  이동을 갖는다. **MONTH 오버레이는 비모달이므로 포커스 트랩을 걸지 않는다**(R10) —
  `Tab` 으로 오버레이 밖으로 나갈 수 있어야 한다. 구간 전환으로 포커스된 요소가 사라진
  경우 포커스는 **그 요소를 담고 있던 카드의 컨테이너**로 이동한다(문서 처음으로
  돌아가지 않는다). 그 밖의 상세(단축키 표·스크린리더 문구)는 **TBD**.
- **R40.** 셸이 렌더하는 모든 조작 요소는 **포커스가 눈에 보이고**(`:focus-visible` +
  `--focus-ring-*`), **히트 영역이 `--target-min`(24px) 이상**이다. R39 의 키보드 규칙은
  포커스 표시 없이는 성립하지 않으므로 이 두 항목이 R39 의 전제다.
  근거: [ADR-004 (design-system)](../../design-system/decisions/adr-004-focus-and-target.md).
- **R41.** 고대비 모드(`forced-colors: active`)에서 셸은 유리 표면·blur·배경 광원을
  포기하고 시스템 색을 따른다. 라이트 모드는 v1 에 없다 — 다크 전용이 결정이며 누락이
  아니다. 근거: [ADR-006 (design-system)](../../design-system/decisions/adr-006-theme-scope.md).

## 성공 지표

- 최소 창 크기부터 전체 화면까지 폭을 연속으로 끌어도 타이머와 오늘 목록이 한 번도
  잘리거나 사라지지 않는다.
- 지원 플랫폼 전부에서 종료 요청 경로가 최소 2개, 복귀 경로가 최소 2개 동작한다.
- 계획 데이터가 0인 새 DB의 첫 화면에서 사용자가 아무 것도 설정하지 않고 첫 세션을
  완주할 수 있다 (원칙 1 검증).
- 창을 닫은 채 완주한 세션의 유실 0.
- 같은 DB 를 두 프로세스가 여는 경로 0.
- 구간 전환 중 상태 유실 0 (진행 중 타이머·입력 중 텍스트·선택 날짜·탭·스크롤 위치).
