# UX Spec: app-shell

> 출처: docs/origin/pomodoro-mockup-v7.html 전체 레이아웃 + docs/origin/pomodoro-prd.md §4·§3.7 (초안) + [결정 원장](../../decision-log/2026-08-04-planning-session.md) Q16·Q17·Q17-1 + [리뷰 결정](../../decision-log/2026-08-04-review-decisions.md) (케이스 7·8)
> 시각 값은 전부 [tokens.md](../../design-system/tokens.md) 토큰 이름으로 기술한다. 시각 판단이 [principles.md](../../design-system/principles.md) 와 충돌하면 그쪽이 이긴다.
> 구간 경계값은 [ADR-001 (design-system)](../../design-system/decisions/adr-001-breakpoint-tokens.md) 이 소유한다 — 이 문서는 `--bp-wide` · `--bp-medium` 이름으로만 부른다.

## 1. 셸의 구성 요소

| 요소 | 내용 |
|---|---|
| 타이틀바 | 프레임리스 창의 커스텀 바. 슬롯 순서는 **플랫폼 조건**이다(§1.1). 창 컨트롤이 점유하지 않는 빈 영역이 창 드래그 핸들 |
| 배경 | `--bg-deep` + `--glow-teal` / `--glow-amber` / `--glow-moss` 라디얼 광원 + 미세 별. **정적 렌더** (장식성 무한 애니메이션 금지 — principles §4) |
| 컬럼 | 유리 카드(`--glass`, `--glass-border`, `--radius-lg`)들의 flex column. 카드 헤더의 eyebrow 라벨은 `--text-2xs` + `--tracking-wider` |
| eyebrow | `MONTH` / `WEEK` / `TODAY` — 컬럼이 어느 레이어인지 알리는 유일한 표지. 색은 **`--ink-dim`** 이다 ([ADR-003 §3](../../design-system/decisions/adr-003-contrast-baseline.md) — 유일한 표지를 `--ink-faint` 2.26:1 로 두지 않는다) |
| 트레이 | 창 밖 상주. 창이 닫힌 동안에도 항상 사용 가능한 복귀 경로 (§6) |

카드 내부 구성은 각 기능(timer, today-tasks, week-plan, milestones, calendar-records,
weekly-review)이 소유한다. 셸은 **자리와 접힘**만 정의한다.

유리 표면의 backdrop·inset 하이라이트·드롭 섀도는
[tokens.md §5](../../design-system/tokens.md) 의 Surface 토큰으로 기술한다 — 카드·오버레이·
다이얼로그는 `--glass-backdrop` · `--glass-highlight` · `--glass-shadow`, 버튼·칩은
`--control-*` 3종이다 ([ADR-002](../../design-system/decisions/adr-002-glass-surface-tokens.md)
가 PRD R38 의 TBD 를 닫았다). 오버레이는 전용 레벨 없이 표면 레벨을 쓰고 차이는
배경 토큰(`--glass-strong`)으로만 준다. **창 그림자는 토큰이 아니다 — OS 가 그린다.**

### 1.1 타이틀바 슬롯 (플랫폼 조건)

창 컨트롤(닫기·최소화·최대화)이 놓이는 변은 OS 관용구를 따르고, 셸의 요소는 그 변을
침범하지 않는다 (PRD R4).

| 플랫폼 | 창 컨트롤 | 좌측 | 우측 |
|---|---|---|---|
| macOS | 좌측 (트래픽 라이트) | 컨트롤 영역 → 앱 이름 | MONTH 토글(미디엄) → 테마 세그먼트 → 날짜 라벨 |
| Windows·Linux | 우측 | 앱 이름 | MONTH 토글(미디엄) → 테마 세그먼트 → 날짜 라벨 → **창 컨트롤 폭 예약(비움)** |

- 창 컨트롤 영역과 겹치는 클릭 타깃을 두지 않는다. 미디엄의 MONTH 토글이 Windows·Linux 에서
  창 컨트롤과 겹치지 않는 것이 이 규칙의 검증 대상이다 (PRD A17).
- **폭을 플랫폼별 상수로 박지 않는다.** `titleBarOverlay` 를 켜면 **Window Controls Overlay
  CSS 환경 변수**(`env(titlebar-area-x)` · `env(titlebar-area-width)` ·
  `env(titlebar-area-height)`)가 활성화되어 OS 가 실제 폭을 런타임에 알려준다. 상수를 박으면
  OS 업데이트로 어긋나지만 이 값은 어긋날 여지가 구조적으로 없다. 환경 변수에 폴백을 함께
  주어(`env(titlebar-area-x, 0px)`) 활성화되지 않는 환경에서도 레이아웃이 무너지지 않게 한다.
- 테마 세그먼트는 `-webkit-app-region: no-drag` 이어야 한다 — 타이틀바 전체가 드래그 핸들이라
  이것이 없으면 버튼이 눌리지 않는다.

### 1.2 날짜 라벨의 반응형 포맷

| 구간 | 포맷 | 예 |
|---|---|---|
| 와이드·미디엄 | `YYYY년 M월 D일` | `2026년 8월 4일` |
| 내로우 | `M월 D일` — 연도를 생략한다 | `8월 4일` |

- 요일은 어느 구간에서도 표시하지 않는다(캘린더가 소유하는 정보다).
- 포맷 축약은 표시만 바꾼다 — 날짜 자체(오늘 판정)는 today-tasks·calendar-records 의
  `local_date` 규칙을 그대로 따르며 셸이 재정의하지 않는다.

## 2. 와이드 (폭 ≥ `--bp-wide`)

시안 3컬럼 그대로.

```
┌ 타이틀바 ─────────────────────────────────────────────┐
│ ○○○  Pomodoro                          2026년 8월 4일 │
├───────────────┬───────────────────┬───────────────────┤
│ MONTH         │                   │ WEEK              │
│  마일스톤 카드 │      타이머        │  이번 주 할당 카드 │
│               │   (timer §1 구성)  │  ─────────────    │
│ ─────────────│                   │  (측정 시간은 헤더)│
│  캘린더 카드   │                   ├───────────────────┤
│  (월 그리드    │                   │ TODAY             │
│   + 날짜 패널) │                   │  오늘 할 일 카드   │
│               │                   │  (입력 + 목록)     │
└───────────────┴───────────────────┴───────────────────┘
   계획 레이어           코어 루프          계획 → 실행
```

- 좌 컬럼 = MONTH(마일스톤 카드 + 캘린더 카드), 중앙 = 타이머 단일 카드,
  우 컬럼 = WEEK 카드 + TODAY 카드. 타이머 카드의 내부 구성은 timer ux-spec §1 이 소유한다.
- 캘린더의 `‹ ›` 월 이동이 마일스톤 카드와 동기 전환된다 — 셸은 두 카드를 **같은 컬럼에
  인접 배치**해 그 연동이 시야 안에서 일어나게 한다 (별도 탭·모달을 만들지 않는다).

### 2.1 스크롤 영역 구현 규칙

PRD R7 의 "각 카드는 독립 스크롤 영역을 가지며 창 전체는 스크롤되지 않는다"를 구현하는
레시피다. 세 구간 전부 동일하게 적용한다.

- 카드는 flex column. 고정 요소(헤더·입력)는 `flex-shrink: 0`. 이번 주 측정 시간 합은
  헤더 안에 있으므로 별도 고정 요소가 아니다 (week-plan ux-spec §7 — 하단 고정 게이지는
  2.0.0 에서 사라졌다).
- 스크롤 영역만 `flex: 1; min-height: 0; overflow-y: auto` + 상하 마스크 페이드.
- 창 루트(`html`/`body`)는 `overflow: hidden` — 가로·세로 어느 쪽으로도 창 전체가
  스크롤되지 않는다.

## 3. 미디엄 (`--bp-medium` 이상 `--bp-wide` 미만)

> `--bp-medium` 은 720px 이다(값의 출처는 [tokens.md §4](../../design-system/tokens.md#4-breakpoint)).
> 800px 이 아니라 720px 인 이유와 오버레이 방향은 [design-system ADR-011](../../design-system/decisions/adr-011-medium-range-revision.md) 참조.

MONTH 컬럼이 접히고, 타이머와 WEEK/TODAY 가 남는다.

```
┌ 타이틀바 ─────────────────────────────────────────────┐
│ ○○○  Pomodoro          [ MONTH ▸ ]     2026년 8월 4일 │
├───────────────────────────┬───────────────────────────┤
│                           │ WEEK                      │
│         타이머             │  이번 주 할당 카드         │
│      (§2 구성 그대로)      ├───────────────────────────┤
│                           │ TODAY                     │
│                           │  오늘 할 일 카드           │
└───────────────────────────┴───────────────────────────┘
```

### 3.1 MONTH 오버레이 토글

| 항목 | 규칙 |
|---|---|
| 토글 위치 | 타이틀바의 날짜 라벨 왼쪽 — **놓이는 변은 §1.1 의 플랫폼 조건을 따른다.** 라벨 `MONTH` + lucide `PanelRight` 아이콘 |
| 콜드 스타트 초기값 | **접힘.** 이 값은 "그 실행에서 아직 MONTH 를 본 적이 없을 때"의 초기값일 뿐이며, 구간을 넘나든 뒤의 상태는 §5 의 연속성 규칙이 결정한다 |
| 열림 | **우측에서 슬라이드-인 — WEEK·TODAY 컬럼 위를 덮는다.** 좌측에서 열면 좁은 창에서 타이머를 덮어 같은 표의 비모달 규칙과 충돌한다([design-system ADR-011](../../design-system/decisions/adr-011-medium-range-revision.md)). 폭은 와이드의 MONTH 컬럼 폭 유지, 표면은 `--glass-strong` + `--glass-border` |
| 내용 | 와이드의 MONTH 컬럼 그대로 (마일스톤 카드 + 캘린더 카드) — 내용을 축약하지 않는다 |
| **비모달** | 화면 전체를 덮지 않고, **열린 동안에도 타이머 조작이 가능하다** (PRD R10). 스크림을 넣지 않고 **포커스 트랩도 걸지 않는다**(§8). WEEK·TODAY 는 오버레이가 덮는 대상이므로 열려 있는 동안 `inert` 로 빠진다 — 트랩이 없다는 것과 "가려진 컨트롤에 `Tab` 이 닿아도 된다"는 다른 말이고, 계획 두 면은 자리를 교대한다([ADR-011](../../design-system/decisions/adr-011-medium-range-revision.md) §2) |
| 닫힘 | **토글 재클릭 / `Esc` / 오버레이 내부 우상단 닫기 버튼(lucide `X`)** — 이 세 가지뿐이다. **오버레이 밖 클릭으로 닫지 않는다**: 타이머 버튼은 정의상 "밖"이므로, 밖 클릭 닫힘을 두면 일시정지를 누를 때마다 오버레이가 예고 없이 닫힌다 |
| 모션 | 슬라이드-인은 상태 변화 전달이므로 허용. `prefers-reduced-motion: reduce` 시 즉시 표시 |

### 3.2 주간 정산 패널의 자리

| 구간 | 자리 |
|---|---|
| 와이드 | **WEEK 카드 자리를 인라인으로 점유**한다 (우 컬럼 상단). 별도 모달·드로어를 만들지 않는다 |
| 미디엄 | 와이드와 동일 — WEEK 카드 자리 인라인 점유 |
| 내로우 | `주간` 탭 **전체**를 차지한다 (§4.2) |

- 패널의 내용·문구·결정 전송 방식은 weekly-review 가 소유한다. 셸은 자리만 정한다
  (PRD R12).
- 패널이 WEEK 카드 자리를 점유하는 동안에도 타이머·TODAY 는 그대로 조작 가능하다 —
  패널은 모달이 아니다.
- 정산 **배너**는 패널과 별개로 해당 카드 상단에 붙고, 셸이 탭·구간을 강제 전환하지
  않는다.

## 4. 내로우 (폭 < `--bp-medium`)

1컬럼. 타이머 축약형이 상단에 고정되고, 그 아래가 탭 영역이다.

```
┌ 타이틀바 ─────────────────┐
│ ○○○  Pomodoro     8월 4일 │
├───────────────────────────┤
│ 집중   12:34      [ ▶ ]   │  ← 타이머 축약형 (고정, 탭 전환에도 유지)
├───────────────────────────┤
│  오늘  │  주간  │  월간    │  ← 탭
├───────────────────────────┤
│                           │
│   (선택된 탭의 카드 하나)   │  ← 스크롤 영역
│                           │
└───────────────────────────┘
```

### 4.1 타이머 축약형 — 구성의 유일한 정의

timer ux-spec §9 가 이 배치의 정의를 셸에 위임했고, **PRD 는 이 표를 참조만 한다**
(PRD R11). 구성 목록은 이 문서 한 곳에만 존재한다. 축약형은 **한 줄**이다.

| 슬롯 | 내용 |
|---|---|
| 좌 | 현재 모드 — `집중` / `짧은 휴식` / `긴 휴식` 텍스트. `--text-sm`, `--ink-dim`. 탭 형태가 아니라 **표시 전용** |
| 중 | `MM:SS` — `--font-mono` + tabular-nums. 크기는 `--text-xl` (`--text-display` 는 축약형에 쓰지 않는다) |
| 우 | 시작/일시정지 단일 버튼 (lucide `Play` / `Pause`) |

- **진행률 링은 렌더하지 않는다.** 진행은 상단 고정 바 하단의 얇은 진행 인디케이터로만
  암시한다 — 색은 `--teal`, 초과·강조 없음.
- 축약형에서 **하지 않는 것**: 모드 전환, 조절 칩(±1/±5/±10), 초기화, 완료 처리,
  집중 대상 지정. 이 조작들은 `오늘` 탭 안의 전체 타이머 카드에서 한다.

> ⚠️ 가정: 축약형에 모드 전환을 넣지 않는 것은 한 줄 안에서 3개 탭이 터치 타깃으로
> 성립하지 않는다는 판단이다. 실측 후 모드 전환이 필요하다고 판명되면 축약형 탭
> 대신 `오늘` 탭 진입으로 유도한다.

> ⚠️ 가정: 좌측 모드 텍스트가 **표시 전용**이라는 점은 "탭처럼 생겼는데 눌리지 않는"
> 죽은 어포던스가 될 위험이 있다. 완화책으로 이 텍스트에는 버튼·탭의 시각 어포던스
> (보더·배경 `--glass-strong`·hover 변화·포인터 커서)를 **일절 주지 않고** `--ink-dim`
> 평문으로만 둔다. 실측에서 여전히 눌러보게 된다면 모드 전환을 여기로 올릴지
> `오늘` 탭 유도를 강화할지 재판단한다.

### 4.1.1 사후 캡처 바의 지연 노출

캡처 바는 timer 소유이며(timer ux-spec §5), **사용자 행동으로만 닫힌다** — `기록` 저장 /
`건너뛰기` / `Esc`. 셸은 그 전제 위에서 좁은 창의 노출 시점만 정한다.

- 캡처 바는 축약형에 붙지 않는다. `오늘` 탭의 타이머 카드 하단에 나타난다.
- 다른 탭(`주간`·`월간`)에 있을 때 세션이 완료되면 **셸은 탭을 강제 전환하지 않는다.**
  캡처 바는 **다음 `오늘` 탭 진입 시 노출된다.**
- **다음 세션이 시작돼도 지연 노출은 취소되지 않는다** — 캡처 바의 닫힘은 사용자 행동
  뿐이므로(timer ux-spec §5), 대기 중인 캡처 기회가 세션 시작으로 사라지지 않는다.
- 어느 경로든 **세션 기록 자체는 이미 저장돼 있다** (캡처는 이름 붙이기일 뿐).

### 4.2 탭

| 탭 | 담는 것 |
|---|---|
| `오늘` | 타이머 전체 카드 + 오늘 할 일 카드 (콜드 스타트 기본 선택 탭) |
| `주간` | 이번 주 할당 카드 (측정 시간 합은 헤더에 있다 — 하단 고정 요소 없음). 정산 패널이 열려 있으면 탭 전체를 패널이 차지한다(§3.2) |
| `월간` | 마일스톤 카드 + 캘린더 카드 |

- 콜드 스타트 기본 선택은 `오늘` — 코어 루프가 첫 화면이다. 구간을 넘나든 뒤의 선택은
  §5 가 결정한다.
- 탭 라벨은 텍스트만. 아이콘을 붙일 경우 lucide 컴포넌트로만 하고 **이모지 금지**
  ([principles §6](../../design-system/principles.md)).
- 활성 탭 강조는 `--glass-strong` + `--ink`, 비활성은 `--ink-dim`.
- 탭 전환은 표시 전환일 뿐이다 — 각 탭의 스크롤 위치·펼침 상태(드로어 등)는 탭을
  떠났다 돌아와도 유지된다.
- **탭 수는 3개로 닫는다.** 새 화면(설정 등)은 탭을 늘리지 않고 오버레이로 들어온다
  (PRD R35).
- 접근성: 탭 줄은 `tablist`, 각 탭은 `tab`, 아래 영역은 `tabpanel` role 을 갖고
  좌우 화살표로 이동한다(§8).

## 5. 리사이즈와 상태 보존

구간 전환은 **표시의 재배치일 뿐, 아무 사실도 만들지 않는다.**

구간 판정의 1차 출처는 **CSS 미디어 쿼리**이고, JS 판정이 필요한 곳은 같은 상수를 쓰며
`resize` 는 rAF/디바운스로 합쳐 프레임당 1회만 반영한다 (PRD R13). 경계 폭을 왕복
드래그해도 아래 표의 상태가 반복 초기화되지 않는 것이 이 규칙의 목적이다.

| 상태 | 구간 전환 시 |
|---|---|
| 진행 중 타이머 | 영향 없음 — main 이 소유하므로 renderer 재배치와 무관 ([ADR-005](../../architecture/decisions/adr-005-timer-architecture.md)) |
| 입력 중인 텍스트 (오늘 할 일 입력·캡처 바·플래너 필드) | 값 유지. 포커스는 요소가 살아 있으면 유지, 접히는 컬럼 안에 있었다면 §8 의 행선지로 이동 |
| 선택된 날짜 (캘린더) | 유지 |
| 열려 있던 드로어·펼침 | 유지 |
| 각 카드·탭의 스크롤 위치 | **유지** — 구간을 왕복해도 초기화하지 않는다 |
| 대기 중인 캡처 기회 | 유지 (§4.1.1 — 구간이 바뀌어도 취소되지 않는다) |
| 열려 있던 확인 다이얼로그 | 유지 (종료 확인은 구간과 무관) |

### 5.1 MONTH 가시성의 연속성

"MONTH 를 보고 있었다"는 사실이 구간을 넘어 이어진다. **양방향 전부** 정의한다 —
`§3.1 의 접힘`은 콜드 스타트 초기값일 뿐이므로 아래 규칙이 그것을 덮는다.

| 전환 | MONTH 의 결과 상태 |
|---|---|
| 미디엄(오버레이 열림) → 와이드 | 오버레이가 사라지고 원래 MONTH 컬럼 자리로 복귀 |
| 미디엄(오버레이 닫힘) → 와이드 | 컬럼이 그대로 보인다 (와이드에는 접힘이 없다) |
| **와이드 → 미디엄** | **오버레이 열린 상태로 진입** — 와이드에서 MONTH 가 보이고 있었으므로 가시성이 이어진다 |
| 미디엄(오버레이 열림) → 내로우 | `월간` 탭 선택으로 이어진다 *(내로우 미구현 — 창 최소 폭으로 진입이 막혀 있다. [design-system ADR-011](../../design-system/decisions/adr-011-medium-range-revision.md))* |
| 미디엄(오버레이 닫힘) → 내로우 | 직전 탭 선택을 유지한다 (없으면 `오늘`) *(내로우 미구현 — 창 최소 폭으로 진입이 막혀 있다.)* |
| **내로우(`월간` 탭) → 미디엄** | **오버레이 열린 상태로 진입** *(내로우 미구현 — 창 최소 폭으로 진입이 막혀 있다.)* |
| 내로우(`오늘`·`주간` 탭) → 미디엄 | 오버레이 닫힘 *(내로우 미구현 — 창 최소 폭으로 진입이 막혀 있다.)* |
| 내로우(`주간` 탭) → 와이드·미디엄 | 탭 선택을 기억해 두고, 다시 내로우가 되면 그 탭으로 돌아간다 *(내로우 미구현 — 창 최소 폭으로 진입이 막혀 있다.)* |

- 즉 **"미디엄 진입 시 항상 접힘"은 성립하지 않는다.** 접힘은 그 실행에서 MONTH 를
  아직 본 적이 없을 때의 초기값이다.
- 내로우 탭 선택은 넓혀도 **버리지 않는다** — 왕복 드래그가 탭을 계속 `오늘` 로
  초기화하는 것을 막기 위한 규칙이다 (PRD R14).
- 구간 전환 도중에 데이터 리페치·mutation 을 트리거하지 않는다.
- 창 폭 이외의 조건(높이·OS·화면 개수)으로 구간을 바꾸지 않는다.

## 6. 창 닫기·복귀·트레이 (Q16 + 리뷰 케이스 7)

### 6.1 종료 요청이라는 하나의 개념

셸은 플랫폼 관용구를 **"종료 요청"** 하나로 흡수한다 (PRD R2). 이 열거는 셸이 소유하며,
다른 기능 문서는 특정 단축키가 아니라 이 개념을 참조한다.

| 경로 | 조건 |
|---|---|
| 플랫폼 종료 단축키 | macOS `⌘Q`, Windows·Linux `Ctrl+Q` |
| 앱 메뉴 Quit | 앱 메뉴를 갖는 플랫폼 (macOS) |
| 트레이 `종료` | 전 플랫폼 (트레이 없는 빌드가 존재하지 않는다 — §6.5) |
| OS 주도 종료 | 로그아웃·재시동·시스템 종료·강제 종료 (§6.4) |

**창 닫기는 종료 요청이 아니다** — ×, `Alt+F4`(Windows·Linux), `⌘W`(macOS)는 모두
창 닫기다.

### 6.2 창 상태와 앱 상태

| 사용자 행동 | 창 | 앱 | 타이머 |
|---|---|---|---|
| 최소화 | 숨김 | 실행 | 계속 (main) |
| 창 닫기 (×·`Alt+F4`·`⌘W`) | 닫힘 | **실행** | 계속 (main) |
| 트레이 `창 열기` / OS 알림 클릭 / Dock·작업표시줄 클릭 / 재실행 시도 | 복원·포커스 | 실행 | 계속 — 자동 시작 없음 |
| 종료 요청 (§6.1) | 닫힘 | **종료** | 중단, 진행 중 세션 미기록 |

- 창이 닫힌 동안에도 완료 판정·세션 기록·OS 알림은 main 이 수행한다. 창 닫기는
  **표시를 끄는 것**일 뿐이다.
- 창을 닫을 때 확인·안내를 띄우지 않는다. 종료가 아니므로 잃는 것이 없다.
- 복원 시 renderer 는 main 에서 타이머 스냅샷을 당겨오므로 남은 시간이 정확히 이어진다
  (ADR-005 §4).

### 6.3 단일 창 불변식과 복귀 경로 4개

셸은 언제나 창을 **0개 또는 1개** 갖는다 (PRD R17). 복귀 경로 네 개는 모두 같은
동작으로 수렴한다 — **기존 창이 있으면 복원·포커스, 없으면 1개를 만든다.**

| 경로 | 동작 | 비고 |
|---|---|---|
| 트레이 `창 열기` | 복원 + 포커스 | 창이 열려 있어도 비활성화하지 않는다 (§6.5) |
| OS 알림 클릭 | 복원 + 포커스 | 타이머 자동 시작 없음 (timer ux-spec §6) |
| **Dock / 작업표시줄 아이콘 클릭** | 트레이 `창 열기` 와 **완전히 동일** | 창을 닫은 사용자가 가장 먼저 하는 행동이다. 이 경로가 없으면 "앱이 죽었다"로 읽고 재실행한다 |
| **앱 재실행 시도** | 두 번째 인스턴스가 기존 창을 포커스하고 즉시 종료 | 단일 인스턴스 잠금(PRD R19). 없으면 두 프로세스가 같은 DB 를 열어 타이머 2개·알림 2회가 생긴다 |

- 네 경로 중 어느 것도 두 번째 창을 만들지 않는다. 새 창을 여는 UI 를 두지 않는다.

### 6.4 종료 확인의 소유권

focus 실행 중 종료 요청 시 확인 1회를 거친다. 경계는 다음과 같다.

- **셸이 소유하는 것**: 종료 요청 **경로의 열거**(§6.1)와 "그 경로 전부가 동일한 확인을
  거친다"는 사실. 그리고 **창이 닫혀 있으면 창을 먼저 복원해 다이얼로그를 보인다**
  는 규칙 — 사용자가 못 보는 확인창을 만들지 않는다 (PRD R22).
- **timer 가 소유하는 것**: "종료 요청 시 focus 가 running/paused 인 경우"라는 조건과
  다이얼로그의 문구·버튼 (timer ux-spec §7). 셸은 이를 복제하지 않는다.

**OS 주도 종료는 예외다** — 로그아웃·재시동·시스템 종료·강제 종료에서는 확인을 요구하지
않고 진행 중 세션을 유실한다. 종료를 막거나 지연시키지 않으며 복구도 하지 않는다.
크래시 복원과 동일 취급이다 (v1 비범위, PRD R23).

### 6.5 트레이

- **창 닫기=숨김과 트레이 상주는 분리 배포할 수 없다** (PRD R25). 두 규칙은 하나의
  배포 단위이며, **트레이가 없는 빌드에서는 창 닫기가 종료로 동작한다.** 복귀 경로가
  0개인 유령 상태를 어떤 중간 빌드에서도 만들지 않는다.

| 항목 | 동작 | 상태 표기 |
|---|---|---|
| `창 열기` | 창 복원 + 포커스. 창이 이미 열려 있으면 포커스만 | 라벨은 **항상 `창 열기` 고정**이며 **비활성화하지 않는다** — 비활성 항목은 "앱이 응답하지 않는다"로 오독된다 |
| (구분선) | | 미래에 트레이 타이머 조작이 들어올 자리는 이 구분선 **위** 그룹이다 (PRD R35) |
| `테마` ▸ | 서브메뉴 **2택** — `라이트` / `다크`. 현재 선택에 체크 표기 | 자기 그룹을 갖는다 — 위 그룹은 타이머 조작 예약석이므로 침범하지 않는다 |
| (구분선) | | |
| `종료` | §6.4 의 확인을 거쳐 앱 종료 | — |

- 메뉴 항목에 이모지를 쓰지 않는다. 아이콘이 필요하면 OS 트레이 메뉴가 허용하는
  범위에서 lucide 기반 아이콘 이미지로 만든다 (principles §6).
- **`테마` 는 표시 설정이므로 새 화면을 만들지 않는다** (PRD R35 의 "탭·컬럼을 늘리지
  않는다"를 지킨다). 선택값은 `settings` 의 `theme` 키에 저장되며 값은 **`light` 또는
  `dark` 둘뿐이고 기본은 `dark`** 다. **OS 선호를 따르지 않는다 — 앱이 소유한다**
  ([ADR-010](../../design-system/decisions/adr-010-app-owned-theme.md)).
  고대비 모드에서는 OS 가 이미 밝고 어두움을 결정하므로 이 선택이 아무 효과를 갖지 않는다.
- **전환 경로는 트레이만이 아니다.** 1차 경로는 **타이틀바의 2택 세그먼트**(§1.1 슬롯)이고,
  트레이 서브메뉴는 창이 닫힌 동안에도 닿는 보조 경로로 트레이 도입 시 함께 온다.
  두 입구가 같은 설정을 쓰게 되는 시점에 `settings:changed` 이벤트가 필요해진다 —
  한쪽이 바꾼 값을 다른 쪽이 모르기 때문이다 (ADR-026 의 4단계를 따른다).
- 트레이 아이콘 **형태**(모노크롬 템플릿 이미지 여부), **남은 시간·모드의 트레이 표시
  방식, 알림음 세부는 TBD** — 결정 원장 §F 미결(M4). 남은 시간 표시는 가산점이며 v1
  필수 아님. **TBD 는 형태에 한하고 트레이의 존재는 M1 확정**이다(PRD R25·R29).

> ⚠️ 가정: 트레이 메뉴의 최소 구성을 `창 열기` + `종료` 2항목으로 둔다. 타이머 조작
> (시작/일시정지)을 트레이에 넣을지는 M4 에서 트레이 표시 세부와 함께 판단한다 —
> 지금 넣으면 "창 없이 조작 가능한 범위"라는 별개 설계 결정을 선취하게 된다.

## 7. 콜드 스타트 (§3.7)

첫 실행(계획 0개, 세션 0개)에도 **레이아웃은 완전히 동일하다.** 셸은 카드를 숨기거나
전용 온보딩 화면으로 갈아치우지 않는다.

```
┌───────────────┬───────────────────┬───────────────────┐
│ MONTH         │                   │ WEEK              │
│  (빈 상태 카피 │      타이머        │  (빈 상태 카피     │
│   + CTA)      │   25:00           │   + CTA)          │
│               │   자유 집중        │                   │
│ ─────────────│   [ 시작 ]        ├───────────────────┤
│  캘린더        │                   │ TODAY             │
│  (점 없음,     │   ← 여기만 이미    │  (빈 상태 카피     │
│   오늘만 강조) │      완전히 동작    │   + CTA)          │
└───────────────┴───────────────────┴───────────────────┘
```

| 원칙 | 규칙 |
|---|---|
| 타이머 우선 | 타이머는 첫 프레임부터 완전히 동작한다. `자유 집중` 상태로 서 있고, 시작을 누르면 그대로 코어 루프가 돌아간다 (PRD R30·R34) |
| 투어 없음 | 환영 모달·단계별 투어를 만들지 않는다. 각 카드의 빈 상태 카피가 그 카드의 역할을 설명한다 |
| 온보딩 설정은 1회 오버레이 | §7.1 — 셸은 **자리만** 정의하고 항목·기본값은 pomo-baseline 이 소유한다 |
| 카피의 **존재**는 셸이 검증 | 각 카드는 비어 있을 때 **역할 설명 카피 1개 이상 + CTA 1개 이상**을 실제로 렌더한다. 내용은 §7.2 의 소유 기능이 정한다 |
| 실패 프레임 금지 | 빈 상태에 경고색(`--danger`)·경고 아이콘·"데이터 없음"·"설정이 필요합니다" 금지. 톤은 중립(`--ink-dim` / `--ink-faint`)이고 CTA 는 고스트 버튼 ([principles §1](../../design-system/principles.md)) |
| 정상 상태 | 계획 0개는 오류가 아니라 정상 상태다. 세 컬럼 전부 자리에 있고, 비어 있음이 곧 "아직 안 정했음"으로만 읽힌다 |

- 첫 세션을 완주하면 캘린더에 점 하나, 타이머 하단 스트릭에 첫 문구가 생긴다 —
  계획을 하나도 세우지 않은 경로로도 앱이 자기 결과를 보여준다.
- 미디엄·내로우의 콜드 스타트도 같다. 내로우에서는 `오늘` 탭이 기본이므로 첫 화면이
  타이머 + 빈 오늘 목록이다.

### 7.1 첫 실행 온보딩 설정 화면의 자리

뽀모 길이 3종은 **상시 편집 가능**하고
([ADR-029](../../architecture/decisions/adr-029-baseline-immediate-effect.md) §1),
**첫 실행 온보딩이 그 편집 경로 중 하나**다. 셸이 정하는 것은 자리뿐이다.

> **2.0.0 축소.** 가용량이 폐기되면서 이 화면이 물을 값은 길이 3종만 남았다
> ([ADR-030](../../architecture/decisions/adr-030-time-as-progress-currency.md)).
> **화면은 아직 구현돼 있지 않다** — 아래 표는 만들 때 지킬 자리 규약이며,
> 근거였던 ADR-013 §3 은 전체 폐기됐다.

| 항목 | 규칙 |
|---|---|
| 형태 | **첫 실행 시 1회 오버레이.** 셸의 다른 오버레이(MONTH)와 달리 진입 직후 1회만 뜬다 |
| 건너뛰기 | 명시적으로 건너뛸 수 있다. 건너뛰면 §7 의 기본 상태로 진입하고 타이머는 즉시 사용 가능하다 (설정 강요 화면이 아니다) |
| 재등장 | 두 번째 실행부터 자동으로 뜨지 않는다. 다시 여는 경로는 상시 편집 진입점(pomo-baseline 소관) |
| 구간 | 세 구간 모두 오버레이 형태다 — **탭·컬럼을 늘리지 않는다** (PRD R35) |
| 내용 | 표시 항목·기본값·검증 규칙·문구는 **pomo-baseline 이 소유한다.** 셸은 값도 문구도 정의하지 않는다 |

### 7.2 빈 상태 카피의 소유권

셸은 **존재만 검증**하고 내용은 위임한다. 셸이 요구하는 것은 카드마다 **역할 설명 카피
1개 이상 + CTA 1개 이상**이므로, 초안에 카피는 있어도 **CTA 원문이 없는 항목은 소유
기능이 신규 작성해야 한다.** 아래 표가 그 구분이다.

| 빈 상태 | 소유 기능 | 카피 원문 | CTA 원문 |
|---|---|---|---|
| 오늘 목록이 비어 있음 (계획 0개 분기) | today-tasks | 확정 | **확정** — `자유 집중 시작` (today-tasks R20. focus idle 일 때만) |
| 캘린더 날짜 패널에 기록 없음 | calendar-records | 확정 | **확정** — 오늘 선택 + focus idle 일 때만 `자유 집중 시작` (calendar-records R21) |
| 이번 주 할당 카드가 비어 있음 | week-plan | 확정 | 확정 (`+ <주> 할당 잡기` — week-plan §8) |
| 그 달 마일스톤이 비어 있음 | milestones | 확정 | 확정 (`결과물 추가` — milestones R23) |

- 카피·CTA 원문은 전부 소유 기능의 문서가 확정했다 (2026-08-05 로 신규 2건이 닫혔다).
  셸은 자리와 "존재해야 한다"는 요구만 갖는다 (PRD R32).
- `자유 집중 시작` 두 건은 **같은 라벨·같은 동작**(타이머 `시작` 의 진입점)이다 —
  같은 개념에 같은 말을 쓴다. 콜드 스타트는 정의상 focus idle 이므로 두 CTA 모두
  첫 화면에 항상 렌더되고, §7 의 "카피 1 + CTA 1" 검증(A24)이 성립한다.

## 8. 모션·아이콘·색·접근성

- 배경 광원·별은 정적. 오버레이 슬라이드·탭 전환·구간 전환만 모션을 갖고, 전부
  `prefers-reduced-motion: reduce` 에서 전이 없이 즉시 반영된다 (principles §4).
- 셸의 아이콘(오버레이 토글·닫기, 트레이, 축약형 재생/일시정지)은 전부 lucide-react
  컴포넌트. **이모지 금지** (principles §6).
- `--danger` 는 셸 어디에도 쓰지 않는다 — 창 닫기·종료는 데이터를 없애는 행위가
  아니다 (principles §2, timer ux-spec §7 과 동일 판단).
- 색·폰트·radius·브레이크포인트·유리 표면은 토큰 이름으로만 (principles §5, §1).

### 8.1 접근성 최소선

| 항목 | 규칙 |
|---|---|
| **포커스 표시** | `:focus-visible` 에 `--ink` 링(`--focus-ring-*` 토큰). 이 표의 나머지 규칙이 전부 여기에 의존한다 — 포커스가 보이지 않으면 아래 항목들은 검증할 수 없다 ([ADR-004](../../design-system/decisions/adr-004-focus-and-target.md)) |
| **조작 타깃** | 히트 영역 `--target-min`(24px) 이상. 라벨을 키우지 않고 투명 패딩으로 넓힌다. 인접 컨트롤의 히트 영역이 겹치지 않는다 (ADR-004 §2) |
| 내로우 탭 | `tablist` / `tab` / `tabpanel` role. 좌우 화살표로 탭 이동, `Tab` 은 탭 줄을 하나의 정차점으로 취급 |
| MONTH 오버레이 | **비모달이므로 포커스 트랩을 걸지 않는다.** `Tab` 으로 오버레이 밖(타이머)에 도달할 수 있어야 한다. 덮이는 WEEK·TODAY 는 열려 있는 동안 `inert` 이므로 탭 순서에서 빠진다 — 보이지 않는 컨트롤에 포커스 링만 뜨는 상태를 만들지 않는다. **사용자가 토글로 연 경우에만** 포커스가 오버레이 첫 요소로 이동하고, 갇히지는 않는다. 구간 전환으로 저절로 열린 오버레이는 포커스를 가져오지 않는다 (창을 끄는 동안 입력 중인 문장에서 포커스를 뺏는 것이 된다) |
| 구간 전환 시 포커스 | 포커스된 요소가 접힘으로 사라지면 포커스를 **그 요소를 담고 있던 카드의 컨테이너**로 옮긴다. 문서 처음(body)으로 되돌리지 않는다 |
| 고대비 모드 | `forced-colors: active` 에서 유리 표면·blur·광원을 포기하고 시스템 색을 따른다. 셸의 카드·오버레이·다이얼로그에 `1px solid CanvasText` 경계를 준다 ([ADR-006 §2](../../design-system/decisions/adr-006-theme-scope.md)) |
| 트레이 메뉴 | OS 네이티브 메뉴이므로 OS 접근성에 위임한다 |

- 포커스 링이 스크롤 컨테이너(`overflow: hidden`) 경계에서 잘리지 않게 오프셋 2px 만큼의
  여유를 남긴다 — 구현 시 확인 항목이다 (ADR-004 Consequences).
