## 문제

주간 계획을 세워 두어도 하루를 시작할 때 "지금 뭐부터 하나"는 다시 정해야 한다.
이 판단을 매일 아침 처음부터 계획하는 일로 만들면 계획 자체가 부담이 되고, 반대로
주간 항목 전체를 늘 눈앞에 펼쳐 두면 지금 할 일이 묻힌다. 또한 오늘 목록을 주간과
별개의 복사본으로 만들면 소진 집계가 두 갈래로 갈라져 게이지와 항목 합이 어긋난다.

필요한 것은 **주간 풀에서 조각만 끌어오는 얇은 뷰**다 — 오늘 목록에 있다는 사실이
task 의 별도 사본이 아니라 "그날 끌어왔다"는 관계 한 줄로만 표현되어야 한다.

## 대상 사용자

- 앱 소유자 1인 (로컬 단독, 로그인·멀티유저 없음)

## 목표

1. 오늘 할 일을 **새로 계획하지 않고 pull 로만** 세운다. 하루 3개 이하를 권장한다(원칙 2).
2. 오늘 목록의 어떤 조작도 데이터를 잃지 않는다 — 목록에서 빼기는 삭제가 아니고,
   지난 날짜의 "그날 무엇을 했는가"는 이후 조작에도 불변이다.
3. 오늘 목록의 어떤 조작도 집계 술어를 흔들지 않는다. 집계 정합 자체는 이 기능이 아니라
   [ADR-012](../../architecture/decisions/adr-012-aggregation-predicate.md) §1 이 보장한다.
4. 계획이 하나도 없어도 막히지 않는다 — 오늘 목록에 직접 입력할 수 있다 (원칙 1).
5. 하루 경계(로컬 자정)의 동작을 사용자가 놀라지 않고 알 수 있다 (Q1·Q18).

## 범위 / 비범위

**범위:** 오늘 목록의 조회·정렬, pull 로 만들어지는 행의 날짜 규칙, 오늘 목록 직접 입력,
완료 체크·해제, 목록에서 빼기(×)와 "치움" 표현, 부모 항목 상태 변화에 대한 불변,
소진 뽀모 도트 표시, 자정 경계 동작, 빈 상태 카피 2종, 자정 관련 맥락 힌트 2종.

**비범위:**
- 주간 항목 자체의 생성·est·요일 배치·이월 판단, 주간 카드의 게이지·드로어 UI
  (→ **week-plan**. 이 문서는 "그 항목의 task 를 오늘로 가져온다"까지만 정의한다)
- pull 을 시작하는 진입 UI("+오늘로" 드로어)의 화면 구성 (→ **week-plan**)
- 미래 날짜 pull("내일 몫 미리 담기") — ADR-012 §2 가 명시적으로 v1 비범위로 남긴다
- 조각(task) 삭제 UI. `tasks.deleted_at` 을 세우는 경로는 이 기능이 제공하지 않는다
  ([ADR-014](../../architecture/decisions/adr-014-deletion-and-archive.md) §1).
  이 문서는 "삭제된 조각은 오늘 목록에 나타나지 않는다"는 조회 조건만 소유한다
- 타이머 조작과 집중 대상 지정 (→ **timer**. 이 문서는 "오늘 목록이 집중 대상의
  후보 집합"이라는 사실까지만)
- 세션 기록·사후 캡처 (→ **timer**)
- 지난 날짜의 오늘 목록 열람 화면 (→ **calendar-records**. 이 문서는 그 열람이
  가능하도록 pull 이력을 보존한다는 요구만 정의한다)
- 마일스톤 태그·월간 집계 (→ **milestones**)
- 주간 정산의 이월 3택 (→ **weekly-review**)
- task 단위 요일 배정 (명시적 비목표 — ADR-011 §8)

## 요구사항

### 목록의 정체와 조회

- **R1.** 오늘 목록은 별도 엔티티가 아니라 task 의 뷰다. 구성 조건은
  "오늘 날짜의 pull 행이 존재하고(치우지 않은 행) `tasks.deleted_at IS NULL` 인 task"
  이며, task 사본을 만들지 않는다. 삭제 표현의 근거는
  [ADR-014](../../architecture/decisions/adr-014-deletion-and-archive.md) §1
  (`tasks.deleted_at`, NULL = 살아 있음, 모든 조회의 기본 조건)이다.
- **R2.** "오늘 목록에 있다"는 사실은 `task_pulls(task_id, pull_date)` **행**으로
  표현한다 (ADR-011 §2). task 에 단일 `pulled_date` 컬럼을 두지 않는다 — 재-pull 시
  과거 날짜의 이력이 덮여 지난 날짜 패널이 거짓을 말하기 때문이다.
- **R3.** 각 항목은 제목, 출처(소속 주간 항목명), 소진/est 뽀모 도트, 완료 상태를
  표시한다. 뽀모 도트의 소진 값은 저장값이 아니라 그 task 에 연결된 세션의 집계
  파생값이다 (원칙 8 — 상위 소진량 저장 금지).
- **R3-1.** (2026-08-05 shape) 각 항목에 **재생 버튼**(lucide `Play`, 히트 영역
  `--target-min`)을 둔다. 클릭 = **그 할 일을 집중 대상으로 설정 + focus 세션 시작,
  한 클릭에.** 이것이 계획→실행 핸드오프의 유일한 대상 지정 제스처이며, 타이머의
  `시작` 은 항상 자유 집중이다 (timer ux-spec §1.1 이 대상의 수명·해제를 소유한다).
  - 노출 조건: **focus 가 idle 이고 그 할 일이 미완료일 때만.** running/paused 중에는
    렌더하지 않는다 — 돌아가는 세션 옆에 시작 버튼을 두지 않는다 (R20 CTA 의 idle
    가드와 같은 규칙).
  - 세션 완료는 할 일을 자동 체크하지 않는다 — 완료는 이 목록의 체크로만.
- **R3-2.** 항목마다 표시하는 값은 그 조각의 **측정 시간**이며, 표기는
  [week-plan ux-spec §0](../week-plan/ux-spec.md#0-측정-시간-표기-규칙--이-절이-원본이다)
  의 규칙 한 벌을 그대로 따른다 (이 프로젝트에서 그 절이 표기 규칙의 원본이다).
- **R3-3.** **조각 단위 합산에는 주 조건을 걸지 않는다** — 그 조각에 붙은 완료 focus
  세션 전부를 합한다. 항목(할당) 단위 합산에는 주 조건이 있고(ADR-012 §1) 조각에는
  없다는 **비대칭은 의도된 것**이며, 두 숫자가 답하는 질문이 다르기 때문이다.
  - 조각의 숫자: **"이 조각으로 얼마나 했나"**. 이월된 조각은 재부모화로 새 주의 항목
    아래로 옮겨 오므로(ADR-012 §3), 주 조건을 걸면 지난 주에 2시간 태운 조각이 이번 주
    오늘 목록에서 `0분` 으로 보인다. 오늘 목록은 "지금 이 조각을 얼마나 밀었나"를
    보는 자리이므로 그 이력이 끊기면 안 된다.
  - 항목의 숫자: **"이 주에 이 할당으로 얼마나 했나"**. 주 조건이 빠지면 같은 세션이
    두 주에서 세어지고 `주 총합 = Σ항목 + 기타` 가 깨진다 (ADR-012 §1).
  - **대가를 명시적으로 수용한다**: 이월된 조각에서 오늘 목록의 숫자가 그 조각이 속한
    주간 카드 항목의 숫자보다 클 수 있다. 개수 통화에서도 같은 비대칭이었으나 시간으로
    바뀌며 격차가 크게 읽힌다 (`1시간 30분` vs `0분`). 그럼에도 유지하는 이유는
    (a) 주 조건을 조각에 걸면 이월 조각의 이력이 화면에서 사라지고 (b) 항목에서 주
    조건을 빼면 차액 항등식이 깨지기 때문 — 어느 쪽도 이 비대칭보다 싸지 않다.
- **R4.** 오늘 목록의 정렬은 **미완료 우선 → pull 순**이다. 즉 1차 키는 완료 여부
  (`completed_at IS NULL` 이 앞), 2차 키는 그 날짜 pull 행의 생성 순서(오름차순)다.
  완료 체크는 항목을 목록에서 없애지 않고 미완료 그룹 아래로 이동시킨다. 사용자가
  바꿀 수 있는 정렬 옵션·수동 순서 변경은 v1 에 없다.

### pull 의 범위와 날짜

- **R5.** 오늘 목록으로 pull 할 수 있는 조각은 **주에 제한되지 않는다** — 지난 주·다음 주
  항목에 소속된 조각도 오늘 목록으로 가져올 수 있다
  ([ADR-012](../../architecture/decisions/adr-012-aggregation-predicate.md) §2).
  "지난 주 미완료 조각을 이번 주에 재개"는 이 경로로 성립한다.
  - 근거: 집계 등식은 pull 시점의 주가 아니라 `sessions.local_week = week_items.week`
    조건이 보장한다(ADR-012 §1). 따라서 pull 을 제한할 이유가 없어졌고, 제한이 만들던
    개념(다음 주 항목 선택 불가 상태)과 대가도 함께 사라졌다.
- **R6.** pull 로 생기는 `task_pulls.pull_date` 는 **항상 오늘의 로컬 달력 키**다.
  다른 날짜(특히 미래 날짜)의 pull 행을 만드는 경로를 제공하지 않는다 — 미래 날짜 pull 은
  별개 결정이며 v1 비범위다 (ADR-012 §2). "오늘"의 정의는 ADR-009 §2, "그 주"의 정의는
  ADR-010(월요일 시작)을 따른다.
- **R7.** 완료된(`completed_at` 이 있는) 조각은 pull 대상이 아니다. 이미 오늘 목록에
  표시 중인 조각도 다시 선택할 수 없다 — 같은 (조각, 날짜)에 중복 행이 생기지 않는다.
  단 R13 으로 목록에서 치운 조각은 다시 선택 가능하다(R14).

  > ⚠️ 가정: "하루 3개 이하 권장"은 카피상의 권장이며, 4개 이상 pull 을 막거나 경고하는
  > 규칙은 결정 원장에 없다. 차단·경고 없음으로 해석한다.

- **R8.** **부모 항목의 상태 변화는 이미 존재하는 오늘 pull 행에 영향을 주지 않는다.**
  정오에 부모 주간 항목이 완료 확정·폐기(`dropped_at`)·이월되어도 그 조각은 오늘 목록에
  그대로 남고, 계속 집중 대상으로 지정할 수 있으며 세션도 정상 기록된다. 오늘 목록이
  주간 항목 상태를 다시 읽어 행을 없애거나 잠그는 동작은 없다.
  - 근거: 세션 귀속은 ADR-012 §1 의 주 조건으로 닫히므로, 부모 상태가 무엇이든 그 세션은
    자기 주에서 정확히 한 번 세어진다. 폐기 항목의 소진도 주간 카드의 "기타" 행이
    차액으로 흡수한다(ADR-012 §4). 따라서 pull 행을 건드릴 필요가 없다.

### 직접 입력과 부모 배선

- **R9.** (Q7) 오늘 목록에 제목을 직접 입력해 task 를 추가할 수 있다. 이때도 **부모
  없는 task 는 만들지 않는다** — 시스템 "기타" 항목에 배선하고, 그 항목이 없으면
  그 시점에 생성한다(lazy).
  - 사용자 관점과 데이터 관점은 다르게 읽힌다: 화면에서는 "주간 계획에 속하지 않은
    일간 항목"으로 보이지만, 데이터에는 항상 그 주의 "기타" 항목에 붙어 있어
    `tasks.week_item_id` NOT NULL 이 유지된다. 이것이 "고아 task 0건"(성공 지표)의 근거다.
- **R10.** 시스템 "기타" 항목 자체의 규칙은 **ADR-011 §4 를 따른다** (여기서 재진술하지
  않는다). 이 문서가 소유하는 사실은 **"오늘 목록의 직접 입력이 그 항목에 배선된다"**
  하나뿐이다.
  - 어느 주의 "기타" 항목을 쓰는가는 [ADR-012](../../architecture/decisions/adr-012-aggregation-predicate.md) §3
    에 따라 **세션의 `local_week` 기준**으로 선택·생성한다("오늘"의 주가 아니다).
    오늘 목록 직접 입력은 그 조각의 세션이 오늘 기록되므로 실질적으로 오늘의 주와
    같지만, 규칙의 출처는 사후 캡처와 동일한 ADR-012 §3 이다.

### 완료와 빼기

- **R11.** (S3) 완료는 boolean 이 아니라 `completed_at` 타임스탬프로 기록한다
  (ADR-011 §5). 완료 시각이 남으므로 "8/5 에 끝낸 task 가 8/1 날짜 패널에서 완료로
  보이는" 일이 발생하지 않는다.
- **R12.** 완료 체크는 **해제할 수 있다.** 해제 시 `completed_at` 을 NULL 로 되돌리고,
  이 변경은 주간·월간 집계에 즉시 반영된다.
- **R13.** ×(목록에서 빼기)는 **오늘 날짜의 pull 행에만** 허용한다. 과거 날짜의 행에는
  × 를 노출하지 않는다. 동작은 그 조각에 **그날 세션이 있는지**로 갈린다.
  - 그날 세션이 **0건**이면 그 날짜의 pull 행을 삭제한다(남길 이력이 없으므로 무해하다).
  - 그날 세션이 **1건 이상**이면 행을 삭제하지 않고 **"목록에서 치움" 표시**만 남긴다.
    치운 행은 오늘 목록에 표시되지 않지만 **그 날짜의 이력으로는 남는다** — 지난 날짜
    화면은 치운 행도 그날 목록으로 보여준다.
  - 어느 경우든 task 자체는 주간 항목에 남으며 **삭제가 아니다.** 확인창을 띄우지 않는다.
  - 근거: 행을 무조건 지우면, 뽀모 2회를 기록한 조각을 밤에 × 한 날이 다음 날
    "뽀모 2개인데 한 일 목록은 비어 있는 날"이 된다. `task_pulls` 를 행으로 승격한
    유일한 목적이 "그날 무엇을 하려 했는가"의 보존이므로 그 목적과 어긋난다.
- **R14.** × 로 뺀 조각을 **같은 날 다시 pull 할 수 있으며, 결과 행은 원래 행과
  구분되지 않는다** — 사용자에게는 다시 목록에 나타난 같은 항목이고, 집계·지난 날짜
  열람 결과도 한 번만 pull 한 경우와 같다(치움 표시가 해제되든 행이 다시 생기든 관측
  가능한 차이가 없다). 다른 날 다시 pull 해도 과거 날짜의 pull 행은 영향받지 않는다.
- **R15.** 이미 세션이 기록된 task 를 목록에서 빼도 그 세션과 집계는 변하지 않는다 —
  pull 행과 세션 귀속은 독립된 사실이다.

### 하루 경계 (로컬 자정)

- **R16.** (Q1·Q2) 하루 경계는 **로컬 자정**이다. 오늘 목록의 기준 날짜는 로컬 기준
  달력 키이며, 쓰는 순간 1회 계산해 불변 저장한다 (ADR-009 §2). 따라서 이후 OS
  타임존·시각을 바꿔도 이미 기록된 pull 행의 날짜와 지난 날짜 화면의 내용은 변하지 않는다.
- **R17.** 자정이 지나면 **pull 행을 다음 날로 갱신하지 않는다.** 결과적으로 미완료
  조각은 다음 날 오늘 목록에서 사라지고 주간 풀로 반납된다. 이 전이에 **어떤 확인창도
  띄우지 않으며**, 사용자는 필요하면 주간 카드에서 다시 pull 한다.
- **R18.** 앱이 자정을 걸쳐 실행 중이어도 목록은 새 날짜 기준으로 다시 판정된다
  (실행 중 화면이 어제 목록에 머물러 있지 않는다).
- **R19.** (Q18-A) 하루 경계를 알리는 **맥락 힌트 2종만** 제공한다. 상시 라벨("하루는
  자정에 바뀝니다" 류)은 만들지 않는다. 두 힌트의 노출 조건은 매 분 재평가하는
  판정 가능한 술어이며, 조건이 거짓이 되는 즉시 사라진다(수동 닫기 버튼은 없다).

  | 힌트 | 노출 시작 술어 | 노출 종료 |
  |---|---|---|
  | H1 **"자정이 지나면 남은 조각은 주간 카드로 돌아가요"** | 로컬 시각이 `23:00` 이상 `24:00` 미만이고, 오늘 목록의 미완료 항목이 1개 이상 | 자정을 지나거나 미완료 항목이 0개가 되면 |
  | H2 **"새 날이 시작됐어요 — 어제 조각은 주간 카드에서 다시 가져올 수 있어요"** | 로컬 시각이 `00:00` 이상 `06:00` 미만이고, 오늘 날짜의 pull 행이 0건 | 오늘 날짜 pull 행이 1건 이상이 되거나 `06:00` 을 지나면 |

  - 힌트는 사실만 알리고 훈계하지 않는다. 실패 색(`--danger`)을 쓰지 않는다
    (principles.md §1·§2).

  > ⚠️ 가정: H2 의 `06:00` 상한은 결정 원장에 없다. 원장에는 "자정 직후"라는 미정의
  > 표현만 있었고, 판정 가능한 술어로 만들기 위해 이 문서가 정한 값이다. H1 의 `23:00`
  > 하한은 원장 확정값이다. 두 술어 모두 "오늘 목록이 비었다"가 아니라 **pull 행 수**로
  > 판정한다 — 치운 행(R13)이 있는 날에는 오늘 목록이 비어도 H2 를 띄우지 않는다.

### 빈 상태

- **R20.** 빈 상태 카피는 2종이며, 이번 주 주간 항목 존재 여부로 갈린다.
  - 이번 주 주간 할당이 **있을 때**: **"위 주간 할당에서 +오늘로 를 눌러 오늘 몫을
    골라오세요 (3개 이하 권장)"** — CTA 는 별도로 두지 않는다. 카피가 가리키는
    `+ 오늘로` 버튼이 주간 카드에 실재하는 CTA 다.
  - 주간 할당이 **없을 때**: **"계획이 없어도 타이머는 돌아가요."** (원칙 1)
    + CTA **`자유 집중 시작`** (고스트 버튼).
    - 동작은 타이머 카드의 `시작` 과 **완전히 동일**하다 — focus idle 에서 세션을
      시작한다. 타이머의 상태 기계·기록은 timer 소유이며 이 버튼은 진입점일 뿐이다.
    - **focus 세션이 running/paused 인 동안에는 렌더하지 않는다** — 진행 중 세션
      위에 "시작"을 겹쳐 두지 않는다. 콜드 스타트(계획 0·세션 0·타이머 idle)에서는
      항상 보이므로 app-shell 콜드 스타트 요구(카피 1 + CTA 1)를 충족한다.
    - 이 CTA 는 계획을 권하지 않는다 — "계획 없이 시작하는 경로"가 이 분기의
      메시지이므로, `할당 잡기` 류의 CTA 를 여기 두지 않는다 (원칙 1).
- **R20-1.** 직접 입력(R9)의 접근 가능한 이름과 placeholder 는
  **"오늘 할 일 직접 적기"** 다. placeholder 만으로 접근 가능한 이름을 대신하지
  않는다 (`aria-label` 동반).
- **R21.** 빈 상태 판정에서 "주간 할당 있음"은 그 주의 사용자 항목 존재를 뜻하며,
  시스템 "기타" 항목만 있는 경우는 **없음**으로 취급한다(기타는 사용자가 세운 계획이 아니다).
- **R22.** 빈 상태 카피와 자정 힌트는 배타적이지 않다 — H2 노출 조건(R19)이 참인
  자정 직후의 빈 목록에는 R20 의 카피와 H2 가 **함께** 노출된다.

## 성공 지표

- 이력 불변: pull → × → 재-pull 을 반복해도 이전 날짜의 날짜 패널 내용이 변하지 않는다
- 이력 완결: 어떤 날짜에 세션이 1건 이상 있으면 그 날짜 화면의 목록도 비어 있지 않다
  (R13 이 만드는 성질)
- 고아 없음: 어떤 경로로 만든 task 든 부모 항목이 NULL 인 행이 0건이다 (R9)
- 계획 0 상태에서 오늘 목록 직접 입력 → 체크 → 집계가 전 구간 동작한다 (원칙 1)
- 하루 pull 개수는 지표로 삼지 않는다 — 적게 가져온 날이 실패가 아니다 (원칙 7)

> 게이지 정합(`주간 총 소진 = Σ(항목 소진) + 미분류`)은 **이 기능의 지표가 아니다.**
> 그 등식은 [ADR-012](../../architecture/decisions/adr-012-aggregation-predicate.md) §1 의
> 집계 술어가 정의상 보장하며, 이 문서는 그 술어를 소유하지 않는다. 이전 판이 이것을
> 자기 성공 지표로 단언한 것은 과장이었다
> ([리뷰 결정 원장](../../decision-log/2026-08-04-review-decisions.md) "특기 사항" 참조).
