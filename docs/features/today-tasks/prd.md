# PRD: today-tasks

> 출처: docs/origin/pomodoro-prd.md §3.2 (초안) + [결정 원장](../../decision-log/2026-08-04-planning-session.md) §A (Q1·Q2·Q18), §C (Q7·Q10, ERD 평가 B3·S3)
> 초안과 이 문서가 다르면 이 문서가 이긴다. 특히 초안의 `tasks.pulled_date` 단일 컬럼과
> "주간 미연결 임시 task" 서술은 각각 `task_pulls` 행(B3)과 시스템 "기타" 항목(Q7)으로 대체된다.

## 문제

주간 계획을 세워 두어도 하루를 시작할 때 "지금 뭐부터 하나"는 다시 정해야 한다.
이 판단을 매일 아침 처음부터 계획하는 일로 만들면 계획 자체가 부담이 되고, 반대로
주간 항목 전체를 늘 눈앞에 펼쳐 두면 지금 할 일이 묻힌다. 또한 오늘 목록을 주간과
별개의 복사본으로 만들면 소진 집계가 두 갈래로 갈라져 게이지와 항목 합이 어긋난다.

필요한 것은 **주간 풀에서 조각만 끌어오는 얇은 뷰**다 — 오늘 목록에 있다는 사실이
task 의 별도 사본이 아니라 "그날 끌어왔다"는 관계 한 줄로만 표현되어야 한다.

## 대상 사용자

- 앱 소유자 1인 (로컬 단독, 로그인·멀티유저 없음)

## 목표

1. 오늘 할 일을 **새로 계획하지 않고 pull 로만** 세운다. 하루 3개 이하를 권장한다(원칙 2).
2. 오늘 목록의 어떤 조작도 데이터를 잃지 않는다 — 목록에서 빼기는 삭제가 아니고,
   지난 날짜의 "그날 무엇을 했는가"는 이후 조작에도 불변이다.
3. 날짜 기준 집계(주간 게이지)와 관계 기준 집계(항목별 소진)가 항상 일치한다 (Q10).
4. 계획이 하나도 없어도 막히지 않는다 — 오늘 목록에 직접 입력할 수 있다 (원칙 1).
5. 하루 경계(로컬 자정)의 동작을 사용자가 놀라지 않고 알 수 있다 (Q1·Q18).

## 범위 / 비범위

**범위:** 오늘 목록의 조회·정렬, 주간 항목에서의 pull 대상 제약, 오늘 목록 직접 입력,
완료 체크·해제, 목록에서 빼기(×), 소진 뽀모 도트 표시, 자정 경계 동작,
빈 상태 카피 2종, 자정 관련 맥락 힌트 2종.

**비범위:**
- 주간 항목 자체의 생성·est·요일 배치·이월 판단, 주간 카드의 게이지·드로어 UI
  (→ **week-plan**. 이 문서는 "그 항목의 task 를 오늘로 가져온다"까지만 정의한다)
- pull 을 시작하는 진입 UI("+오늘로" 드로어)의 화면 구성 (→ **week-plan**)
- 타이머 조작과 집중 대상 지정 (→ **timer**. 이 문서는 "오늘 목록이 집중 대상의
  후보 집합"이라는 사실까지만)
- 세션 기록·사후 캡처 (→ **timer**)
- 지난 날짜의 오늘 목록 열람 화면 (→ **calendar-records**. 이 문서는 그 열람이
  가능하도록 pull 이력을 보존한다는 요구만 정의한다)
- 마일스톤 태그·월간 집계 (→ **milestones**)
- 주간 리뷰의 이월 3택 (→ **weekly-review**)
- task 단위 요일 배정 (명시적 비목표 — ADR-011 §8)

## 요구사항

### 목록의 정체와 조회

- **R1.** 오늘 목록은 별도 엔티티가 아니라 task 의 뷰다. 구성 조건은
  "오늘 날짜의 pull 행이 존재하고 삭제되지 않은 task" 이며, task 사본을 만들지 않는다.
- **R2.** "오늘 목록에 있다"는 사실은 `task_pulls(task_id, pull_date)` **행**으로
  표현한다 (ADR-011 §2). task 에 단일 `pulled_date` 컬럼을 두지 않는다 — 재-pull 시
  과거 날짜의 이력이 덮여 지난 날짜 패널이 거짓을 말하기 때문이다.
- **R3.** 각 항목은 제목, 출처(소속 주간 항목명), 소진/est 뽀모 도트, 완료 상태를
  표시한다. 뽀모 도트의 소진 값은 저장값이 아니라 그 task 에 연결된 세션의 집계
  파생값이다 (원칙 8 — 상위 소진량 저장 금지).

### pull 대상의 범위 제약

- **R4.** (Q10) 오늘 목록으로 pull 할 수 있는 task 는 **오늘이 속한 주의 주간 항목에
  소속된 task 로 제한한다.** 다음 주 항목의 task 는 그 주가 오기 전에는 pull 할 수 없다.
  - 근거: 날짜 기준 집계(주간 총 소진)와 관계 기준 집계(항목별 소진)를 구조적으로
    일치시켜 "게이지 = 항목 합 + 미분류"가 항상 닫히게 한다.
  - 수용한 대가: "내일(다음 주) 계획을 오늘 밤 미리 시작"은 불가능하다.
  - "오늘이 속한 주"의 정의는 ADR-010(월요일 시작)을 따른다.
- **R5.** 이미 오늘 목록에 있는 task 는 다시 pull 대상으로 선택할 수 없다(중복 행이
  생기지 않는다). 완료된 task 도 pull 대상이 아니다.

### 직접 입력과 부모 배선

- **R6.** (Q7) 오늘 목록에 제목을 직접 입력해 task 를 추가할 수 있다. 이때도 **부모
  없는 task 는 만들지 않는다** — 그 주의 시스템 "기타" 항목에 배선하고, 그 항목이
  없으면 그 시점에 생성한다(lazy).
- **R7.** 시스템 "기타" 항목은 다음 규칙을 지킨다 (ADR-011 §4): `is_system` 표시,
  est 0(과적 경고·요일 부하에 산입되지 않음), 주간 플래너에서 편집·삭제 불가,
  주간 리뷰의 이월 3택 대상에서 제외.
- **R8.** 사용자 관점의 표현과 데이터 표현을 구분한다 — 화면에서는 "주간 계획에
  속하지 않은 일간 항목"으로 읽히지만, 데이터에는 항상 그 주의 "기타" 항목에
  붙어 있어 부모 없는 task 는 존재하지 않는다.

### 완료와 빼기

- **R9.** (S3) 완료는 boolean 이 아니라 `completed_at` 타임스탬프로 기록한다
  (ADR-011 §5). 완료 시각이 남으므로 "8/5 에 끝낸 task 가 8/1 날짜 패널에서 완료로
  보이는" 일이 발생하지 않는다.
- **R10.** 완료 체크는 **해제할 수 있다.** 해제 시 `completed_at` 을 NULL 로 되돌리고,
  이 변경은 주간·월간 집계에 즉시 반영된다.
- **R11.** ×(목록에서 빼기)는 **그 날짜의 pull 행 1개를 삭제**하는 것이다. task 자체는
  주간 항목에 남으며 **삭제가 아니다.** 확인창을 띄우지 않는다.
- **R12.** 같은 task 를 같은 날 다시 pull 할 수 있고, 다른 날 다시 pull 해도 과거
  날짜의 pull 행은 영향받지 않는다(그날의 이력이 보존된다).
- **R13.** 이미 세션이 기록된 task 를 목록에서 빼도 그 세션과 집계는 변하지 않는다 —
  pull 행과 세션 귀속은 독립된 사실이다.

### 하루 경계 (로컬 자정)

- **R14.** (Q1·Q2) 하루 경계는 **로컬 자정**이다. 오늘 목록의 기준 날짜는 로컬 기준
  달력 키이며, 쓰는 순간 1회 계산해 불변 저장한다 (ADR-009 §2).
- **R15.** 자정이 지나면 **pull 행을 다음 날로 갱신하지 않는다.** 결과적으로 미완료
  조각은 다음 날 오늘 목록에서 사라지고 주간 풀로 반납된다. 이 전이에 **어떤 확인창도
  띄우지 않으며**, 사용자는 필요하면 주간 카드에서 다시 pull 한다.
- **R16.** 앱이 자정을 걸쳐 실행 중이어도 목록은 새 날짜 기준으로 다시 판정된다
  (실행 중 화면이 어제 목록에 머물러 있지 않는다).
- **R17.** (Q18-A) 하루 경계를 알리는 **맥락 힌트 2종만** 제공한다. 상시 라벨("하루는
  자정에 바뀝니다" 류)은 만들지 않는다.
  1. 로컬 23시 이후이고 오늘 목록에 미완료 항목이 1개 이상일 때:
     **"자정이 지나면 남은 조각은 주간 카드로 돌아가요"**
  2. 자정 직후 오늘 목록이 비었을 때:
     **"새 날이 시작됐어요 — 어제 조각은 주간 카드에서 다시 가져올 수 있어요"**
  - 힌트는 사실만 알리고 훈계하지 않는다. 실패 색(`--danger`)을 쓰지 않는다
    (principles.md §1·§2).

  > ⚠️ 가정: 2번 힌트의 노출 종료 조건(예: 목록에 첫 항목이 생기면 사라짐, 또는
  > 특정 시각까지 유지)은 결정 원장에 정의되어 있지 않다. 노출 시작 조건만 확정이며
  > 종료 조건은 **TBD** — ux 구현 시 확정한다.

### 빈 상태

- **R18.** 빈 상태 카피는 2종이며, 이번 주 주간 항목 존재 여부로 갈린다.
  - 이번 주 주간 할당이 **있을 때**: **"위 주간 할당에서 +오늘로 를 눌러 오늘 몫을
    골라오세요 (3개 이하 권장)"**
  - 주간 할당이 **없을 때**: **"계획이 없어도 타이머는 돌아가요."** (원칙 1)
- **R19.** 빈 상태 판정에서 "주간 할당 있음"은 그 주의 사용자 항목 존재를 뜻하며,
  시스템 "기타" 항목만 있는 경우는 **없음**으로 취급한다(기타는 사용자가 세운 계획이 아니다).
- **R20.** 자정 직후의 빈 목록에는 R17-2 힌트가 R18 카피와 함께 노출된다.

### 표시 규율

- **R21.** 렌더되는 UI 에 이모지를 쓰지 않는다. 아이콘은 lucide-react 컴포넌트,
  뽀모 도트는 토큰 기반 커스텀 SVG/CSS 로 만든다 (principles.md §6). 초안 문서의
  🍅 표기는 문서용 속기이며 구현 지시가 아니다.
- **R22.** 시각 값은 토큰 이름으로만 기술한다 (principles.md §5). 미완료 조각의 반납,
  하루 3개 초과 등을 실패로 프레이밍하지 않는다 (principles.md §1).

  > ⚠️ 가정: "3개 이하 권장"은 카피상의 권장이며, 4개 이상 pull 을 막거나 경고하는
  > 규칙은 결정 원장에 없다. 차단·경고 없음으로 해석한다.

## 성공 지표

- 게이지 정합: 임의 주에서 `주간 총 소진 = 항목별 소진 합 + 미분류 소진` 이 항상
  성립한다 (R4 가 만드는 구조적 성질의 검증)
- 이력 불변: pull → × → 재-pull 을 반복해도 이전 날짜의 날짜 패널 내용이 변하지 않는다
- 고아 없음: 어떤 경로로 만든 task 든 부모 항목이 NULL 인 행이 0건이다 (R6·R8)
- 계획 0 상태에서 오늘 목록 직접 입력 → 체크 → 집계가 전 구간 동작한다 (원칙 1)
- 하루 pull 개수는 지표로 삼지 않는다 — 적게 가져온 날이 실패가 아니다 (원칙 7)
