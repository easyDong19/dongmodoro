# PRD: milestones

> 출처: docs/origin/pomodoro-prd.md §3.4 (초안) + [결정 원장](../../decision-log/2026-08-04-planning-session.md) §D (Q15), §C (ERD 평가 S3), §A (시간 포맷 규약)
> 초안과 이 문서가 다르면 이 문서가 이긴다.

## 문제

한 달 단위 계획이 "할 일 목록"이 되면 월 레이어와 주 레이어가 같은 질문에 두 번
답하게 되고, 어느 쪽이 진짜 계획인지 알 수 없어진다. 월은 **결과물**에,
주는 **얼마만큼**에 답해야 한다 (원칙 2). 또한 월 레이어에 소진량을 따로 저장하면
주간 카드의 숫자와 어긋날 수 있으므로, 월의 진행 표시는 아래에서 올라온 값이어야 한다
(원칙 8 — 아래→위 단방향 파생).

## 대상 사용자

- 앱 소유자 1인 (로컬 단독, 로그인·멀티유저 없음)

## 목표

1. 이번 달의 결과물을 상태 문장으로 2~3개 적고, 달성/미달성이 아니라 **끝났는지 여부**만
   사실로 표시한다.
2. 주간 항목을 결과물에 매달 수 있게 해, 주간 소진이 월 레이어에서 진행으로 보이게 한다.
   단 마일스톤은 어떤 수치도 스스로 갖지 않는다.
3. 지난달 카드는 리뷰 데이터를 보호하고, **없는 숫자를 만들어 보여주지 않는다** (Q15).

## 범위 / 비범위

**범위:** 월 마일스톤 목록의 조회·인라인 편집(추가·제목 수정·삭제), 완료 토글과 해제,
표시 순서 변경, 보관, 이번 달/지난달/미래 달의 표시 모드 분기, 달 이동 시 동기 전환,
연결된 주간 항목으로부터의 소진 롤업 표시, 빈 상태 카피.

**비범위:**

- 주간 항목 자체의 생성·편집·삭제와 마일스톤 태그의 표시 — **week-plan** 기능이 소유한다.
  이 문서는 "주간 항목이 마일스톤에 선택적으로 연결된다"는 사실과 그 연결이 월 카드에
  어떻게 집계되는지까지만 정의한다.
- **월 누적 소진 집계** (그 달 전체 기간의 소진 합) — v1.1. v1 은 이번 주 기준 롤업만 (Q15).
- 월말 정산 화면에서의 마일스톤 재설정 흐름(다음 달로 복사 / 보관 2택) — 정산 화면의
  구성은 **weekly-review** 기능이 소유한다. 이 문서는 그 흐름이 호출할 **보관 요구사항
  (R12)** 까지만 정의한다.
- 달 그리드·날짜 점·날짜 패널 — **calendar-records**. 이 문서는 "달 이동 조작이 캘린더의
  이전/다음 컨트롤과 하나"라는 요구(R13)만 갖는다.
- 마일스톤 단위의 알림·리마인더. v1 에 없다.
- 마일스톤에 직접 task·세션을 붙이는 경로. 구조적으로 존재하지 않는다 (R9).

## 요구사항

### 월 키와 달 판별

- **R1.** 마일스톤은 `month` 달력 키 `'YYYY-MM'`(zero-pad)에 속한다. 이 값은 **로컬 기준으로
  행을 쓰는 순간 1회 계산해 저장하고 이후 재계산하지 않는다** (ADR-009 §2). 조회 시
  순간(UTC) 컬럼에서 달을 파생하지 않는다.
- **R2.** 달의 과거/현재/미래 판별과 정렬은 `month` 문자열의 **사전순 비교**로만 한다
  (사전순 = 시간순). 달 산술이 필요한 경우(직전 달·다음 달)는 시간 모듈의 함수를 쓴다
  (ADR-009 §3 — 화면 코드에서 즉석 계산 금지).

### 결과물의 형태

- **R3.** 마일스톤은 **제목(상태 문장) 하나만** 갖는다. 마일스톤에는 할당량·예상 뽀모·예산
  등 **수치 입력 필드를 두지 않는다** — 숫자가 처음 등장하는 레벨은 주(週)다 (원칙 2).
- **R4.** 이번 달 카드는 2~3개를 **권장 힌트로만** 안내한다. 개수 상한·하한을 강제하지 않고,
  4개 이상이어도 저장을 막거나 경고색으로 표시하지 않는다 (원칙 6 — 판단은 사용자).
- **R5.** 표시되는 `M1`·`M2` 번호는 저장값이 아니라 그 달의 `sort_order` 순서에서 파생하는
  **렌더 전용 라벨**이다. 순서가 바뀌면 번호도 함께 바뀐다.

### 편집

- **R6.** 이번 달 카드에서 마일스톤을 추가·제목 수정·삭제할 수 있다. 편집은 카드 안에서
  인라인으로 이뤄지며, 별도 화면·모달로 이동하지 않는다.
- **R7.** 마일스톤을 삭제하면 그 마일스톤에 연결돼 있던 주간 항목의 `milestone_id` 는
  NULL 이 되어 UI 상 "기타"로 이동한다. 주간 항목·task·세션과 그 소진 기록은 삭제되지
  않는다 (연결은 선택 관계이므로 부모가 없어도 자식이 유효하다).

  > ⚠️ 가정: 삭제를 물리 삭제로 볼지 soft delete 로 볼지는 스키마에 아직 반영돼 있지
  > 않다 (ADR-011 시점의 milestones 에는 `archived_at` 만 있고 `deleted_at` 이 없다).
  > 이력 보존이 필요한 경우는 삭제가 아니라 **보관(R12)** 으로 처리하는 것을 전제로 한다.
  > 물리/논리 삭제 확정은 구현 시 ADR 로 남긴다 — TBD.

- **R8.** 표시 순서는 `sort_order` 로 결정되며, 사용자가 이번 달 카드에서 순서를 변경할 수
  있다. 변경 결과는 즉시 저장되고 다음 조회에도 유지된다. 지난달·미래 달 카드에서는
  순서 변경이 불가하다 (R14).

### 연결과 소진 파생

- **R9.** 마일스톤에는 task 와 세션이 **직접 붙지 않는다.** 마일스톤은 주간 항목의 부모일
  뿐이고, 계층은 `milestone → week_item → task → session` 한 방향이다.
- **R10.** 주간 항목 → 마일스톤 연결은 **선택**이다 (`milestone_id` nullable — ADR-011 §4).
  연결이 없는 주간 항목은 어떤 마일스톤에도 집계되지 않고 UI 상 "기타"로 다뤄진다.
  연결 없음은 오류 상태가 아니며, 누락으로 표시하거나 연결을 요구하는 문구를 띄우지 않는다.
- **R11.** 마일스톤의 소진량은 **저장하지 않는다** (원칙 8). 표시값은 항상
  "연결된 주간 항목들의 소진 합"으로 쿼리 시 파생하며, **기간 필터가 반드시 붙는다.**
  v1 의 필터는 **이번 주**이고, 이번 달 카드에만 표시한다. 필터가 붙지 않은 합계(월 누적)는
  v1 에서 계산하지도 표시하지도 않는다 (Q15 — 비범위).
- **R12.** 마일스톤은 `archived_at`(순간 — ADR-009)으로 보관할 수 있다. 보관된 마일스톤은
  그 달 카드의 목록과 완료 집계(R16 의 N·M 양쪽)에서 제외되고, 연결된 주간 항목의
  `milestone_id` 는 유지된다 — 데이터와 이력은 남고 표시에서만 빠진다. 보관은 해제
  가능하다(`archived_at` 을 NULL 로).

### 달 이동과 표시 모드

- **R13.** 달 이동 조작은 캘린더의 이전/다음 달 컨트롤과 **하나다.** 마일스톤 전용 탭·모달·
  월 선택기를 별도로 두지 않는다. 캘린더의 표시 달이 바뀌면 마일스톤 카드가 같은 달로
  동기 전환된다.
- **R14.** 표시 모드는 `month` 와 이번 달의 사전순 비교로 3가지로 갈린다.

  | 모드 | 조건 | 동작 |
  |---|---|---|
  | 편집 가능 | `month` == 이번 달 | R6·R8·R15 전부 가능. 이번 주 소진 롤업 표시 (R11) |
  | 읽기 전용 | `month` < 이번 달 | 추가·수정·삭제·순서 변경·완료 토글 전부 불가. 시각적으로 감쇠(`--ink-dim`) + 달성 배지 (R16) |
  | 계획 전 | `month` > 이번 달, 또는 그 달에 마일스톤 0건 | 빈 상태 카피 + 계획 시작 CTA (R17) |

- **R15.** 완료는 카드 안에서 토글한다. 완료 시 `completed_at`(순간)을 기록하고, 해제 시
  NULL 로 되돌린다 — boolean `done` 을 쓰지 않는다 (ADR-011 §5). 완료 시각이 남으므로
  "언제 끝냈는지"를 나중에 기간으로 걸러낼 수 있다.
- **R16.** 지난달 카드는 **"N/M 달성" 배지만** 표시한다 (Q15). N = 그 달의 `completed_at` 이
  있는 마일스톤 수, M = 그 달의 보관되지 않은 마일스톤 수. **월 누적 소진 숫자를 함께
  표시하지 않는다** — v1 에 그 값이 존재하지 않으므로 지어내지 않는다.
- **R17.** 문구는 사실만 말한다 (원칙 6·7, principles.md §1).
  - 이번 달 빈 상태: **"이번 달이 끝나면 뭐가 달라져 있을까요?"** + 결과물 추가 CTA
  - 미래 달: **"아직 계획 전"** + **"N월 계획 잡기"** CTA (N = 그 달의 월 숫자)
  - 지난달 배지: **"N/M 달성"**
  - **금지:** "미달성", "실패", "목표 초과", "N건 남음" 같은 부정·결핍 프레임과
    "이번 달엔 더 해보세요" 류 훈계 문구. 완료되지 않은 마일스톤에는 별도의 부정 표기를
    붙이지 않는다 (완료 표시의 **없음**으로만 드러난다).
- **R18.** 시각 값은 토큰 이름으로만 기술한다 (principles.md §5). 이 기능이 쓰는 것은
  진행·완료의 `--teal`, 읽기 전용·메타 정보의 `--ink-dim` / `--ink-faint` 이며,
  `--danger` 는 쓰지 않는다 (성과·진척 표현에는 금지 — principles.md §2).
- **R19.** 배지·CTA·빈 상태 카피를 포함한 모든 렌더 텍스트에 **이모지를 쓰지 않는다.**
  아이콘은 lucide-react 컴포넌트, 뽀모 개수 표시는 토큰 기반 뽀모 도트 컴포넌트를 쓴다
  (principles.md §6).

## 성공 지표

- 마일스톤 화면에 수치 입력 필드가 0개다 (R3 — 월/주 레벨의 질문이 섞이지 않음).
- 마일스톤 소진 표시값과, 같은 시점 주간 카드의 항목별 소진 합이 항상 일치한다
  (파생 경로가 하나뿐이므로 구조적으로 성립 — 원칙 8).
- 지난달 카드에 표시되는 숫자가 배지의 N/M 뿐이다 (Q15 — 없는 값 0건 노출).
- 마일스톤이 0건인 상태에서도 주간 계획·타이머·기록이 전 구간 동작한다 (원칙 1).
- 문구 검수: 렌더 텍스트에서 부정 프레임 표현과 이모지 검출 0건 (R17·R19).
