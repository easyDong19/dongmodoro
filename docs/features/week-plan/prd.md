# PRD: week-plan

> 출처: docs/origin/pomodoro-prd.md §3.3 (초안) + [결정 원장](../../decision-log/2026-08-04-planning-session.md) §C (Q7·Q10~Q14), §A (Q8-1·Q9·plan_lead_days) + [리뷰 결정](../../decision-log/2026-08-04-review-decisions.md) D1·D3
> 초안과 이 문서가 다르면 이 문서가 이긴다. 특히 초안의 "일요일 시작 주 / ISO week 문자열 주 키"는 [ADR-010](../../architecture/decisions/adr-010-week-definition.md) 으로 폐기됐다.
> 원장 Q10 의 "pull 은 오늘이 속한 주로 제한"은 [ADR-012](../../architecture/decisions/adr-012-aggregation-predicate.md) 로 **폐기**됐고, `weeks.budget` NULL 파생은 [ADR-013](../../architecture/decisions/adr-013-baseline-budget-effect.md) 으로 **폐기**됐다.
> **진행의 통화가 뽀모 개수에서 측정 시간으로 바뀌었다** ([ADR-030](../../architecture/decisions/adr-030-time-as-progress-currency.md)). 예상 뽀모·주간 예산·요일별 가용량과 그 위에 서 있던 과적 경고가 전부 폐기됐고, 이 문서의 문제 서술·목표·성공 지표는 그 결정 위에서 다시 쓰였다. 폐기된 요구에는 각 항목에 **폐기** 표기를 남긴다 — 지우면 "아직 안 옮긴 것"인지 "죽은 것"인지 구분할 수 없다.

## 문제

월간 마일스톤은 "이번 달이 끝나면 뭐가 달라져 있나"라는 상태 기술이고, 오늘 목록은
"지금 뭐 하나"라는 실행이다. 그 사이에 **주 단위로 무엇을 할지 잡아 두는 층**이 없으면
두 가지가 무너진다.

1. 마일스톤이 실행 가능한 크기로 쪼개지지 않아, 오늘 목록에 매일 새 계획을 즉흥으로
   짜게 된다 (원칙 2 위반 — 일 레이어는 pull 만 해야 한다).
2. 집중한 시간이 **무엇을 위한 시간이었는지** 남지 않는다. 세션은 날짜별로 흩어져
   캘린더의 점이 되고, "이번 주에 이 일로 얼마나 했나"를 한자리에서 볼 곳이 없다.
   할당이 그 귀속처이며, 시간은 거기에 자동으로 쌓인다.

주 레이어는 이 두 구멍을 하나의 카드로 메운다. 동시에, 이 카드는 **계획이 0개여도
타이머가 완전히 동작해야 한다는 원칙 1을 깨지 않아야** 한다 — 있으면 풍부해지는
레이어여야 하고, 없으면 막히는 것이 없어야 한다.

## 대상 사용자

- 앱 소유자 1인 (로컬 단독, 로그인·멀티유저 없음)

## 목표

1. 주간 항목 하나가 "이번 주에 무엇을 하나"를 **제목으로** 표현하고, 그 항목에 쌓인
   집중 시간이 세션에서 자동으로 파생돼 별도 입력 없이 갱신된다. **계획 시점에 매기는
   숫자는 없다** (ADR-030 §2) — 답하는 질문이 "얼마만큼"이 아니라 "무엇을"이다.
2. 헤더의 주 총합과 항목별 합이 **정의상** 일치한다 — 집계 술어를
   `sessions.local_week = week_items.week` 로 고정하고, 화면의 기타 행을 차액으로
   정의해 이중 계상과 누락을 산술적으로 불가능하게 만든다 (ADR-012 §1, ADR-031 §2).
   차액은 **초 단계에서** 낸다.
3. 계획 화면이 사용자를 판단하지 않는다 — 견줄 분모가 사라졌으므로 과적이라는 상태도,
   그것을 알리는 경고도, 확정을 막는 경로도 없다 (원칙 3·6).
4. "시간을 다 쓴 것"과 "일이 끝난 것"을 구분한다 — 시간이 얼마나 쌓였는지로 완료를
   제안하지 않는다 (Q14).
5. 계획을 세우려는 사용자가 **어느 주를 고치는지 언제나 알 수 있다** — 편집 대상 주는
   달력에서 파생된 숨은 값이 아니라 화면에 보이는 선택 상태다.

## 범위 / 비범위

**범위:** 주 정의(월요일 시작·주 키)의 적용, 주간 카드 일반 뷰의 항목 목록, 주간
플래너(편집 대상 주 선택·항목 추가·마일스톤 연결·요일 배치·확정), 항목 드로어(자식
task 목록·생성·오늘로 가져오기), 항목 완료 제안·확정·폐기, 주차별 시스템 "기타" 항목,
헤더의 주 측정 시간 합, 이월 배지 표시.

**비범위:**

- 오늘 목록 자체의 관리(표시·체크·× 제거·자정 반납) → today-tasks. 이 문서는 "주간
  항목에서 오늘로 pull 한다"까지만 정의한다.
- 이월 3택(다음 주로 / 줄여서 / 보내주기)과 정산 판정·병합 → weekly-review. 이 문서는
  이월된 항목을 **표시**하는 규칙(배지)만 정의하고, 이월의 데이터 동작(재부모화·승계)은
  [ADR-012](../../architecture/decisions/adr-012-aggregation-predicate.md) §3 을 전제로 인용한다.
- 뽀모 길이(focus/short/long) 변경 → pomo-baseline. 주간 계획은 그 값을 읽지 않는다 —
  길이는 타이머의 관심사이고, 이 카드가 그리는 시간은 실제로 잰 값이다.
- 마일스톤 자체의 생성·편집·월 이동 → milestones. 이 문서는 마일스톤 칩으로 연결하는
  것까지만.
- 3컬럼/탭 레이아웃, 카드가 어느 컬럼에 앉는지, 창 크기 하한 → app-shell.
- 스키마 DDL·쿼리·마이그레이션·제약 형태 → [ADR-011](../../architecture/decisions/adr-011-schema-final.md).
- task 단위 요일 배정 (요일 배치는 항목 단위뿐 — ADR-011 §8 에서 명시적 보류).
- 월 누적 측정 시간 롤업 (v1.1 — Q15).
- **주 네비게이션.** v1 의 주간 카드에는 "지난 주 보기"·주 이동 화살표가 없다. 일반
  뷰는 항상 오늘이 속한 주이고, 편집 대상 주 선택(R3)은 이번 주 / 다음 주 두 값만
  갖는다. 과거 주를 되짚는 통로는 캘린더·주간 정산다.
- **항목 우선순위 정렬.** 사용자가 항목 순서를 직접 정하는 기능은 v1 비목표다 (R10).
- 미래 날짜 pull("내일 몫 미리 담기") — v1 비범위 (ADR-012 §2).

## 용어

| 용어 | 뜻 |
|---|---|
| **시스템 "기타" 항목** | `is_system = 1` 인 주차별 week_item. 부모 없는 task 가 붙는 실제 데이터 행 (R14) |
| **기타 행** | 주간 카드 목록 맨 아래에 렌더되는 **화면상의 한 행.** 시스템 항목 + 미분류 세션을 합친 표시 단위이고, 그 측정 시간은 차액으로 정의된다 (R17) |
| **`마일스톤 없음`** | 플래너에서 "마일스톤에 연결하지 않음"을 고르는 칩의 라벨. 위 두 개념과 **무관하다** — 라벨을 `기타` 로 쓰지 않는 이유가 이것이다 |

## 요구사항

### 주의 정의와 편집 대상 주

- **R1.** 주는 **월요일에 시작**하고, 주 키는 그 주 월요일 날짜 `'YYYY-MM-DD'` 다
  (ADR-010 §1·§2). 요일을 다루는 모든 UI(요일 핍, 요일 칩)는 월요일부터 일요일 순으로
  배열하며, 배열 인덱스 0 = 월요일이다.
- **R2.** `W32` 같은 주 번호 라벨은 저장하지 않고 표시 시점에 계산한다 (렌더 전용).
  카드 헤더의 주 범위 표기도 주 키에서 파생한다.
- **R3.** 플래너의 **편집 대상 주는 파생값이 아니라 선택 가능한 상태**다. 값은
  `이번 주`(= 오늘이 속한 주)와 `다음 주`(= 그 다음 주) 둘이다.
  - 진입 시 기본 선택값은 `week_of(오늘 + plan_lead_days)` 이며 `plan_lead_days`
    기본값은 1이다 (ADR-010 §3) — 즉 일요일에는 `다음 주` 가, 평일에는 `이번 주` 가
    기본 선택된다.
  - 사용자는 플래너 안에서 이 선택을 언제든 바꿀 수 있다. **일요일에도 `이번 주` 를
    골라 진행 중인 주의 항목을 고칠 수 있다** (R23 의 주중 재수정이 계획일에도
    무효가 되지 않는다).
  - 선택을 바꾸면 초안 목록이 그 주의 항목으로 다시 채워진다.
  - v1 에서 `plan_lead_days` 자체의 설정 UI 는 노출하지 않는다.
- **R4.** 일반 뷰가 보여주는 주는 **항상 오늘이 속한 주**다. 편집 대상 주와 다를 수
  있으며, 그때도 일반 뷰는 이번 주를 계속 보여준다.
- **R5.** 헤더 제목, 빈 상태 CTA 라벨, 플래너 확정 버튼 라벨은 **모두 R3 의 편집 대상
  주 선택 상태에서 파생한다.** 달력상의 오늘 요일에서 직접 파생하지 않는다 — 그렇게
  하면 "이번 주 할당 잡기"를 눌러 다음 주가 열리는 모순이 생긴다. 문구 표는
  [ux-spec](./ux-spec.md) §1·§5·§8 소관이다.

### 주간 항목

- **R6.** 주간 항목은 제목, 마일스톤 연결(선택 — 미연결 시 `마일스톤 없음`),
  요일 배치 의도(선택 — 다중 선택, 미선택 = 미배치)를 갖는다. **계획 시점에 매기는
  숫자를 갖지 않는다** (ADR-030 §1 — `예상 뽀모` 는 폐기된 용어다).
  - ~~est 는 정수 ≥ 1 이고 시스템 항목만 0 이다~~ — **폐기.** est 입력이 사라졌으므로
    하한도, 시스템 항목의 예외도 요구사항으로 남지 않는다. 컬럼이 스키마에서 걷힐
    때까지 남는 자리 채움 값은 요구사항이 아니라 구현 세부다.
  - 마일스톤 미연결은 정상 상태다 — 연결은 선택이며, 마일스톤이 물리 삭제되면 연결이
    자동으로 끊겨 미연결이 된다 (ADR-014 §3).
- **R7.** 요일 배치는 **예약이 아니라 배치 의도**다. 배정된 요일이 되어도 항목이
  오늘 목록에 자동으로 들어가지 않는다. 오늘 배정된 항목은 목록 상단으로 정렬하고
  시각적으로 강조하는 것까지만 한다.
- **R8.** 항목의 **측정 시간**은 저장하지 않고 항상 세션에서 파생한다 (원칙 8).
  집계 술어는 **주 조건을 포함한다** (ADR-012 §1). 통화만 개수에서 초로 바뀌었고
  술어는 그대로다 (ADR-030 §5):

  ```
  항목 측정 시간(초) = sum(s.duration_sec)
                       FROM sessions s JOIN tasks t ON s.task_id = t.id
                      WHERE t.week_item_id = <항목>
                        AND s.kind = 'focus'
                        AND s.local_week = <그 항목의 week>
  ```

  **초로 파생해 초로 계약에 싣는다** — 분으로 접는 것은 표시 직전 한 번뿐이다
  (ADR-031 §2). 표기 형식은 [ux-spec §0](./ux-spec.md) 소관이다.

  `sessions.local_week` 는 기록 시 1회 계산 후 불변이므로(ADR-009 §2, ADR-011 §3)
  **모든 focus 세션의 시간은 자기 주에서 정확히 한 번 더해진다.** 항목의 주와 어긋나는
  세션(주 경계를 넘긴 집중 등)은 그 주의 미분류로 떨어진다.
  이 술어를 화면이 각자 조립하지 않고 **한 곳(도메인 함수)에서만** 계산한다 —
  조건을 빠뜨리면 조용히 틀린 숫자가 나온다 (ADR-012 Consequences, ADR-008 계층 규칙).
- **R9.** ~~항목 est 와 자식 task est 합은 독립적인 값이다 (Q13). 남은 몫은
  `max(0, est − 소진)` 으로 0 에서 클램프한다.~~ — **폐기** (ADR-030 §1, ADR-031 §1).
  두 값이 사라졌으므로 어긋남도, 그 어긋남을 표시할지 말지의 판단(Q13-B)도, 남은 몫도
  함께 죽었다. 정산의 처분은 2택이 되어 "줄일 대상"이 없다.

- **R10.** 일반 뷰 항목 목록의 정렬은 **생성순(오래된 것부터)** 이고, 유일한 예외는
  "오늘 배정된 항목을 상단으로"(R7)다. 사용자가 순서를 직접 정하는 **항목 우선순위는
  v1 비목표**다 — 정렬 기준을 저장하는 컬럼을 만들지 않는다.
- **R11.** 이월된 항목에는 "N주째" 배지를 표시한다. N = `(week − origin_week)/7 + 1` 로
  계산하며(ADR-011 §4), `carry_from_id` 사슬 길이는 배지 값으로 쓰지 않는다 —
  건너뛴 주에서 값이 틀어진다. N = 1 일 때는 배지를 표시하지 않는다.
  - `origin_week` 는 항목이 **최초 생성된 주**를 박제한 값이며, **이월로 만들어진 새
    항목은 원본의 `origin_week` 를 승계한다(새 주로 재계산하지 않는다).** 승계하지
    않으면 이월 항목의 `origin_week` 가 매주 자신의 주와 같아져 배지가 영원히 1 이 되고,
    "3주째" 가 표시될 수 없다.
  - 이월은 `milestone_id` 도 함께 승계한다 (ADR-012 §3) — 승계하지 않으면 여러 주에
    걸친 결과물의 월간 진척이 주 경계마다 0 으로 초기화된다.

### 자식 task 와 pull

- **R12.** 항목 드로어에서 자식 task 목록을 보고, 새 task 를 **제목으로** 생성하고,
  기존 task 를 다중 선택해 오늘 목록으로 가져올 수 있다. 조각에도 계획 숫자를 매기지
  않는다 — 할당과 같은 이유다 (R6). **첫 pull 은 생성이고 이후
  pull 은 선택**이다 — 자식 task 가 0개인 항목의 드로어는 목록 대신 새 task 입력만
  보이며, 그 항목을 처음 오늘로 가져오는 행위가 곧 첫 조각을 만드는 행위다.
  task 목록은 계획서가 아니라 그 항목으로 무엇을 해왔는지의 누적 기록이다.
- **R13.** **pull 대상에 주 제한이 없다** (ADR-012 §2). 다음 주 항목의 task 도 오늘
  목록으로 가져올 수 있고, 지난 주 항목의 미완료 조각도 재개할 수 있다. 드로어의
  `오늘로 가져오기` 버튼은 그 항목이 어느 주에 속하든 활성이다 — 비활성 사유는 항목이
  완료 상태인 경우뿐이다 (R26).
  - 다만 `task_pulls.pull_date` 에는 **오늘 날짜만** 기록한다. 미래 날짜 pull("내일 몫
    미리 담기")은 별개 결정이며 v1 비범위다.
  - 이 제한 해제가 집계를 깨지 않는 근거는 R8 의 주 조건이다 — 세션은 자기
    `local_week` 에서만 세어지므로, 다른 주 항목으로 한 집중은 그 주의 미분류로
    떨어지고 등식은 유지된다.
- **R14.** pull 은 `task_pulls(task_id, pull_date)` 행으로 기록되며, 오늘 목록에서
  빼도 그 날짜의 pull 이력은 남는다 (ADR-011 §2). 오늘 목록에서 빼는 것은 삭제가 아니다.

### 시스템 "기타" 항목과 미분류

- **R15.** 부모 주간 항목이 없는 task(오늘 목록에 직접 추가한 것, 사후 캡처로 소급
  생성된 것)는 시스템 "기타" 항목(`is_system = 1`)에 귀속된다 (Q7).
  - 어느 주의 기타 항목에 붙는지는 **그 세션의 `local_week` 기준**이다 — "오늘"이 속한
    주가 아니다 (ADR-012 §3). 자정을 걸친 세션에 사후 캡처로 조각을 붙일 때 두 값이
    다르다.
  - 이 항목은 실제로 필요해질 때만 생성한다(lazy) — 사용하지 않는 주에는 존재하지 않는다.
- **R16.** 기타 항목의 규칙: 플래너 초안 목록에 나타나지 않으며 편집·삭제할 수 없고,
  주간 정산의 처분 2택 대상에서 제외된다. ~~est 는 0 이며 과적 경고와 요일별 부하
  계산에 산입하지 않는다~~ — **폐기**: 산입할 계산 자체가 없어졌다 (ADR-030 §3).
- **R17.** 주간 카드에서는 기타 항목과 미분류 집중(task 에 연결되지 않은 focus 세션)을
  **한 행으로 통합**해 표시한다 (Q11). 행 이름은 "기타 — 계획에 없던 집중" 이다.
  - **그 행의 측정 시간은 독립 계산하지 않고 차액으로 정의한다**
    (정의역은 [ADR-027](../../architecture/decisions/adr-027-other-row-domain.md) §1,
    통화 교체는 [ADR-031](../../architecture/decisions/adr-031-settlement-without-est.md) §2):

    ```
    기타 행 측정 시간(초) = 주 총 focus 초 − Σ(목록에 표시되는 항목의 focus 초)
    ```

    `Σ` 의 정의역은 **그 주에 화면 목록으로 표시되는 항목** —
    `is_system = 0 AND dropped_at IS NULL AND deleted_at IS NULL` — 이고, 각 항목의
    시간은 R8 의 술어로 계산한다. 이 정의로 ① 시스템 항목이 `Σ` 에 다시 더해지는 이중
    계상과 ② 목록에 표시되지 않는 폐기 항목(R18)의 시간 누락이 동시에 닫힌다.
    **폐기 항목을 `Σ` 에 포함하면 A24 가 깨진다** — 그 시간이 차액에서 상쇄되어 기타
    행에 나타나지 않는다. **뺄셈은 초 단계에서** 한다.
  - **주 총 focus 초는 그 주 완료 focus 세션 전체의 합이다.** 항목의 폐기·삭제가 이
    값을 줄이지 않는다 (ADR-027 §2). 같은 세션이 캘린더 점·타이머 기록에도 나타나므로,
    항목을 지웠다고 이 숫자가 줄면 세 화면이 서로 다른 사실을 말하게 된다.
  - **표시 조건 (세 갈래 중 하나라도 참이면 표시):**
    ① 그 주에 미분류 focus 세션이 있다 · ② 부모 없는 조각이 있다 ·
    ③ **목록에 보이는 항목으로 설명되지 않는 focus 세션이 그 주에 하나라도 있다.**
    ①②는 **값이 0 이어도** 행을 띄우기 위한 것이다 — 그렇지 않으면 사용자가 직접 만든
    조각이 주간 카드 어디에도 나타나지 않는다. ③은 **폐기·삭제로 흘러든 집중**을 잡는다
    (ADR-027 §3) — ①②만 보면 폐기 항목의 집중만 있는 주에서 행이 숨겨져 A24 가 깨진다.
    세 갈래가 모두 거짓인 주에는 행이 없다.
  - **③ 은 크기가 아니라 존재로 판정한다** (결정 2026-08-13). 개수 통화 시절 이 갈래는
    `기타 행 소진 > 0` 이었고, 통화를 옮기며 `차액 > 0` 으로 읽는 안이 먼저 있었다.
    그러나 `duration_sec = 0` 인 세션 — 타이머를 시작한 직후 `완료 처리` 로 만들어지는
    **정상 경로**다 — 만 붙은 항목을 폐기하면 차액이 정확히 0 초가 되어 행이 사라진다.
    집중은 실재했는데(캘린더 점도 그 세션을 센다) 주간 카드에서만 증발하므로 A24 가
    깨진다. 그래서 술어를 "설명되지 않는 세션이 **있는가**"라는 존재 판정으로 바꿨고,
    차액은 그 행이 뜬 뒤에 **보여줄 값**으로만 쓴다.
    - 존재 판정의 정의역은 `Σ` 와 **같아야 한다.** 갈리면 차액이 0 이 아닌데 행이 숨거나
      그 반대가 된다. 정의역이 옳으면 차액은 음수가 될 수 없고, 그럼에도 `차액 ≠ 0` 을
      표시 조건에 함께 두는 것은 술어 버그를 조용하게 만들지 않기 위해서다
      ([ux-spec §3.4](./ux-spec.md) — 음수를 감추지 않는다).
  - 그 행의 드릴다운에서 이름이 있는 것(소급 생성·직접 추가된 task)과 이름이 없는 것
    (미분류 세션)을 구분해 보여준다.
- **R18.** `dropped_at` 이 있는 항목은 일반 뷰 목록에 표시하지 않는다. 그 항목에 붙어
  있던 집중 시간은 **R17 의 차액 정의에 따라 기타 행에 흡수되어 계속 보인다** — 폐기가
  주 총합을 줄이지 않으므로 사용자는 그 1시간 15분의 행방을 기타 행에서 추적할 수 있다.
  폐기는 삭제가 아니다: 이력에 남고 정산 요약에 집계된다 (ADR-014 §1).

### 재수정과 초안 제거

- **R23.** 주중 재수정을 허용한다 (편집 대상 주를 `이번 주` 로 선택 — R3). 플래너 확정
  시 기존 항목은 **ID 기준으로 매칭**해 자식 task 이력과 `carry_from_id`·`origin_week`·
  `milestone_id` 를 유지한다 (제목 기준 매칭 금지 — 제목을 고치면 이력이 끊긴다).
  - ~~확정 시각을 `weeks.planned_at` 에 기록하고 재수정으로 갱신하지 않는다.~~ —
    **폐기** (ADR-030 §4). `weeks` 테이블이 제거되면서 이 이력이 함께 사라진다. 어떤
    화면도 읽지 않던 값이라 구제하지 않는다. **재수정 자체는 요구로 남는다** — 위 문단의
    ID 기준 매칭이 그것이다.
- **R24.** 플래너 초안에서 행을 제거(`×`)할 때 결과는 **그 행이 기존 항목인지 신규
  초안인지에 따라 다르다.**
  - **기존 항목**(수정 진입 시 프리필된 행): 확정하면 **삭제가 아니라 `dropped_at`
    기록(폐기)** 이다. 자식 task 와 그에 붙은 세션은 **전부 보존**된다. 그 시간은 R18 에
    따라 기타 행에 흡수되어 계속 보인다. 세션 9개가 달린 항목을 × 해도 그 3시간 45분은
    사라지지 않는다.
  - **신규 초안 행**(이 플래너 세션에서 추가했고 아직 확정되지 않은 행): 아무 데이터도
    만들지 않았으므로 제거는 **무해한 취소**다.
  - `deleted_at` 을 쓰는 진짜 삭제는 이 화면의 조작이 아니다 — 폐기와 삭제의 구분은
    [ADR-014](../../architecture/decisions/adr-014-deletion-and-archive.md) §1 을 따른다.

### 완료와 폐기

- **R25.** ~~소진 ≥ est 는 완료가 아니다.~~ — 비교할 est 가 사라져 이 문장은 **폐기**
  됐지만, 그것이 지키려던 성질은 그대로다: **시간이 얼마나 쌓였는지로 완료를 제안하지
  않는다.** 시간을 쓴 것과 일이 끝난 것은 다르다. 항목 완료는 **자동 제안 + 수동 확정**이다
  (Q14) — 자식 task 가 전부 완료되면 완료를 제안하되, 완료의 사실을 만드는 것은 항상
  사용자 클릭이다. 자식 task 가 하나도 없는 항목도 수동으로 완료할 수 있다.
- **R26.** 완료는 `completed_at`, 폐기는 `dropped_at` 에 시각으로 기록한다. 둘 다 NULL
  이면 active 다 (ADR-011 §5). boolean 상태값을 쓰지 않는다.
- **R27.** 완료된 항목의 드로어는 열람 가능하되 **pull 만 차단**한다. 완료를 해제하면
  (`completed_at` 을 NULL 로) 다시 pull 할 수 있다.
- **R28.** **완료 확정은 시간 집계를 멈추지 않는다.** 완료 후에 그 항목의 자식 task 에
  세션이 더 붙으면(오늘 목록에 이미 있던 조각으로 계속 집중한 경우 등) 그 세션도 R8 의
  술어에 따라 항목 측정 시간과 주 총합에 반영된다.
  - ~~초과 표시(`+N`)~~ — **폐기.** 넘길 대상이 없다. 측정 시간이 계속 자라는 것을
    사실로 보여주는 것까지가 전부다.
  - **완료 제안은 재발생시키지 않는다.** 이미 `completed_at` 이 있는 항목에 완료를 다시
    제안하지 않으며, 세션이 추가돼도 `completed_at` 을 갱신하거나 NULL 로 되돌리지 않는다.

## 성공 지표

- **닫히는 등식:** 임의의 주에 대해

  ```
  헤더의 주 측정 시간 합(초) == Σ(is_system = 0 인 항목의 측정 시간) + 기타 행(초)
  ```

  이 **초 단계에서** 성립한다. 기타 행이 이 등식의 차액으로 **정의**되므로(R17), 이
  등식은 검증 대상이 아니라 정의다. 실제 검증 대상은 두 가지다: ① R8 의 주 조건이 모든
  항목 시간 계산 경로에 들어 있는지(= 도메인 함수 한 곳만 쓰는지) ② 반올림이 표시 직전
  한 번뿐인지. 화면에 **표시된 분**끼리는 각자 내림한 결과라 ±1분이 어긋날 수 있으며,
  그것은 결함이 아니라 통화 전환의 명시된 대가다 ([ux-spec §0.2](./ux-spec.md)).
- 계획 데이터가 0인 주에도 타이머·세션 기록이 정상 동작하고, 주간 카드는 빈 상태
  카피만 보여준다 (원칙 1).
- **플래너에 확정을 막는 경로가 0개다.** 항목이 0개든 20개든 확정은 성공한다 — 과적
  경고를 무시하고 확정하는 시나리오 자체가 사라졌으므로, 지표는 "무시해도 성공한다"가
  아니라 "막는 코드가 없다"로 바뀐다.
- **할당 하나를 추가하는 데 필요한 숫자 입력이 0회다.** 제목을 적고 `항목 추가` 를 누르면
  끝난다 (요일 배치·마일스톤 연결은 선택). 개수 시절의 "예산 프리필을 그대로 쓰면 예산
  입력 0회" 지표를 이 문장이 대체한다 — 프리필할 숫자 자체가 없어졌다.
- 일요일에 주간 카드의 `수정` 을 눌러 **이번 주 항목을 고칠 수 있다** (R3 — 계획일에도
  주중 재수정이 무효가 되지 않는다).
