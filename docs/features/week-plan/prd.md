# PRD: week-plan

> 출처: docs/origin/pomodoro-prd.md §3.3 (초안) + [결정 원장](../../decision-log/2026-08-04-planning-session.md) §C (Q7·Q10~Q14), §A (Q8-1·Q9·plan_lead_days)
> 초안과 이 문서가 다르면 이 문서가 이긴다. 특히 초안의 "일요일 시작 주 / ISO week 문자열 주 키"는 [ADR-010](../../architecture/decisions/adr-010-week-definition.md) 으로 폐기됐다.

## 문제

월간 마일스톤은 "이번 달이 끝나면 뭐가 달라져 있나"라는 상태 기술이고, 오늘 목록은
"지금 뭐 하나"라는 실행이다. 그 사이에 **숫자로 답하는 층**이 없으면 두 가지가 무너진다.

1. 마일스톤이 실행 가능한 크기로 쪼개지지 않아, 오늘 목록에 매일 새 계획을 즉흥으로
   짜게 된다 (원칙 2 위반 — 일 레이어는 pull 만 해야 한다).
2. 소진량을 비교할 기준(예산·est)이 없어, 세션 기록이 "얼마나 했다"는 사실만 남기고
   "계획 대비 어땠다"는 정보를 주지 못한다.

주 레이어는 이 두 구멍을 하나의 카드로 메운다. 동시에, 이 카드는 **계획이 0개여도
타이머가 완전히 동작해야 한다는 원칙 1을 깨지 않아야** 한다 — 있으면 풍부해지는
레이어여야 하고, 없으면 막히는 것이 없어야 한다.

## 대상 사용자

- 앱 소유자 1인 (로컬 단독, 로그인·멀티유저 없음)

## 목표

1. 주간 항목 하나가 "이번 주 이만큼"을 est 뽀모 수로 표현하고, 그 소진이 세션에서
   자동으로 파생돼 별도 입력 없이 갱신된다.
2. 오늘 목록의 모든 항목이 주간 항목에서 pull 된 것이거나 시스템 "기타" 항목에
   귀속돼, 주간 게이지와 항목별 합이 구조적으로 항상 일치한다 (Q10·Q11).
3. 계획 시점의 과적을 알리되 확정을 막지 않는다 — 예산은 추정치이고 초과는 실패가
   아니다 (원칙 3).
4. "시간을 다 쓴 것"과 "일이 끝난 것"을 구분한다 — 소진 ≥ est 는 완료가 아니다 (Q14).

## 범위 / 비범위

**범위:** 주 정의(월요일 시작·주 키)의 적용, 주간 카드 일반 뷰의 항목 목록, 주간
플래너(항목 추가·est·마일스톤 연결·요일 배치·과적 경고·확정), 항목 드로어(자식 task
목록·생성·오늘로 가져오기), 항목 완료 제안·확정·폐기, 주차별 시스템 "기타" 항목,
주간 뽀모 예산 게이지(주별 오버라이드 포함), 이월 배지 표시.

**비범위:**

- 오늘 목록 자체의 관리(표시·체크·× 제거·자정 반납) → today-tasks. 이 문서는 "주간
  항목에서 오늘로 pull 한다"까지만 정의한다.
- 이월 3택(다음 주로 / 줄여서 / 보내주기)과 정산 판정·병합 → weekly-review. 이 문서는
  이월된 항목을 **표시**하는 규칙(배지)만 정의한다.
- `weekly_capacity` 정의 UI, 뽀모 길이(focus/short/long) 변경, 베이스라인 스냅샷의
  생성·관리 → pomo-baseline. 이 문서는 그 값을 예산 기본값과 요일 부하 기준선으로
  **소비**하는 쪽이다.
- 마일스톤 자체의 생성·편집·월 이동 → milestones. 이 문서는 마일스톤 칩으로 연결하는
  것까지만.
- 3컬럼/탭 레이아웃, 카드가 어느 컬럼에 앉는지, 창 크기 하한 → app-shell.
- 스키마 DDL·쿼리·마이그레이션 → [ADR-011](../../architecture/decisions/adr-011-schema-final.md).
- task 단위 요일 배정 (요일 배치는 항목 단위뿐 — ADR-011 §8 에서 명시적 보류).
- 월 누적 소진 롤업 (v1.1 — Q15).

## 요구사항

### 주의 정의

- **R1.** 주는 **월요일에 시작**하고, 주 키는 그 주 월요일 날짜 `'YYYY-MM-DD'` 다
  (ADR-010 §1·§2). 요일을 다루는 모든 UI(요일 핍, 요일 칩, 요일 부하 그래프)는
  월요일부터 일요일 순으로 배열한다. `weekly_capacity` 배열 인덱스 0 = 월요일이다.
- **R2.** `W32` 같은 주 번호 라벨은 저장하지 않고 표시 시점에 계산한다 (렌더 전용).
  카드 헤더의 주 범위 표기도 주 키에서 파생한다.
- **R3.** 사용자가 **지금 계획하는 대상 주** = `week_of(오늘 + plan_lead_days)` 이고
  `plan_lead_days` 기본값은 1이다 — 즉 일요일에는 다음 주를 계획한다 (ADR-010 §3).
  v1 에서 이 값의 설정 UI 는 노출하지 않는다.
- **R4.** 일반 뷰가 보여주는 주는 **오늘이 속한 주**다. 계획 대상 주와 오늘이 속한
  주가 다를 수 있으며(일요일), 그때 플래너는 다음 주를 편집하고 일반 뷰는 이번 주를
  계속 보여준다.

### 주간 항목

- **R5.** 주간 항목은 제목, est 뽀모 수(정수 ≥ 1), 마일스톤 연결(선택 — 미연결 시
  "기타" 칩), 요일 배치 의도(선택 — 다중 선택, 미선택 = 미배치)를 갖는다.
- **R6.** 요일 배치는 **예약이 아니라 배치 의도**다. 배정된 요일이 되어도 항목이
  오늘 목록에 자동으로 들어가지 않는다. 오늘 배정된 항목은 목록 상단으로 정렬하고
  시각적으로 강조하는 것까지만 한다.
- **R7.** 항목의 소진 뽀모는 **자식 task 들의 소진 합**으로 항상 파생하며 저장하지
  않는다 (원칙 8). task 소진은 그 task 에 연결된 focus 세션 수다.
- **R8.** 항목의 est 와 자식 task 들의 est 합은 **독립적인 값**이다 (Q13). 항목 est 는
  "이번 주 이만큼", task est 는 "이 조각 이만큼"이라는 서로 다른 질문에 답한다.
  주간 리뷰의 "남은 몫" 계산 기준은 항목 est 다. 두 값이 어긋나도 오류가 아니다.

  > ⚠️ 가정: 드로어에서 "항목 est vs task est 합"의 어긋남을 사실로 표시할지는 **미결**
  > 이다 (Q13-B). 표시하면 정보가 되지만, 판단하지 않는다는 원칙 6 을 지키기 어려워질
  > 수 있다. v1 구현 시 재판단하며, 그때까지 이 문서는 어느 쪽도 요구하지 않는다.

- **R9.** 이월된 항목에는 "N주째" 배지를 표시한다. N = `(week − origin_week)/7 + 1` 로
  계산하며(ADR-011 §4), `origin_week` 는 항목이 최초 생성된 주를 박제한 값이다.
  `carry_from_id` 사슬 길이는 배지 값으로 쓰지 않는다 — 건너뛴 주에서 값이 틀어진다.
  N = 1(최초 생성 주)일 때는 배지를 표시하지 않는다.

### 자식 task 와 pull

- **R10.** 항목 드로어에서 자식 task 목록을 보고, 새 task 를 제목 + est 로 생성하고,
  기존 task 를 다중 선택해 오늘 목록으로 가져올 수 있다. **첫 pull 은 생성이고 이후
  pull 은 선택**이다 — task 목록은 계획서가 아니라 그 항목으로 무엇을 해왔는지의
  누적 기록이다.
- **R11.** 오늘 목록으로의 pull 은 **오늘이 속한 주의 항목**에서만 가능하다 (Q10).
  일요일에 다음 주를 계획한 직후에도 다음 주 항목은 pull 대상이 아니다. 이 제한으로
  날짜 기준 집계(주간 총 소진)와 관계 기준 집계(항목별 소진)가 구조적으로 일치해,
  게이지 = 항목 합 + 기타가 항상 닫힌다. 대가("내일 계획을 오늘 밤 미리 시작")는 수용한다.
- **R12.** pull 은 `task_pulls(task_id, pull_date)` 행으로 기록되며, 오늘 목록에서
  빼도 그 날짜의 pull 이력은 남는다 (ADR-011 §2). 오늘 목록에서 빼는 것은 삭제가 아니다.

### 시스템 "기타" 항목과 미분류

- **R13.** 부모 주간 항목이 없는 task(오늘 목록에 직접 추가한 것, 사후 캡처로 소급
  생성된 것)는 그 주의 시스템 "기타" 항목(`is_system = 1`)에 귀속된다 (Q7).
  이 항목은 실제로 필요해질 때만 생성한다(lazy) — 사용하지 않는 주에는 존재하지 않는다.
- **R14.** 기타 항목의 규칙: est 는 0 이며 **과적 경고와 요일별 부하 계산에 산입하지
  않는다**. 플래너에서 편집·삭제할 수 없다. 주간 리뷰의 이월 3택 대상에서 제외된다.
- **R15.** 주간 카드에서는 기타 항목과 미분류 집중(task 에 연결되지 않은 focus 세션)을
  **한 행으로 통합**해 표시한다 (Q11). 행 이름은 "기타 — 계획에 없던 집중" 이다.
  그 행의 드릴다운에서 이름이 있는 것(소급 생성된 task)과 이름이 없는 것(미분류 세션)을
  구분해 보여준다.

### 예산과 과적

- **R16.** 주간 예산의 기본값은 `weekly_capacity` 의 합이다. 주별 오버라이드는
  `weeks.budget` 에 저장하고, NULL 이면 기본값을 쓴다 (ADR-011 §1).
- **R17.** 주간 게이지는 `소진 / 예산` 을 표시한다. 소진은 그 주의 focus 세션 수
  전체(기타·미분류 포함)다. 예산이 없으면(capacity 미설정, 오버라이드 없음) 바를 숨기고
  소진량만 표시한다.
- **R18.** 예산 **초과 시 빨간색·경고 아이콘·경고 문구를 쓰지 않는다** (원칙 3,
  principles §1·§2). 초과는 `--amber` 글로우 + `+N` 배지로 긍정 처리한다.
- **R19.** (계획 시점 검증 2종 — 둘 다 경고만, **확정 차단 금지**)
  1. **총량 과적:** 항목 est 합 > 예산이면 초과분을 알린다.
  2. **요일별 부하:** 각 항목의 est 를 배정 요일 수로 균등 분산해 요일별 합을 내고,
     그 요일의 `weekly_capacity` 값과 비교한다. 미배치 항목과 기타 항목은 부하에
     산입하지 않는다.
- **R20.** 주중 재수정을 허용한다. 플래너 확정 시 기존 항목은 **ID 기준으로 매칭**해
  자식 task 이력과 `carry_from_id`·`origin_week` 를 유지한다 (제목 기준 매칭 금지 —
  제목을 고치면 이력이 끊긴다).

### 완료와 폐기

- **R21.** 소진 ≥ est 는 완료가 아니다. 항목 완료는 **자동 제안 + 수동 확정**이다
  (Q14) — 자식 task 가 전부 완료되면 완료를 제안하되, 완료의 사실을 만드는 것은 항상
  사용자 클릭이다. 자식 task 가 하나도 없는 항목도 수동으로 완료할 수 있다.
- **R22.** 완료는 `completed_at`, 폐기는 `dropped_at` 에 시각으로 기록한다. 둘 다 NULL
  이면 active 다 (ADR-011 §5). boolean 상태값을 쓰지 않는다.
- **R23.** 완료된 항목의 드로어는 열람 가능하되 **pull 만 차단**한다. 완료를 해제하면
  (`completed_at` 을 NULL 로) 다시 pull 할 수 있다.

## 성공 지표

- **닫히는 게이지:** 임의의 주에 대해 `주간 게이지 소진 == Σ(항목별 소진) + 기타 행 소진`
  이 항상 성립한다 (R7·R11·R15 의 통합 검증).
- 계획 데이터가 0인 주에도 타이머·세션 기록이 정상 동작하고, 주간 카드는 빈 상태
  카피만 보여준다 (원칙 1).
- 과적 경고를 무시한 확정이 100% 성공한다 (R19 — 차단 0건).
- 주간 계획 소요 클릭 수는 지표로 삼지 않되, 예산 기본값을 그대로 쓰는 경로에서
  예산 관련 입력이 0회여야 한다 (§3.3 초안의 "기본값 유지 시 클릭 0" 승계).
