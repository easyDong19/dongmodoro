# UX Spec: week-plan

> 출처: docs/origin/pomodoro-mockup-v7.html 주간 카드·플래너(초안, 요일 UI 는 폐기) + [결정 원장](../../decision-log/2026-08-04-planning-session.md) Q7·Q10~Q14 + [리뷰 결정](../../decision-log/2026-08-04-review-decisions.md) D1·D3
> 시각 값은 전부 [tokens.md](../../design-system/tokens.md) 토큰 이름으로 기술한다. 시각 판단이 [principles.md](../../design-system/principles.md) 와 충돌하면 그쪽이 이긴다.
> **시안의 일요일 시작 요일 UI 는 이 문서에서 전부 월요일 시작으로 뒤집혀 있다** ([ADR-010](../../architecture/decisions/adr-010-week-definition.md) §1).
> pull 의 주 제한과 그에 딸린 "다음 주 항목 선택 불가" 상태는 [ADR-012](../../architecture/decisions/adr-012-aggregation-predicate.md) §2 로 폐기됐다 — 이 문서에 그 상태가 없다.

## 1. 카드의 3개 모드

주간 카드는 같은 자리에서 배타적인 3개 모드 중 하나를 렌더한다.

| 모드 | 진입 | 헤더 제목 | 예산 게이지 |
|---|---|---|---|
| **일반 뷰** (§3) | 기본 | `이번 주 할당` (일반 뷰는 항상 오늘이 속한 주 — PRD R4) | 표시 |
| **플래너** (§5) | 빈 상태 CTA / `수정` | **편집 대상 주 선택에서 파생** — `이번 주 계획` / `다음 주 계획` (§5.0) | 숨김 (플래너 내부에 계획 합계 바가 따로 있음) |
| **정산 패널** | 정산 배너의 `정산 시작` | — | 숨김 |

- **라벨 파생 규칙 (PRD R5).** 플래너의 헤더 제목·확정 버튼 라벨과 일반 뷰 빈 상태의
  CTA 라벨은 **모두 §5.0 의 편집 대상 주 선택 상태 하나에서만 파생한다.** 오늘이 무슨
  요일인지에서 직접 파생하지 않는다 — 그렇게 하면 일요일에 `이번 주 할당 잡기` 를 눌러
  다음 주가 열리는 모순이 생긴다.

| 편집 대상 주 선택 | 플래너 헤더 | 확정 버튼 | 빈 상태 CTA |
|---|---|---|---|
| `이번 주` | `이번 주 계획` | `이번 주 시작` | `+ 이번 주 할당 잡기` |
| `다음 주` | `다음 주 계획` | `다음 주 시작` | `+ 다음 주 할당 잡기` |

- 정산 패널의 내용·상태·문구는 **weekly-review ux-spec 소관**이다. 이 문서는 "그 모드가
  이 카드 자리를 점유한다"는 사실과, 배너가 일반 뷰 상단에 얹힌다는 것만 정의한다.
- 정산 배너는 무시 가능하다 — 배너가 떠 있어도 일반 뷰의 목록·드로어·pull·게이지가
  모두 정상 동작한다 (원칙 5).

## 2. 카드 골격 (위→아래)

| 요소 | 내용 |
|---|---|
| eyebrow + 제목 | `WEEK` (`--text-2xs`, `--tracking-wider`, `--ink-dim`) + 모드별 제목 (`--text-lg`) |
| 주 범위 | 헤더 우측 보조 텍스트 — `8/3 – 8/9` 형식, 주 키에서 파생 (PRD R2). `--text-xs` / `--ink-dim`. 플래너에서는 **편집 대상 주**의 범위를 보여준다 |
| 정산 배너 | 대기 중일 때만. `--amber` 톤 (weekly-review 소관) |
| 항목 목록 | 스크롤 영역. 카드 = flex column, 목록만 `flex: 1; min-height: 0; overflow-y: auto` |
| 예산 게이지 | 카드 하단 고정 (`flex-shrink: 0`) — §7 |

- 주 이동 화살표·"지난 주 보기" 컨트롤은 **없다** (PRD 비범위). 일반 뷰는 항상 오늘이
  속한 주이며, 다른 주로 가는 통로는 플래너의 편집 대상 주 선택(§5.0)뿐이다.

> 저장하지 않는다 (PRD R2).

## 3. 일반 뷰 — 항목 행

### 3.1 행 구성

```
[▸] 제목                        [M2]  [3주째]        [+ 오늘로]
    (뽀모 도트 소진/est)  · 조각 2/4   (월 화 수 목 금 토 일)
```

| 요소 | 규칙 |
|---|---|
| 캐럿 | 드로어 열림/닫힘. lucide `ChevronRight` (열리면 `ChevronDown`) — 드로어(다중 선택·새 조각·완료 처리)로 가는 경로는 캐럿이다 |
| 제목 | `--text-sm` / `--ink`. 1줄 말줄임 |
| 마일스톤 태그 | 연결된 마일스톤의 `M<n>` 배지. `--radius-sm` / `--text-2xs` / `--ink-dim`. 미연결이면 표시하지 않는다 (플래너의 `마일스톤 없음` 칩은 선택 UI 일 뿐, 행에 배지로 남기지 않는다) |
| 이월 배지 | `N주째` (N ≥ 2일 때만). `--amber` 텍스트 + `--radius-sm`. 판단 문구를 붙이지 않는다 (principles §1) — 3주째든 5주째든 색·문구가 같다 |
| pull 버튼 | `+ 오늘로` — **원클릭 pull 이다** (2026-08-05 shape, 라벨이 약속한 대로). 클릭 = **다음 유자격 조각 1개를 바로 오늘로 pull.** 유자격 = 미완료 · 미삭제 · 오늘 pull 행 없음(치운 조각은 재선택 가능 — today-tasks R14), 순서는 생성순. **유자격 조각이 0개면**(조각이 아예 없거나 전부 오늘 목록/완료) **드로어가 열린다** — 첫 조각 작성 플로우(§6.4)가 그 안에 있다. pull 성공 시 토스트 `오늘로 가져왔어요 — <조각 제목>` (제목이 변수라 조사(을/를)를 붙이지 않는 형태다) (`--layer-toast`, 정산 확정 토스트와 같은 패턴) — 내로우에서 오늘 목록이 안 보이는 문제를 이 한 줄이 닫는다. 상태별 처리는 §3.3 |
| 뽀모 표시 | **뽀모 도트 컴포넌트** — 채움 = 소진, 미채움 = 남은 est. 초과분은 `--amber` extra 도트 + `+N` 배지 (lucide `Flame` 동반). 숫자 병기 `소진/est` 는 `--font-mono` + tabular-nums |
| task 카운트 | `· 조각 <완료>/<전체>`. `--text-xs` / `--ink-dim`. 자식 task 0개면 이 표기를 숨긴다 |
| 요일 핍 | §3.2 |

- 목록 정렬은 **생성순**이고, 오늘 배정된 항목만 상단으로 올린다 (PRD R7·R10).
  사용자가 순서를 바꾸는 UI 는 없다.

### 3.2 요일 핍 — 월요일 시작

7개 핍을 **월 화 수 목 금 토 일** 순으로 배열한다 (ADR-010 §1). 배열 인덱스 0 = 월요일.

**색과 모양 두 채널로 구분한다** — 색만으로 구분하지 않는다
([principles §3.5](../../design-system/principles.md),
[ADR-006 §3](../../design-system/decisions/adr-006-theme-scope.md)).

| 핍 상태 | 조건 | 색 | 모양 (제2 신호) |
|---|---|---|---|
| 미배정 | 그 요일이 배치 의도에 없음 | `--ink-faint` | solid (가장 작다) |
| 배정 · 지난 요일 | 배정됨 & 그 요일 < 오늘 | `--teal` | **윤곽선만** (속을 비운다) |
| 배정 · 오늘 | 배정됨 & 그 요일 = 오늘 | `--amber` + 글로우 | **바깥 링 1겹** (지름이 커진다) |
| 배정 · 다가올 요일 | 배정됨 & 그 요일 > 오늘 | `--teal` | solid 채움 |

- **"지난 요일"을 불투명도로 표현하지 않는다.** 불투명도는 고대비 모드에서 사라지고
  색각 이상에서도 teal 두 상태(지난/다가올)를 구분하지 못한다. 속을 비우는 것이 그 역할을
  대신한다 (ADR-006 §3).
- "지난 요일"은 **놓쳤다는 표시가 아니다.** 실패 문구·`--danger` 를 붙이지 않는다
  (principles §1·§2). 지나간 요일이라는 사실만 시각적으로 낮춘다.

> ⚠️ 가정: 5px 지름 핍 7개에서 solid / 윤곽선 / 링 3형태가 실제로 구분되는지는 구현 후
> 확인이 필요하다. 안 읽히면 핍 지름을 키우는 것이 다음 수단이다 (ADR-006 Consequences).
- 일요일 핍에 별도 색(시안의 `.sun` 처리)을 주지 않는다 — 주의 마지막 칸일 뿐이다.

### 3.3 행 상태

| 상태 | 조건 | 표시 |
|---|---|---|
| 기본 | active | §3.1 그대로 |
| 오늘 배정 | 배치 의도에 오늘 포함 | 테두리 강조(`--glass-border` → 강조 톤) + **목록 상단 정렬**. 자동 pull 없음 (PRD R7) |
| 완료 제안 | 자식 task 전부 완료 & 미완료 항목 | 행 우측에 `완료로 표시` 버튼 노출. 클릭 전까지 행은 active 그대로 (§4) |
| 완료 | `completed_at` 있음 | 제목 취소선 + `--ink-dim`. 캐럿은 남고 pull 버튼은 `완료됨` 비활성 라벨로 대체. `완료 해제` 액션 제공 |
| 완료 + 추가 소진 | `completed_at` 있음 & 소진 > est | 위와 같고, 뽀모 도트에 `--amber` extra 도트 + `+N` 배지를 **그대로 표시한다** (PRD R28 — 사실이므로 숨기지 않는다). 완료 제안은 다시 뜨지 않는다 |
| 폐기 | `dropped_at` 있음 | 일반 뷰 목록에 **표시하지 않는다.** 그 항목의 소진은 §3.4 기타 행 값에 흡수되어 계속 보인다 (PRD R18) |

- pull 버튼이 항목의 소속 주 때문에 비활성이 되는 상태는 **없다** (PRD R13).
  비활성 사유는 항목이 완료 상태인 경우뿐이다.

### 3.4 기타 행 (Q11)

목록 **맨 아래** 한 행. 표시 조건과 값의 정의가 다르다는 점에 주의한다.

| 항목 | 규칙 |
|---|---|
| 표시 조건 | 그 주에 미분류 focus 세션 **또는** 부모 없는 조각(소급 생성·직접 추가 task)이 하나라도 있으면 표시한다. **소진이 0 이어도 조각이 있으면 표시한다** — 그래야 사용자가 직접 만든 조각이 카드 어딘가에 존재한다 (PRD R17) |
| 숨기는 경우 | 세션도 조각도 없는 주 (기타 항목 행 자체가 없는 주) |
| 행 이름 | `기타 — 계획에 없던 집중` |
| 소진 값 | **차액으로 정의한다** — `주간 총 소진 − Σ(is_system = 0 인 항목의 소진)` (PRD R17, ADR-012 §4). 이 행의 값을 별도 쿼리로 세지 않는다 |
| 표시 요소 | 뽀모 도트 + 소진 수. **est·요일 핍·이월 배지·pull 버튼 없음** |
| 톤 | 점선 테두리(`--glass-border-soft`) + `--ink-dim`. 계획 항목과 시각적으로 구분되되 낮춰 보이게 하지 않는다 — 실제로 한 집중이다 |
| 캐럿 | 드릴다운(§6.4) 펼침 |

- **뽀모 도트의 중립 채움 변형.** 이 행은 est 가 0 이므로(PRD R16) 일반 규칙("est 초과분은
  `--amber` extra 도트")을 그대로 적용하면 **모든 도트가 초과로 렌더된다.** 기타 행은
  `neutral` 변형을 쓴다: 소진 개수만큼 도트를 `--teal` 로 채우고, 미채움 도트·extra 도트·
  `+N` 배지·lucide `Flame` 을 **모두 렌더하지 않는다.** 숫자 병기는 `<소진>` 단독이며
  `소진/0` 형태를 쓰지 않는다.
- **폐기 항목의 소진이 여기로 들어온다.** 3뽀모를 태운 항목을 보내주면 그 항목 행은
  사라지지만 주간 총 소진은 줄지 않으므로, 차액 정의에 의해 그 3뽀모가 이 행의 값으로
  옮겨 온다. 사용자가 "그 3뽀모는 어디 갔나"를 추적할 수 있는 유일한 자리다 (PRD R18).
  - 드릴다운(§6.4)은 이 소진의 출처를 **task 이름 단위로만** 보여준다 — 폐기된 부모
    항목의 제목을 되살려 보여주지는 않는다. 폐기 이력 자체는 정산 쪽 관심사다.

## 4. 완료 제안과 확정 (Q14)

```
자식 task 전부 완료  →  [완료 제안 표시]  →  사용자 클릭  →  completed_at 기록
                                    └─ 무시하면 active 유지 (제안은 사라지지 않음)
```

- 제안 문구: `할 일을 다 끝냈어요 — 이 할당도 완료할까요?` + `완료로 표시` 버튼.
  거절 버튼을 따로 두지 않는다 (무시가 곧 거절이다).
- 소진 ≥ est 만으로는 제안하지 않는다. 시간을 다 쓴 것과 일이 끝난 것은 다르다.
- 자식 task 가 0개인 항목은 제안이 뜨지 않으며, 드로어에서 수동 완료만 가능하다.
- 완료 해제: `완료 해제` → `completed_at` NULL. 확인 다이얼로그 없음 (되돌리기가 쉽다).
- **완료 뒤에 세션이 더 붙는 경우** (PRD R28): 소진 숫자와 초과 배지는 계속 갱신되지만
  **완료 제안은 다시 뜨지 않고** `completed_at` 도 변하지 않는다. "다시 열까요?" 류의
  되묻기를 하지 않는다 — 완료를 되돌리는 통로는 사용자가 직접 누르는 `완료 해제` 뿐이다.
- 폐기(`보내주기`)는 이 카드가 아니라 주간 정산의 3택에서 수행한다. 드로어에도 폐기
  액션을 두되(§6.3) `--danger` 는 hover 시에만, 문구는 `보내주기` — `버리기` 금지
  (principles §2, 원칙 7).

## 5. 플래너 모드

### 5.0 ⓞ 편집 대상 주 선택 (PRD R3)

플래너 최상단, 예산 입력보다 위에 놓는다. **이 화면이 어느 주를 고치는지 항상 보이는
것이 이 컨트롤의 목적이다.**

| 항목 | 규칙 |
|---|---|
| 형태 | 2개 세그먼트 토글 — `이번 주` · `다음 주`. 선택된 세그먼트는 `--glass-strong` + `--teal` 텍스트 |
| 부제 | 선택된 주의 범위를 사실로 병기 (`8/3 – 8/9`), `--text-xs` / `--ink-dim` |
| 기본 선택 | `week_of(오늘 + plan_lead_days)` — 일요일이면 `다음 주`, 평일이면 `이번 주` (PRD R3) |
| 전환 효과 | 초안 목록·예산 입력·총량 바·요일 부하가 **그 주의 값으로 전부 다시 채워진다** |
| 미저장 변경이 있을 때 | 전환 전 확인 1회: `고치던 내용이 있어요 — 저장하지 않고 다른 주로 갈까요?` (`--danger` 금지, 파괴적 톤 금지) |
| 세 번째 값 | 없다. 지난 주·2주 뒤를 고르는 값은 v1 에 없다 (PRD 비범위) |

- 일요일에 `이번 주` 를 고르면 진행 중인 주가 편집 대상이 된다 — 이때도 확정은 정상
  성공하며(PRD R23), `weeks.planned_at` 은 최초 확정 시각을 유지한다.

### 5.1 단계 구성

한 화면에 5단계를 위에서 아래로 쌓는다. 단계 간 화면 전환·마법사 없음 — 스크롤로
전부 보이며, 어느 단계든 언제나 되돌아가 고칠 수 있다.

| 단계 | 내용 | 기본값으로 통과 가능? |
|---|---|---|
| ⓞ 편집 대상 주 | `이번 주` / `다음 주` 토글 | **예** (기본 선택 있음 — §5.0) |
| ① 예산 확인 | 예산 숫자 입력(프리필됨) + 산출 힌트 | **예** (프리필 값 그대로 저장, 클릭 0) |
| ② 항목 추가 | 제목 + est 스테퍼 + 마일스톤 칩 → `항목 추가` | 아니오 (최소 1개 필요) |
| ③ 요일 배치 | 요일 칩 다중 선택 (**월~일**) | **예** (미선택 = 미배치) |
| ④ 경고 확인 | 총량 합계 바 + 요일별 부하 그래프 | **예** (경고는 차단하지 않음) |

### 5.2 ① 예산

- 라벨: 편집 대상 주에 따라 `이번 주 예산 (추정치)` / `다음 주 예산 (추정치)`.
  숫자 입력은 `--font-mono` + tabular-nums.
- **입력은 비어 있지 않다 — 프리필된 값으로 시작한다** (PRD R19). 사용자가 손대지 않고
  확정하면 그 값이 `weeks.budget` 에 그대로 저장된다. "기본값 유지"와 "오버라이드"를
  구분하는 UI 상태가 없다.
- 힌트: 프리필 값의 산출 근거를 사실로 표시 (예: `요일별 가용 합 22`). 구체적 문구,
  프리필 값을 무엇으로 정하는지, capacity 편집 진입은 **pomo-baseline 소관**이며 이
  화면은 그 값을 읽어 쓴다.
- 프리필할 값이 없는 경우(capacity 미설정): 입력을 비워 둘 수 있고, 그 경우 ④의 총량
  경고를 계산하지 않고 `예산을 정하면 과적을 알려줘요` 만 표시한다. 비운 채 확정하면
  게이지는 §7 의 `예산 없음` 상태로 렌더된다 (PRD R20 의 가정 블록).

### 5.3 ② 항목 추가

- 제목 입력(최대 40자) + `예상 뽀모` 스테퍼(**하한 1** — PRD R6) + 마일스톤 칩
  (`M1..Mn` + `마일스톤 없음`).
- **`마일스톤 없음` 칩**은 "마일스톤에 연결하지 않음"의 선택 UI 다. 시스템 기타
  항목(PRD R15)이나 화면의 기타 행(§3.4)과 **아무 관계가 없다** — 라벨을 `기타` 로
  쓰지 않는 이유가 이것이다 (PRD 용어 표).
- `항목 추가` 또는 Enter → 초안 목록에 행 추가, 제목 입력 포커스 유지, 요일 선택 초기화.
- 초안 행: `[M2] 제목  월수금  (뽀모 3)  [×]`.
- 이미 존재하는 항목을 수정하러 들어온 경우 초안 목록에 **그 주의 기존 항목이 채워져
  있고**, 확정 시 ID 기준으로 매칭된다 (PRD R23).
- **기타 항목은 초안 목록에 나타나지 않는다** (PRD R16 — 편집·삭제 불가).

#### 5.3.1 `×` 의 의미는 행의 출신에 따라 다르다 (PRD R24)

| 행의 출신 | `×` 의 결과 | 시각·확인 |
|---|---|---|
| **신규 초안 행** (이 세션에서 추가, 미확정) | 아무 데이터도 만들지 않았으므로 **무해한 취소** | 확인 없음. `--danger` 는 hover 에만 |
| **기존 항목** (수정 진입 시 프리필된 행) | 확정 시 **폐기(`dropped_at`)** — 삭제가 아니다. 자식 task 와 세션은 **전부 보존**되고, 소진은 §3.4 기타 행에 흡수된다 | 초안 행을 **제거하지 않고 `보내줄 예정` 표시로 바꾼다**(취소선 + `--ink-dim` + 되돌리기 링크). 확인 1회: `이 할당을 보내줄까요? 지금까지 한 집중과 조각은 남아요.` |

- 기존 항목의 `×` 를 되돌리기 링크로 취소하면 초안 행이 원래대로 복구된다 — 확정 전에는
  어떤 것도 확정되지 않는다.
- 세션이 붙은 항목의 `×` 를 "저장 전이므로 무해하다"고 취급하지 않는다. 확정 버튼 한
  번으로 폐기가 일어나므로, 결과를 확정 전에 문구로 알린다.

### 5.4 ③ 요일 칩

- 7개 칩을 **월 화 수 목 금 토 일** 순으로. 다중 선택 토글, 선택 시 `--teal` + `--glass-strong`.
- 라벨: `언제 (선택)`. 미선택 상태의 초안 행에는 `미배치` 라고 사실만 적는다.
- 요일 칩 토글은 부분 갱신으로 처리해 제목 입력 포커스를 잃지 않는다.

### 5.5 ④ 경고 2종 — 알리되 막지 않는다

**총량 과적**

- 표시: `계획 합계 <합> / 예산 <예산>` + 진행 바.
- 초과 시: 합계 숫자를 `--amber`, 바에 `--amber` 글로우, 뒤에 한 줄 —
  `+N 과적이에요. 예상 뽀모를 줄일까요, 항목을 덜어낼까요?`
- **이 화면에 없는 액션을 권하지 않는다** (PRD R22). 플래너에서 실제로 가능한 조작은
  ① est 스테퍼 낮추기 ② 초안 행 `×`(기존 항목이면 폐기 — §5.3.1) ③ 예산 입력 올리기
  세 가지이며, "다음 주로 미루기"는 이 화면의 조작이 아니라 주간 정산의 이월 3택이다.
  - 편집 대상 주를 `다음 주` 로 바꾸는 것은 "미루기"가 아니다 — **다른 주를 편집하는
    것**이므로 과적 안내에서 그 전환을 권하지 않는다.
- **금지:** `--danger`, 경고 아이콘(lucide `AlertTriangle` 등), "초과했습니다" 류의 단정.
  질문형으로 선택지를 제시하는 것까지만 (principles §1, PRD R21·R22).

**요일별 부하**

- 7열 막대 그래프. 열 순서 **월~일**. 각 열: 상단 부하 숫자 / 막대 / 하단 요일 라벨.
- 기준선: 그 요일의 `weekly_capacity` 값 위치에 가로선.
- 부하 = Σ(항목 est / 배정 요일 수), 배정된 요일에만 분산. **미배치 항목과 기타 항목은
  산입하지 않는다** (PRD R16·R22).
- 초과 요일: 막대와 숫자를 `--amber` + 글로우. 헤더 우측에 넘친 요일을 사실로 나열
  (`화·목 넘침`). 여유 있으면 `여유 있음` (`--teal`).
- capacity 가 미설정이면 기준선 없이 부하 막대만 그리고, 초과 판정을 하지 않는다.

### 5.6 확정과 취소

| 액션 | 결과 |
|---|---|
| 확정 (`이번 주 시작` / `다음 주 시작` — §1 의 파생 규칙) | 초안 확정 → 일반 뷰로 복귀. 과적 여부와 **무관하게 항상 성공** (PRD R22). 예산·항목·폐기 처리(§5.3.1)가 한 트랜잭션으로 반영된다 |
| `취소` | 초안 폐기 → 일반 뷰로 복귀. 확인 다이얼로그 없음 (기존 항목의 `보내줄 예정` 표시도 함께 폐기된다) |

- 확정 후 첫 렌더에서 일반 뷰는 오늘 배정 항목을 상단에 정렬한다 (§3.3).
- 편집 대상 주가 `다음 주` 였다면 확정 후에도 일반 뷰는 **이번 주**를 보여준다
  (PRD R4) — 방금 만든 항목이 목록에 보이지 않는 것이 정상이므로, 복귀 직후 한 줄
  안내를 띄운다: `다음 주 계획을 저장했어요 — 다음 주가 되면 여기에 보여요.`
- 주중 재수정으로 들어온 확정도 같은 경로다. 기존 항목의 자식 task·`origin_week`·
  `carry_from_id`·`milestone_id` 는 유지된다 (PRD R23).
- 확정 시각의 기록 규칙(`weeks.planned_at` 은 최초 확정만, 재수정 시 갱신하지 않음)은
  **PRD R23 소관**이다 — 이 문서는 화면 전이만 정의한다.

## 6. 항목 드로어

**캐럿** 클릭 시 항목 행 아래로 인라인 펼침 — **모달이 아니다.** 열려 있는 동안
타이머·오늘 목록 조작을 막지 않는다. 동시에 하나만 열린다.
(`+ 오늘로` 는 드로어를 열지 않는다 — §3.1 의 원클릭 pull 이며, 유자격 조각 0개인
폴백에서만 이 드로어로 진입한다. 골라서 가져오기·다중 선택·새 조각은 캐럿 경로다.)

### 6.1 구성

| 요소 | 내용 |
|---|---|
| task 목록 라벨 | `이 할당의 조각 — 오늘 할 것을 고르세요` (task ≥ 1일 때만) |
| task 행 | 체크박스 + 제목 + 뽀모 도트 `소진/est` + 상태 라벨 |
| 새 task 입력 라벨 | task ≥ 1: `또는 새 조각 추가` / task 0: `오늘 할 몫을 쪼개서 적어요 — 이게 첫 조각이 돼요` |
| 새 task 입력 | 제목(최대 40자) + est 스테퍼 |
| 푸터 | `닫기` · `오늘로 가져오기`(primary) |
| 항목 액션 | `완료로 표시` / `완료 해제` (§4), `보내주기` (ghost, hover 시 `--danger`) |

### 6.2 task 행 상태

| 상태 | 조건 | 표시 |
|---|---|---|
| 선택 가능 | 미완료 & 오늘 목록에 없음 | 체크박스 활성. 클릭으로 토글, 다중 선택 |
| 선택됨 | 위 + 사용자 선택 | `--glass-strong` + `--teal` 체크 |
| 이미 오늘 목록에 | 그 날짜의 pull 존재 | 상태 라벨 `오늘 목록에`, 선택 불가 (`--ink-faint`) |
| 완료 | `completed_at` 있음 | 제목 취소선 + `--ink-dim`, 상태 라벨 `완료`, 선택 불가 |

- 항목이 속한 주 때문에 task 가 선택 불가가 되는 상태는 **없다** (PRD R13).

### 6.3 드로어 액션

| 액션 | 동작 |
|---|---|
| `오늘로 가져오기` | 새 task 입력이 있으면 생성 후 pull, 선택한 기존 task 도 함께 pull → 드로어 닫힘. `pull_date` 는 항상 오늘이다 (PRD R13). 오늘 목록 표시 자체는 today-tasks 소관 |
| `닫기` | 선택 상태 폐기, 드로어 닫힘 |
| `완료로 표시` / `완료 해제` | §4 |
| `보내주기` | `dropped_at` 기록 → 일반 뷰 목록에서 사라짐. 확인 1회 (`이 할당을 보내줄까요? 지금까지 한 집중과 조각은 남아요.`) — 소진은 §3.4 기타 행에 흡수된다 |

### 6.4 드로어 상태별 예외

| 상황 | 표시 |
|---|---|
| 항목이 완료 상태 | task 목록·새 입력은 보이되 `오늘로 가져오기` 가 비활성. 안내 한 줄: `완료된 할당이에요 — 해제하면 다시 가져올 수 있어요` (PRD R27) |
| 항목이 완료 상태 & 소진 > est | 위와 같고, 도트에 `+N` 을 그대로 표시한다. `초과했어요` 류 문구를 붙이지 않는다 (PRD R28) |
| task 가 0개 | 목록 영역 없이 `오늘 할 몫을 쪼개서 적어요 — 이게 첫 조각이 돼요` 만. 여기서 적고 `오늘로 가져오기` 하면 **첫 조각 생성 + pull 이 한 번에** 일어난다 (PRD R12) |
| **기타 행의 드릴다운** (Q11) | 두 그룹으로 나눠 읽기 전용 표시:<br>· `이름을 남긴 것` — 소급 생성·직접 추가된 task 제목 + 뽀모 수<br>· `이름 없는 집중` — `뽀모 N — 어떤 일에도 연결되지 않았어요` 한 줄 요약<br>생성·pull·완료·폐기 액션 **전부 없음** |

- 다음 주 항목이라서 pull 이 막히는 예외는 **없다** — 그 규칙은 ADR-012 §2 로 폐기됐다.

## 7. 예산 게이지 (카드 하단 고정)

| 상태 | 표시 |
|---|---|
| 예산 있음 · 여유 | `<소진> / <예산>` (`--font-mono`, tabular-nums) + `--teal` 진행 바. 보조 문구 `예산은 추정치예요 — 넘어가도 괜찮아요` |
| 예산 있음 · 초과 | 바 가득 + `--amber` 글로우, `+N` 배지 (lucide `Flame` 동반). 문구는 같다. **빨간색·경고 금지** (PRD R21) |
| 예산 없음 | 바를 숨기고 소진량만 — `<소진> / 미설정` + `예산을 정하면 예산 대비 소진이 보여요` |

- **`예산 없음` 의 실제 조건** (PRD R20): `weeks.budget` 은 NOT NULL 이므로(ADR-013 §1)
  이 상태는 ① 그 주에 `weeks` 행이 아직 없거나 ② `budget = 0` 인 경우다. 카피를
  `주간 계획을 잡으면 …` 으로 쓰지 않는다 — 계획을 잡지 않아도 첫 세션이 행을 만들고,
  거꾸로 계획을 잡았는데 예산을 비워 둔 경우도 이 상태이기 때문이다. 조건에 맞는 문구는
  "예산을 정하면"이다.
- 소진은 그 주 focus 세션 수 전체(기타·미분류 포함)다. `Σ(is_system = 0 항목 소진) +
  기타 행 소진` 과 항상 같다 — 기타 행이 차액으로 정의되므로 산술적으로 그렇다
  (PRD 성공 지표).
- 플래너·정산 모드에서는 게이지를 숨긴다 (§1).

## 8. 빈 상태

CTA 라벨은 §1 의 파생 규칙을 따른다 — 아래 표의 `+ <주> 할당 잡기` 는 편집 대상 주의
기본 선택값에 따라 `+ 이번 주 할당 잡기` 또는 `+ 다음 주 할당 잡기` 로 렌더된다.

| 상황 | 카피 | CTA |
|---|---|---|
| 항목 0 · 마일스톤 있음 | `마일스톤을 이번 주 몫으로 쪼개볼까요?` | `+ <주> 할당 잡기` |
| 항목 0 · 마일스톤 없음 | `이번 주 할당을 잡으면 뽀모 예산이 여기 보여요` | `+ <주> 할당 잡기` |
| 항목 0 · 그 주 세션·조각은 있음 | 기타 행(§3.4)만 표시되고, 그 아래 `계획이 없어도 기록은 남아요` | `+ <주> 할당 잡기` |
| 활성 항목 0 · 전부 완료 | `이번 주 할당을 다 끝냈어요` (사실만 — 칭찬 문구 금지) | `수정` (플래너로 항목 추가) |

- 일요일에는 CTA 가 `+ 다음 주 할당 잡기` 로 렌더되고, 플래너 진입 후 §5.0 에서
  `이번 주` 로 바꿀 수 있다 — **라벨과 실제 편집 대상이 어긋나는 상태가 없다** (PRD R5).
- 빈 상태 카피에 이모지를 쓰지 않는다 (principles §6). 아이콘이 필요하면 lucide 컴포넌트.

## 9. 모션·아이콘

- 드로어 펼침/접힘, 게이지 바 변화, 편집 대상 주 전환 시 초안 목록 교체는 상태 변화의
  결과 전달이므로 허용. `prefers-reduced-motion: reduce` 시 전이 없이 즉시 반영
  (principles §4).
- 초과 글로우는 정적 처리다 — 무한 펄스 애니메이션 금지 (principles §4).
- 뽀모 표시는 **뽀모 도트 컴포넌트**(토큰 기반 커스텀 SVG/CSS)이며 `default` 와
  `neutral`(§3.4) 두 변형을 갖는다. 초과 배지의 불꽃은 lucide `Flame` 아이콘
  컴포넌트다. 이모지(🍅·🔥) 금지 — 초안·시안의 이모지 표기는 문서용 속기일 뿐이다
  (principles §6).

## 10. 반응형

| 구간 | 처리 |
|---|---|
| 와이드 (≥ `--bp-wide`) | WEEK 컬럼에 카드 그대로. §2 골격 유지 |
| 미디엄 (`--bp-medium` ~ `--bp-wide`) | WEEK 컬럼 유지 (접히는 것은 MONTH 컬럼) |
| 내로우 (< `--bp-medium`) | `주간` 탭 안으로 이동. 카드 내부 구성은 §2~§8 그대로 |

- 탭 구조·컬럼 접힘·최소 창 크기 등 배치 자체는 **app-shell ux-spec 소관**이다.
  이 문서는 "WEEK 는 미디엄까지 살아 있고, 내로우에서 탭으로 들어간다"는 것만 정의한다.
- 내로우에서 플래너의 요일 부하 그래프는 7열을 유지한다 (요일이 줄어들 수는 없다).
  가로 폭이 부족하면 막대 폭을 줄이고, 그래도 부족하면 그래프만 가로 스크롤한다.
- 편집 대상 주 토글(§5.0)은 내로우에서도 2개 세그먼트를 유지한다 — 드롭다운으로
  접지 않는다. 어느 주를 고치는지가 항상 보여야 한다.
