# PRD: pomo-baseline

> **2.0.0 재작성.** 이 기능은 원래 "뽀모 1개의 크기"와 "그 주에 쓸 수 있는 개수"를 함께
> 소유했다. 후자(가용량·예산·주 스냅샷·조회 계약 2개)는
> [ADR-030](../../architecture/decisions/adr-030-time-as-progress-currency.md) 이 계획의
> 통화를 측정 시간으로 바꾸면서, 전자의 효력 지연은
> [ADR-029](../../architecture/decisions/adr-029-baseline-immediate-effect.md) 가 각각
> 폐기했다. 무엇이 왜 죽었는지는 아래 **폐기된 요구사항** 표에 남긴다.
>
> 스키마 정의(컬럼·자료형·제약)의 소유자는
> [ADR-011](../../architecture/decisions/adr-011-schema-final.md) §1 +
> [ADR-019](../../architecture/decisions/adr-019-constraint-implementation.md) §3 이며,
> 이 문서는 그 값들의 의미만 소유한다. 충돌 시 ADR 이 이긴다.

## 문제

타이머는 "몇 분짜리 세션을 돌릴 것인가"를 알아야 시작할 수 있다. 그 값은 앱이 정해줄 수
없고 — 집중력이 좋아지면 25분이 짧아지고, 컨디션이 나쁜 주에는 50분이 무리다 — 그래서
사용자가 정한다. 문제는 **바꾸는 순간에** 생긴다.

1. **바꿔도 안 바뀌는 것처럼 보인다.** 1.x 는 길이를 주 단위로 박제하고 "효력은 다음 주
   경계부터"를 규칙으로 삼았다. 사용자가 정산에서 길이를 고쳤는데 타이머가 이전 길이로
   계속 돌았고, 그것이 **버그로 인지됐다** (ADR-029 Context). 저장은 정상이었다.
2. **진행 중인 세션이 중간에 흔들리면 안 된다.** 20분을 달린 세션의 길이가 갑자기 50분이
   되면, 사용자가 시작할 때 합의한 것과 다른 세션이 된다.
3. **과거 기록이 재해석되면 안 된다.** 오늘 길이를 바꿨다고 지난달 기록의 의미가
   달라지면 기록은 신뢰할 수 없는 것이 된다.

2·3 을 지키기 위해 1 을 감수할 필요가 없다는 것이 이 문서의 출발점이다. 세 문제는 서로
독립이고, **적용 시점을 "다음 세션 시작"으로 잡으면 셋이 동시에 닫힌다.**

## 대상 사용자

- 앱 소유자 1인 (로컬 단독, 로그인·멀티유저 없음)
- 특히 "기준을 다시 정하고 싶어진 시점"의 자기 자신 — 그 시점이 일요일 정산일 수도 있고
  화요일 밤일 수도 있다

## 목표

1. **저장한 값이 곧 다음 세션의 값이다.** 사용자가 화면에서 본 숫자와 타이머가 도는
   숫자가 어긋나는 상태를 만들지 않는다.
2. 진행 중인 세션은 시작할 때 읽은 길이로 끝까지 돈다 — 길이 변경이 달리는 세션을
   건드리지 않는다.
3. 과거 기록의 의미를 길이에 매지 않는다. `1뽀모 = focus 세션 1회 완료`이고, 시간이
   필요하면 세션이 실제로 남긴 `duration_sec` 로 복원한다.
4. 길이를 읽는 경로를 **전역값 직독 하나**로 유지한다 — 폴백 순서를 아는 코드가 없게
   한다.

## 범위 / 비범위

**범위:** 뽀모 1개의 정의, 전역 길이 3종(`focus_min`·`short_break_min`·`long_break_min`)의
의미·하한·기본값, 길이 편집의 **효력 시점**과 편집 진입점.

**비범위:**

- 주간 정산 패널의 화면·문구·편집 섹션 배치 — weekly-review 소관. 이 문서는 "정산에
  진입점이 있다"는 사실만 소유한다.
- 첫 실행 온보딩 화면의 구성·순서 — app-shell 소관.
- 타이머의 ±1/±5/±10분 조절 동작 — timer 소관 (그 조절은 길이를 바꾸지 않는다, R2).
- 진행 표시의 통화와 그 합산 — ADR-030 과 각 기능 문서 소관. **이 기능은 분모를 갖지
  않는다.**
- 소진량·측정 시간의 저장 (PRODUCT.md 원칙 8 — 항상 세션에서 파생).

## 요구사항

### 뽀모의 정의와 단위 규약

- **R1.** **1뽀모 = focus 세션 1회 완료이며, 세션 길이와 무관하다.** 35분짜리 focus
  세션도, 12분에 완료 처리한 focus 세션도 각각 1뽀모다.
  > 이 정의는 살아 있지만 **집계의 통화는 더 이상 이 개수가 아니다** (ADR-030) —
  > 화면이 진행을 말할 때 쓰는 값은 완료 focus 세션의 측정 시간 합이다.
  > `뽀모` 는 사이클의 이름으로 남는다.
- **R2.** 세션 중 ±1/±5/±10분 조절은 **그날의 예외 대응**이며 저장된 길이를 변경하지
  않는다. 조절 후에도 `settings` 의 길이 값은 그대로다.
- **R3.** 시간 해석이 필요한 경우는 세션의 `duration_sec`(초)로 복원한다. 뽀모 개수에
  길이를 곱해 과거 시간을 추정하지 않는다 — 길이는 주마다 달랐을 수 있고, 조기 완료·
  세션 중 조절은 곱셈으로 복원되지 않는다.
- **R4.** 길이는 분 단위 INTEGER 로 다루며 필드명에 `_min` 접미사를 붙인다
  ([ADR-009](../../architecture/decisions/adr-009-time-format-convention.md) §1).
  측정된 경과만 `_sec` 이다. 접미사 없는 시간 값은 쓰지 않는다.
- **R5.** 길이의 하한은 **1분**이며 정수만 허용한다. 0 이하·음수·비정수·빈 값의 저장
  시도는 **거부되고 기존 값이 유지된다.** 거부는 경계에서 이뤄진다 (IPC 스키마 +
  SQLite CHECK — ADR-011 §6 · ADR-019 §3).
- **R6.** 전역 기본값은 focus 25분 / short 5분 / long 15분이며 `settings` 에 시딩된다
  ([ADR-018](../../architecture/decisions/adr-018-first-run-state.md) §4).

### 저장소와 효력 시점

- **R7.** **길이의 유일한 저장소는 `settings` 전역값이다** (ADR-029 §2). 주별 스냅샷을
  읽는 경로는 없다 — 어떤 주를 인자로 받아 길이를 돌려주는 계약(`유효 베이스라인(week)`)이
  폐기됐고, 모든 소비자는 전역값을 직독한다.
- **R8.** **편집은 언제든 허용되고 저장은 즉시 효력을 갖는다.** 편집 경로를 특정 화면·
  특정 요일로 좁히지 않는다.
- **R9.** **적용 시점은 다음 세션 시작이다** (ADR-029 §1). 진행 중인 세션은 시작할 때
  읽은 길이로 끝까지 돈다. 이 규칙은 새 장치가 아니라 타이머의 기존 구조 그대로다 —
  세션 시작·idle 진입 시점마다 길이를 새로 읽는다 (timer R1).
- **R10.** **길이 변경으로 과거 기록은 재해석되지 않는다** (R1·R3 의 직접 결과). 25분
  기준으로 기록한 32뽀모는 길이를 50분으로 바꾼 뒤에도 32뽀모이고, 그 세션들의 측정
  시간도 그대로다 — 저장된 사실이지 길이에서 파생한 값이 아니기 때문이다.
- **R11.** 길이 편집은 **두 경로로 제공한다:** (a) **첫 실행 온보딩** (b) **주간 정산의
  편집 진입점.** 이 두 경로 외의 상시 설정 화면을 v1 에 두지 않는다.
  소유 경계: **자리·접힘·진입 방식**은 화면의 주인(app-shell 온보딩 / weekly-review 정산
  진입점)이 갖고, **표시 항목·기본값·검증 규칙은 이 문서가 갖는다.** 화면 문구는 그
  문구가 놓이는 화면의 ux-spec 이 갖는다 (ADR-029 §4).
- **R12.** **길이를 바꾸기 전후를 비교해 보여주지 않는다.** 비교의 분모였던 주간 예산·
  가용량 합이 소멸했고 (ADR-029 §3), 남은 값으로 비교를 지어내지 않는다.

## 관찰 사항

- **주중에 25분이 안 맞는 사용자에게 답이 둘 있다** — 그 세션만 넘기려면 ±조절(R2,
  timer 소관), 기준이 변한 것이면 길이 편집(R8)이다. 1.x 에서는 후자가 "다음 주까지
  기다리라"는 답이었고, 그 기다림이 이 기능을 다시 쓴 이유다.
- **휴식 길이 2종(`short_break_min`·`long_break_min`)을 읽는 곳은 타이머뿐이다.**
  집계·표시에 등장하는 길이는 없다 — 진행 표시가 측정 시간이 되면서 길이는 **다음
  세션이 얼마나 돌지**만 정하는 값이 됐다.

## 성공 지표

- 길이를 바꾼 직후 시작한 세션이 **항상** 새 길이로 돈다 (회귀 테스트로 고정).
  1.x 의 결함은 이 문장이 거짓이었던 것이다.
- 진행 중인 세션의 길이가 편집으로 바뀌는 경우가 0건이다.
- 길이를 읽는 코드 경로가 **전역값 직독 1곳**이며, 폴백·파생 분기가 0개다 (R7).
- 전역 길이를 바꾼 뒤 과거 어떤 주의 뽀모 개수·측정 시간도 변하지 않는다.
