# PRD: calendar-records

> 출처: docs/origin/pomodoro-prd.md §3.5 (초안) + [결정 원장](../../decision-log/2026-08-04-planning-session.md) §A (Q1·Q2·Q8-1)
> 초안·시안과 이 문서가 다르면 이 문서가 이긴다. (시안 v7 의 일요일 시작 그리드는 뒤집는다 — ADR-010)

## 문제

세션은 끊임없이 쌓이지만, "내가 언제 얼마나 했는가"를 되돌아볼 창구가 없으면 기록은
DB 안에만 남는다. 특히 "그날 나는 무엇을 하려 했고 그중 무엇이 끝났는가"는 시간이
지나면 복원이 불가능해지기 쉽다 — 오늘 목록이 매일 덮이는 구조였다면 과거 날짜는
현재 상태로 물들어 거짓말을 한다.

여기에 시간 자체의 문제가 겹친다. 하루의 경계가 어디인지, 자정을 걸친 세션이 어느
날짜에 속하는지, 타임존을 옮겨도 과거 기록이 그대로인지가 정해지지 않으면 캘린더의
점 하나하나가 신뢰할 수 없는 숫자가 된다.

## 대상 사용자

- 앱 소유자 1인 (로컬 단독, 로그인·멀티유저 없음)

## 목표

1. 한 달을 한눈에 보고 "공부한 날"을 즉시 식별한다 — 계획 데이터가 0개여도 성립한다 (원칙 1).
2. 과거 날짜를 골랐을 때 **그 시점의 사실**이 정확히 복원된다 (오늘 상태로 오염되지 않는다).
3. 날짜 귀속 기준이 하나로 고정되어, 캘린더 점·스트릭·날짜 패널의 숫자가 서로 어긋나지 않는다.
4. 사실만 표시하고 판단하지 않는다 — 기록이 없는 날도 결핍으로 프레이밍하지 않는다 (원칙 6·7).

## 범위 / 비범위

**범위:** 월 그리드 캘린더(요일 헤더·월 이동·오늘 표시), 날짜별 공부 점 렌더,
날짜 선택 → 날짜 기록 패널(집중 횟수·그날의 조각 목록·빈 상태), 공부한 날 수 표시(스트릭),
날짜 귀속 기준(로컬 자정·`started_at`)의 열람 측 정의.

**비범위:**

- **세션을 만드는 것** — 타이머 완료 판정과 `sessions` 행 기록(`local_date`·`local_week` 계산 포함)은 timer 소관. 이 문서는 이미 기록된 값을 **읽는 규칙**만 정의한다.
- **주간 집계·소진 게이지·과적 경고** — week-plan 소관. 캘린더는 주 단위 합계를 표시하지 않는다.
- **주간 리뷰 요약·이월 분류** — weekly-review 소관. 캘린더 점은 정산 여부와 무관하게 언제나 사실을 표시한다.
- **월간 마일스톤 카드·"N/M 달성" 배지** — milestones 소관 (같은 MONTH 컬럼에 나란히 놓이지만 데이터가 다르다).
- **오늘 목록의 편집(추가·pull·× 제거)** — today-tasks 소관. 날짜 패널은 읽기 전용이다.
- **자정 경계 힌트 문구 2종**(자정 임박 / 자정 직후 빈 목록, Q18) — 오늘 목록에 붙는 힌트이므로 today-tasks 소관.
- 하루 경계 오프셋 설정(새벽 4시 등) — Q1 에서 기각. 경계는 로컬 자정 고정이다.
- 월 누적 소진량 표시 — Q15 에서 v1.1 로 미룸. 없는 숫자를 지어내지 않는다.
- 기록 내보내기(CSV·이미지), 연간 히트맵, 임의 기간 통계 — v1 범위 밖.

## 요구사항

### 날짜 귀속 기준

- **R1.** 하루의 경계는 **OS 로컬 타임존의 자정**이다 (Q1). 타임존 값을 코드·문서에 하드코딩하지 않으며, 로컬 변환은 시간 모듈 하나를 통해서만 한다 (ADR-009 §3).
- **R2.** 세션의 날짜 귀속은 **시작 시각(`started_at`) 기준**이다 (Q2). 23:50 에 시작해 다음 날 00:15 에 끝난 focus 세션은 **시작일**의 기록이다. 캘린더 점·스트릭·날짜 패널의 집중 횟수는 모두 이 하나의 기준에서 파생되며, 화면마다 다른 기준을 쓰지 않는다.
- **R3.** 캘린더 조회는 세션의 순간 컬럼(`started_at`)에서 날짜를 파생하지 않고, 기록 시점에 1회 계산해 불변 저장된 `sessions.local_date`(월 범위 조회) 및 `local_week`(주 단위 조회)의 **범위 조건**으로 수행한다 (ADR-009 §2, ADR-011 §3). 술어에 `strftime()`·`date()` 를 씌우지 않는다. 결과적으로 사용자가 타임존을 바꿔도 과거 캘린더 점은 이동하지 않는다.
- **R4.** 화면에 표시되는 모든 수치(집중 횟수, 공부한 날 수, 완료 개수)는 세션·task 조회로부터 파생하며 **별도로 저장하지 않는다** (원칙 8).

### 월 그리드

- **R5.** 그리드는 월 단위이며 요일 헤더와 날짜 셀 순서 모두 **월요일 시작**이다 (ADR-010 §1 — 시안 v7 의 일요일 시작을 뒤집는다). 1일 앞의 빈 칸 수는 월요일 기준으로 계산한다.
- **R6.** 이전/다음 달로 이동할 수 있다. 이동은 표시 대상 월만 바꾸며 선택된 날짜·타이머 상태에 영향을 주지 않는다.
- **R7.** 오늘 날짜는 다른 날짜와 구별되게 강조한다(숫자를 `--amber`). 미래 날짜는 셀로 존재하지만 기록이 없으므로 점이 없다.
- **R8.** 날짜 셀은 선택 가능하며, 현재 선택된 날짜는 시각적으로 구별된다. 기본 선택은 오늘이다.

### 공부한 날 점

- **R9.** 점의 기준은 **그 날짜에 귀속된 완료 `focus` 세션 수**다.
  - 1개 이상: 기본 점 (`--teal`)
  - 4개 이상: 진한 점 — 더 크고 강조된 점 (`--amber`)
  - 0개: 점 없음
- **R10.** 휴식 세션(`short`·`long`)은 점 집계에 포함하지 않는다.
- **R11.** **미분류 집중**(task 연결이 없는 세션)도 점 집계에 포함한다. task 연결 여부는 그 날짜에 집중했다는 사실을 바꾸지 않는다.
- **R12.** 점은 lucide 아이콘이나 이모지가 아니라 **토큰 기반 커스텀 SVG/CSS 컴포넌트**로 구현한다 (principles.md §6). 색·크기는 tokens.md 의 토큰 이름으로만 기술한다.

### 날짜 기록 패널

- **R13.** 날짜를 선택하면 하단 패널에 그 날짜의 기록을 표시한다: 날짜 라벨(`M월 D일`), 그 날짜에 귀속된 완료 focus 세션 수, 그리고 그날의 조각 목록.
- **R14.** 그날의 조각 목록은 **`task_pulls(task_id, pull_date)` 에서 `pull_date` 가 그 날짜인 행**으로 구성한다 (ADR-011 §2). 단일 컬럼(`pulled_date`)이었다면 같은 task 를 다시 pull 할 때 과거 이력이 덮여 지난 날짜 패널이 거짓말을 했을 것이다. 행으로 보존되므로 과거 날짜도 정확히 복원된다.
- **R15.** 각 조각의 완료 여부는 `tasks.completed_at`(ADR-011 §5) 으로 판정한다. **`completed_at` 의 로컬 날짜가 대상 날짜보다 늦거나 NULL 이면 그 날짜 패널에서는 미완료로 표시한다** — 8월 5일에 끝낸 조각이 8월 1일 패널에서 완료로 보이지 않는다. 즉 "그 시점엔 미완료였다"가 정확히 그려진다.
- **R16.** 요약 줄에는 조각이 있을 때 완료/전체 개수를 함께 표시한다(예: `할 일 2/3 완료`). 조각이 없으면 집중 횟수만 표시한다.
- **R17.** 세션도 조각도 없는 날짜를 선택하면 빈 상태 문구 `이날은 기록이 없어요` 를 표시한다. 결핍·훈계 표현을 쓰지 않는다 (원칙 6·7, principles.md §1).
- **R18.** 오늘 날짜가 선택된 상태에서 세션이 완료되거나 오늘 목록이 바뀌면 패널이 갱신된다. 과거 날짜가 선택된 상태에서는 오늘의 변화가 패널을 바꾸지 않는다.
- **R19.** 패널은 읽기 전용이다. 조각의 완료 토글·삭제·재-pull 을 여기서 제공하지 않는다.

### 공부한 날 수 표시 (스트릭)

- **R20.** 타이머 하단에 이번 주 기준 공부한 날 수를 표시한다: `이번 주 N일 공부 중`. 여기서 "이번 주"는 **월요일 시작 주**이며(ADR-010), 집계 대상은 R9 와 같은 기준(그 날짜에 귀속된 focus 세션 ≥ 1)이다.
- **R21.** N=0 이면 `오늘부터 기록이 쌓여요` 를 표시한다. 끊긴 날·못 한 날을 세거나 실패로 프레이밍하는 표현(연속 기록 중단 경고 등)을 쓰지 않는다 (원칙 6·7, principles.md §1).

> ⚠️ 가정: v1 의 이 표시는 "연속 일수(consecutive streak)"가 아니라 **이번 주에 공부한 날의 수**다.
> 초안 §3.5 는 이를 "스트릭"이라 불렀지만 시안 v7 의 실제 계산은 주 내 일수 카운트이며,
> 연속 일수 정의(주 경계를 넘는 사슬, 끊김 처리)에 대한 결정은 없다. 연속 일수 도입은
> v1 비범위로 두고, 필요해지면 별도 결정으로 추가한다.

## 성공 지표

- 계획·task 가 0개이고 세션만 있는 DB 에서 캘린더 점·날짜 패널·공부한 날 수가 전 구간 동작 (원칙 1 검증)
- 화면 간 숫자 불일치 0: 같은 날짜에 대해 캘린더 점 등급, 날짜 패널 집중 횟수, 주 단위 공부한 날 수가 항상 같은 기준에서 나온다
- 과거 날짜 패널의 재현성: 같은 과거 날짜를 며칠 뒤에 다시 열어도 조각 목록과 그 시점 완료 여부가 동일하다
- "공부한 날 수"는 목표 수치로 삼지 않는다 (많을수록 좋다는 프레임을 만들지 않는다 — 원칙 7)
