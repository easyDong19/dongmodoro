# PRD: calendar-records

> 출처: docs/origin/pomodoro-prd.md §3.5 (초안) + [결정 원장](../../decision-log/2026-08-04-planning-session.md) §A (Q1·Q2·Q8-1)
> + [2026-08-04 리뷰 결정](../../decision-log/2026-08-04-review-decisions.md) (케이스 6 반영 — "기록 있음" 술어 단일화)
> 초안·시안과 이 문서가 다르면 이 문서가 이긴다. (시안 v7 의 일요일 시작 그리드는 뒤집는다 — ADR-010)

## 문제

세션은 끊임없이 쌓이지만, "내가 언제 얼마나 했는가"를 되돌아볼 창구가 없으면 기록은
DB 안에만 남는다. 특히 "그날 나는 무엇을 하려 했는가"는 시간이 지나면 복원이
불가능해지기 쉽다 — 오늘 목록이 매일 덮이는 구조였다면 과거 날짜는 현재 상태로 물들어
거짓말을 한다.

여기에 시간 자체의 문제가 겹친다. 하루의 경계가 어디인지, 자정을 걸친 세션이 어느
날짜에 속하는지, 타임존을 옮겨도 과거 기록이 그대로인지가 정해지지 않으면 캘린더의
점 하나하나가 신뢰할 수 없는 숫자가 된다.

세 번째 문제는 **한 화면이 두 입으로 말하는 것**이다. 월 그리드의 점, 날짜 패널의 목록,
빈 상태 문구가 각자 다른 조건으로 "기록이 있다"를 판정하면 같은 날짜에 대해 캘린더는
"아무 일 없었음", 날짜 패널은 "3개 다 완료"라고 말한다 (리뷰 케이스 6). 판정은 한 번만
정의되어야 한다.

## 대상 사용자

- 앱 소유자 1인 (로컬 단독, 로그인·멀티유저 없음)

## 목표

1. 한 달을 한눈에 보고 "기록이 있는 날"을 즉시 식별한다 — 계획 데이터가 0개여도 성립한다 (원칙 1).
2. 과거 날짜를 골랐을 때 **그날 무엇을 하려 했는가**(그날의 조각 목록과 집중 횟수)가 정확히 복원된다. 완료 여부는 현재 상태를 보여준다 — 그 정밀도의 한계는 R19 에 명시한다.
3. "기록 있음"의 판정이 **한 곳에만 정의되어**, 캘린더 점·날짜 패널·빈 상태가 같은 날짜에 대해 서로 반대로 말하지 않는다.
4. 사실만 표시하고 판단하지 않는다 — 기록이 없는 날도 결핍으로 프레이밍하지 않는다 (원칙 6·7).

## 범위 / 비범위

**범위:** 월 그리드 캘린더(요일 헤더·월 이동·오늘 표시·셀 상태 조합 규칙), 날짜별 공부 점 렌더,
날짜 선택 → 날짜 기록 패널(집중 횟수·그날의 조각 목록·빈 상태), 공부한 날 수 표시,
날짜 귀속 기준(로컬 자정·`started_at`)의 열람 측 정의,
"기록 있음" 술어의 정의와 공개, 표시 대상 월 상태의 소유.

**비범위:**

- **세션을 만드는 것** — 타이머 완료 판정과 `sessions` 행 기록(`local_date`·`local_week` 계산 포함)은 timer 소관. 이 문서는 이미 기록된 값을 **읽는 규칙**만 정의한다.
- **주간 집계·소진 게이지·과적 경고** — week-plan 소관. 캘린더는 주 단위 합계를 표시하지 않는다.
- **주간 정산 요약·이월 분류** — weekly-review 소관. 캘린더 점은 정산 여부와 무관하게 언제나 사실을 표시한다.
- **월간 마일스톤 카드·"N/M 달성" 배지** — milestones 소관 (같은 MONTH 컬럼에 나란히 놓이고 표시 대상 월을 공유하지만, 데이터가 다르다 — R25).
- **오늘 목록의 편집(추가·pull·× 제거·완료 토글)** — today-tasks 소관. 날짜 패널은 읽기 전용이다.
- **자정 경계 힌트 문구 2종**(자정 임박 / 자정 직후 빈 목록, Q18) — 오늘 목록에 붙는 힌트이므로 today-tasks 소관.
- 하루 경계 오프셋 설정(새벽 4시 등) — Q1 에서 기각. 경계는 로컬 자정 고정이다.
- 월 누적 소진량 표시 — Q15 에서 v1.1 로 미룸. 없는 숫자를 지어내지 않는다.
- **완료 여부의 시점 복원**(그 날짜 화면에 "그날 시점의 완료 여부"를 그리는 것) — v1 비범위. 불변 완료 달력 키가 선행되어야 하며 그것은 새 ADR 사안이다 (R19 아래 가정 블록).
- 기록 내보내기(CSV·이미지), 연간 히트맵, 임의 기간 통계 — v1 범위 밖.

## 요구사항

### 날짜 귀속 기준

- **R1.** 하루의 경계는 **OS 로컬 타임존의 자정**이다 (Q1). 타임존 값을 코드·문서에 하드코딩하지 않으며, 로컬 변환은 시간 모듈 하나를 통해서만 한다 (ADR-009 §3).
- **R2.** 세션의 날짜 귀속은 **시작 시각(`started_at`) 기준**이다 (Q2). 23:50 에 시작해 다음 날 00:15 에 끝난 focus 세션은 **시작일**의 기록이다. 캘린더 점·공부한 날 수·날짜 패널의 집중 횟수는 서로 다른 기준을 각자 정의하지 않고, **하나의 정책(로컬 자정 경계 + 발생 시점 1회 계산된 불변 달력 키)에서 파생된다.**
- **R3.** 캘린더 조회는 세션의 순간 컬럼(`started_at`)에서 날짜를 파생하지 않고, 기록 시점에 1회 계산해 불변 저장된 `sessions.local_date`(월 범위 조회) 및 `local_week`(주 단위 조회)의 **범위 조건**으로 수행한다 (ADR-009 §2, ADR-011 §3). 술어에 `strftime()`·`date()` 를 씌우지 않는다. 결과적으로 사용자가 타임존을 바꿔도 과거 캘린더 점은 이동하지 않는다.
- **R4.** 화면에 표시되는 모든 수치(집중 횟수, 공부한 날 수, 완료 개수)는 세션·task 조회로부터 파생하며 **별도로 저장하지 않는다** (원칙 8).

### "기록 있음" 술어 — 한 번만 정의한다

- **R5.** 이 기능은 날짜 `D` 에 대한 **`기록 있음(D)`** 술어를 한 번 정의하고, 아래 세 곳이 **이 정의만 참조한다** (각자 조건을 다시 쓰지 않는다):

  ```
  기록 있음(D) = (D 에 귀속된 완료 focus 세션 수 ≥ 1)
              또는 (pull_date = D 인 task_pulls 행 수 ≥ 1)
  ```

  | 참조하는 곳 | 규칙 |
  |---|---|
  | 월 그리드의 점 | `기록 있음(D)` 이 참이면 점을 렌더한다 (R11) |
  | 날짜 패널의 조각 목록 | `기록 있음(D)` 이 참이면 목록 영역을 렌더한다 (R17) |
  | 날짜 패널의 빈 상태 | `기록 있음(D)` 이 거짓일 때만 빈 상태 문구를 표시한다 (R21) |

- **R6.** **점의 등급(기본/진한)만 완료 focus 세션 수로 계산한다** (R11). 즉 세션이 0이고 조각만 있는 날은 "점 있음 · 기본 등급"이며, 등급 계산에 조각 수는 들어가지 않는다.

> **왜 이 정의인가 (변경 이력):** 시안 v7 의 판정은 `뽀모 > 0 || 완료된 조각 있음` 이었다.
> 이전 버전의 이 문서는 점의 술어를 "완료 focus 세션 수" 단독으로 좁혔으면서 그 변경을
> 기록하지 않았고, 그 결과 **타이머를 한 번도 돌리지 않고 조각 3개를 체크만 한 날**이
> 캘린더에서는 점 없음, 날짜 패널에서는 "집중 0회 · 할 일 3/3 완료"로 나오는 모순이 생겼다
> (리뷰 케이스 6). R5 는 시안의 "또는" 구조를 복원하되 조건을 **완료 여부가 아니라
> pull 행 존재**로 바꿨다 — 완료 여부는 현재 상태여서 과거 날짜에 대해 변할 수 있지만
> (R19), pull 행은 그날의 불변 사실이다.

### 월 그리드

- **R7.** 그리드는 월 단위이며 요일 헤더와 날짜 셀 순서 모두 **월요일 시작**이다 (ADR-010 §1 — 시안 v7 의 일요일 시작을 뒤집는다). 1일 앞의 빈 칸 수는 월요일 기준으로 계산한다.
- **R8.** 이전/다음 달로 이동할 수 있다. 이동은 **표시 대상 월만** 바꾸며, **선택된 날짜와 타이머 상태를 바꾸지 않는다.** 따라서 표시 월과 선택 날짜의 달이 다를 수 있고, 그때:
  - 날짜 패널은 선택 날짜의 기록을 그대로 유지한다.
  - 그리드에는 선택 강조가 보이지 않는다(선택 날짜가 그 달에 없으므로) — 이는 정상 상태다.
  - 어느 달·어느 해의 기록인지 오독되지 않게 **날짜 패널 라벨에 연도를 포함한다** (R16).
- **R9.** 월 이동에 **범위 제한을 두지 않는다.** 기록이 없는 과거·미래 달로도 이동할 수 있고, 그 달은 점이 없는 그리드로 렌더된다(에러·빈 화면이 아니다). 데이터 시작일을 하한으로 삼는 규칙을 두지 않는다.
- **R10.** 오늘 날짜는 다른 날짜와 구별되게 강조한다(숫자를 `--amber`). "오늘"은 **현재 로컬 시각에서 계산**하며, 점은 **기록 당시의 불변 달력 키에서** 나온다. 두 값의 출처가 다르므로 타임존을 크게 옮긴 뒤에는 어긋날 수 있다:
  - 그리드가 8/3 을 오늘로 강조하는데 8/3 날짜 패널의 집중 횟수가 0 일 수 있다.
  - **오늘보다 뒤인 셀(8/4)에 점이 찍힐 수 있다.** 이는 버그가 아니다 — **점은 기록 당시의 사실이고, 오늘 표시는 현재 시각의 사실이다.** 둘 다 참인 값을 그대로 보여준다 (ADR-009 Consequences 의 수용된 대가).
  - 따라서 "미래 날짜에는 기록이 없으므로 점이 없다"는 규칙을 두지 않는다. 미래 셀도 다른 셀과 같은 규칙(R5)으로 렌더한다.
- **R11.** 점의 렌더 규칙:
  - `기록 있음(D)` 이 거짓: 점 없음
  - 참 + 그 날짜의 완료 focus 세션 1~3개(0개 포함): 기본 점 (`--teal`)
  - 참 + 완료 focus 세션 4개 이상: 진한 점 — 더 큰 지름 + `--amber`
- **R12.** 휴식 세션(`short`·`long`)은 점 집계에 포함하지 않는다.
- **R13.** **미분류 집중**(task 연결이 없는 세션)도 점 집계에 포함한다. task 연결 여부는 그 날짜에 집중했다는 사실을 바꾸지 않는다.
- **R14.** 점은 lucide 아이콘이나 이모지가 아니라 **토큰 기반 커스텀 SVG/CSS 컴포넌트**로 구현한다 (principles.md §6). 색·크기는 tokens.md 의 토큰 이름으로만 기술한다.
- **R15.** 날짜 셀의 상태는 **세 개의 독립 채널**로 표현하며, 셋이 한 셀에 겹쳐도 서로를 덮지 않는다. 채널과 우선순위는 다음 표로 확정한다.

  | 상태 | 채널(적용 대상) | 토큰 | 겹칠 때 |
  |---|---|---|---|
  | 기본 (그 달의 평일) | 숫자 | `--ink-dim` | — |
  | 그 달에 속하지 않는 앞·뒤 빈 칸 | 숫자 | `--ink-faint` | 점·선택 대상이 아니다 |
  | **오늘** | 숫자 | `--amber` + `--weight-semibold` | **숫자 채널의 최우선.** 선택·점 어느 것과 겹쳐도 유지된다 |
  | **선택** | 셀 배경·보더 | 배경 `--glass-strong`, 보더 `--glass-border`, `--radius-md` | **배경 채널 단독.** 숫자 색을 바꾸지 않는다 |
  | 기본 점 | 점 요소 | `--teal` | **점 채널 단독.** 숫자·배경을 바꾸지 않는다 |
  | 진한 점 | 점 요소 | `--amber` + 큰 지름 | 위와 동일 |

  - 규칙: **"오늘"은 숫자 색으로만, "선택"은 배경·보더로만, "기록"은 점으로만 표현한다.** 한 채널을 두 상태가 함께 쓰지 않으므로 `오늘 + 선택 + 진한 점` 이 겹친 셀에서도 세 정보가 모두 읽힌다. 진한 점과 오늘 숫자가 같은 `--amber` 지만 서로 다른 요소이므로 "오늘"이라는 정보가 사라지지 않는다.
  - 선택 상태를 숫자 색·점 색으로 표현하는 구현은 금지한다(그 순간 "오늘" 또는 "기록"이 지워진다).
- **R16.** 날짜 셀은 선택 가능하다. **미래 날짜도 선택할 수 있다** — 기본 선택은 오늘이다. 선택된 날짜의 패널은 다른 날짜와 같은 규칙으로 렌더하며, 미래 날짜 전용 문구를 두지 않는다(`기록 있음` 이 거짓이면 R21 의 빈 상태 문구가 그대로 쓰인다). 미래 날짜에도 점이 있을 수 있으므로(R10) 미래를 특별 취급하는 것이 오히려 거짓말이 된다.

> ⚠️ 가정: **점 등급은 "횟수" 기준이며, 뽀모의 길이 차이를 반영하지 않는다.**
> 1뽀모의 길이는 pomo-baseline 이 소유하는 값이고 주별 스냅샷으로 달라질 수 있으며,
> 타이머 조절도 자유롭다. 따라서 5분 4회인 날과 25분 4회인 날이 **같은 진한 점**으로 보인다.
> 길이·시간 기준의 강도 표현(예: 총 집중 시간 기반 히트맵)은 **v1 비범위**다.
> 임계값 `4` 는 상대값(그 주 예산 대비 등)이 아니라 **절대값이며, 시안 v7 에서 온 값**이다 —
> 사용자 데이터에서 도출한 근거는 없다.
> 리뷰는 **점을 1단계(있음/없음)로 줄이는 대안**도 제시했다. 그러면 이 가정과 R15 의 채널
> 충돌 문제가 함께 사라지지만, "많이 한 날"의 시각적 밀도가 없어진다. v1 은 2단계를
> 유지하고 위 한계를 명시하는 쪽으로 간다.

### 날짜 기록 패널

- **R17.** 날짜를 선택하면 하단 패널에 그 날짜의 기록을 표시한다: 날짜 라벨(**`YYYY년 M월 D일`** — 표시 월과 선택 날짜의 달이 다를 수 있으므로 연도를 포함한다, R8), 그 날짜에 귀속된 완료 focus 세션 수, 그리고 그날의 조각 목록.
- **R18.** 그날의 조각 목록은 **두 원천의 합집합(중복 제거)** 으로 구성한다:
  1. `task_pulls(task_id, pull_date)` 에서 `pull_date` 가 그 날짜인 행 — "그날 오늘 목록에 있었다" (ADR-011 §2)
  2. 그 날짜에 귀속된 세션(`sessions.local_date` = 그 날짜)이 연결된 task — "그날 이 조각으로 집중했다"

  두 원천이 필요한 이유: **사후 캡처로 이름이 붙은 조각은 오늘 목록을 거치지 않아 pull 행이 없다.** 원천 1만 쓰면 자유 집중 3회 후 각각 이름을 붙인 날의 패널에 사용자가 붙인 이름 세 개가 나타나지 않는다. 반대로 원천 2만 쓰면 가져왔지만 집중하지 않은 조각이 사라진다.
  - 목록의 각 항목은 **출처를 구분해 표시한다**: 원천 1에만 해당(가져왔고 세션 없음) / 원천 2에만 해당(세션으로 생긴 항목, 사후 캡처 포함) / 둘 다.
  - today-tasks 의 "× 로 뺐지만 그날 세션이 있는 조각은 행을 지우지 않고 **치움 표시**만 남긴다" 규칙과 정합한다 — 치움 표시된 행도 원천 1에 그대로 포함되며, 패널은 그 사실을 숨기지 않는다.
  - `task_pulls` 는 오늘 날짜만 기록되고 미래 날짜 pull 은 v1 비범위다 (ADR-012 §2).
- **R19.** 각 조각의 완료 여부는 `tasks.completed_at`(ADR-011 §5)의 **NULL 여부로만** 판정한다 — **현재 완료 상태**를 표시한다. `completed_at` 은 순간(UTC)이며 달력 키가 아니므로(ADR-009 §1), 그 값에 로컬 날짜 변환을 씌워 "대상 날짜보다 늦으면 미완료"로 판정하지 **않는다.** 그 판정은 조회 시점 로컬 변환이고 ADR-009 §2 가 금지한 것이며, 타임존을 옮기면 과거 화면의 완료 표시가 뒤집힌다.
  - **잃는 정밀도(명시적 수용):** 8월 1일에 가져와 8월 5일에 끝낸 조각은 **8월 1일 패널에서도 완료로 보인다.** 날짜 패널이 복원하는 것은 "그날 목록에 있던 조각(+ 그날 세션이 붙은 조각)"이며, 완료 여부는 "지금 끝났는가"다. 즉 목록은 그 날짜의 사실이고 완료 표시는 현재의 사실이다.
  - 같은 이유로 **완료를 해제하면 과거 날짜 패널의 완료 표시도 소급해서 되돌아간다.** today-tasks 가 완료 해제를 허용하므로 이는 도달 가능한 경로다.

> ⚠️ 가정: 시점별 완료 여부를 정확히 복원하려면 `tasks` 에 **불변 완료 달력 키**
> (완료 처리 시 1회 계산해 저장하는 `completed_local_date` 성격의 컬럼)를 추가해야 한다.
> 그것은 스키마 확장이며 **새 ADR 이 선행되어야** 하므로(ADR-011 의 컬럼 집합 변경 +
> ADR-009 의 달력 키 규약 적용), 이 문서는 그 선택지를 기록만 하고 v1 은 위 후퇴안으로 간다.
> 후퇴안의 대가는 R19 에 적힌 정밀도 손실 하나로 한정된다 — 조각 목록 자체의 복원은 온전하다.

- **R20.** 요약 줄에는 조각이 있을 때 완료/전체 개수를 함께 표시한다(예: `할 일 2/3 완료`). 조각이 없으면 집중 횟수만 표시한다. 이 개수는 R19 의 현재 완료 상태 기준이다.
- **R21.** `기록 있음(D)` 이 **거짓인** 날짜를 선택하면 빈 상태 문구 `이날은 기록이 없어요` 를 표시한다 (R5 의 술어를 참조하며 조건을 다시 정의하지 않는다). 결핍·훈계 표현을 쓰지 않는다 (원칙 6·7, principles.md §1).
  - **선택 날짜가 오늘이고 focus 세션이 idle 일 때만** CTA **`자유 집중 시작`** (고스트 버튼)을 함께 렌더한다. 동작은 타이머 카드의 `시작` 과 완전히 동일하며(진입점일 뿐, 상태 기계는 timer 소유), 세션이 완료되면 이 날짜에 점이 생긴다 — 카피가 말하는 "기록 없음"을 사용자가 지금 바꿀 수 있는 유일한 정직한 행동이다.
  - **과거·미래 날짜에는 CTA 를 두지 않는다.** 지나간 날짜의 기록을 만들 방법은 없고, 없는 행동을 권하는 버튼은 거짓말이다.
  - 이 CTA 는 R23(패널 읽기 전용)과 충돌하지 않는다 — R23 이 금지하는 것은 **기록의 조작**(완료 토글·삭제·재-pull)이고, 세션 시작 진입점은 기록을 편집하지 않는다.
  - 콜드 스타트의 기본 선택은 오늘(R16)이므로, 이 규칙으로 app-shell 콜드 스타트 요구(카피 1 + CTA 1)가 충족된다.
- **R22.** 오늘 날짜가 선택된 상태에서 세션이 완료되거나 오늘 목록이 바뀌면 패널이 갱신된다. 과거 날짜가 선택된 상태에서는 **그날의 조각 목록과 집중 횟수**가 오늘의 변화로 바뀌지 않는다(완료 표시는 R19 의 예외).
- **R23.** 패널은 읽기 전용이다. 조각의 완료 토글·삭제·재-pull 을 여기서 제공하지 않는다.

### 공부한 날 수 표시

- **R24.** 이번 주 기준 공부한 날 수를 `이번 주 N일 공부 중` 으로 표시한다. 여기서 "이번 주"는 **월요일 시작 주**이며(ADR-010), 집계 대상 날짜의 판정은 R5 의 `기록 있음` 이 아니라 **완료 focus 세션 ≥ 1 인 날**이다 — 이 문구가 말하는 것은 "공부한 날"이고, 조각을 체크만 한 날은 집중한 날이 아니다. 이 차이는 의도된 것이며, 캘린더 점(R5)과 다른 조건을 쓰는 **유일한 지점**이다.
- **R25.** N=0 이면 `오늘부터 기록이 쌓여요` 를 표시한다. 끊긴 날·못 한 날을 세거나 실패로 프레이밍하는 표현(연속 기록 중단 경고 등)을 쓰지 않는다 (원칙 6·7, principles.md §1).

> ⚠️ 가정: v1 의 이 표시는 "연속 일수(consecutive streak)"가 아니라 **이번 주에 공부한 날의 수**다.
> 초안 §3.5 는 이를 "스트릭"이라 불렀지만 시안 v7 의 실제 계산은 주 내 일수 카운트이며,
> 연속 일수 정의(주 경계를 넘는 사슬, 끊김 처리)에 대한 결정은 없다. 연속 일수 도입은
> v1 비범위로 두고, 필요해지면 별도 결정으로 추가한다.

### 경계·소유권

- **R26.** **표시 대상 월(`YYYY-MM`) 상태는 이 기능이 소유하고 외부에 공개한다.** 월 이동(R8)의 결과는 이 값 하나이며, 같은 MONTH 컬럼에 놓이는 milestones 의 월간 카드는 **이 값을 따라 전환한다**(자기 월 상태를 따로 갖지 않는다). 캘린더 그리드와 마일스톤 카드가 서로 다른 달을 말하는 상태가 존재할 수 없다.
- **R27.** 타이머 카드 하단의 "공부한 날 수" 위젯(R24·R25)은 **데이터와 카피의 소유가 이 기능**이고, **렌더되는 자리만 타이머 카드**다. 문구·판정 조건을 바꿀 때 고치는 문서는 이 PRD 이며, 타이머 문서는 자리(행)만 갖는다. (타이머 카드 구성표에 그 행을 추가하는 작업은 후속 PR — 리뷰 결정 원장의 "문서 수정으로 닫은 것" 표 마지막 항목.)

### 구현 메모

- `task_pulls` 의 PK 는 `(task_id, pull_date)` 순서다 (ADR-011 §2). 따라서 **`pull_date` 단독 조회(R18 의 원천 1)는 이 인덱스의 선행 컬럼을 쓰지 못해 스캔이 된다.** 날짜 패널이 실제로 그 조회를 하므로 **초기 마이그레이션에서 `idx_task_pulls_date` 를 만든다** (ADR-019 §8).

## 성공 지표

- 계획·task 가 0개이고 세션만 있는 DB 에서 캘린더 점·날짜 패널·공부한 날 수가 전 구간 동작 (원칙 1 검증)
- **술어 참조의 단일성:** 코드에서 `기록 있음` 판정이 한 함수에만 존재하고, 점·조각 목록·빈 상태가 그 함수를 호출한다(각자 조건을 재작성한 곳이 0). R24 는 명시된 예외다.
- 같은 날짜에 대해 캘린더가 "점 없음"인데 날짜 패널이 조각·집중 횟수를 표시하는 조합이 존재하지 않는다(그 역도 성립).
- **과거 날짜 조각 목록의 재현성:** 같은 과거 날짜를 며칠 뒤에 다시 열어도 **조각 목록과 집중 횟수가 동일하다.** — 예외: 각 조각의 **완료 표시**는 현재 상태이므로, 그 뒤에 완료·완료 해제가 있었다면 달라진다 (R19 에서 수용한 정밀도 손실).
- "공부한 날 수"는 목표 수치로 삼지 않는다 (많을수록 좋다는 프레임을 만들지 않는다 — 원칙 7)
