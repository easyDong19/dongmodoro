# PRD: timer

> 출처: docs/origin/pomodoro-prd.md §3.1 (초안) + [결정 원장](../../decision-log/2026-08-04-planning-session.md) §B (Q3·Q4·Q16), §A (Q2)
> 후속 정정: [리뷰 결정](../../decision-log/2026-08-04-review-decisions.md) D1·D2·D3·D4 (ADR-012·013·014)
> 초안과 이 문서가 다르면 이 문서가 이긴다.

## 문제

집중 시간을 재는 도구는 많지만, "잰 결과"가 계획과 같은 데이터로 이어지지 않으면
주간 계획 대비 소진을 집계할 수 없다. 타이머가 만든 세션 기록 하나가 오늘 목록의
도트, 주간 게이지, 캘린더 점, 월간 마일스톤 소진의 유일한 원천이 되어야 한다
(원칙 8 — 집계는 아래→위 단방향 파생).

## 대상 사용자

- 앱 소유자 1인 (로컬 단독, 로그인·멀티유저 없음)

## 목표

1. 계획이 0개여도 타이머·기록·알림이 완전히 동작한다 (원칙 1).
2. 완료된 focus 세션 1회 = 1뽀모라는 화폐가 정확히 한 번, 유실 없이 기록된다.
3. 기록 마찰 최소화 — 세션 시작 전에 무엇도 묻지 않는다.

## 범위 / 비범위

**범위:** 타이머 카드(모드·조절·시작/정지/초기화·완료 처리), 집중 대상 지정,
focus 완료 시 세션 기록, 사후 캡처 바, 모드 자동 전환, 완료 알림,
focus 실행 중 앱 종료 확인.

**비범위:**
- 트레이 아이콘·창 수명 주기, 그리고 **종료 요청 경로의 열거** (→ app-shell.
  이 문서는 "focus 실행 중 종료 요청 시 확인"이라는 조건만 정의한다)
- 뽀모 길이(25/5/15) 변경 UI 와 그 효력 시점 (→ pomo-baseline.
  편집은 상시 가능하고 저장 즉시 효력을 가진다 — 적용 시점은 **다음 세션 시작**이다,
  [ADR-029](../../architecture/decisions/adr-029-baseline-immediate-effect.md) §1)
- 오늘 목록 자체의 관리 (→ today-tasks. 이 문서는 "그 목록에서 대상을 고른다"까지만)
- 크래시 복원 (Q16 소결정 — v1 에서 만들지 않음)
- 완료 세션 롤백·수정 UI (Q4 — 오조작이 실제로 잦아지면 후속 버전에서 재검토).
  세션은 벌어진 사실이므로 삭제도 하지 않는다 —
  [ADR-014 §2](../../architecture/decisions/adr-014-deletion-and-archive.md) (`sessions.deleted_at` 없음)

## 요구사항

### 모드와 조작

- **R1.** 모드는 `focus` / `short` / `long` 3종이다. 길이 기본값은 25/5/15분이며,
  기준값은 **pomo-baseline 이 소유하는 조회 계약 `유효 베이스라인(week)` 의 반환값**을 쓴다.
  이 문서는 그 값을 소비할 뿐 해석 규칙(스냅샷 유무·폴백)을 소유하지 않는다
  ([ADR-013](../../architecture/decisions/adr-013-baseline-budget-effect.md) §2 — 세션이 있는 주는
  반드시 자기 스냅샷을 가진다).
  - 사용자가 길이를 편집해도 **진행 중인 주의 기준 길이는 변하지 않는다** — 효력은 다음 주
    경계부터다 (ADR-013 §3). "길이 변경은 주간 정산에서만"이라는 이전 전제는 폐기됐다.
- **R2.** 시간 조절은 ±1/±5/±10분 칩으로 하며, 실행 중에도 가능하고, 하한은 1분이다.
- **R3.** 시작 / 일시정지 / 초기화를 제공한다. 초기화는 현재 모드의 기준 길이로 되돌린다.
- **R4.** (Q4) **완료 처리** 버튼: 실행 중 남은 시간과 무관하게 그 세션을 완료로
  기록한다. 온전한 1뽀모로 집계되며, 실제 경과 시간이 별도로 저장되어 시간 기준
  통계를 나중에 복원할 수 있다.

### 집중 대상

- **R5.** 오늘 목록의 task 1개를 집중 대상으로 지정할 수 있다. 미지정이거나 대상이
  완료 상태면 "자유 집중"이다. 대상 지정은 main 에 IPC 명령으로 전달되어 타이머
  상태의 일부가 된다 (renderer 전역 상태 아님 — ADR-005).

### 세션 기록 (focus 완료 시)

- **R6.** focus 세션이 완료되면(자연 만료 또는 R4) sessions 에 무조건 1행이
  기록된다. task 연결은 집중 대상이 있으면 그 task, 없으면 NULL(미분류).
- **R7.** 세션의 날짜·주 귀속은 **시작 시각 기준**이며(Q2), 기록 시점에 1회 계산해
  불변 저장한다 (ADR-009 달력 키, ADR-011 §3).
  - 참조(이 문서가 소유하지 않음): 항목별 소진 집계는
    `sessions.local_week = week_items.week` 조건으로 계산된다
    ([ADR-012](../../architecture/decisions/adr-012-aggregation-predicate.md) §1).
    즉 **세션의 주가 그 세션의 집계 귀속을 결정한다** — 항목의 주와 어긋나는 세션은
    그 주의 미분류로 떨어진다.
- **R8.** (사후 캡처) 자유 집중이 완료되면 캡처 바가 나타난다. 한 줄 입력 시 완료된
  task 를 소급 생성해 세션에 연결한다. 소급 task 가 붙는 시스템 "기타" 항목은
  **그 세션의 `local_week` 기준**으로 선택·생성한다 — "오늘"의 주가 아니다
  ([ADR-012](../../architecture/decisions/adr-012-aggregation-predicate.md) §3, ADR-011 §4).
  자정을 걸친 세션에서는 두 값이 다르다.
  건너뛰기·Esc 면 미분류로 남는다. **세션 시작 전에 묻는 다이얼로그는 금지한다.**
  캡처 바는 사용자 행동(기록·건너뛰기·Esc)으로만 닫히며, 다음 세션이 시작돼도
  대기 상태가 취소되지 않는다 (ux-spec §5).
- **R9.** 휴식(short/long) 완료도 세션으로 기록하되, 뽀모 집계에는 포함하지 않는다.

### 사이클과 알림

- **R10.** (Q3) focus 완료 시 모드가 휴식으로 자동 전환된다 — 마지막 long 세션 이후
  focus 4회째면 long, 아니면 short (S10 파생식 — 자정 경계에서 끊기지 않는다).
  휴식 완료 시 focus 모드로 돌아온다. **다음 세션의 시작은 항상 사용자가 누른다.**
- **R11.** 세션 완료 시 알림음과 OS 알림을 보낸다.

### 소유권과 종료

- **R12.** 완료 판정·세션 기록·알림은 main 프로세스만 수행한다 (ADR-005).
  renderer 의 표시 계산이 0에 도달해도 아무 사실도 만들지 않는다.
- **R13.** (Q16) **종료 요청이 들어왔을 때 focus 가 running/paused 이면** 확인을 1회 묻는다 —
  종료하면 그 세션은 기록되지 않는다. 조건은 종료 경로와 무관하게 동일하며,
  **어떤 조작이 종료 요청인지의 열거는 app-shell 이 소유한다.** 창 닫기(×)는 종료가 아니며
  타이머는 계속 돈다 (상세는 app-shell).

## 성공 지표

- 계획 데이터가 0인 새 DB에서 타이머 시작→완료→기록이 전 구간 동작 (원칙 1 검증)
- 세션 유실 0: 완료 판정 시점의 강제 종료를 제외하면 focus 완료 1회당 정확히 1행
- 사후 캡처 입력률은 지표로 삼지 않는다 (건너뛰기가 실패가 아님 — 원칙 7)
