# UX Spec: timer

> 시각 값은 전부 [tokens.md](../../design-system/tokens.md) 토큰 이름으로 기술한다. 시각 판단이 [principles.md](../../design-system/principles.md) 와 충돌하면 그쪽이 이긴다.

## 1. 카드 구성 (위→아래)

| 요소 | 내용 |
|---|---|
| 모드 탭 | `집중` / `짧은 휴식` / `긴 휴식` 3개. 활성 탭 강조는 `--glass-strong` |
| 진행률 링 | SVG 원형. 진행분은 `--teal` → `--amber` 그라디언트 (tokens.md §1.4 — 별도 그라디언트 색 금지) |
| 시간 표시 | 링 중앙 `MM:SS`. `--font-mono` + `--text-display` + tabular-nums |
| 세션 라벨 | 시간 아래 한 줄 — 현재 모드/차례 표시 (§4) |
| 집중 대상 | 세션 라벨 아래. 지정된 task 제목, 미지정 시 `자유 집중` (`--ink-dim`) |
| 조절 칩 | `−10 −5 −1 | +1 +5 +10` (분). radius 는 `--radius-sm` |
| 액션 버튼 | `초기화`(ghost) · `시작/일시정지`(primary) · `완료 처리`(ghost) |
| 공부한 날 수 | 액션 버튼 아래 한 줄. 이번 주 기준 공부한 날 수를 표시하는 자리. **이 문서는 자리(카드 하단, 액션 버튼 다음)만 정의하고, 표시 내용·집계 술어·카피의 소유는 calendar-records 기능이다** |
| 캡처 바 | 평소 숨김. 자유 집중 완료 직후에만 등장 (§5) |

## 2. 상태 기계

상태 = 모드(`focus`/`short`/`long`) × 진행(`idle`/`running`/`paused`).
전이의 사실은 전부 main 이 push 하는 이벤트다 — renderer 는 표시만 바꾼다 (ADR-005).

| 현재 | 행동 | 다음 | 비고 |
|---|---|---|---|
| idle | `시작` | running | |
| running | `일시정지` | paused | primary 버튼 라벨이 `일시정지` ↔ `계속` 토글 |
| paused | `계속` | running | |
| running/paused | `초기화` | idle | 현재 모드 기준 길이로 리셋. 기록 없음 |
| running/paused | `완료 처리` | idle (모드 자동 전환) | focus 면 온전한 1뽀모로 기록 (PRD R4) |
| running | 시간 만료 | idle (모드 자동 전환) | 완료 기록 + 알림 (§6) |
| idle/running/paused | 모드 탭 클릭 | 해당 모드 idle | 실행 중 전환은 확인 없이 현재 세션 폐기 — 기록 없음 |

- 조절 칩은 idle·running·paused 모두 동작, 하한 1분 (PRD R2).
- `완료 처리`는 focus 의 running/paused 에서 노출된다.

> ⚠️ 가정: 휴식 모드의 running 중에도 같은 자리 버튼이 "휴식을 끝내고 집중으로
> 복귀" 로 동작한다 (시안의 버튼 배치 유지). 휴식 세션은 기록되되 집계 미포함(PRD R9)
> 이라 데이터 영향이 없다. 구현 시 라벨만 `완료 처리` 대신 `건너뛰기` 로 둘지 재판단.
>
> 이 가정은 내로우 축약형(§9)에서 더 강하게 작용한다 — 축약형에는 모드 탭이 없으므로,
> 같은 자리의 시작/일시정지 버튼이 **자동 전환된 휴식을 시작하는 유일한 경로**다.
> 축약형에서 이 버튼이 사라지거나 다른 뜻을 가지면 사용자는 휴식을 시작할 수 없다.

## 3. 모드 자동 전환의 표시

- focus 완료 → 모드 탭이 자동으로 `짧은 휴식` 또는 `긴 휴식` 으로 이동하고 idle 로
  선다. **자동으로 시작하지 않는다** (PRD R10).
- 긴 휴식 차례(마지막 long 이후 focus 4회째 완료)면 `긴 휴식` 탭이 선택되고,
  세션 라벨에 차례임을 알린다 (§4).
- 휴식 완료 → `집중` 탭 idle 로 복귀.

## 4. 세션 라벨 문구

| 상황 | 문구 |
|---|---|
| focus idle/running | `N번째 집중` (오늘 시작 기준 서수) |
| short 대기 | `짧게 쉬어가요` |
| long 대기 (4회차) | `네 번째 집중 완료 — 길게 쉴 차례예요` |
| 휴식 running | `쉬는 중` |

문구는 사실만 말하고 판단하지 않는다 (principles §1). "잘했어요" 류의 평가 문구 금지.

## 5. 사후 캡처 바

- **등장**: 자유 집중(대상 미지정) focus 세션 완료 직후, 타이머 카드 하단.
- **입력창** placeholder: `이 N분, 뭐 했는지 한 줄 남길래요?` — N 은 실제 경과 분.
  최대 60자. 버튼: `기록` / `건너뛰기`.
- **닫힘**: **사용자 행동으로만 닫힌다** — `기록` 저장 / `건너뛰기` / `Esc` 세 가지뿐이다.
  **다음 세션(휴식·집중)이 시작돼도 대기 상태는 취소되지 않는다.** 좁은 창에서 다른 탭에
  있는 동안 세션이 끝나면 셸이 캡처 바 노출을 다음 `오늘` 탭 진입 시점으로 지연하는데,
  "다음 세션 시작 시 자동 닫힘"이 있으면 그 사이에 휴식을 시작한 사용자는 캡처 바를
  보지도 못하고 기회를 잃는다 — 넓은 창에는 없는 손실이라 같은 기능이 창 크기에 따라
  달라진다. 어느 경로든 세션 기록 자체는 이미 저장돼 있다 — 캡처는 이름 붙이기일 뿐,
  잃는 것이 없다.
- **금지**: 세션 시작 전에 목적을 묻는 다이얼로그 (PRD R8). 캡처 바가 다른 조작을
  막아서도 안 된다 (모달 아님).
- 집중 대상이 있던 세션 완료 시에는 나타나지 않는다.

## 6. 완료 알림

- OS 알림 (Electron Notification) + 알림음. 문구:
  - focus 완료: `집중 완료 — 쉬어가요`
  - 휴식 완료: `휴식 끝 — 준비되면 시작하세요`
- 알림을 눌러 창이 복원되어도 자동 시작하지 않는다.

## 7. 종료 확인 다이얼로그 (Q16)

- **조건**: **종료 요청이 들어왔을 때 focus 가 running/paused 인 경우**에 1회 묻는다.
  그 외 상태의 종료 요청은 확인 없이 즉시 종료한다. **어떤 경로가 종료 요청인지(키 조합·
  앱 메뉴·트레이 메뉴 등)의 열거는 app-shell 이 소유한다** — 이 문서는 특정 키나 메뉴를
  지정하지 않으며, 모든 종료 경로가 이 조건 하나를 공통으로 통과한다.
- **소유 경계**: 문구·버튼 구성·`--danger` 미사용 판단은 계속 이 문서가 소유한다.
- **문구**: 제목 `지금 종료할까요?` / 본문 `종료하면 진행 중인 이 세션은 기록되지 않아요.`
- **버튼**: `계속 집중`(기본 포커스) / `종료`. 종료를 파괴적 행위로 보아 `--danger`
  를 쓰지 않는다 — 세션 하나가 안 남을 뿐 데이터를 없애는 게 아니다 (principles §2).
- 창 닫기(×)는 이 다이얼로그와 무관 — 창만 닫히고 타이머는 계속 (app-shell ux-spec 소관).

## 8. 모션·아이콘

- 링 진행은 상태 변화의 결과 전달이므로 허용. `prefers-reduced-motion: reduce` 시
  전이 애니메이션 없이 즉시 반영 (principles §4).
- 이모지 금지. 아이콘이 필요한 곳(알림·버튼)은 lucide-react, 뽀모 개수 표현은
  커스텀 뽀모 도트 컴포넌트 (principles §6).

## 9. 반응형

- 와이드·미디엄: 타이머 카드는 중앙 컬럼에 §1 구성 그대로.
- 내로우(< `--bp-medium`): 상단 고정 축약형 — 링 없이 `MM:SS` + 모드 + 시작/일시정지만.
  축약형의 상세 배치는 app-shell ux-spec 이 정의한다.
