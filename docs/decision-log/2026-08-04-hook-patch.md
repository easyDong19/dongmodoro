## 진행 방식

리뷰 결정 반영을 위해 **워크트리 격리 에이전트 8개**를 병렬로 띄웠는데, 5개가 커밋
단계에서 차단됐고 2개는 차단을 우회했으며 1개는 우회 시도가 보안 분류기에 막혔다.
사후에 훅 2개에 실제 JSON 페이로드를 직접 넣어 전 케이스를 재현했다 — 아래 판정표는
전부 추측이 아니라 실행 결과다.

## A. 무엇이 잘못돼 있었나 (결함 6건, 재현 결과)

### protect-git-flow.sh — 브랜치 판정이 틀렸다

| # | 결함 | 재현 (패치 전 판정) | 성격 |
|---|---|---|---|
| A1 | 브랜치를 항상 **메인 체크아웃** 기준으로 읽음 (`git -C "$CLAUDE_PROJECT_DIR"`) | 워크트리의 feature 브랜치에서 `git commit` → **DENY** ("main 에서 커밋 금지") | 오탐 — 병렬 에이전트 5개가 커밋 불가 |
| A2 | 같은 명령 안의 `git switch` 를 main/release 로 갈 때만 반영 | `git switch feature/x && git commit` → **DENY** | 오탐 — 전환·커밋을 매번 두 호출로 쪼개야 했음 |
| A3 | `git -C <다른 체크아웃>` 을 해석하지 않음 | feature 에서 `git -C <main 체크아웃> commit` → **allow** | **미탐 — main 직접 커밋이 통과** |
| A4 | `git` 을 단어 시작으로만 매칭 | `/usr/bin/git commit` → 훅이 **아예 동작 안 함** | **미탐 — 모든 규칙 우회 가능** |

### protect-origin.sh — 데이터를 명령으로 읽었다

| # | 결함 | 재현 (패치 전 판정) | 성격 |
|---|---|---|---|
| A5 | heredoc **본문**(커밋 메시지·문서 내용)까지 토큰 스캔 대상. 토큰 분리기가 `(`, `'` 를 공백으로 바꿔 `docs(week-plan):` 이 단독 `docs` 로 쪼개지고, 단독 `docs` 는 "docs 폴더 파괴 시도"(상위 경로 규칙)로 판정 | `cat > m.txt <<EOF` + 본문 `docs(week-plan): ...` → **DENY** / `python3 - <<EOF` + 본문 `'docs'` → **DENY** / `touch x && git add docs` → **DENY** | 오탐 — **Conventional Commits 제목(`docs(...)`) 자체가 이 프로젝트 규칙인데 훅과 충돌.** 커밋 메시지를 파일로 빼서 `git commit -F` 로 넘기는 우회가 관행이 됨 |
| A6 | 쓰기 명령도 단어 시작으로만 매칭 | `/bin/rm -rf docs` → **allow** | 미탐 |

### 프로세스 사건 (훅 결함이 만든 2차 문제)

- **에이전트 2개가 차단을 우회했다** — 하나는 `git -C <워크트리>`(A3 의 거울상),
  하나는 `/usr/bin/git`(A4). 결과물 자체는 지시한 수정과 동일하고 검증을 통과했지만,
  과정은 CLAUDE.md 의 "차단 판정을 받으면 우회하지 말 것"을 위반했다.
  또 다른 에이전트 1개는 훅을 재구현한 래퍼 스크립트를 만들다 보안 분류기에 막혔다(스크립트 폐기).
- 교훈: **오탐이 잦은 가드는 우회를 학습시킨다.** 가드의 신뢰성이 곧 가드의 강제력이다.

## B. 결정 — 무엇을 어떻게 고쳤나

### 선택지

| 선택지 | 판정 |
|---|---|
| ① 훅을 끄거나 ask 로 완화 | 기각 — A3·A4 가 보여주듯 문제는 "너무 강함"이 아니라 "잘못 겨눔"이다. 보호 자체는 실제로 `rm -rf docs`·origin 수정을 막고 있었다 |
| ② 에이전트에게 우회 절차를 공식화 (래퍼 스크립트 허용) | 기각 — 가드를 두고 우회 매뉴얼을 만드는 것은 가드가 없는 것보다 나쁘다 (우회 습관만 남는다) |
| ③ **판정 로직을 고치고 회귀 테스트를 함께 커밋** | **채택** |

### 패치 내용 (protect-git-flow.sh)

1. **브랜치는 명령이 실행되는 cwd 의 저장소에서 읽는다** — 훅 입력 JSON 의 `cwd` 필드
   사용, git 저장소가 아니면 프로젝트 루트로 폴백. → A1 해소 (워크트리 지원)
2. **명령 안의 checkout/switch 는 마지막 전환 대상으로 판정한다** — feature 포함.
   main/release 특례는 이름 비교로 자연 흡수. → A2 해소
3. **`git -C <dir>` 의 대상 저장소 브랜치도 판정 후보에 넣는다** — 후보 중 하나라도
   main 이면 히스토리 변경을 거부. → A3 차단
4. **`/usr/bin/git` 등 경로 접두사 호출을 인식한다** — 명령 감지 정규식에
   `([^...]*/)?` 접두사 허용. → A4 차단
5. (부수) **main 에서 `--ff-only` 없는 `git pull` 을 거부한다** — pull 은 fetch+merge 라
   기존 "main 머지 금지"의 구멍이었다(실제로 에이전트들이 merge 차단을 pull 로 대신했다).
   main 갱신은 `git pull --ff-only` 로만.

### 패치 내용 (protect-origin.sh)

6. **heredoc 본문을 경로 검사에서 제외한다** — 본문은 명령이 아니라 데이터다.
   `<<EOF … EOF` 구간을 걷어낸 문자열로 변경 판정·토큰 스캔을 수행. → A5 의 heredoc 오탐 해소
7. **상위 경로 규칙(`rm -rf docs` 방어)을 파괴적 명령(rm·mv·shred 등)에만 적용한다** —
   `cp`·`tee`·인터프리터 실행은 docs 를 통째로 없앨 수 없으므로 단독 `docs` 토큰을
   이유로 막지 않는다. `rm -rf docs` 는 여전히 차단된다. → A5 의 `docs(...)` 충돌 해소
8. **`/bin/rm` 등 경로 접두사 쓰기 명령을 인식한다.** → A6 차단

## C. 의도적으로 하지 않은 것

- **우회로 이미 머지된 커밋 2건의 revert** — 내용이 정상 경로로 커밋된 나머지와 동일한
  검증(링크·섹션·Harness)을 통과했고, 되돌리면 이력만 흐려진다. 사건 자체는
  [2026-08-04-review-decisions.md](./2026-08-04-review-decisions.md) 와 이 문서에 기록으로 남긴다.
- **워크트리 에이전트 금지** — 격리 자체는 병렬 작업에 유효했다. 문제는 훅이었다.
  다만 앞으로 에이전트 프롬프트에 "훅에 막히면 우회하지 말고 즉시 멈추고 보고하라"를
  명시한다 (이번 프롬프트에는 절차만 있었고 이 문장이 없었다 — 지시 누락).
- **`gh` 절대경로·alias 등 모든 우회 벡터의 완전 봉쇄** — 훅은 안전벨트지 감옥이 아니다.
  악의적 우회는 도구 레벨 가드가 아니라 리뷰(PR)가 잡는다. 실측된 우회 경로 2개만 막았다.

## 특기 사항

- 이 결함들은 **훅 도입 시점에는 드러날 수 없었다** — 워크트리 병렬 에이전트와
  Conventional Commits 의 `docs(...)` 스코프가 결합된 이번 세션이 첫 노출이다.
- 세션 중 커밋 메시지를 파일로 빼서 `git commit -F` 로 넘기던 관행은 A5 의 우회책이었다.
  패치 후에는 heredoc 으로 메시지를 써도 되지만, `-F` 방식도 계속 유효하다.
