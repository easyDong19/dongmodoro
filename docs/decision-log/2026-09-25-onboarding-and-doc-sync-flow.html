1 · 결정 — 문서끼리 어긋난 온보딩

남은 문서 작업을 4단계로 정리해 보고했고, 사용자가 그중 "결정이 필요한" 항목의 상세 설명을 요구했다.

Q1 재설명

첫 실행 온보딩 화면을 어떻게 하나

문제

길이 규칙의 소유자(pomo-baseline PRD R11, ADR-033 §3)는 "편집 경로는 대기 중인 타이머 하나, 기본값은 시딩"으로 이미 정리돼 있었다. 그런데 app-shell R31·A23·ux-spec §7.1 과 PRODUCT.md 는 여전히 "온보딩이 편집 경로 중 하나"라고 적었다. 스펙대로 구현하면 편집 경로가 다시 둘이 된다.

선택지
  • 온보딩 폐기 (AI 추천) — 소유자 쪽에 나머지를 맞춘다. 대신 "길이를 바꿀 수 있다"는 안내는 ± 칩의 가시성에 기댄다
  • 유지 + ADR-033 부분 개정 — 처음부터 자기 리듬으로 시작. 대신 온보딩 값과 ± 칩의 관계, ADR-018 을 다시 정해야 한다
  • 보류 — 결정을 미룬다. 불일치는 남는다
결정

폐기. R31·A23 은 번호를 남긴 채 폐기 표기, ux-spec §7.1 은 폐기 노트로. 새 ADR 은 만들지 않는다 — 결론은 ADR-033 §3 이 이미 갖고 있다.

1번 온보딩 폐기하자

2 · 실행 — 같은 PR 의 범위를 좁힌 두 판단

사실 정정을 함께 하면서, AI 가 정할 수 없는 것과 분량이 큰 것을 뺐다.

Q2 검증

옛 UI 용어(#86) 동기화를 이번에 함께 하나

문제

#85 가 없앤 + 오늘로 버튼(동작 차이)과 #86 이 바꾼 문구(조각 만 143곳)가 섞여 있었다. PR 설명을 읽고 코드와 대조해 확인했다.

결정

+ 오늘로 만 이번에, 용어 동기화는 별도 PR. 동작이 다른 쪽이 AI 가 없앤 기능을 되살릴 위험이 크다. today-tasks R20 카피는 지어내지 않고 "다시 써야 한다" 경고만 달았다.

Q3

기능 상태(Draft·In Review·Published)를 이번에 맞추나

문제

docs/CLAUDE.md 는 상태 값 3개를 나열만 하고 뜻을 정의하지 않는다. 값을 고르는 순간 정의를 새로 만드는 셈이다.

결정

빼고 사용자에게 묻는다.

정정 반전

기타 행의 "캐럿 없음" — 잘못 고쳤다가 되돌림

week-plan ux-spec §3.4 의 "pull 버튼 없음"을 "캐럿 없음"으로 바꿨으나, §3.4 는 드릴다운용 캐럿을 정의하고 있어 스펙과 충돌했다. 커밋 전에 되돌렸다.
