1 · 방향 — 넘침을 어떻게 처리하나

사용자가 버그 두 갈래를 보고하며 스크롤 방향을 제안했고, 코드 진단이 그 방향을 뒷받침했다.

진단 검증

원인은 정책이 아니라 배선 — 높이 사슬 단절

네 카드의 코드를 읽어 확인: 주간 카드(WeekCard)만 루트에 h-full 이 있어 내부 스크롤이 정상 발동한다. 캘린더·결과물 카드는 스크롤 설정이 있어도 루트가 내용 높이로 자라 기준 높이가 성립하지 않았고, 오늘 목록은 스크롤 설정 자체가 없었다. 결과물 섹션은 하한(min-h-[148px])만 있고 상한이 없어 무한정 자랐다.

Q1

목록이 카드보다 길어지면 무엇이 일어나야 하나

문제

항목을 여러 개 넣으면 내용이 유리 카드 모서리 밖까지 그려졌다. 한 카드의 데이터량이 이웃 카드의 공간을 잠식했다.

선택지
  • 카드 안에서 목록만 스크롤 — 카드 크기가 안정, WeekCard 가 이미 쓰는 문법이라 새 패턴 아님
  • 카드가 내용만큼 자람(현상) — 데이터량이 이웃 카드 공간을 잠식
  • 항목 수 제한 — "개수를 막지 않는다"(milestones R4) 기획 원칙과 충돌
결정

카드 안에서 목록만 스크롤. 카드 골격은 창 크기에서만 결정되고 데이터량은 스크롤이 흡수한다.

지금 디자인 상 문제가 리스트들이 여러개 추가될때 카드들을 벗어나는 문제가 생김 내 생각에는 스크롤이 생겨야 한다고 생각하거든
→ Q2 (스크롤이 성립하려면 결과물 카드에 상한이 필요)
Q2

결과물 카드의 상한 — % 인가 px 인가

문제

상한이 없으면 항목 수만큼 자라 같은 컬럼의 캘린더가 짓눌린다 — 사용자가 보고한 "캘린더가 밀리는" 버그의 원인.

선택지
  • 컬럼의 40% (max-h-[40%]) — 창 높이에 비례, 큰 화면은 더 보여주고 작은 화면은 캘린더 몫을 지킴
  • 고정 px (예: 280px) — 예측 가능하지만 창이 크면 낭비, 작으면 여전히 짓누름
결정

컬럼의 40%. 하한 min-h-[148px] 는 별개 근거(달 이동 출렁임 방지)로 유지.

상한방식은 %이며, docs에 버그 수정 내역 md파일로 남겨야함 왜 이런 의사결정을 선택했고, 어떻게 조치했는지 알았으면 시작해

2 · 구현 — 승인 범위 안의 기술 결정

사용자 승인 후 AI 가 내린 구현 수준의 결정들. CSS 제약이 형태를 정했다.

Q3

높이 사슬 복구 — 왜 결과물 섹션만 flex 컨테이너인가

문제

캘린더·오늘 섹션은 flex-1 로 높이가 확정이라 자식의 h-full(%) 이 풀리지만, 결과물 섹션은 내용 따라 자라는(auto) 높이라 % 가 성립하지 않는다.

선택지
  • 결과물 섹션만 flex flex-col, 나머지는 루트에 h-full — 각 섹션의 CSS 제약에 맞는 최소 수단, WeekCard 기존 문법 유지
  • 다섯 섹션 전부 flex 컨테이너로 통일 — 일관되지만 잘 동작하는 WeekCard 까지 건드림
결정

비대칭 유지. 상한에 닿았을 때 자식을 줄이는 길이 flex 수축(min-h-0)뿐인 섹션만 flex 로. 이 비대칭은 CSS 제약이지 취향이 아니며 App.tsx 주석으로 남겼다.

Q4 · Q5

스크롤 경계와 안전망

결정

보관 목록을 스크롤 영역 안으로 — 밖에 있으면 펼치는 순간 상한을 우회해 카드를 통째로 키운다. 제목·배지·추가 버튼·직접 입력 폼은 스크롤 밖 고정 — 항목이 몇 개든 진입점이 밀려나지 않는다. 다섯 섹션 전부 overflow-hidden — 사슬이 또 끊겨도 카드 밖으로 그려지는 최악은 막는다. .card 는 표면만 소유한다는 규율이 있어 클래스가 아니라 App.tsx 섹션에 얹었다.

검증 검증 반전

e2e 회귀 테스트 — 단언 하나를 정정

jsdom 은 레이아웃을 계산하지 않아 e2e 로만 검증 가능. 임시 프로필에 항목 15개(오늘)·10개(결과물)를 넣고 scrollHeight > clientHeight· 40% 상한·캘린더 생존을 단언 (e2e/card-overflow.spec.ts). 초안의 "마지막 행이 섹션 상자 안" 좌표 단언은 Playwright boundingBox 가 overflow 클리핑을 반영하지 않아 잘못 실패 — "스크롤 전 뷰포트 밖 → 스크롤 후 안" 판정으로 정정. 최종: 유닛 791 · e2e 10 전부 통과, 실화면 스크린샷 확인.
