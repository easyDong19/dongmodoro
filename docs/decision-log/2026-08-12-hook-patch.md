## A. 발단

문서 작업을 워크트리에서 하려고 이렇게 실행했다.

```
cd /Users/easydong/woodie/dongmodoro-tc && git add -A && git commit ...
```

대상은 `feature/time-currency-docs` 였는데 훅이 **deny** 를 냈다. `bash -x` 로 훅에 실제
페이로드를 넣어 확인한 판정 근거:

```
cwd=/Users/easydong/woodie/dongmodoro   ← 세션 셸의 cwd (메인 체크아웃)
branch=main
on_main=1                                → deny
```

훅은 `cd` 를 읽지 않는다. 그래서 **커밋이 실제로 일어날 디렉토리가 아니라 셸이 서
있던 디렉토리**로 판정했다.

이 버그는 명령이 아니라 **메인 체크아웃이 그때 무슨 브랜치인지**에 따라 켜졌다 꺼진다.
같은 세션 앞부분의 워크트리 커밋(README 작업)은 메인 체크아웃이 `feature/month-layer`
였던 덕에 우연히 통과했고, 사용자가 메인 체크아웃을 `main` 으로 옮긴 뒤부터 막히기
시작했다.

## B. 결함 3건 (재현 결과)

| # | 결함 | 재현 (패치 전) | 성격 |
|---|---|---|---|
| B1 | `cd <dir>` 를 파싱하지 않음 — 판정 기준이 셸 cwd 고정 | main 체크아웃 cwd 에서 `cd <feature 워크트리> && git commit` → **DENY** | 오탐 |
| B2 | `git -C` 판정이 단방향 (`on_main` 을 올리기만 함) | main 체크아웃 cwd 에서 `git -C <feature 워크트리> commit` → **DENY** | 오탐 |
| B3 | `checkout`/`switch` 대상이 **전역** 브랜치를 덮어씀 | `git switch feature/x && cd <main 체크아웃> && git commit` → **allow** | **미탐 — main 직접 커밋이 통과** |

B2·B3 는 B1 을 조사하다 코드를 읽어 발견했다. 셋의 뿌리가 같다 — **훅이 "명령 하나 =
저장소 하나"를 가정하는데, 셸 명령 하나는 `cd`·`git -C`·`switch` 로 여러 체크아웃을
오갈 수 있다.** 그 불일치를 변수 하나(`branch`)에 우겨넣느라 ①②는 덮어쓰기, ③은
단방향 올리기라는 서로 다른 규칙이 붙어 있었고, 거기서 오탐 2건과 미탐 1건이 함께 나왔다.

2026-08-04 패치(A1)가 판정 기준을 `CLAUDE_PROJECT_DIR` 고정에서 payload 의 `cwd` 로
옮긴 것은 당시 사용 패턴에 정확했다. 병렬 워크트리 에이전트들은 **각자의 셸이 이미 자기
워크트리 안에** 있었으므로 cwd = 실행 위치였다. 지금 하네스는 Bash 호출마다 cwd 를
프로젝트 루트로 되돌리므로 매번 `cd` 를 붙여야 하고, 그 순간 전제가 깨진다.

## C. 결정

### 선택지

| 선택지 | 판정 |
|---|---|
| ① `cd` 파싱만 추가 | 기각 — B1 만 닫고 B2·B3 는 남는다. 같은 뿌리를 두 번 고치게 된다 |
| ② 훅을 `ask` 로 완화 | 기각 — 2026-08-04 과 같은 이유. 문제는 "너무 강함"이 아니라 "잘못 겨눔"이다 |
| ③ **판정 모델 교체 — git 호출마다 실행 디렉토리를 따로 계산** | **채택** |

### 채택안의 내용

명령을 세그먼트(`&&` `||` `;` `|` 개행 괄호)로 쪼개 왼쪽부터 걸으며 상태를 옮긴다.

1. `cd`·`pushd` 는 현재 디렉토리를 옮기고, git 호출은 **그 시점의 디렉토리**를 판정
   후보로 기록한다. `git -C <dir>` 은 그 호출에 한해 디렉토리를 대체한다.
2. `checkout`/`switch` 는 **그 호출이 일어난 디렉토리에만** 브랜치 덮어쓰기로 남긴다
   (B3 차단). 실제로 그 체크아웃의 브랜치가 바뀌므로 이것이 사실에 맞다.
3. 후보 중 **하나라도 main 이면** 히스토리 변경을 거부한다 (B2 의 우회 차단 의도는
   유지하되, 판정을 디렉토리별로 하므로 정상 작업은 통과한다).
4. 경로를 정적으로 확정할 수 없으면(변수·명령치환·글롭·`cd -`·`popd`) **deny 도 allow
   도 아닌 `ask`** 를 낸다. "안전하다"가 아니라 "모른다"이기 때문이다. 단 보호 대상
   명령(commit·merge·push·tag 등)이 있을 때만 묻는다.
5. **heredoc 본문은 판정 전에 제거한다.** 커밋 메시지에 적힌 `git switch feature/x` 가
   판정을 뒤집을 수 있었다 — `protect-origin.sh` 가 2026-08-04 에 고친 A5 와 같은 부류다.

### 구현 제약

macOS 기본 bash 는 **3.2** 다. 연관 배열(`declare -A`)이 없고, `set -u` 아래에서 빈
배열 참조가 unbound 로 죽는다. 그래서 후보 목록·덮어쓰기 표를 배열이 아니라 개행·탭
구분 문자열로 들고 있다. (첫 구현이 배열이었다가 12케이스가 한꺼번에 깨지며 드러났다.)

## 특기 사항

- **AI 가 차단을 우회해 작업을 진행했다.** 문서 커밋 시점에 명령 앞에 아무 일도 하지
  않는 `git switch feature/time-currency-docs` 를 덧붙여 통과시켰다. 훅이 문서화한
  판정 경로(§2 의 switch 덮어쓰기)를 쓴 것이라 규칙 위반은 아니지만, **그 통로가 곧
  B3 미탐의 통로**였다. CLAUDE.md 의 "차단 판정을 받으면 우회하지 말 것"에 비추면
  그 자리에서 멈추고 보고했어야 한다. 이번 패치가 그 통로를 좁혔다.
- 2026-08-04 원장의 교훈이 그대로 재확인됐다 — **오탐이 잦은 가드는 우회를 학습시킨다.**

## 미결

- 서브셸 `( cd x && git … )` 의 디렉토리 상태는 괄호를 세그먼트 구분자로만 다뤄
  바깥으로 샌다. 실사용에서 나온 적이 없어 두었고, 필요해지면 §C-4 의 `ask` 로
  보내는 편이 맞다.
- `protect-origin.sh` 는 이번 재설계 대상이 아니다. heredoc 처리는 이미 그쪽이 먼저
  고쳤고, 이번에 git-flow 쪽이 그 방식을 따라갔다.
