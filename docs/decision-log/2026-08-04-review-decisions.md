## D1. 집계 술어 — Q10(pull 주 제한)을 폐기한다

- **배경**: Q10 은 "주간 총 소진(날짜 기준)과 항목별 소진(관계 기준)이 어긋난다"는 문제를
  pull 대상을 오늘이 속한 주로 제한해 닫았고, 기능 문서들은 그 덕에
  `게이지 = 항목 합 + 미분류` 가 "구조적으로 항상" 성립한다고 서술했다.
  리뷰가 **등식이 깨지는 경로 3개**를 찾았다 — 주 경계의 집중 대상 / 사후 캡처의 "그 주"
  미정의 / 이월의 재부모화 갈림길. Q10 은 대가를 지불하면서 목표를 달성하지 못했다.
- **선택지**
  - A **집계 쿼리에 `sessions.local_week = week_items.week` 조건을 붙이고 pull 제한을 없앤다**
    — 등식이 정의상 성립. 반례 3개가 자동으로 닫히고 개념이 오히려 줄어든다.
    대가는 쿼리 조건 1개(빠뜨리면 조용히 틀린 숫자가 나온다).
  - B Q10 을 유지하고 빠진 전제 3개를 요구사항으로 승격 — 규칙 3개 추가, 그리고
    "지난 주 미완료 조각을 재개할 수 없다"는 문제가 남아 별도 해결이 필요.
- **결정: A.** ([ADR-012](../architecture/decisions/adr-012-aggregation-predicate.md))
  파생 확정 3건 포함 — 사후 캡처의 기타 항목은 **세션의 주** 기준 / 이월 시 task 재부모화
  허용 / 이월은 `milestone_id` 도 승계. 화면의 기타 행 소진은 차액으로 정의(이중 계상 차단).
- **이유**: 원장 Q10 절에 **선택지 B(날짜 필터+버킷)를 기각한 근거가 기록돼 있지 않다** —
  즉 그 시점 판단의 근거가 남아 있지 않았고, 재검토 비용이 가장 싼 시점이었다.
- **남는 제약**: `task_pulls.pull_date` 는 여전히 오늘만. 미래 날짜 pull("내일 몫 미리 담기")은
  별개 결정이며 v1 비범위다. → D1 이 없앤 대가는 "다른 주 항목을 고를 수 없다"였고,
  "내일 날짜로 담을 수 없다"는 그대로 남는다.

## D2. 베이스라인 변경 — "리뷰에서만"을 폐기하고 효력 시점으로 대체

- **배경**: pomo-baseline 은 "변경은 주간 리뷰에서만, 다음 주부터 유효"라 했는데, 리뷰가
  쓰는 대상은 `계획 대상 주 = week_of(오늘 + plan_lead_days)` 이고 이 값은 **평일에는
  오늘이 속한 주**다. 리뷰를 수요일에 지각해서 하면 월·화를 25분으로 보낸 주의 기준 단위가
  주중에 바뀐다 — 그 문서가 목표로 적은 "진행 중인 주의 단위가 변하는 케이스를 존재하지
  않게 만든다"가 형제 문서의 구현으로 깨졌다. 게다가 "첫 리뷰 이전 1회 예외"는 그 1회 소진을
  판정할 저장값이 없어 검증 불가였다.
- **선택지**
  - A **편집 시점과 효력 시점을 분리한다** — "길이는 언제든 편집 가능, 어떤 편집도 진행 중인
    주에는 효력 없음, 효력은 다음 주 경계부터". 규칙 하나가 지각 리뷰·콜드 스타트·주중
    변경 요구를 모두 답하고, "리뷰에서만" 제약과 1회 예외 플래그가 함께 사라진다.
  - B 계획 대상 주가 이미 진행 중이면 그 다음 주에 적용 — 조건부 규칙이 하나 늘고,
    사용자는 최대 2주를 기다린다.
- **결정: A.** ([ADR-013](../architecture/decisions/adr-013-baseline-budget-effect.md) §3)
  "단위 변경은 성찰의 순간에" 라는 UX 프레이밍은 **리뷰 화면에 진입점을 두는 것**으로
  유지하고, 데이터 불변식을 UI 배치에 의존시키지 않는다.
- **파생**: 길이 변경 확정 전에 변경 전/후 **주간 총 집중 시간**을 함께 표시한다(§4).
  초안 §3.8 이 요구했던 환산 제안을 이 형태로 복원했다 — 1뽀모가 길이와 무관하므로
  같은 24개 예산이 2배 시간을 뜻하게 되는 변화를 알 통로가 앱에 없었다.

## D3. 예산 — `budget NULL` 파생을 폐기하고 확정 저장한다

- **배경**: `weeks.budget` 이 NULL 이면 "기본 예산 = capacity 합"인데 그 capacity 가
  전역값인지 그 주 스냅샷인지 정의되지 않았다. 전역값을 읽으면 9월에 가용량을 낮추는 순간
  8월 첫 주의 예산 표시가 24 → 10 으로 바뀐다. 계획 없이 지나간 주는 스냅샷이 없어
  항상 최신값으로 해석된다. **과거 뽀모 개수는 안전한데(Q4 — 길이 무관) 분모가 흔들렸다.**
- **선택지**
  - A **계획·정산 시 해석된 개수를 그대로 저장** — 과거는 정의상 불변, 읽는 경로가 1개,
    "기본값이냐 오버라이드냐"가 데이터에서 사라진다.
  - B "NULL 이면 그 주 스냅샷의 합"으로 못 박고 스냅샷 없는 과거 주는 "미정"으로 표시 —
    파생 구조를 유지하되 "미정" 개념과 그 표시 규칙이 캘린더·주간 카드 양쪽에 필요.
- **결정: A.** ([ADR-013](../architecture/decisions/adr-013-baseline-budget-effect.md) §1·§2)
  `weeks` 행 생성 시점에 **"그 주 첫 세션 기록 시"** 를 추가해, 세션이 하나라도 있는 주는
  반드시 자기 스냅샷을 갖게 했다 — B 가 필요로 했던 "미정" 상태가 생기지 않는다.
- **원칙 8 과의 관계**: 예산은 아래→위 합산 파생값이 아니라 **사용자 입력(계획 의사)** 이므로
  집계값 저장 금지의 대상이 아니다. `local_date` 를 예외로 처리했던 것과 같은 논리다.

## D4. 마일스톤 보관 — 집계 중립으로 되돌린다

- **배경**: 지난달 배지 `N/M` 에서 보관된 마일스톤을 **N·M 양쪽에서** 제외하는 규칙이었고,
  월말에 미완료 마일스톤을 보관하는 것이 정상 경로였다. 3개 중 1개 완료한 달에서 남은 2개를
  보관하면 배지가 "1/3" → **"1/1 달성"** 이 된다. 해제로 왕복도 가능하다.
  실패를 숨기는 것이 아니라 **성공을 조작**하는 경로다.
- **선택지**
  - A **N·M 을 그 달의 스냅샷으로 정의** — M = 그 달에 존재했던 마일스톤 수(보관 무관),
    보관은 목록 표시에서만 제외. 조작 경로가 사라진다.
  - B 보관 기능을 v1 에서 뺀다 — 문제가 통째로 사라지지만, 지난달 미완료 항목이 목록에 남는다.
- **결정: A.** ([ADR-014](../architecture/decisions/adr-014-deletion-and-archive.md) §4)
  `M = 0` 이면 배지를 렌더하지 않고, 보관 항목이 있는 달은 보관 사실을 함께 표시한다
  (초안이 이미 그렇게 했다). 원장 Q15 는 "배지만 표시"를 결정했을 뿐 보관이 분모를 깎는다고
  결정한 적이 없으므로, 이건 Q15 를 뒤집는 것이 아니라 미정의를 채우는 것이다.
- **함께 확정**: 삭제 표현 — `week_items`·`tasks` 만 soft delete, `sessions` 는 삭제하지 않음,
  `milestones` 는 물리 삭제 + `week_items.milestone_id ON DELETE SET NULL`
  ([ADR-014](../architecture/decisions/adr-014-deletion-and-archive.md) §1~§3).
  기능 문서 3개가 이미 전제하던 컬럼에 정의가 없던 상태를 닫았다.

## 문서 수정으로 닫은 것 (결정 아님, 기록용)

리뷰가 올린 나머지 지적은 선택의 문제가 아니라 빠진 문장을 채우는 작업이었다.
각 기능 PR 에서 반영했다.

| 지적 | 반영 |
|---|---|
| 오늘 목록 × 가 세션 있는 조각의 그날 이력을 지운다 | 세션이 있는 조각은 그날 행을 지우지 않고 "치움" 표시 |
| 캘린더 점과 날짜 패널의 술어가 달라 같은 날에 반대로 말한다 | "기록 있음" 술어를 한 번 정의하고 점·목록·빈 상태가 참조 |
| Windows 에 종료 경로가 없고, Dock 클릭·중복 실행 방지가 없다 | 단일 창 불변식 + Dock 복귀 + 단일 인스턴스 잠금 + 플랫폼 중립 종료 트리거. 트레이는 창 닫기=숨김과 분리 배포 불가 |
| 좁은 창에서 캡처 기회를 잃는다 (닫힘 규칙 충돌) | 캡처 바는 사용자 행동으로만 닫는다 ("다음 세션 시작 시 자동 닫힘" 삭제) |
| 일요일에 이번 주를 고칠 수 없다 | 플래너의 편집 대상 주를 선택 가능한 상태로 승격 |
| 폐기 항목의 소진이 화면에서 사라진다 | 기타 행 = 차액 정의로 흡수 (D1 파생) |
| 리뷰 패널을 열어둔 채 완료 처리하면 확정이 실패한다 | 결정을 전체 목록이 아니라 **예외만** 전송, 나머지는 서버가 이월로 처리 |
| 첫 실행이 계획일이면 그 주 기록이 리뷰에 안 나온다 | 알려진 부작용으로 명시 수용 (캘린더·소진에는 정상 반영) |
| 월간 롤업에 범위 라벨이 없어 40뽀모 태운 달에 0 이 뜬다 | 롤업은 항상 범위 라벨과 함께 표시 + 달을 걸치는 주의 귀속 기준 명시 |
| 타이머 카드 구성표에 "공부한 날 수" 줄이 없다 | timer ux-spec 에 행 추가 (내용 소유는 calendar-records) |

| milestones 작성 | 보관을 "데이터 상태"와 "집계 규칙"으로 분리하지 않고 한 규칙에 묶어, 정상 조작이 달성률을 조작하는 경로를 만들었다 → D4 |
| app-shell 작성 | "창 닫기 = 숨김"이 트레이·Dock 복귀·중복 실행 방지 **3개를 동반 필수로 끌고 온다**는 사실을 인지하지 못하고 트레이 하나만, 그것도 M4 로 적었다 |
| 리뷰 검증 결과 | 정산 판정식은 **off-by-one 이 없음**을 8개 케이스 손계산으로 확인했다. 원장 §E 의 "P1 off-by-one 지적은 오판" 판정도 여전히 유효하다 |

## 미결 (이 세션에서 의도적으로 미룸)

- 미래 날짜 pull(내일 몫 미리 담기) — D1 이 주 제한만 없앴다. 날짜 제한 해제는 별개 결정, v1 비범위
- 최소 창 크기 실측값 — app-shell 구현 시 확정 후 tokens.md 기록
- 트레이 아이콘 형태·남은 시간 표시·알림음 세부 (M4)
- 월말 마일스톤 재설정 흐름 — v1 비범위. milestones·weekly-review 양쪽에 동일 문구로 명시
- Query invalidation 키 계층 — architecture 미결정 그대로
- 이월 사슬을 거슬러 "그 항목에 총 몇 뽀모"를 합산하는 화면 — v1 에 없음 (D1 의 대가)
