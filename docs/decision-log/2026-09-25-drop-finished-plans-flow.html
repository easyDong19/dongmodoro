Q1 반전 재설명

구현이 끝난 계획서를 어떻게 다루나

문제

계획서는 Goal:·- [ ] Task 형식이라 LLM 이 검색으로 만나면 현재 지시로 읽는다. 옛 모델(뽀모 개수 통화, 마일스톤 보관, 정산의 조정 폼)이 현재 사실처럼 남는다.

선택지
  • 상태 줄만 추가하고 보존 (AI 첫 추천) — 2026-08-04 규칙과 맞고 수정이 작다. 끝난 계획서는 계속 검색에 걸린다
  • 끝난 계획은 삭제하고 규칙을 바꿈 — 트리에 진행 중인 계획만 남는다. 링크·근거·백로그를 먼저 옮겨야 한다
결정

끝난 계획은 삭제한다. 이력은 git 과 PR 이 보존한다 — 2026-08-04 에 docs/plans/ 를 만든 근거("git 이력에 남는다")가 오히려 이쪽을 지지한다.

흠 내생각에 이미 실행이 끝나 Code로 구현된 문서들은 삭제하는게 LLM이 문서를 이해하고 활용하는데 도움이 될거라 생각하는데 그래서 claude.md나 규칙들을 좀 수정하는 방향성이 괜찮아 보이는데 타당성에 대해서 어떻게 생각해?

Q2 검증

일괄 삭제인가, 문서 종류를 나눠 처리하나

문제

ADR-033 이 설계 문서를 "결정 근거 원장" 으로 링크했다. ADR-025·026, design-system ADR-011 도 설계 스펙을 근거로 가리켰다. 일괄 삭제하면 ADR 의 근거가 사라진다.

선택지
  • 일괄 삭제 — 간단하지만 ADR 근거 유실·링크 깨짐
  • 실행 계획은 삭제, 설계 문서는 근거를 ADR 로 옮긴 뒤 삭제 — 4건을 하나씩 대조해 다른 곳에 없는 내용만 옮긴다
결정

종류를 나눠 처리. ADR-033 에 기각된 선택지와 "저장이 먼저" 불변식, design-system ADR-011 에 useBreakpoint 단일 판정 §4 를 추가. 나머지 2건은 이미 ADR·폐기 결정에 흡수돼 옮길 것이 없었다.

Q5 검증

계획서에만 있던 "미룬 범위"를 어떻게 하나

문제

m3a·m3b 계획서의 "이번 마일스톤에서 뺀 것" 표는 다른 문서 어디에도 없었다. 기타 행 드릴다운은 지금도 미구현이고, 흔적은 테스트 이름 하나뿐이었다.

결정

코드와 대조해 아직 안 만들었고 유효한 것만 docs/tmp/ 로. 구현됐거나 이후 결정으로 의미가 없어진 항목은 버린다.

ㅇㅇ 그렇게하자
감사 검증

이연 항목 약 45건 → tmp 메모 7건

서브에이전트가 17건 전체의 이연 항목을 코드·ADR·PRD 와 대조했다. 구현됨 11 · 무의미 6 · 이미 추적 중 약 20 은 버리고, 어디에도 없던 7건(기타 행 드릴다운, Sprint 의 Milestone 배지, 오늘 목록 빈 상태, 플래너 확정 동시성, Windows·Linux 배포, 코어 루프 E2E, timer-host 만료 타이머 버그)을 docs/tmp/ 로 옮겼다. 같은 감사에서 AI 가 놓친 PRODUCT.md 의 계획 링크 6곳도 드러났다.
