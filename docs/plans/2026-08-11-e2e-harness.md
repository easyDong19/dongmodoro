# E2E 하네스 + CI 파이프라인 구현 계획

> **상태: 실행 완료** (2026-08-11, [PR #42](https://github.com/easyDong19/dongmodoro/pull/42)).
> Task 1~5 를 전부 구현했고 macOS 로컬에서 6종(타입체크·린트·서식·단위 545개·빌드·E2E)이
> 통과한다. **한 가지가 계획대로 되지 않았다 — Task 4 의 E2E 스텝을 CI 에 넣지 못하고
> 보류했다** (사용자 결정 2026-08-11).
>
> 원인은 하네스가 아니라 **앱이 Linux 에서 종료되지 않는 것**이다. 러너에서도 단언은 전부
> 통과하는데(앱이 뜨고 카드 3장이 렌더된다) `app.quit()` 에 프로세스가 반응하지 않고
> `exit` 이벤트조차 오지 않아 teardown 이 30초를 넘긴다. macOS 에서는 1초 안에 죽는다.
> 세 가설(세션 버스 부재 · 실행 중 Electron 다운로드 · CDP 응답 유실)을 실측으로 전부
> 기각했다. 상세는 `.github/workflows/ci.yml` 의 보류 주석에 있다.
>
> 강제 kill 로 초록을 만드는 선택은 하지 않았다 — Linux 는 배포 대상 OS 이고, 거기서 앱이
> 안 죽는다는 사실을 CI 초록으로 덮는 것이 되기 때문이다. **종료 경로를 고치는 후속 작업이
> 그 스텝을 되살린다.** 그때까지 E2E 는 로컬 전용이다.
>
> 계획 밖의 부산물: 하네스가 첫 실행에서 종료 경로의 결함을 두 건 드러냈다 —
> 종료를 취소해도 DB 가 이미 닫혀 있는 문제와, `timer-host.ts` 의 `stop()` 이 엔진의 보류
> `setTimeout` 을 취소하지 않는 문제. 둘 다 별도 작업으로 넘겼다.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) 문법으로 진행을 추적한다.

**Goal:** 빌드한 Electron 앱을 실제로 띄워 화면을 확인하는 자동 경로를 만들고, 그 위에 타입체크·린트·단위 테스트를 함께 얹은 CI 파이프라인을 세운다. 이 계획서가 끝나면 **PR 마다 앱이 실제로 뜨는지가 기계로 확인되고, 화면 스크린샷이 아티팩트로 붙는다.**

**Architecture:** Playwright 의 Electron 지원(`_electron.launch()`)으로 **빌드 산출물**(`out/main/index.js`)을 그대로 실행한다. 개발 서버가 아니라 산출물을 띄우는 이유는 `electron-vite build` 가 만드는 번들이 실제 배포 대상이고, `main/index.ts` 의 마이그레이션 경로 계산이 `out/main/` 기준으로 짜여 있기 때문이다. DB 는 Chromium 의 `--user-data-dir` 스위치로 매 실행마다 임시 디렉토리에 격리한다 — Electron 이 이 스위치를 존중하므로 `app.getPath('userData')` 가 그쪽을 가리키고, **main 코드를 한 줄도 고치지 않고** 모든 테스트가 순정 첫 실행이 된다.

**Tech Stack:** M3b 스택 그대로. 추가: `@playwright/test` (devDependency 1개).

## Global Constraints

M1~M3b 계획의 Global Constraints 가 전부 그대로 적용된다 (pnpm 전용, `src/shared/` 순수 TS, UI 이모지 금지·토큰만, 커밋 영어 Conventional Commits, husky 훅 우회 금지). 여기에 이번 것:

- **E2E 는 앱 코드를 위해 앱 코드를 고치지 않는다.** 테스트 전용 IPC 채널·전역 훅·`process.env.E2E` 분기를 `src/` 에 만들지 않는다. 관측이 필요하면 화면에 이미 있는 것(`aria-label`·역할·텍스트)으로만 잡는다. 테스트를 위해 프로덕션 코드에 문을 내면 그 문이 배포본에도 남는다.
- **E2E 는 `src/` 밖에 산다.** `e2e/` 최상위 디렉토리다. [vitest.config.ts](../../vitest.config.ts) 의 `include` 가 `src/**`·`scripts/**` 화이트리스트이므로 **두 러너가 서로의 파일을 집지 않으며, 별도 `exclude` 설정이 필요 없다.**
- **스크린샷 회귀(`toHaveScreenshot`)를 쓰지 않는다.** 폰트 렌더링이 OS 마다 달라 macOS 로컬과 ubuntu CI 의 베이스라인이 일치하지 않는다. 넣으면 첫날부터 상시 실패하는 테스트가 되고, 상시 실패하는 테스트는 곧 무시된다. 대신 **스크린샷을 찍어 아티팩트로 올리고 비교는 사람이 한다.**
- **CI 실패는 우회 대상이 아니다.** 워크플로 스텝을 `continue-on-error` 로 두지 않는다. 통과할 수 없는 스텝이면 그 스텝을 넣지 않는 것이 맞다.
- **작업 브랜치는 `feature/e2e-harness` 하나**이며 태스크마다 커밋한다.

## 이번 계획서에서 뺀 것

| 뺀 것 | 이유 | 언제 살아나나 |
|---|---|---|
| **코어 루프 E2E** (타이머 시작·오늘 목록 pull·정산 확정) | 하네스 도입과 테스트 백필은 다른 작업이다. 여기서 시작하면 이 PR 이 "E2E 도입"이 아니라 "M2·M3 테스트 백필"이 된다 | 하네스가 자리 잡은 뒤 별도 계획서 |
| **스크린샷 회귀 비교** | 베이스라인 기준 OS 를 정하는 별개 결정이 선행되어야 한다 | 기준 OS 결정 후 |
| **macOS·Windows CI 러너** | ubuntu 하나로 시작한다. 3 OS 매트릭스는 비용이 3배이고, 지금 확인하려는 것("앱이 뜨는가")은 한 OS 로 충분하다 | 패키징(M4, ADR-004) 때 함께 |
| **패키징된 앱(asar) 테스트** | 패키징 자체가 M4 다. 지금은 `out/` 산출물을 직접 띄운다 | M4 |

**이 계획서가 닫지 못하는 것:** 타이틀바·시각 디자인의 정확성. E2E 는 "요소가 있다"까지만 보고 "시안과 같은가"는 못 본다. 그 판단은 아티팩트 스크린샷을 사람이 보는 것으로 남는다.

## CI 러너를 ubuntu 로 두는 것의 의미

기존 [pr-language.yml](../../.github/workflows/pr-language.yml) 이 `ubuntu-latest` 이고, 같은 러너를 쓴다. 여기에는 **의도한 덤과 의도하지 않은 한계**가 하나씩 있다.

- (+) **덤**: 개발 환경이 macOS 하나뿐인 상태에서, CI 가 매 PR 마다 **Linux 에서 앱이 기동되는지**를 확인해 준다. 지금까지 아무도 확인한 적 없는 사실이다.
- (−) **한계**: 아티팩트 스크린샷은 **Linux 렌더링**이다. 폰트가 macOS 와 다르므로 자간·줄바꿈이 다르게 보인다. 시각 확인의 기준 화면으로 쓰지 말고, "레이아웃이 무너지지 않았는가" 수준으로만 읽는다.

### Task 1: Playwright 설치와 설정

- [ ] **Step 1:** `pnpm add -D @playwright/test` 로 devDependency 추가. **`pnpm exec playwright install` 은 하지 않는다** — Electron 테스트는 `node_modules/electron` 의 바이너리를 그대로 쓰므로 Chromium·Firefox·WebKit 다운로드가 불필요하다. 이 한 줄을 아끼는 것이 CI 시간의 대부분이다.
- [ ] **Step 2:** `playwright.config.ts` 를 만든다.
  - `testDir: './e2e'`
  - `fullyParallel: false`, `workers: 1` — Electron 앱 인스턴스가 여럿 뜨면 임시 userData 는 격리되어도 **창 포커스·트레이 같은 단일 자원**에서 서로 간섭한다. 지금 테스트가 하나뿐이라 병렬로 얻을 것도 없다.
  - `retries: process.env.CI ? 1 : 0` — 앱 기동은 느린 러너에서 간헐 실패한다. 재시도 1회는 은폐가 아니라 기동 지연에 대한 정직한 대응이며, 2회 이상은 문제를 숨기므로 두지 않는다.
  - `reporter`: 로컬은 `list`, CI 는 `html` (아티팩트로 올린다)
  - `use.trace: 'on-first-retry'` — 실패한 실행만 추적을 남긴다
- [ ] **Step 3:** `package.json` 에 스크립트를 넣는다.
  - `"test:e2e": "playwright test"` — **빌드를 여기 넣지 않는다.** CI 는 빌드 스텝을 따로 두어 빌드 실패와 테스트 실패를 구분해야 하고, 로컬에서는 이미 빌드해 둔 산출물로 반복 실행하고 싶기 때문이다.
  - `"test:e2e:build": "pnpm build && playwright test"` — 로컬에서 한 번에 돌릴 때
- [ ] **Step 4:** `.gitignore` 에 `playwright-report/`, `test-results/`, `e2e-artifacts/` 를 넣는다.
- [ ] **Step 5:** `pnpm typecheck` 통과 확인. `playwright.config.ts` 는 `tsconfig.node.json` 범위에 들어가야 한다 — 안 들어가면 `include` 에 추가한다.

**검증:** `pnpm exec playwright test --list` 가 테스트 0개로 정상 종료한다(아직 스펙이 없다).

### Task 2: 앱 기동 픽스처

앱을 띄우고 끄는 방법을 한 곳에만 둔다. 스펙마다 `_electron.launch` 를 부르면 임시 디렉토리 정리나 종료 처리가 파일마다 갈린다.

- [ ] **Step 1:** `e2e/fixtures/app.ts` 에 Playwright 픽스처를 만든다. 제공하는 것은 둘이다 — `electronApp`(ElectronApplication)과 `page`(첫 창).
- [ ] **Step 2:** 기동 인자를 정한다.
  - 진입점: `out/main/index.js` (저장소 루트 기준 절대 경로로 푼다)
  - `--user-data-dir=<임시 디렉토리>` — `node:fs.mkdtempSync(join(tmpdir(), 'dongmodoro-e2e-'))`. **이 한 줄이 이 계획서에서 가장 중요하다**: 매 테스트가 빈 DB 로 시작하므로 시딩 기본값·첫 실행 동작을 그대로 검증할 수 있고, 개발용 DB 가 오염되지 않는다.
  - 산출물이 없으면 **명확히 실패시킨다** — `out/main/index.js` 존재를 먼저 확인하고 없으면 `pnpm build 를 먼저 실행하세요` 를 던진다. 없는 파일을 Electron 에 넘기면 나오는 오류가 원인을 말해주지 않는다.
- [ ] **Step 3:** 첫 창을 `electronApp.firstWindow()` 로 잡는다.
- [ ] **Step 4:** 정리(teardown)에서 `electronApp.close()` 후 임시 디렉토리를 재귀 삭제한다. 실패한 테스트에서도 반드시 돌아야 하므로 픽스처의 정리 구간에 둔다.
- [ ] **Step 5:** main 프로세스의 콘솔·크래시를 놓치지 않게 `electronApp.process().stderr` 를 테스트 로그로 흘린다. DB 열기 실패는 창을 띄우지 않고 다이얼로그로 끝나므로(ADR-020 §4), 이 배선이 없으면 **"창이 안 뜬다"는 것만 알고 왜인지는 모른다.**

**검증:** 임시 스펙 하나로 `page.title()` 이 `dongmodoro` 를 반환하는 것을 확인하고, 실행 후 임시 디렉토리가 남지 않는 것을 확인한다.

### Task 3: 스모크 테스트

- [ ] **Step 1:** `e2e/smoke.spec.ts` 에 케이스 하나를 쓴다 — **앱이 뜨고 카드 3장이 보인다.**
  - 잡는 방법은 [App.tsx](../../src/renderer/app/App.tsx) 가 이미 붙여 둔 `aria-label` 이다: `타이머` · `주간 계획` · `오늘 목록`. 테스트용 `data-testid` 를 새로 심지 않는다 — 접근성 이름은 사용자에게도 의미가 있어 **테스트와 사용자가 같은 것을 본다.**
- [ ] **Step 2:** 대기 조건을 `ClockGate` 기준으로 잡는다. [ClockGate.tsx](../../src/renderer/app/ClockGate.tsx) 가 `clock:now` 응답 전에는 자식을 마운트하지 않으므로, 카드가 보인다는 것은 **IPC 왕복이 성공했다는 뜻**이기도 하다. 임의의 `waitForTimeout` 을 쓰지 않고 요소 가시성으로 기다린다.
- [ ] **Step 3:** 스크린샷을 `e2e-artifacts/smoke.png` 로 저장한다.
- [ ] **Step 4:** 콘솔 오류 0건을 함께 단언한다 — `page.on('console')` 로 `error` 레벨을 모아 테스트 끝에 비어 있는지 본다. 렌더러가 조용히 던지는 예외를 여기서 잡는다.

**검증:** `pnpm build && pnpm test:e2e` 가 로컬(macOS)에서 통과하고 `e2e-artifacts/smoke.png` 에 카드 3장이 보인다.

### Task 4: CI 파이프라인 신설

지금 CI 는 [pr-language.yml](../../.github/workflows/pr-language.yml) 의 PR 언어 검사 하나뿐이고 **타입체크·린트·단위 테스트가 어디서도 자동 실행되지 않는다.** E2E 만 얹으면 지붕부터 얹는 것이 되므로 같은 워크플로에서 아래를 함께 세운다.

- [ ] **Step 1:** `.github/workflows/ci.yml` 을 만든다. 트리거는 `pull_request` + `push: [main]`. 러너는 `ubuntu-latest`.
- [ ] **Step 2:** 설치 단계 — `pnpm/action-setup` → `actions/setup-node` (`cache: 'pnpm'`) → `pnpm install --frozen-lockfile`.
- [ ] **Step 3:** 검사 스텝을 **순서대로, 각각 별도 스텝**으로 넣는다. 한 줄로 묶으면 무엇이 깨졌는지 로그를 뒤져야 한다.
  1. `pnpm typecheck`
  2. `pnpm lint`
  3. `pnpm format:check`
  4. `pnpm test`
  5. `pnpm build`
  6. `xvfb-run -a pnpm test:e2e`
- [ ] **Step 4:** Electron 이 헤드리스 Linux 에서 뜨려면 **X 가상 디스플레이와 시스템 라이브러리**가 필요하다. `xvfb-run` 만으로 부족하면 `libnss3` · `libatk-bridge2.0-0` · `libgtk-3-0` · `libgbm1` · `libasound2` 계열을 `apt-get` 으로 설치한다. **이 스텝은 한 번에 맞추지 못할 가능성이 높다** — 실패 로그의 누락 라이브러리 이름을 그대로 읽어 추가하는 반복 작업이며, 그 반복을 계획서가 미리 숨기지 않는다.
- [ ] **Step 5:** 아티팩트 업로드 — `actions/upload-artifact` 로 `e2e-artifacts/` 와 `playwright-report/` 를 올린다. `if: always()` 로 **실패했을 때도** 올린다. 실패한 실행의 스크린샷이 성공한 실행의 것보다 쓸모 있다.
- [ ] **Step 6:** 이 워크플로가 PR 언어 검사를 흡수하지 않는다 — `pr-language.yml` 은 그대로 둔다. 트리거 조건(`pull_request_target` 계열의 본문 검사)이 다르고, 합치면 한쪽 실패가 다른 쪽을 가린다.

**검증:** 이 브랜치의 PR 에서 6개 스텝이 전부 초록이고, 아티팩트 탭에 스크린샷이 붙는다.
