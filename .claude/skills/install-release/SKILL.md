# install-release — 배포한 dmg 로 갈아 끼우고 연다

## 무엇을 하는가

GitHub 릴리스의 `.dmg` 를 받아 `/Applications/dongmodoro.app` 을 교체하고 앱을 연다.
`pnpm dev` 로는 재현되지 않는 것들 — asar 밖으로 뺀 마이그레이션 `.sql`, 네이티브
바이너리, 재시작 동작 — 을 실제 배포물로 확인하는 자리다.

**사용자 데이터는 건드리지 않는다.** 앱 번들(`/Applications`)과 데이터
(`~/Library/Application Support/dongmodoro`)는 서로 다른 자리에 있고, 이 절차는 번들만
바꾼다. 그래서 실제 사용자가 겪는 것과 같은 **업그레이드** 조건이 된다.

## 실행

```bash
.claude/skills/install-release/install-release.sh
```

인자 없이 부르면 최신 릴리스다. 특정 판은 태그를 준다: `install-release.sh v2.1.0`.

스크립트가 하는 일은 순서대로 — 태그 확인 → dmg 내려받기 → 실행 중이면 종료 →
이미지 마운트 → 기존 번들 삭제 → 복사 → quarantine 해제 → 언마운트 → 버전 확인 → 실행.

## 왜 스크립트인가 — 손으로 하면 밟는 것들

한 줄씩 손으로 치면 아래에서 넘어진다. 전부 실제로 밟은 것이다.

| 함정 | 무슨 일이 나는가 | 스크립트가 하는 일 |
|---|---|---|
| `gh release download` 를 저장소 밖에서 호출 | `not a git repository` 로 죽는다 | `--repo` 를 항상 붙인다 |
| 볼륨 이름을 파일명에서 짐작 | 실제 이름은 `dongmodoro 2.1.0-arm64` 라 빗나간다 | `hdiutil attach -plist` 출력에서 마운트 지점을 받는다 |
| `hdiutil info` 로 마운트 지점 찾기 | 시뮬레이터 런타임 등 무관한 이미지가 함께 나온다 | 위와 같음 — attach 시점 값만 쓴다 |
| 실행 중인 앱 위에 덮어쓰기 | 앱이 반쯤 죽은 채로 돌고, 새로 열어도 단일 인스턴스 잠금이 옛 창을 앞으로 낼 뿐이다 | 먼저 종료하고 최대 10초 기다린다 |
| quarantine 을 안 지움 | 애드혹 서명 + 공증 없음(ADR-028)이라 macOS 가 실행을 막는다 | `xattr -dr` 로 지운다 |
| 실패 후 이미지가 붙은 채로 남음 | 다음 실행이 `... 1` 짜리 두 번째 볼륨을 만든다 | `trap` 으로 반드시 detach 한다 |

## 알아 둘 것

- **집중 세션이 돌고 있으면 멈춘다.** 종료 확인 대화상자에서 `계속 집중` 을 고르면
  종료가 취소되는데, 그건 사용자의 선택이므로 강제로 죽이지 않고 안내하고 끝낸다.
  세션을 정리한 뒤 다시 부른다.
- **태그와 번들 버전이 다르면 경고한다.** 릴리스를 자를 때 `package.json` bump 를
  빠뜨리면 여기서 드러난다.
- **데이터를 비우고 첫 실행을 보고 싶으면** 이 스크립트가 아니라 앱 안의 `데이터` →
  `모든 데이터 초기화…` 를 쓴다. 그쪽은 지우기 전에 백업을 남기고, 이 스크립트는
  데이터에 손대지 않으므로 백업도 만들지 않는다.

## 이 스킬이 아닌 경우

- 개발 중인 코드를 화면으로 보고 싶다 → `run-app` 스킬
- 릴리스 노트를 쓴다 → `release-notes` 스킬
- 태그를 자르는 절차 → [CONTRIBUTING.md](../../../CONTRIBUTING.md) §2
