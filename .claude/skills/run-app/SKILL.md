# run-app — 앱을 띄워서 눈으로 확인하기

## 두 가지 경로 — 먼저 고른다

| 목적 | 경로 | DB |
|---|---|---|
| 사람이 화면을 본다 (레이아웃·색·간격) | `pnpm dev` | **실데이터** |
| 클릭·검증을 코드로 한다 | Playwright e2e (`e2e/fixtures/app.ts`) | 매 실행 임시 폴더 |

**쓰기 조작(체크·삭제·타이머 시작)을 반복해야 하면 e2e 쪽을 쓴다.** `pnpm dev` 는
`~/Library/Application Support/dongmodoro` 의 실제 DB 를 연다 — 개발 중 눌러본 흔적이
사용자의 진짜 기록에 남는다. 화면만 볼 때는 상관없지만, 상태를 여러 번 바꿔야 하면
남는다는 사실을 사용자에게 먼저 말한다.

## pnpm dev 로 띄우기

**셋 다 저장소 루트에서 돌린다** (`node_modules/...` 를 상대 경로로 찾는다). 워크트리를
쓰는 중이면 그 워크트리 루트다.

```bash
cd <저장소·워크트리 루트>
pnpm install
node node_modules/electron/install.js   # 항상 돌린다 — 이미 돼 있으면 즉시 끝난다
pnpm dev                                # 반드시 백그라운드로 (아래)
```

`pnpm dev` 는 **백그라운드로 돌리되 출력을 남긴다.** 포그라운드로 잡으면 앱이 떠 있는
동안 아무것도 못 하고, 출력을 버리면 **성공을 확인할 로그 자체가 사라진다.**

- 도구에 백그라운드 실행이 있으면 그걸 쓴다. 출력 파일 경로를 돌려주므로 **그 경로**를
  아래 확인에 쓴다 — 이 문서에 적힌 경로가 아니라.
- 직접 백그라운드로 넘겨야 하면 `nohup pnpm dev > /tmp/dongmodoro-dev.log 2>&1 &`.
  **샌드박스 셸은 이 형태를 거부할 수 있다.** 거부당하면 `cd` 와 리다이렉션을 담은 한 줄짜리
  스크립트를 만들어 그 스크립트를 백그라운드로 돌린다.

기동에는 보통 몇 초, 느리면 20초쯤 걸린다. 다 끝나기 전에 로그를 읽으면 빌드가 덜 된
상태라 실패로 오해하기 쉬우니, **한 번 읽고 판단하지 말고 표시가 나올 때까지 다시 읽는다.**
`until ... sleep` 같은 블로킹 루프는 셸이 거부할 수 있으므로, 거부당하면 그 루프도
백그라운드로 돌리거나 시간을 두고 두어 번 읽는다.

뜬 것을 확인하는 방법 두 가지:

- 로그 끝에 `starting electron app...` (그 앞에 렌더러 dev 서버 `localhost:5173`).
- `pgrep -fl "Contents/MacOS/Electron"` 에 **이 체크아웃 경로의** 프로세스가 잡힌다.
  `--app-path=<체크아웃>` 을 단 렌더러까지 보이면 창까지 뜬 것이다.

DB 마이그레이션은 앱이 시작하면서 스스로 적용한다 — 먼저 돌릴 단계가 따로 없다.

종료는 경로로 좁혀서 죽인다. 좁히지 않으면 사용자가 따로 켜 둔 다른 Electron 앱까지
같이 죽는다.

```bash
pkill -f "<체크아웃 루트>.*Electron"
```

`pgrep` 이 찍는 건 그 아래 `node_modules/...` 까지 내려간 긴 경로다. 패턴에는 **체크아웃
루트까지만** 넣으면 충분하고, 그게 다른 Electron 앱을 건드리지 않는 최소한이다. 다만
루트를 쓸 때 **`pgrep` 출력에 나온 형태 그대로** 쓴다 — macOS 에서 `/tmp` 는
`/private/tmp` 의 심볼릭 링크라 둘이 다른 문자열이고, 틀린 쪽을 쓰면 아무것도 못 죽이고도
조용히 성공한 것처럼 끝난다.

이 한 번으로 dev 서버(vite·electron-vite) 프로세스도 함께 끝난다 — 따로 죽일 필요가
없다. 죽인 뒤 `pgrep -fl "<체크아웃 루트>"` 로 0건인지 확인한다. 이때 로그 끝에 붙는
`Network service crashed`·`GPU process exited unexpectedly` 는 **정상 종료 소음이다.**
실패로 읽지 않는다.

## 함정: 이전 dev 를 안 죽이고 또 띄우면 — 싱글 인스턴스 락

앱에 싱글 인스턴스 락이 있다 (src/main/index.ts 의 `second-instance`). 이전 `pnpm dev`
를 내리지 않고 새로 띄우면 **새 인스턴스는 exit 0 으로 조용히 죽고, 화면에 떠 있는 창은
옛 인스턴스다.** 이때 로그의 `Port 5173 is in use, trying another one...` 이 그 신호다.

이 상태가 지독한 이유: 옛 인스턴스의 vite 가 같은 작업 디렉토리를 보고 있어서 **렌더러만
HMR 로 새 코드가 되고 main·preload 는 옛것으로 남는다.** 새로 추가한 IPC 채널을 렌더러가
부르면 조용히 실패해서, 방금 짠 기능이 "동작 안 하는 버그"처럼 보인다. 코드를 의심하기
전에 인스턴스 수부터 센다:

```bash
pgrep -fl "Contents/MacOS/Electron" | grep -v Helper
```

1개가 아니거나 로그에 포트 대체 메시지가 있으면, 전부 죽이고 하나만 다시 띄운다.

## 함정: 새 워크트리에서 `Electron uninstall`

```
error during start dev server and electron app:
Error: Electron uninstall
    at getElectronPath (.../electron-vite/dist/chunks/lib-*.js)
```

`pnpm install` 이 `electron` 의 postinstall(바이너리 내려받기)을 건너뛰어서 나는 오류다.
`node_modules/electron/` 에 `dist/` 와 `path.txt` 가 없으면 이 상태다. 고치는 법:

```bash
node node_modules/electron/install.js
```

그 버전이 이미 로컬 캐시에 있으면 몇 초면 끝난다. 처음 받는 버전이면 100MB 가량을
내려받으므로 그만큼 걸린다. **워크트리를 새로 팔 때마다 반복된다** — 원래 체크아웃에서
되던 것이 워크트리에서 안 되면 이것부터 의심한다.

## 코드를 고치면서 화면으로 확인하기

렌더러(`src/renderer/**`)는 **HMR 이 붙어 있다.** 앱을 띄워둔 채 파일을 저장하면 화면이
바로 갱신되므로, `수정 → 저장 → 같은 자리 다시 확인` 을 앱 재시작 없이 돌릴 수 있다.
레이아웃 점프·간격 같은 시각 결함은 이 루프로 수정 전후를 비교하는 것이 가장 확실하다.

main 프로세스(`src/main/**`)를 고치면 electron-vite 가 앱을 재시작한다 — 창이 한 번
사라졌다 다시 뜨는 것은 정상이다.

## 창을 눈으로 보고 클릭할 때

로그와 프로세스는 "떴다"까지만 말해준다. **창에 뭐가 그려졌는지는 스크린샷을 한 장 찍어야
안다** — 빈 창으로 뜨는 것도 기동 실패의 한 형태다. computer-use 로 찍는데, 순서와 이름이
둘 다 함정이다.

> **먼저 `request_access` 로 권한을 받아야** 스크린샷·클릭이 나간다. 세션마다 한 번 필요하다.
>
> **요청할 앱 이름은 `Electron` 이다 — `dongmodoro` 가 아니다.** dev 실행은
> `node_modules` 의 Electron 바이너리로 뜨므로 시스템에는 그 이름으로 잡힌다. 함정은
> **`dongmodoro` 로 요청해도 거절당하지 않는다**는 것이다 — 패키징된 앱이 설치돼 있으면
> 그 이름이 그대로 승인된다. 스크린샷은 승인된 앱만 담기므로, 승인은 됐는데 **지금 띄운
> 창만 쏙 빠진 빈 화면**이 나온다. 앱이 안 뜬 것처럼 보이지만 원인은 이름이다.

`request_access` 응답의 `windowLocations` 가 창이 어느 모니터에 있는지 알려준다. 주
모니터가 아니면 `switch_display` 로 옮겨서 찍는다 — 빈 화면을 찍어보고 되짚는 것보다 싸다.
빈 화면이 나왔다면 모니터보다 **이름을 먼저 의심한다.**

화면을 보여주는 것이 목적이었다면 여기까지 하고 끝낸다. 이어서 클릭으로 조작한다면 두
가지를 알고 시작한다.

- **첫 클릭이 창 포커스에 먹힐 수 있다.** 다른 앱이 앞에 있었다면 한 번은 헛클릭이 된다.
- **스크린샷이 한 박자 늦을 수 있다.** 클릭 직후 화면이 그대로라고 "안 먹었다"고 판단하지
  않는다. 1초쯤 두고 새로 찍어 확인하고, 그래도 그대로면 그때 원인을 찾는다.

## 하지 않는 것

- **`pnpm build` 로 확인하지 않는다** — 빌드는 e2e 와 배포용이다. 화면 확인은 dev 가 빠르다.
- **앱을 띄운 채 방치하지 않는다.** 확인이 끝나면 프로세스를 내린다. 실 DB 를 연 인스턴스가
  둘이 되면 타이머가 두 개가 된다.
