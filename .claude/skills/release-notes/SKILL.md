# release-notes — 릴리스 페이지에 그대로 실리는 한국어 본문

## 언제 쓰는가

- **태그를 자르기 전에.** 노트 파일이 없으면 릴리스 워크플로가 빌드 전에 죽는다.
- 파괴적 마이그레이션이 있는 판은 복귀선이 노트에 도달하지 않으면 publish 하지 않는다
  ([ADR-032](../../../docs/architecture/decisions/adr-032-destructive-migration-safety.md)).

## 위치·파일명

`docs/release-notes/<X.Y.Z>.md` — `v` 를 붙이지 않는다 (`2.0.1.md`).

태그는 release 브랜치에서 잘리므로 **그 브랜치에도 이 파일이 있어야** 태그가 통과한다.
main 에 머지한 뒤 cherry-pick 하는 경로를 탄다.

## 자동 구간은 쓰지 않는다

`## What's Changed` · `## New Contributors` · `**Full Changelog**` 는 **GitHub 이 붙인다.**
손으로 쓰면 같은 목록이 두 벌이 된다.

파일은 그 **위**만 담고, [release.yml](../../../.github/workflows/release.yml) 이
`body_path` 로 넣는다. **변환 단계가 없다 — 파일이 곧 본문이다.** 저장소 사람만 아는
이야기를 적으면 그대로 배포된다.

## 구조

| 섹션 | patch | minor·major |
|---|---|---|
| H1 `# dongmodoro X.Y — <한 줄 정체>` | 금지 | major 만 필수 |
| 리드 문단 (제목 없이 1~2문장) | 필수 | 필수 |
| `## 고친 것` / `## 새로 생긴 것` | 필수 | 필수 |
| `## 알아 둘 것` | 조건부 | 조건부 |
| `## 업그레이드 — 되돌릴 수 없다` | 조건부 | 조건부 |
| `## 설치` | 필수 | 필수 |
| `## 근거 문서` | 금지 | 조건부 |

- **업그레이드**의 조건은 하나다 — 그 판이 파괴적 마이그레이션을 도는가. 돌면
  `### 시작하기 전에` · `### 복귀선` · `### 마이그레이션이 실패하면` 이 전부 필수다.
  안 돌면 절 자체를 쓰지 않는다. `마이그레이션 없음` 같은 빈 안내를 두지 않는다.
- **알아 둘 것** — 버그로 오해할 수 있는 **의도된** 동작이 있을 때만.
- **근거 문서** — 패치에는 달지 않는다. 패치의 근거는 커밋이고 자동 구간이 이미 말한다.
- 본문 불릿은 `- **<화면·기능 이름>** — <무엇이 어떻게 달라졌는지>` 꼴이다.

레퍼런스: 패치는 [2.0.1](../../../docs/release-notes/2.0.1.md),
메이저는 [2.0.0](../../../docs/release-notes/2.0.0.md) (업그레이드 절 포함).

## 설치 블록

서명을 받지 않는 동안 매 판에 그대로 싣는다. 아래를 복사한다.

~~~markdown
## 설치

`.dmg` 를 받아 `dongmodoro.app` 을 응용 프로그램 폴더로 옮긴 뒤, **첫 실행 전에 한 번만**:

```
xattr -dr com.apple.quarantine /Applications/dongmodoro.app
```

서명·공증을 받지 않아서 macOS 가 기본으로 막습니다.
~~~

**링크로 대신하지 않는다.** 이 안내가 필요한 순간은 앱이 안 열리는 순간이라, 클릭이 하나
더 있으면 안 된다.

## 링크

- **절대 URL 만.** 상대 경로는 릴리스 페이지에서 100% 깨진다.
- **그 릴리스의 태그에 고정한다** — `https://github.com/easyDong19/dongmodoro/blob/v2.0.1/docs/...`.
  `main` 은 움직이므로 쓰지 않는다. 2.0.0 노트에서 연 문서는 2.0.0 을 설명해야 한다.
- 대상이 그 태그에 실재하는지 확인한다: `git cat-file -e v2.0.1:docs/...`
- **자기 자신을 링크하지 않는다** — 노트 파일은 그 태그 시점에 없다.

## 작성 원칙

1. **사용자의 손에서 무엇이 달라지는지로 쓴다.** 내부 구조·리팩터링·테스트는 자동 구간의
   몫이다. `TodayList 를 2단으로 리팩터링` 이 아니라 `할 일 제목이 더 이상 잘리지 않는다`.
2. **리드 문단이 전부다.** 릴리스 목록과 알림에서 보이는 것은 첫 두 줄뿐이다.
3. **되돌릴 수 없으면 그 사실이 제목에 온다.** 복귀선은 `무엇 + 무엇` 조합으로 적는다.
4. **[CONTEXT.md](../../../CONTEXT.md) 캐노니컬 용어만 쓴다.** 폐기 용어는 과거 노트에만
   남는다 — 그때는 사실이었으므로 소급 수정하지 않는다.
5. **문구는 사실만 말한다.** `드디어`·`대폭 개선` 같은 자평을 붙이지 않는다.

## 금지

- 저장소 내부 사정 (이 파일의 용도·워크플로 설명·CONTRIBUTING 절차)
- 상대 경로 링크
- 손으로 쓴 `## What's Changed` · `**Full Changelog**`
- 이모지
- 릴리스 이름을 반복하는 H1 (`# 릴리스 노트 2.0.0`) — 릴리스 이름이 이미 `v2.0.0` 이다
- 신규 파일에 폐기 용어 (예상 뽀모·예산·가용량·소진·계획 대비·과적)
